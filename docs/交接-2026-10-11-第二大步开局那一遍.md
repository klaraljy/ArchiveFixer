## 4. 已定位的错误（全部有运行期证据）

### ③ 多出来那一层里的"片"（断点 `ResultFinalizer.cs:450`，逐字）
```
hasInner=true inPlace=false unopened=false inner=111__ dest=…\in\111__\111__ items=1 chain=0
name=111_.par删t1.ra除r  isDir=false
```
- 两道闸门（`:414` 就地替换层已在树里、`:440` 根上就是那个没被打开的内层包）**都不成立**（根上是**一个文件**、无目录、无 chain）⇒ `ResolveWrapperName` 按"最内层 = 内层包基名目录"照建 ⇒ `111__\111__\111__\`。
- **那一层本身是设计里那一层**（`ResultFinalizer.cs:256~265` 明写"与 destDir 最后一段同名也照建"）；错在**它里面躺着的是分卷组 `111_` 的第 1 片，而且是脏名**。
- 硬链接钩子（`ARCHIVEFIXER_HARDLINK_PROBE`）逐字 3 条，**没有一条**落在 `111__\111__\111__` ⇒ 那文件不是链接建的（移动/拷贝）；程序日志**全文没有任何一行认领它**。
- **第 0 档没能碰到它**：它是在递归层产物**被定稿搬进落点层之后**出现在那儿的，而第 0 档跑的是**递归层的候选**（路径对不上）。

### ④ 8 次被闸门拦
- 闸门判据输入逐字：`过路层的其余物这次没删 —— 其余物里有不属于这一组的文件（判不出它是不是被接手的过程物）`。
- 与 ③ 同源：没人认领的"片/过程物"不清掉，④ 过不去。（**这条的"哪一档没收走"还没取证** —— 首要嫌疑：账上记的是**规范名**、盘上是**脏名**，两个名字对不上 ⇒ 收不到；未取证，不许当结论。）

## 6. 工具纪律（本会话实测，省下一次踩坑）

- `debug_launch` 的 `env` 参数**会直接报错** ⇒ 调试档位走 `debug-sample.txt`（配置文件**优先于**环境变量，否则 User 级 `ARCHIVEFIXER_EEEE_COPY` 会悄悄盖掉它）。
- 断点**必须在 `debug_launch` 之前**设（pending 会在进程起来时绑上）；`batch_evaluate` 在"停在入口点"那一刻设触发器绑不上（0 命中）。
- `debug_continue` 之后用 `stacktrace_get` 轮询（没有 `breakpoint_wait`）。
- 一次 `evaluate` 用**字符串插值**读多个值（`$"a={x} b={y}"`）；⛔ 别用 `??`、别用 `[...]`（解析器会炸）；`TaskCollection.Count` 之类**没有索引器**，要在有局部变量的帧里读。
- 夹具自查：`_tmp\ArchiveFixer\cleanup.ps1`；`ffff-real\in` 是**从 `H:\` 复制重建**的（删了要重建：`FFF\111__\111__.rar` + `FFFF\{1112__,1113__}\*.rar` + `FFFF\1114__\111_.part4.rar`→改名 `111_.part4.raAAAAAr`）。
