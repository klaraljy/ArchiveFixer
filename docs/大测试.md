# 大测试（随机伪装原包 × 12 种用户选择 × 20 轮）

> 目的：用**随机组合的大批量真实伪装原包**，把 ArchiveFixer 的**基础设置**一次压出原形 ——
> 引擎能不能吃下每一种格式、专属算法（解压 + 后缀）够不够程序性、轮次模型（`1+=1`）撑不撑得住多层链、
> 清理口径在 12 种用户选择下是否都对、以及**只靠日志**能不能把每一个错误定位到行。
>
> ⛔ 三条铁律（本轮大测试特有）：
> 1. **禁止把原包复制到 E 盘**：整场测试都在 `H:\BaiduNetdiskDownload\大测试\` 里进行（副本、输出、其余物、回收站都落在 H:）。
> 2. **只能看日志排查**：测试期间不看盘上文件、不做逐步调试 ⇒ 日志必须**自足**（判据输入、身份卡、配方与种子、每层产物清单全在日志里）。
> 3. **每一次都必须是随机出来的**：不允许"跑第二遍就复用手工挑好的那一种"。

## 2. 引擎与格式矩阵（"引擎能干什么"）

本机实测：自带 `src\ArchiveFixer\tools\7zip\7z.exe`（**26.03**）+ `src\ArchiveFixer\tools\unrar\UnRAR.exe`（560 848 B）；
用户装了完整 WinRAR **6.11**（`Rar.exe` / `WinRAR.exe` / `UnRAR.exe`）。

### 2.1 单一压缩包（第一大步）

| 格式 | 怎么造 | 专属解压算法 | 专属后缀算法 |
|---|---|---|---|
| 7z | `7z.exe a -t7z` | 7-Zip | 魔数 ⇒ `.7z` |
| RAR5 | `Rar.exe a -ma5` | WinRAR / UnRAR | 魔数 ⇒ `.rar` |
| RAR4 | `Rar.exe a -ma4` | 同上 | 同上 |
| RAR4 之前（RAR2/3） | ⚠ **本机 Rar.exe 6.11 造不出** | 只做**识别**专项（按格式构造头 + 真样本若有） | 同上 |
| zip（7-Zip 造） | `7z.exe a -tzip` | 7-Zip | 魔数 ⇒ `.zip` |
| zip（WinRAR 造） | `WinRAR.exe a -afzip -ibck -m0`（⚠ **`Rar.exe` 造不了 zip** —— 它只写 RAR，实测确认） | WinRAR | 同上 |

### 2.2 分卷压缩包（第二大步）

| 族 | 怎么造 | 入口包 | 专属解压算法 | 专属后缀算法 |
|---|---|---|---|---|
| `7z.001` | `7z.exe a -v25m` | `X.7z.001` | 7-Zip（内容里**没有卷号** ⇒ 靠"第 1 片有魔数 + 尺寸规律 + 试开"） | `.00N` 卷标记 |
| `part1.rar`（RAR5 / RAR4 / 前 RAR4） | `Rar.exe a -v25m -ma5/-ma4` | `X.part1.rar` | WinRAR / UnRAR | `partN.rar` 卷标记 |
| `zip + z01…`（WinRAR 跨盘） | `WinRAR.exe a -afzip -ibck -m0 -v25m`（实测：`z01/z02/z03` 各 25 MiB，末片 `.zip` 很小 —— 正是那一族的形状） | **末片 `X.zip`** | WinRAR（头尾编号是反的：`.zip` 是末片） | `z0N` + 末片 `.zip` |
| `zip.001`（7-Zip 切） | `7z.exe a -tzip -v25m` | `X.zip.001` | 7-Zip | `.00N` 卷标记 |

> 「专属算法」= **解压算法 + 后缀算法**，两者的判据都必须**从底层识别到的内容出发**（`FileNature.Inspect` 那张卡：
> 内容格式 / 内容分卷身份 / 名字线索 / 盘上物理身份），⛔ 不许只看基名与后缀。
> 用户自加引擎 ⇒ 走**统一算法**（不认引擎细节）。

## 3. 伪装矩阵（"原打包者想干什么"）

### 3.1 后缀伪装（**每一个压缩包文件都要经历**，含每一片分卷；五种**纯随机**）
1. 后缀里加**中文字符**：`.7z删除`、`part删1.r除ar`
2. 后缀里加**非中文字符**：`.zaa01`、`rabbr`
3. 后缀里加**重复字符**：`.zAAAAAip`、`.7z.00CCCCCC1`
4. **直接删后缀**：`111.zip → 111`、`222.zip.001 → 222`
5. **改成别的类型**：`111.rar → 111.pdf`、`222.part1.rar → 222.jpg`

### 3.2 前面加媒体伪装（**只针对单一压缩包**；≥2 个文件，类型纯随机，视频与图片都要出现）
- 视频池：ffmpeg 现造的 12 个小视频（`testsrc/smptebars/gradients/mandelbrot…`，1–6 秒、160×120–640×480、h264，共 ~0.9 MB）
  ＋ 用户给的真视频 `9月21日.mp4`
- 图片池：ffmpeg 现造的 12 张 PNG/JPG（~0.25 MB）＋ 用户给的真图 `960e….png`
- 生成命令：`pwsh _tmp\ArchiveFixer\大测试-生成媒体.ps1 -Videos 12 -Images 12 -Seed <种子>`
  （⛔ 落在 `原物\生成的媒体\`，⛔ 不碰用户给的两个真文件）
- 目的：造出"**双面文件**"（前缀媒体 + 尾部归档），逼程序走"先定位归档起点、抠出来再解"那条路。

### 3.3 单独分卷的伪装 + 分卷位置摆放
- 单独特定的某一卷被改名成**别族的样子**：`111.part1.rar → 111.zip`、`111.z01 → 111.7z`、`111.7z.001 → 111.rar`
- **摆放 = 像 EEE / FFF 那样**（用户 2026-10-11 澄清）：**一片一个目录**、目录名带这一组的基名（第 1 片 `<基名>`、第 k 片 `<基名>(k)`），
  并且**片与片之间跨层级** —— 父目录 / 子目录 / 孙目录里**都要有片**（EEE 真形状 `111\111\111\111.part1.rar`、FFF 真形状 `1112__\1112__.rLLLLar`）。
  ⛔ 不是"每一片都埋三四层"。
- 每一份样本 ≥2 片时**至少有一片**做过别族伪装（配额，不交给运气）。

### 3.4 深度与 `1+=1`
- 每份原包**至少 5 层压缩**，其中**至少 2 层是分卷**；
- 上一层解出来的东西就是下一层的"原包"（轮次模型的基石）⇒ 第二大步之后可以**又是第二大步**、也可以回到第一大步。

## 4. 随机性规范（每一份原包都是随机排列组合）

| 随机变量 | 取值 | 说明 |
|---|---|---|
| 随机种子 | 32 位整数 | 每份原包一个，**写进日志与配方** |
| 套娃层数 | 5–7 | 每层是"单一包"还是"分卷组"随机（分卷层 ≥2） |
| 每层格式 | 7z / rar5 / rar4 / zip(7z) / zip(WinRAR) | 相邻层可重复；**逐层随机抽** |
| 分卷族 | `7z.001` / `partN.rar`(rar5) / `partN.rar`(rar4) / `zip+z01`(WinRAR 跨盘) / `zip.001`(7z 切) | 分卷层各随机 |
| 分卷大小 | 25 MB | 内容 ~96 MiB ⇒ 一档 **4–5 片** |
| 后缀伪装 | 五种，**逐文件独立抽** | 含分卷的每一片 |
| 单独分卷伪装 | 抽 1–2 片改名成别族 | **≥2 片时至少一片**（配额） |
| 摆放 | 一片一目录 + 跨层级（父/子/孙里都要有片） | 见 §3.3 |
| 媒体前缀 | **≥2 个媒体文件、视频与图片都要出现** | 只对单一包，见 §3.2（配额） |

| 目录名 | 第 n 次 = 这个数字写四遍（1→`1111`、10→`10101010`、20→`20202020`） | §1 |

## 8. 判据（逐份原包都要绿）

| # | 判据 | 读法 |
|---|---|---|
| ① | 能解的都解出来 | 盘上有内容物 —— **按配方里那一个文件名认**（`recipe.json` 的 `content.path` 末段，如 `444.mp4`）+ 字节数与 `content.bytes` 一致 |
| ② | 成品全在同一层 | 内容物只出现在一个目录里 |
| ③ | 盘上只剩成品 | 拿**跑之前那棵树**做差集：跑完之后**新出现**的东西里，除了内容物（以及"其余物不处理"那一档允许留的）不该有别的 |
| ④ | 过程物按档处理 | 其余物 / 回收站 / 彻底删除 —— 与随机到的档一致 |
| ⑤ | 工作区无残留 | 没有 `.ArchiveFixer.work` 残留 |
| ⑥ | 日志自足 | 只拿日志能重建"每一份文件经历了什么、被哪条判据挡下" |
| ⑦ | 纪律 | 全程无 E 盘副本（H 盘空间曲线可证） |

> **判据工装自己出过两次错（如实记账，2026-10-12）**：
> ① 树记录给每条尾巴拼了 `|<字节数>`，而判后缀的正则带 `$` 锚点 ⇒ **真内容物被算成残留**（第 1 遍 ①②③ 全红的假象）；
> ② 内容物原先按一张后缀白名单认（含 `.rar/.7z/.zip`）⇒ **把分卷的"片"也算成成品**，分卷族那几轮的 ①③ 读数是虚的。
> 两处都改在 runner 里（`内容物按配方文件名认` + `残留按跑前跑后差集算`），⛔ 判据定义一个字没改。
> ⚠ 第 1/2 两遍的 `result.json` 是老判据写的，读数只能用离线重算脚本看。

### 8.1 分层与"能不能跑完"的边界（第 1 遍实测）

- 用户真实设置 `MaxRecursionDepth = 5`（只读 `E:\ArchiveFixer\data\appsettings.json` 核过）⇒
  **样本层数只能是 5**（L0..L4）：写成 6–7 层时程序必然停在第 6 层、产物不发布 ⇒ 整单「解压失败」——
  那测的是"样本超限"而不是程序。用户口径是"≥5 层"，5 层正好满足。
- 发现记在 `大测试日志\发现.md`（四族 + 逐字证据 + 修了什么）。

### 8.2 曾经的缺口（第 3 遍实测）——**两条口径都已落地**（2026-10-12）

> **2026-10-12 用户口径（两条都批准、都已实现 + 守门 + 红检）**：
> ① 「我们的逐层只是针对彻底删除的，但是进回收站档，其实也可以弄成过程物逐层进回收站……
>    后面觉得没有什么问题」⇒ **回收站档也逐层**：与「彻底删除」档**共用同一条闸门链**
>    （`PurgeLayerSourcePackage(..., toRecycleBin: true)`），只差动作（永久删 → 送回收站）；
>    三条路都落（递归钩子 / 续解层 / 触发点措辞）。守门 `ChainLayerReclaimTests` 用例E / 用例R3。
> ② 「这个第一大步完成之后就是扫描所有剩余的，我之前说过的什么"父目录+自己这一层+所有子目录"
>    在这个新框架下可能是不成立的」⇒ **收卷窗口那一档作废**：候选来源并上**本批所有剩下的路径**
>    各自所在目录（`VolumeNameRepair.EnumerateVolumeCandidatesNearby(path, extraPaths)`）——
>    ⛔ 只改"去哪儿找"，三道闸门（同族同基名 / 卷号一份对一份 / 整组自洽）与"整组完整才允许搬/删"
>    一个字没动。守门 `CrossLayerVolumeGatherTests.本批所有剩余的都要被看见…`。

**链内解出来的分卷片会被当成「内容物」发布到落点**（于是 ③「盘上无残留」红）。

- 现场（可复现：样本 `6666`（种子 1468998785）× 组合 4 = 就地/原包→其余物/**其余物→回收站**）：
  判据 ①✔②✔④✔⑤✔、**③✘**；残留三条 = `bbb\bbb-L4\bbb-L3.z01|.z02|.z03`（各 26 214 400 字节），
  而内容物就在同层的 `bbb-L1\bbb-L0\444.mp4`（100 714 217 字节）。
- 程序自己的两行日志把成因写得明明白白（同一轮）：
  - `[INFO] …：本次内容物 —— bbb-L3.z01、bbb-L3.z02、bbb-L3.z03、bbb-L1` ← **片被算成内容物**；
  - `[INFO] …：结果校验 —— 校验通过：预期 1 个文件 / 100714217 字节，实际 4 个 / 179357417 字节（实际比预期多 3 个…；判据是「实际多于预期也算通过」）`；
  - 而**同一批**的层扫描那条路**认得出**它们是片：`跳过：…bbb-L3.z01（是分卷的后续卷，起点在第一卷上）`
    ⇒ 两条路对"这一份是不是内容物"给了相反答案。
- 位置（三处，供下一轮动手时定位）：
  - 分类那一处 = `Extraction/ResultFinalizer.cs` 的 `Plan(...)`：它按 `StagedEntry.IsProcessArtifact` /
    `contentRoot` 把暂存树切成 `Moves` 与 `ProcessArtifactMoves`；消费点见
    `ViewModels/ExtractionCoordinator.cs:4950`（`processSources`）与 `:6304-6312`（「本次内容物」那行）。
  - 认得出片的那把尺子已经现成：`OneClickCoordinator.IsVolumeContinuationPart(file)`（`:2347`，
    逐字输出"是分卷的后续卷，起点在第一卷上"）——⛔ 不要在分类那处另写一套名字规则。
  - 逐层回收那一档（`ExtractionCoordinator` 的"这一层的过程物…当场永久删除 N 个"）**只在「彻底删除」档跑**，
    所以回收站档连兜底都没有 ⇒ 这一格在回收站档必然露出来。
- 为什么没顺手改：它动的是**内容物 / 过程物**这条最贵的分类（25 GB 那次事故就在这条线上），
  且要放宽/收紧的是"哪些文件算过程物" ⇒ 按 §「放宽判据要先问用户」与 unsafe-paths 的闸门清单，
  先记缺口、等口径。

### 10.2 造包器（`_tmp\ArchiveFixer\大测试-造困难包.ps1`）——与简单批的差别

1. **三类各 33%**：基础链 = **3 层**，每层一个类别（7z / rar / zip，顺序随机）⇒ 每类**正好一层**；
   类内再选变体：7z{单一, 分卷}、rar{rar5, rar4, 分卷rar5, 分卷rar4}、zip{zip(7z), zip(WinRAR), 分卷zip(7z), 分卷zip(WinRAR)}；
   其中**恰好两层是分卷**（保证样本里必有一组片，且片数 ≥3）。
2. **每一片都伪装**（⛔ 不再只挑 1–2 片）：五法逐文件独立抽 + **EEE 式卷标记塞垃圾**（第 6 法，只对片）——
   真机逐字形态：`111.z0删除1`、`111.z11111111110删除3`、`111(2)_.zi删除p`、`111_.part4.raAAAAAr`、`222-L4.part4.rarzz`。
   五法细则（用户规格逐字）：① 中文只用「删除」「中文」、**穿插在后缀内部、顺序不变**（`111.7删除z`、`222.par删t3.ra除r`）；
   ② 非中文字符**先备 30 个**、随机挑 2–3 个塞进去（`111.zscip`、`333.z0@2`、`444.ra!r`）；
   ③ 直接删后缀（单一包 `111.zip`→`111`；片可只删卷标记 `111.zip.001`→`111.zip`，或两段都删→`111`）；
   ④ 重复字符（`111.ziAAAAAp`、`333.7z.0@@@@@@@01`、`444.part1.ra删删删删删除除除除除r`）；
   ⑤ 改后缀（→`.png`/`.pdf`/`.mp4`）。
3. **每一片可以单独套 0–2 层**：套的那一层也是单一压缩包（格式随机），**套出来的名字同样要伪装**；
   ⇒ 同一组的分支长度**不一致**（这是本批新加的难点）。
4. **媒体前缀只挂在"单一压缩包"前面**（用户口径，§3.2 早已如此）：顶上是分卷组 ⇒ **一片都不挂**
   （真机实测：前缀挂在片上会让整组读不出来 —— `7z x X.part1.rar` 退出码 2 / `ERROR: Data Error`；
   剥掉前缀后同一条命令退出码 0、产物 100 715 242 字节）。
5. **摆放**：一片一个目录（目录名 = 这一支的顶名），**同一组各片跨 ≥3 个不同层级**。
6. **深度上限**：基础 3 层 + 最多 2 层套娃 = **最深 5 层**，正好等于用户设置 `MaxRecursionDepth = 5`（⛔ 不许超，
   超了样本必然停在上限、产物不发布 —— 那测的是样本超限，不是程序，见 §8.1）。
7. **内容物 60 MB**（`-ContentMb`，默认 60）：25 MiB 分卷 ⇒ 一层切 **3 片**；体积压到 ~100–200 MB/份，
   30 份 ≈ 4–6 GB（H 盘只剩 ~68 GB，还要放指定位置那一棵树）。**难度在结构，不在体积**。
8. **加密**：密码 `31中文41密码59！@。26`（密码本第 7 行）。`zip(7z)` 那一格吃不下中文密码
   （实测 `7z a -tzip -p<中文>` ⇒ 退出码 2）⇒ 该格不加密，配方里如实标 `encrypted=false`。

### 10.5 「底层到底能读到什么」——按族实测（2026-10-13，`volinfo` 只读探针）

> 用户口径（逐字）：「卷号就在末尾，而且**底层也能检测到总共有多少卷**，如果和 zip 是一样的话就没有问题，
> 如果不一一样那就要多花点心思写专属算法了」—— 下面是**实测**答案（不是推测）。

| 族 | 自身卷号 | 总卷数 | 能不能证明"我是这一族的分卷成员" |
|---|---|---|---|
| ZIP 跨盘（`x.zip` + `x.z01…`） | **只有末片**读得出（EOCD 的盘号字段）；`z01` 实测 `卷号=判不出` | **末片** EOCD 里有"总盘数" | `z01` = `VolumeMember` ✓；再往后（`z02`）实测 `格式=Unknown` ⇒ 判不出 |
| 7z 切的 zip（`x.zip.001…`） | 判不出（中间片没有 EOCD） | 同末片 | 部分 |
| **RAR5**（`x.partN.rar`） | ✓ 每卷自述（实测 `分卷身份=VolumeMember 卷号=4`） | ✗ 只有"后面还有没有卷" | ✓ `VolumeMember` |
| **RAR4**（`x.partN.rar`） | ✗ **判不出**（实测 `卷号=判不出`） | ✗ | ✓ `VolumeMember` + **首卷标志**（实测 `首卷标志=True/False`） |
| 7z（`x.7z.001…`） | ✗ 格式里没有卷号 | 可用**首卷起始头自述的整包长度 ÷ 片大小**推（`SevenZipStartHeader`，项目已在"免试"那一档用它） | 判不出 |

⇒ **结论：和 zip 不一样**。只有 RAR5（自身卷号）与 ZIP 末片（盘号 + 总盘数）够用；
**RAR4 与 7z 必须写专属算法**，可用证据：
- RAR4：`首卷标志` + 名字（现已能读对，见 §10.6）+ **尺寸规律** + **试开**（把候选按规范名拼起来交给引擎验证）；
- 7z：首卷起始头自述的整包长度 ⇒ 总片数 = ⌈整包长度 ÷ 首片大小⌉ ⇒ 槽位可定。
- ⛔ **引擎报的"缺哪一卷"不能当权威槽位名**：实测它只是**按当前文件名把下一个名字推出来**，
  逐字 `ERROR = Missing volume : bbb-L2.part98598542删除2.rar`（把伪装垃圾原样带进去了）。

### 10.6 已修：卷标记容忍判据按"结构"而不是"个数"（三档 → 五档 + 一处名字闸门）

困难批主族（顶层是多片）连着三处真缺陷，逐字证据与修法见 `大测试日志-困难\发现.md` 顶部：

1. **分卷片被当成"双面文件"**：`检测到内嵌归档：已从偏移 162 处取出 26214238 字节`（切片里恰好含下一层 RAR 的魔数）
   ⇒ `ArchiveDetectService` 加名字闸门（名字自报是分卷片 ⇒ 不做内嵌归档判定）。
2. **卷标记"删 ≤2 个字符"的上限**：`资源222-L2.zip.--p002`（3 个杂质）认不出 ⇒ 第四档 = **任意长度垃圾前缀**
   （标记贴段末 + 垃圾含非字母数字 + 无 ≥3 连续 ASCII 字母才算"塞进去的垃圾"）。
3. **数字型拉长卷号**：`0000000001`（"重复字符"那一法）认不出 ⇒ 链里被当普通内层包去开 ⇒
   `已完成 1 层，停在第 2 层，原因：压缩包损坏` ⇒ 第五档 = 连写 ≥3 的片段可压成 1 或 2 个，取**唯一**合法三位标记。

外加一处 **partN 专属**（实测生效，逐字见 `run-2222`）：`bbb-L2.part98598542删除1.rar`
（EEE 式：`part` + 随机数字 + 「删除」 + 卷号）原来被读成基名 `bbb-L2.part98598542删除1`（卷号 985985421 越界 ⇒
整条 partN 解析失败），现在读到 **`基名=「bbb-L2」，卷号=1，规范名=「bbb-L2.part1.rar」`** ✓。

### 10.8 第十轮（2026-10-13 上午）：坏名字那两族的定案与修法

原包：同种子（`-SeedBase 900000000`）+ 同组合（`-FixedCombos`），30 份重造后逐份跑。

**这一轮的读数（修前）**：9 绿 / 21 红；其中 ①「内容物解出来」红 18 份。按日志把 18 份归类，**缺卷 / 组凑不齐是主族**（13 份里"缺卷"字样 5–42 次不等），另有一族是"顶上的片根本读不出来"。

**定案一：脏**卷标记**那一截还原不出来 ⇒ 入口包在盘上永远不叫规范名**（样本 `11111111`，组合 6）

- 判据输入逐字（12 次）：`222-L2.part3.rar：这一组该拼到哪一层 —— 判不出 ｜ 这一组的引用名=…，入口包=222-L2.part1.rar，产出它的那一单=判不出` ⇒ 接片一个字节都不动 ⇒ 三片永远散在三条链的落点里 ⇒ 整组凑不齐。
- 取证（⛔ 不是读代码推）：探针 `repair` 档直接调产品唯一那个计划器 ⇒ `VolumeNameRepair.Plan("222-L2.part删删删1.rar")` = `CanRepair=True / SuggestedFileName=222-L2.part1.rar` ⇒ **计划器没问题**；探针 `names` 档补两行 ⇒ 差别在第一步 `TryResolveVolumeBaseName(…, DisguisedVolume)`：`222-L2.part2.中文rar` = True、`222-L2.part删删删1.rar` = **False**（脏字符把卷标记自己撑坏了）⇒ 递归层那道"纯文本清洗"整档不做。
- 修法：第 0 档加**第二档**（基名边界拆不出来时按每一个点试拆；基名纯 ASCII + 去完非 ASCII 仍是本来那个形态 + 不许拼出空点段；**结果唯一**才认）。
- 修后实测：日志出现 `还原伪装后缀（只改名、内容一个字节不动）：222-L2.part删删删1.rar → 222-L2.part1.rar`；引擎的话从 `7-Zip 无法识别或不支持该格式` 变成 `ERROR = Missing volume : 222-L2.part2.rar`（**真把这一片读成分卷第 1 卷了**）。①仍红 —— 卡在下一环（见下）。

**定案二：归档后缀被当成"垃圾"吃掉 ⇒ 盘上那份被改名成 `111-L2.924`**（样本 `1111`）

- 盘上事实：`111(3)\111-W2-0\111-L2.924`（10478834 字节）—— 它本来的身份是 `111-L2.7z.003`（这一组的第 3 片）。
- 尺子实测（`names` 档）：`Tolerant(末段「7z-924」) = True（→924，垃圾「7z-」）` ⇒ 读成"基名 `111-L2` 的第 **924** 片" ⇒ 还原工序照那个读法改名 ⇒ `7z` 那一段没了。
- 名字来路 = 造包器的**撞名兜底**（两片伪装成了同一个名字 `111-L2.7z` 时缀一个随机数）。但判据与来路无关：任何 `X.7z-924` / `X.zip-002` 都会被同一条读法吃掉后缀。
- 修法：`LooksLikeInsertedJunk` 开头加结构闸门 —— "垃圾"剔掉尾部非字母数字之后**整个就是归档本体后缀**时不算垃圾。⛔ 不挡 `.001`/`.z`。
- ⚠ 如实记：实测只有 `7z-924` 那一格是这条闸门挡下的（`zip-002`/`rar-1` 老判据本来就否 —— 垃圾里 ≥3 个连续字母那一条）。

**两处都对上了真 7-Zip（`111-L2.7z.yvA001` 那一族）**：同一份字节拿规范名 `.001/.002/.003` 放在同一目录 ⇒ `7z t` = `Everything is Ok`（`Physical Size = 62907634`）；用伪装名直接 `7z l` ⇒ `ERROR: … Cannot open the file as archive` ⇒ **7-Zip 按名字找兄弟卷**，所以"名字必须先还原"这一条是硬约束，不是我们自己的偏好。

### 10.9 下一步方向：把"后缀 / 卷标记"收成**一次解析**（用户 2026-10-13 给的先例清单，逐条对到我们的缺陷上）

用户三条原话与我们的对应：

1. **「连"程序自己产的、已经没用的那份副本" 这个不就是过程物吗」** —— 对。那东西的身份就是**过程物**，所以正确出口是过程物那条（`Extraction/ProcessArtifactLayout` 的"把过程物搬进其余物"），⛔ 不该给"已被整组接走的那份副本"另开一条特殊路（第 9 修是接在"落地片"那条上的，方向对、出口还不是最终那个）。
2. **「这么基础的错误，说明后缀相似匹配无论是单一压缩包还是分卷压缩包这个算法还有待提升」** —— 指的就是这一格（盘上事实）：`111-L2.7z-924` 被读成"基名 `111-L2` 的第 **924** 片"，于是还原工序把盘上那份改名成 `111-L2.924`（`7z` 那一段没了）。第 11 修只是把这一格**挡住**（不吃归档本体后缀），**没有**把它解析对。
3. **先例清单里最对得上我们的一条**：`Complex-Unzip-Tool`「能根据 `.002/.003` 反推被改名的 `.001` 主卷」—— 正是我们"接片 / 收口"那一档要的**组级推断**。

**建议的下一步（唯一出口：一次解析返回 `(clean_base, canonical_format, volume_index?)`）**，顺序照先例（`OnlyUnzip` / `AutoExtract` / `jieyaTool` 都是这个次序）：

1. **归一**：去控制符 / 首尾空格与点 / 路径分隔符；留一份小写副本**仅供判断**（⛔ 不改盘上的名字）。
2. **分卷标记优先**：`part\d+` / `.00N`（含被拉长、夹垃圾的）/ `z0N` / `r0N` ⇒ `(base, family, index)`。第 10 修已经补了"脏字符把卷标记自己撑坏"（`part删删删1`）那一格。
3. **复合格式**：`tar.gz` / `tgz` / `tar.bz2` / `tar.xz` / `tar.zst` —— 我们目前按单段后缀处理，这一档要单独认。
4. **单段格式**：`zip/7z/rar/gz/bz2/xz/zst/tar/iso`。
5. **尾部杂物循环剥**：已知杂物（`.bak/.tmp/.old/.orig/.part/.crdownload/.download`）+ **结构化那一类** —— 本体后缀后面的东西**既不是卷标记、也不是已知杂物**时，按"本体 + 杂物尾巴"处理，⛔ **绝不把 `-924` 读成卷号**（第 11 修挡住的正是这一格；借这条把它**解析对**：`111-L2.7z-924` ⇒ `(111-L2, 7z)`）。
6. **magic 复核**：以上跑完再读文件头；扩展名与 magic 不符 ⇒ 按真实格式改名或拒。⛔ 我们的既有纪律一个字不放宽：**读不出 ⇒ 什么都不做**（⛔ 不按后缀猜格式）。
7. ⛔ **单一包与分卷包共用这同一份解析**（用户点的那句"无论是单一压缩包还是分卷压缩包"）；产出 `(clean_base, canonical_format, volume_index?)`。

**组级那一半（"反推主卷"）**：缺第 N 片时，把"干净基名相同 + 规范格式相同 + 尺寸符合同一组的规律"的候选，按假设名**硬链接**进这一组的目录，再让既有出口 `VolumeProbeVerifier` **真的试开**一次 —— 试开成立才算数（⛔ 不按猜测改名）。这一条把"**分卷伪装成单一**"（`111-L2.7z` / `222-L2.zip` / `333-L2.mp4` —— 造包细则第 ③ 法"两段都删"那一支）从"名字判不出"变成"有证据可判"，而它正是困难批里最大的一族：48 个伪装名里 12 个属于这一族。

**这几条各自的落点（下一轮照着改，⛔ 一处一处来、每处都先做红检）**

- **规则 5（本体后缀 + 杂物尾巴）** ⇒ `Helpers/ExtensionHelper.cs` 的 `TryRecoverDisguisedArchiveBody`（`:851`）
  加一档："这一段**以已知本体后缀打头**、后面粘的尾巴**不是卷标记形状** ⇒ 还原成本体后缀"。
  ⛔ 与"卷标记优先"互斥的判据只有一条：**`.924`（一个点段、三位数字）= 卷标记；`-924`（粘在本体后缀后面）= 杂物尾巴**。
  第 11 修已经把 `-924` 那种读法**挡住**，这一档是把它**解析对**（`111-L2.7z-924` ⇒ `(111-L2, 7z)`）。
- **规则 3（复合格式）** ⇒ 同一个函数 + `KnownArchiveExtensions`：`.tgz/.tbz2/.txz` 已经在表里，
  但 `tar.gz` / `tar.bz2` / `tar.xz` / `tar.zst` 这种**两段**形态要单独认（现在按单段后缀处理）。
- **组级那一半（"反推主卷"）** ⇒ 试开出口已经现成：`Extraction/VolumeProbeVerifier.VerifyAsync`
  （硬链接 + 引擎真列一次目录）；缺的是**给缺片槽位生成候选**那一处（`ExtractionCoordinator` 里
  "这一组该拼到哪一层 / 接片"那一族）。判据顺序：干净基名 + 规范格式 + 尺寸规律 ⇒ 硬链接试开 ⇒ 成立才动。
- **用户点 1（"那份副本就是过程物"）** ⇒ 出口 `Extraction/ProcessArtifactLayout.cs:233` 的归置规划
