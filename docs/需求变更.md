## 2026-09-21 ｜ M1 冒烟测试发现并修复两个改名 bug

- **提出人**：agent 发现（M1 验收测试 `ArchiveFixer.Tests/BaselineSmokeTests.cs` 跑出来的，不是猜的）
- **类型**：修正行为（缺陷修复）
- **归属里程碑**：M1
- **内容**：

  1. **分卷文件会被"智能修正后缀"改名，直接切断分卷链（严重）**
     `volume.7z.001` 被识别为 7Z 后，多重后缀修正把文件名改成 `volume.7z` ——
     而 7z 只认 `.001` 这一套命名，改完之后整组分卷再也解不开。
     修复：新增 `ExtensionHelper.IsVolumePartExtension()` 与 `FileNameHelper.IsVolumePartFileName()`
     （覆盖 `.001`–`.999`、`.z01`–`.z99`、`.r00`–`.r99`、`.part1`/`.part01`），
     在 `RenameService.BuildFixByDetectedFormatFileName()` 开头拦截：分卷文件一律不改名。
     同时 `FileNameHelper.IsMultiExtensionSuspicious()` 不再把分卷报成"多重后缀疑似伪装"
     （改判为"后缀不匹配"；设计.md §七 要求的独立"分卷后缀"状态留到 M2 与分卷组识别一起做）。

  2. **路径写法差异会把"无需改名"变成"改成 `名字(1).ext`"**
     `RenameService.BuildPreview()` 用**原始字符串**比较新旧路径。只要路径写法有差异
     （正斜杠、冗余分隔符、大小写），`File.Exists(newPath)` 就会把文件自己当成"已存在的目标"，
     于是 `data.tar.gz` 这种本来不用改的文件被预览成 `data.tar(1).gz`。
     修复：改用已有的 `SafePathHelper.PathEquals()`（内部走 `Path.GetFullPath` 规范化）比较 ——
     涉及 `RenameService.BuildPreview()`、`RenamePreviewItem.CanRename`、`RenamePreviewItem.SyncNewPathFromNewFileName()` 三处。

- **影响**：`Helpers/ExtensionHelper.cs`、`Helpers/FileNameHelper.cs`、`Services/RenameService.cs`、
  `Models/RenamePreviewItem.cs`；新增回归测试 3 个（分卷不得改名、复合后缀不得被破坏、识别与后缀状态）。
  不变量 1（不破坏源文件）与不变量 3（改名规则）由此得到实际保障。
- **验收判据**：`dotnet test` → 64 通过 / 0 失败（原 43 个单元测试 + 21 个基线冒烟测试）。
