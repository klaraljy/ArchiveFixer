# 造包与检测流程（权威版）

> 生效日期：2026-11-06
> 适用：`H:\BaiduNetdiskDownload\困难大测试` 下的困难包、特定解压包、异常包。
> 本文是造包、复制、运行、检测、落点、日志和验收的**唯一现行口径**。
> 与旧文档（`docs/需求书.md`、`docs/输出与整理模型.md`、`docs/分卷组装算法.md` 等）冲突时，以本文为准；旧文档中与本文冲突的段落作废，不再按旧段落改代码或判红绿。

## 0. 五个目录的硬契约

```text
H:\BaiduNetdiskDownload\困难大测试\
├─ 原物\                     内容与媒体来源；只读，不在这里跑程序
├─ 大测试备份位置\          每次造包的原始备份；只读，不直接拿它跑
├─ 大测试\                  从备份复制出来的工作副本；未指定位置就在这里跑
├─ 大测试指定位置\          指定位置的目标根；只放产物和工作区，不是源包备份
└─ 大测试日志\              造包日志、运行日志、结果和校验记录
```

| 目录 | 放什么 | 谁写入 | 运行程序时是否可改 |
|---|---|---|---|
| `原物` | 内容源文件、媒体源文件 | 用户/造包器只读 | ❌ 不改 |
| `大测试备份位置` | 每次造包的 `原包` + `recipe.json` 备份 | 造包器 | ❌ 不直接跑，不删 |
| `大测试` | 从备份复制出来的工作副本 | 运行前复制、程序解压 | ✅ 可以产生内容物、工作区、删源 |
| `大测试指定位置` | 指定位置运行时的最终输出根、隐藏工作区 | 程序 | ✅ 可以产生内容物、工作区；**不是源包目录** |
| `大测试日志` | 造包控制台、清单、校验结果、运行日志 | 造包器/运行器 | 只追加日志，不改包 |

### 0.1 三条不能混的边界

1. **备份不是运行目录。** `大测试备份位置` 里的是母本；每次跑之前复制到 `大测试`，不要在原备份上解压、改名、删除。
2. **`大测试` 是未指定位置的工作副本。** 未指定位置时，内容物、隐藏工作区、源包处理都发生在 `大测试\<seed>` 里；不会写到 `大测试指定位置`。
3. **`大测试指定位置` 是指定位置的目标根。** 指定位置时，源包仍可在 `大测试` 里；内容物和 `.ArchiveFixer.work` 必须写在指定目标根里，空间占用也记在目标盘。源包在哪个盘、目标在哪个盘，都不改变这条。

### 0.2 盘符不同也按“目标位置”办

WinRAR 的“解压到指定文件夹”只认目标文件夹，不要求源包与目标同盘。本程序同样：

```text
源包在 H:，目标在 E:  → 内容物/工作区在 E:，H: 只读源包（按源包档处理）
源包在 E:，目标在 H:  → 内容物/工作区在 H:，E: 只读源包
```

跨盘时禁止把工作区回落到源盘根、程序目录、`%TEMP%` 或盘根；分卷组入口需要硬链接但跨盘不能硬链接时，把候选片**复制到目标工作区**的 `group-entry`，再交给引擎。复制件只活在目标临时目录里，不改名、不移动用户源片。

## 1. 批次、种子与“70 份”的定义

### 1.1 三种批次

一次“70 份”不是 70 份同形状包，而是：

```text
50 份普通困难包 + 10 份特定解压包 + 10 份异常包 = 70 份
```

三个批次各自有独立种子基、独立备份、独立日志：

| 批次 | 种子基示例 | 样本号范围 | 数量 | 备份目录 |
|---|---|---:|---:|---|
| 普通困难 | `909000000` | `909000001`–`909000050` | 50 | `大测试备份位置\909000000-备份` |
| 特定解压 | `909100000` | `909100001`–`909100010` | 10 | `大测试备份位置\909100000-特定解压-备份` |
| 额外异常 | `909200000` | `909200001`–`909200010` | 10 | `大测试备份位置\909200000-额外异常-备份` |

普通批次的工作副本：

```text
大测试\909000000\909000001\原包
...
大测试\909000000\909000050\原包
```

特定/异常批次同理，分别落在：

```text
大测试\909100000\909100001\原包 ...
大测试\909200000\909200001\原包 ...
```

### 1.2 指定/未指定的正确比例

用户口径：**50 份普通包里，指定位置 25 份、未指定位置 25 份，一半一半。**

当前造包器的实际算法是 8 种场景轮转：

```text
scenario = scenarios[(sampleNumber - 1) % 8]
scenarios[0..3] = Original（未指定）
scenarios[4..7] = Specified（指定）
```

对 50 份，这个算法得到：

```text
未指定：26 份
指定：  24 份
```

**这是当前造包器与“25 + 25”契约不一致的已知缺陷。** 909 批次实测就是 24 指定 / 26 未指定；在修正造包器并重造之前，文档、脚本、验收都必须如实写 24/26，不能把 909 的结果写成 25/25。

修正原则（下一版造包器）：

- 先按样本号把 placement 固定成前 25 份 Original、后 25 份 Specified；
- 再在每个 placement 内轮转 4 种 source/content 组合；
- 保证两种 placement 各 25 份，不再用 `(n-1)%8` 直接切 50 份。

### 1.3 普通/特定/异常的运行根

| 运行方式 | 源包在哪 | 产物和 `.ArchiveFixer.work` 在哪 |
|---|---|---|
| 未指定位置 | `大测试\<seed>\<sample>\原包` | 源包所在目录树内（按包名套一层） |
| 指定位置 | `大测试\<seed>\<sample>\原包` | `大测试指定位置\<seed>-指定位置\...` |
| 特定解压 | `大测试\<seed>\<sample>\原包` | 跟每个外层压缩包自己的父目录走 |
| 额外异常 | `大测试\<seed>\<sample>\原包` | 未指定/跨盘样本按 recipe 的例外规则 |

`大测试指定位置` 不是“源的复制品目录”。源包永远在 `大测试`（或备份复制品）里；指定位置只接收输出和工作区。

## 2. 造包流程（详细）

### 2.1 工具与输入

造包器脚本：

```text
E:\AF\大测试-造困难包.ps1      # 50 普通
E:\AF\大测试-造特定解压包.ps1  # 10 特定
E:\AF\大测试-造异常包.ps1      # 10 异常
```

固定工具/输入：

```text
7z：E:\ArchiveFixer\tools\7zip\7z.exe
Rar：C:\Program Files\WinRAR\Rar.exe
内容：H:\...\原物\困难内容
媒体：H:\...\原物\生成的媒体
普通密码：2中！0@文#2删￥6除%
特定密码：Demo#Pass1 / Demo#Pass2（按层不同）
异常包：不加密
```

造包前检查：

- 7z、Rar 存在；
- 内容/媒体源目录非空；
- 普通/特定/异常的目标批次不存在，或允许 `-Force` 且校验标记通过；
- H 盘剩余空间足够（50 普通约 240 MB 量级，另有工作区峰值）。

### 2.2 普通 50 份的生成结构

每份普通样本：

```text
大测试\<seedBase>\<seed>\
├─ 原包\                用户最终拿到的伪装/分卷/包装形状
├─ 本地成品\            造包器保留的中间结构（不是运行源）
├─ .build\              造包中间目录，默认成功后删除
└─ recipe.json          这一份的层数、卷层、文件、伪装、密码、期望场景
```

每份的层结构：

```text
5 层
其中恰好 2 层是分卷层
最后一层必须是分卷层（4 或 5 片）
最终原包里是“外壳 + 分卷片”的组合
```

分卷层位置：

```text
第 4 层（index 4）固定是分卷
另 1 层从 index 1/2/3 中随机
其余 3 层是单一完整包
```

单一层格式：

```text
7z / rar5 / zip7z
```

分卷层格式：

```text
vol7z / volrar5 / volzip7z / volrar4 / volziprar
```

具体做法：

1. 从内容库取最大文件，截成 4 MB 或 5 MB 的 `content-N.bin`；
2. 逐层用 7z/Rar 重新打包；
3. 每层产物继续作为下一层输入；
4. 最后一层生成 4–5 片；
5. 对每一片做包装和伪装：

```text
第 1 片：0 层包装
第 2 片：1 层包装
第 3 片：2 层包装
其余片：0–2 层包装
```

包装格式随机：

```text
7z / rar5 / rar4 / zip7z
```

伪装方法：

- 媒体前缀（把媒体文件字节拼到包前面）；
- 中文插入；
- 常规后缀；
- 非中文杂质；
- 删加后缀；
- 改后缀但不改基名。

硬约束（造包器会断言）：

- 每份 5 层；
- 分卷层至少 2 层，最后一层必须是分卷；
- 最终片数 4 或 5；
- 0 层/1 层/2 层包装三种都出现；
- 媒体前缀恰好 2 片；
- 没有包装的片必须命中分卷标记；
- 最终文件名不能带 `.zNN` 这种跨盘 ZIP 强锚点；
- 基名不能被改掉；
- 每条最终文件都在 `原包` 里真实存在；
- 生成后复制到备份区（同卷可用硬链接，跨卷复制）。

`recipe.json` 至少记录：

```text
schemaVersion / seedBase / seed / sampleNumber
scenario：placement / sourceHandling / contentHandling
layers：index / kind / cls / format / inputs / outputs / volumeArgs / encrypted
files：originalName / finalRelative / bytes / suffixMethods / markerTouched / wraps / mediaPrefix / baseName
validation：layerCount / volumeLayerCount / lastLayerVolume / wrapCounts
```

### 2.3 普通 50 份的 8 种场景

```text
0 Original + KeepInPlace + Keep
1 Original + KeepInPlace + Delete
2 Original + DeleteInPlace + Keep
3 Original + DeleteInPlace + Delete
4 Specified + KeepInPlace + Keep
5 Specified + KeepInPlace + Delete
6 Specified + DeleteInPlace + Keep
7 Specified + DeleteInPlace + Delete
```

含义：

- `Original`：不选指定位置，产物留在源包树；
- `Specified`：选指定位置，产物进目标根；
- `KeepInPlace`：源包保留；
- `DeleteInPlace`：成功后彻底删源包（失败/未证不删）；
- `Keep/Delete`：最后一层过程物保留/彻底删除。

### 2.4 特定解压 10 份

特定解压不是普通分卷组流程。每份是 1–3 个**独立外层包**，最多 3 层：

```text
外层单一包
  → 内层标准分卷（7z .001/.002…，后缀可加“删”）
  → 或内层单一包
  → 最后一层得到内容物
```

10 份固定布局：

| 样本 | 层数 | 外层 | 内层 | 根上形状 | 输出文件夹 |
|---|---:|---|---|---|---|
| 01 | 2 | rar | 2–3 片 vol7z | 只有一个文件夹 | `111-1` |
| 02 | 2 | rar | 2–3 片 vol7z | 多文件夹/散文件 | `222-22` |
| 03 | 2 | zip | 2–3 片 vol7z | 只有一个文件夹 | `333-3` |
| 04 | 2 | rar | 2–3 片 vol7z | 多文件夹/散文件 | `444-44` |
| 05 | 3 | 7z | 内层 vol7z + 中间单包 | 只有一个文件夹 | `555-5` |
| 06 | 3 | rar | 内层 vol7z + 中间单包 | 多文件夹/散文件 | `666-66` |
| 07 | 3 | zip | 内层单一 7z + 中间单包 | 只有一个文件夹 | `777-7` |
| 08 | 3 | 7z | 内层单一 7z + 中间单包 | 多文件夹/散文件 | `888-88` |
| 09 | 2 | rar | 3 个独立包 `9991/9992/9993` | 各自形状 | `999-1/999-22/999-3` |
| 10 | 2 | rar | 3 个嵌套包 `1111/2222/3333` | 各自形状 | `111-1/222-22/333-3` |

特定解压密码按层：

- 外层、中间层、内层可分别不同；
- `Demo#Pass1`、`Demo#Pass2` 与空密码；
- `recipe.perLayerPasswords` 记录每层实际密码。

特定解压输出根：

```text
跟每个外层压缩包自己的父目录走
不是跟着导入时选的合集根
```

例如外层在 `原包\111\1111.rar`，输出就在 `原包\111\1111-...` 附近；不是 `原包` 根上强行摊一层。

### 2.5 异常 10 份

| 样本 | 类型 | 造法 | 期望 |
|---|---|---|---|
| 01 | 缺失最后一卷 | 7z 分卷，删最后一卷 | 失败/跳过，源包保留，不报“损坏” |
| 02 | 中间卷损坏 | 7z 分卷，截断中间卷 | 失败/损坏，源包保留 |
| 03 | 空归档 | 7z 零条目 | 空归档，不误报密码错误 |
| 04 | 跨盘 | 源 H，目标 E 的指定根 | 成功，目标在 E，源保留 |
| 05 | 长路径/中文 | 深目录 + 中文名 | 成功，源保留 |
| 06 | 同基名不同目录 | `A\dup.7z`、`B\dup.7z` | 两个任务，不合并 |
| 07 | 硬链接双名 | 原名 + 硬链接别名 | 只生成一个任务/一个输出 |
| 08 | 只有媒体前缀 | 纯媒体文件 | 跳过/失败，不强行解压 |
| 09 | 伪分卷标记 | 完整单卷命名为 `.7z.001` | 按内容识别为单一完整，不强行组卷 |
| 10 | 重复导入 | 同一路径导入两次 | 去重或两个独立任务，不重复输出 |

异常包不加密，`recipe.expected` 是验收断言，不是“建议”。

### 2.6 备份、日志、清场

普通造包结束时：

```text
大测试\<seedBase>\<sample>\原包
→ 大测试备份位置\<seedBase>-备份\<sample>\原包
→ recipe.json 同目录
```

特定/异常同理，备份后缀分别是：

```text
-特定解压-备份
-额外异常-备份
```

日志目录：

```text
大测试日志\大测试日志-909000000\
  造包-控制台.log
  造包清单.json
  校验结果.json
  失败.json
  功能测试密码本.txt

大测试日志\大测试日志-909100000-特定解压\
大测试日志\大测试日志-909200000-额外异常\
```

清场规则：

- 造包中间 `.build` 默认删除；
- `.hardpack-generated` 标记与当前 seed 不一致，或批次里有未知内容，拒绝 `-Force` 删除；
- 不删 `原物`、不删其它 seed、不碰已存在的备份；
- 造包成功后，源包在 `原包`，备份在母本目录，运行只拿备份复制品。

### 2.7 造包命令

```powershell
# 50 普通
pwsh -NoProfile -File E:\AF\大测试-造困难包.ps1 `
  -SeedBase 909000000 -SampleCount 50

# 10 特定
pwsh -NoProfile -File E:\AF\大测试-造特定解压包.ps1 `
  -SeedBase 909100000 -SampleCount 10

# 10 异常
pwsh -NoProfile -File E:\AF\大测试-造异常包.ps1 `
  -SeedBase 909200000 -SampleCount 10
```

覆盖已有同名 seed 必须显式 `-Force`，且只在 `.hardpack-generated` 标记与当前 seed 一致时允许。

## 3. 运行流程（从备份复制到出结果）

### 3.1 复制规则

每次运行前：

```text
备份\909000000-备份\909000001\原包
→ 大测试\909000000\909000001\原包
```

- 50/10/10 都从备份复制到 `大测试\<seedBase>\<sample>\原包`；
- 复制完成后，源包在 `大测试` 里运行，不在备份上运行；
- 指定位置的目标根用 `大测试指定位置\<seedBase>-指定位置`，源包仍留在 `大测试`；
- 复制时保留目录结构；硬链接双名样本若跨盘复制，必须用硬链接复制方式保留物理身份，否则会人为制造“两个不同文件”。

### 3.2 两种落点

#### 未指定位置

```text
选中文件夹：内容物留在选中文件夹里面，每个包再套包名目录
选中文件：  内容物在文件所在目录，套包名目录
工作区：    源包所在目录（或目标目录）的 .ArchiveFixer.work
```

#### 指定位置

```text
选中文件夹：目标根\选中文件夹名\相对子路径\包名\内容物
选中文件：  目标根\包名\内容物
工作区：    目标根下的 .ArchiveFixer.work
```

指定位置必须：

- 是绝对路径；
- 不是盘符根（`D:\` 这种拒绝）；
- 盘存在、可写；
- 目标根和源包可以跨盘；
- 空间变化、隐藏工作区、内容物都出现在目标根，不在源目录。

### 3.3 运行方式

| 方式 | 行为 |
|---|---|
| 一键处理 | 全递归、第一大步 + 交界 + 第二大步 + 最终内容判决 |
| 手动“只解压” | 只解当前一层；不自动接手分卷组；不按全递归跑 |
| 特定解压 | 独立 3 层简单管线，不进入普通组 |
| 只修后缀 / 全选 / 清理 | 不触发解压检测链 |

运行日志按 seed 归档到 `大测试日志`。当前测试宿主如果使用临时数据目录，运行结束后必须把该 seed 的日志和结果复制到：

```text
大测试日志\大测试日志-<seedBase>[-特定解压|-额外异常]\运行日志\
```

`大测试日志` 是日志根，不是程序 `E:\ArchiveFixer\data`。程序自己的设置、密码本、data 目录仍归交付目录，不混进测试日志。

## 4. 检测总览：三级事实

检测不是“看后缀猜包”，而是三段完全不同的判断：

```text
文件级：这一份文件到底是什么？
  ↓
组级：这几份是不是同一组？齐不齐？入口是哪一份？
  ↓
最终内容级：这一组到底有没有完整的最终内容？
```

对应三个不可替代的模型：

| 层级 | 事实载体 | 回答的问题 |
|---|---|---|
| 文件级 | `FileNatureCard` | 格式、是否完整单卷、是否分卷成员、卷号、首卷、物理身份、名字事实 |
| 组级 | `FirstStepFileLedger` → `PreparedVolumeGroup` / `VolumeGroupUnit` / `ContentGroup` | 同基名、同族、同落点域、成员齐不齐、入口、owner |
| 最终内容级 | `ContentGroupFinalizer` + `OutputVerifier` / 清单核对 | 有没有最终内容、是否可证完整、能不能删源 |

**任务级 `Outcome=Succeeded` 只说明这一层执行成功，不是最终内容成功。**

## 5. 文件级检测：从导入到 `FileNatureCard`

### 5.1 导入扫描

入口：

```text
ScanCoordinator.AddPathsAsync
→ FileScanService.ScanPathsAsync
→ ScanFolder / ScanFile
→ CreateArchiveTask
```

一文件一任务：

- 不按分卷组合并任务；
- 不按同名文件夹合并；
- 同一路径去重；
- 同一物理文件的多个硬链接名按 `FileIdentity`（卷序列号 + 文件索引）去重；
- 两个名字都干净保留先出现的；一个带中文伪装时保留干净名；
- 真正的 APK（按内容判）不进任务列表；
- 隐藏/系统/大小限制由扫描选项决定；
- 无用物只在文件夹导入时移出列表，不动磁盘文件。

`SourceSelectionKind` / `SourceSelectionRoot` 在导入时写入任务：

- 选中文件：`File`；
- 选中文件夹：`Folder`，并记录选中的根；
- 它们决定指定位置时是否保留选中文件夹名和相对子路径。

### 5.2 识别头部

`ArchiveDetectService.DetectAsync`：

```text
读 34 KB 文件头
→ 量文件大小 + 修改时间
→ 头魔数识别
→ 头认识：直接返回并做加密判读
→ 头不认识：看尾部/顺序扫
```

已知格式（按检测优先级）：

```text
7Z       37 7A BC AF 27 1C
RAR4     52 61 72 21 1A 07 00
RAR5     52 61 72 21 1A 07 01 00
ZIP      PK 03 04
ZIP_EMPTY PK 05 06
ZIP_SPANNED PK 07 08（跨盘/特殊）
GZIP / BZIP2 / XZ / TAR / CAB / ARJ / LZH / Z / ZSTD / LZ4 / RPM / ISO
```

魔数只回答“容器格式”，不回答“是否加密”，也不回答“是不是分卷组”。

### 5.3 头不认识时：尾部与顺序扫

优先级固定：

```text
1. 分卷片名字（LegacyVolumeNames.IsVolumePart）
    → 不做内嵌归档判定
2. 尾部 256 KB 的 ZIP EOCD
    → 能自洽推出起点 → 内嵌 ZIP
3. 顺序扫一遍（默认上限 512 MiB；媒体头 64 MiB）
    → ZIP EOCD 候选优先
    → RAR/7z 魔数其次
4. 都不命中 → 原头结果（Unknown）
```

关键限制：

- 头已认识时**不读尾部**，避免自解压安装器、PE + 尾部归档被大面积误报；
- 分卷片内容里出现魔数不算内嵌归档，因为分卷切片本来可能包含任意字节；
- 尾部内嵌 ZIP 的起点是 EOCD + 中央目录偏移反推，终点是 `EOCD + 22 + 注释`，不是文件末尾；
- RAR/7z 尾部归档终点取文件末尾，因为它们没有 ZIP 那种精确终点结构；
- 内嵌归档不改后缀，不能让用户把 `video.mp4` 改成 `.zip` 后仍打不开。

### 5.4 识别缓存

缓存键只认：

```text
文件大小
修改时间 ticks
头部指纹
尾部指纹（头不认识时）
证据等级：WholeFile / Head / HeadAndTail
```

文件在读取期间大小或修改时间变了，整条缓存都不使用；缓存命中返回克隆，调用方改加密注脚不会污染缓存。

### 5.5 加密判读

唯一出口 `ApplyEncryptionVerdict`：

| 格式 | 判据 | 说明 |
|---|---|---|
| RAR4/RAR5 | 主头/文件头加密位、加密头 | 读头，不调引擎 |
| ZIP | 中央目录通用位 bit0 | 至少一个条目加密 |
| 7z | coder 链 AES-256；多卷看全部卷 | 需要卷组信息 |
| 其它 | 不判 | 宁可漏报，不误报 |

- 加密判读只读头尾，有读入上限；
- 读不出/结构不符 → 不报加密；
- 多卷 7z 元数据在最后一卷，必须带 `VolumePaths` 再看一次；
- 加密结论不缓存；
- 任何界面/日志都不能输出明文密码。

### 5.6 后缀状态

`GetExtensionStatus` 的优先级：

```text
1. 内嵌归档（EmbeddedArchiveOffset > 0） → 内嵌归档
2. ZIP_SPANNED                         → 分卷后缀
3. LegacyVolumeNames.IsVolumePart      → 分卷后缀
4. Unknown / 非归档 / 未知格式          → 格式未知
5. 没有后缀                            → 后缀缺失
6. ZIP 容器合法后缀（apk/jar/docx…）    → 后缀正常
7. 当前后缀 == 建议后缀                 → 后缀正常
8. 多后缀且其中一个是建议后缀但最后不是 → 多重后缀疑似伪装
9. 其它                                → 后缀不匹配
```

自动改名只在**一键处理**且满足以下条件之一时发生：

- 内容自证 `SingleComplete`；
- 内容 `Unknown`、任务 `IsArchive=true`，且后缀状态是“不匹配/缺失/多重伪装”。

以下永远不改：

- 分卷成员；
- 跨盘 ZIP 成员；
- 内嵌归档；
- 延后由第二大步统一命名的组；
- 名字本身已经正确。

### 5.7 `FileNatureCard`：文件级唯一事实

`FileNature.Inspect(path)` 生成，不是另一个“检测器”，只把已有事实摆到一张卡上：

| 字段组 | 字段 | 来源/含义 |
|---|---|---|
| 路径/大小 | `Path` / `Size` | 盘上事实，大小直接问 FileInfo |
| 内容格式 | `Format` | 魔数；魔数 Unknown 时允许内容读数补 Zip |
| 分卷成员 | `Membership` | `VolumeMember` / `ProvablyNotVolumeMember` / `Unknown` |
| 卷号 | `VolumeNumber` / `RawVolumeField` | RAR5/RAR4/跨盘 ZIP 内容头；7z 没有 |
| 首卷 | `FirstVolumeFlag` | RAR4 主头 / RAR5 第 1 卷 |
| 内容身份 | `BodyKind` | `Unknown` / `SingleComplete` / `VolumeFirstPiece` / `VolumePiece` |
| 7z 自述 | `DeclaredTotalBytes` / `DeclaredVolumeCount` | 7z 起始头；片数不是强推 |
| ZIP 证据 | `HasZipEndRecord` / `ZipEndRecordMeansSplit` / `HasZipLocalHeader` | 跨盘/普通分片 |
| 名字事实 | `VolumeIndexByName` / `FirstVolumeNameByName` / `CanonicalVolumeName` / `ArchiveBaseName` | 只是线索，不是身份 |
| 物理身份 | `HasIdentity` / `VolumeSerial` / `FileIndex` | 同一卷改名/移动不变 |
| 内嵌 | `EmbeddedOffset` / `EmbeddedLength` | 媒体前缀/尾部归档 |
| 加密 | `Encryption` | RAR 头加密等 |

#### 5.7.1 `BodyKind` 判定顺序

```text
7z：
  起始头自述整包 bytes <= 自己大小       → SingleComplete
  起始头自述整包 bytes > 自己大小       → VolumeFirstPiece
  没有起始头/中间片/读不出              → Unknown
  荒谬值（自述/自己 > 1024）             → 不升级

RAR：
  内容卷号 > 1                          → VolumePiece
  内容卷号 == 1 / RAR4 首卷标记          → VolumeFirstPiece
  主头可读、不是分卷成员                 → SingleComplete

ZIP：
  跨盘 EOCD 盘号 > 1                    → VolumePiece
  跨盘第 1 片（有本地头/跨盘标记）       → VolumeFirstPiece
  EOCD 自证单盘且不是 split              → SingleComplete
  split EOCD 的末片                      → 不是 SingleComplete
```

#### 5.7.2 7z 的特殊性

- 7z 只有第 1 片有魔数；
- 中间片没有魔数、没有卷号，内容通常只能判 Unknown；
- 7z 起始头自述“整包字节数”，可判断单卷/首卷，但不能无条件推总片数（非均匀分卷会错）；
- 片数由族算法用入口、名字、已收片数、自述字节数一起推；
- 不能把 7z 中间片当成独立包去解。

#### 5.7.3 不要把“名字”当身份

名字只回答：

- 它像不像某一族的卷名；
- 第几槽；
- 标准名是什么；
- 同组入口名是什么。

名字不回答：

- 内容是不是该族；
- 是否完整；
- 是否真是分卷成员；
- 该不该删源。

`LegacyVolumeNames.IsVolumePart` 只用于“像分卷片”的线索；真正的成员身份看内容卡。

### 5.8 识别结果应用到任务

`ApplyDetectResultAsync` 写入：

```text
DetectedFormat
SuggestedExtension
ExtensionStatus
IsArchive
IsEncrypted
EmbeddedArchiveOffset / End / DirectReadSupported
VolumeRenameSuggestion
Status
ErrorMessage
```

- 识别为归档 → `Recognized`；
- 识别不出但名字是后续卷 → `VolumeMissing`（提示把首卷加进来），不改格式结论；
- 其余 → `UnknownFormat`；
- 任务列表的状态不是机器终态，检测结束后仍可能被第一/第二大步改写。

## 6. 第一大步：单一完整包 vs 分卷成员

第一大步只做两件事：

```text
能证的单一完整包 → 解一层
能证/能按名字槽证明是分卷成员 → 只登记，不解
```

### 6.1 入口判定顺序

在 `ProcessExtractTaskAsync` 中：

```text
1. 取 FileNatureCard
2. 判断 isSecondStepEntry（是否已被第二大步点名）
3. 计算 contentSingleComplete
4. 计算内容分卷候选：
   - BodyKind = VolumeFirstPiece / VolumePiece
   - RAR 且 Membership=VolumeMember 且 Size>0
   - ZIP 且 ZipEndRecordMeansSplit 且 Size>0
5. 计算 7z 名字槽候选：
   - nameSlotIndex > 1
   - BodyKind=Unknown 且 Format=Unknown，或 Format=SevenZip
   - 同批有内容自证的首卷兄弟
6. 计算 RAR 名字槽候选：
   - Format=Rar，Size>0，nameSlotIndex>1
7. 若不是第二大步入口，但有上述分卷候选：
   → 登记 FirstStepFileLedger + VolumeHandoff
   → 任务 Skip，不调用解压引擎
   → 源文件原地不动
8. 否则：
   → 登记账本
   → 可自动改名则改名
   → 进入解压（一键递归 / 手动单层）
   → 产出登记账本
```

### 6.2 各判据的边界

- `contentSingleComplete` 优先于“名字像分卷”：内容自证单卷的 `.7z.001` 不会被强行组卷；
- ZIP 的 `Membership=VolumeMember` 不等于分卷，普通单卷 ZIP 也常有这个结论；ZIP 只看 split EOCD；
- 分卷成员不调用第一大步引擎；
- 7z 中间片只有“名字槽 + 同批首卷内容自证”才有门票；
- RAR 加密头读不出卷号时，标准名 `partN` 是唯一门票；
- 判不出就登记为交接事实，不猜“不是分卷”。

### 6.3 自动改名

一键处理在闸门通过后、真正解压前自动修后缀，但只对：

- `SingleComplete`；
- 或 `Unknown` + `IsArchive` + 后缀不匹配/缺失/多重伪装。

改名只改后缀，不改基名；分卷成员、内嵌归档、跨盘 ZIP 不改。

### 6.4 第一大步账本

`FirstStepFileLedger` 记录：

```text
Path / BaseName / Size / Format / Membership / BodyKind
VolumeNumber / FirstVolumeFlag / RawVolumeField / DeclaredTotalBytes / DeclaredVolumeCount
ZIP/RAR 证据 / Encryption / NameSlot / NameEvidence
Source / SourceLayer / FileIdentity
OriginRootId / ProducedByTaskId / ArtifactRole
CandidateLeaseId / PlacementKey
```

规则：

- 账本只收已发布产物，不收 `.ArchiveFixer.work` 临时路径；
- 产出物在任务收尾后扫描并登记，包装/递归产出的 Unknown 和中间片也登记；
- 同一路径 `AddOrReplace`；任务级物理输入另外按 `FileIdentity` 去重；
- 已持有候选租约的片不会被后续“普通产出登记”降级成可回收过程物；
- `ByOriginRoot` / `LeasedEntries` 是后续组和删除闸门的只读入口。

## 7. 交界处：组级检测

### 7.1 唯一候选来源

```text
FirstStepFileLedger
```

不是 `VolumeHandoffEntries`、不是 `extraGroupSeeds`、不是目录扫描。`VolumeHandoffEntries` 只做事实记录，第二大步的正式候选仍以 ledger 为准。

### 7.2 归组管线

```text
FirstStepFileLedger
→ VolumeBoundaryPipeline.ResolveAllAsync
→ 按 BaseName 取账本
→ VolumeFamilyArbiter.Select 判族
→ 对应族 resolver
→ PreparedVolumeGroup
→ ContentGroup
```

`VolumeBoundaryPipeline` 只负责：

- 按基名遍历；
- 选族；
- 调族 resolver；
- 异常落 Unknown；
- 不扫目录、不读文件、不建链接。

### 7.3 族判定与完整性

| 族 | 典型名字 | 入口 | 完整性依据 |
|---|---|---|---|
| 7z 数字族 | `X.7z.001…` | 第 1 片 | 起始头自述整包、首片大小、名字槽、已收片数 |
| RAR part 族 | `X.part1.rar…` | 第 1 卷 | RAR5 卷号、RAR4 首卷/卷号、入口/末卷 |
| ZIP 跨盘 | `X.z01…X.zip` | 末片 `X.zip` | EOCD 盘号、末片自述总盘数 |
| ZIP 通用分片 | `X.zip.001…` | 首片 `.zip.001` | 本地头、EOCD、序号连续 |

四族共同规则：

- 同基名、同族、同落点域才是一组；
- 目录不是组键，跨目录同基名仍可同组；
- 内容优先于名字；
- 组不全 → `Missing` / `Unknown` / `SizeAnomaly`，不建入口、不解压、不删源；
- 组完整 → `Complete`，交给第二大步；
- 组完整但跨卷/跨盘入口做不了硬链接 → 复制候选到目标 `group-entry`，不回落盘根；
- 组键不允许把不同落点域硬合并；落点冲突要标记，不能悄悄取第一个。

### 7.4 `PreparedVolumeGroup` / `ContentGroup`

`PreparedVolumeGroup` 是族 resolver 的结论：

```text
BaseName / Family / SourceLayer
EntryLayer / OriginalEntryPath / EntryCanonicalName
Pieces / MissingNumbers / State / Evidence / SizeAnomalyDetail
```

`ContentGroup` 是交界处的内容组：

```text
GroupId = BaseName | Family | SourceLayer
PlacementKey / PlacementRoot
MemberPaths
SourceRootIds
State / Evidence / MissingNumbers
OwnerTaskFileName / OwnerTaskPath
FinalOutputRoot / FinalContentPath / FinalState
```

`SourceRootIds` 来自账本项的 `OriginRootId`；`PlacementRoot` 从 `PlacementKey` 的落点域解析。组状态只由 prepared/组服务写，交界处不猜。

### 7.5 组状态

```text
Complete       成员齐、入口确定
Missing        能点名缺号/缺片
Unknown        证据不足/冲突
SizeAnomaly    结构矛盾（数量/大小/槽位/混族）
```

只有 `Complete` 进入第二大步。`Missing/Unknown/SizeAnomaly`：

- 不建入口；
- 不点名解压；
- 不删任何片；
- 日志写清缺什么/判不出什么；
- 留给下一轮或批末，不静默当成功。

---

## 8. 第二大步：一组只解一层

### 8.1 入口层

完整组在目标工作区建：

```text
<目标目录>\.ArchiveFixer.work\group-entry\<基名>-<guid>\
```

- 同卷：硬链接；
- 跨卷：复制；
- 不移动、不改名、不覆盖用户源片；
- 目标根不可用/创建失败 → 组 Unknown，不建目录、不删源；
- 不再回落源卷根或盘根。

### 8.2 owner

- 一组只写一个 owner；
- owner 一旦写下不许换；
- owner 是入口任务；
- 入口任务解一层；
- 组内其他片是跟班/过程任务，不各自解整组；
- 组成功后按规范名/已消费片收过程物；
- 用户源片由源包档处理，不在收片阶段误删。

### 8.3 解一层

第二大步只解一层：

```text
组入口 → 引擎 → 一层产物
```

产物不再当“普通第一层”重新归组；它进入本轮产物扫描，若又出现新归档/新组，交给下一轮交界。

### 8.4 安全闸门

- 缺片/Unknown 不调引擎；
- 密码错/缺卷/失败 → 片全留；
- owner 失败 → 不删源；
- 组成功但输出校验失败 → 不发布最终内容；
- 组成功但清单不能逐条核对 → 至多 Partial，不是 Verified。

---

## 9. 一键递归与最终内容

### 9.1 一键处理

```text
第 1 轮：第一大步
轮边界：交界屏障 → 组分析
第 2 轮：第二大步 owner 解一层
继续轮：扫描新内层包，递归展开
最后一轮后：最终内容判决 → 源包处理 → 汇总
```

一键处理是**全递归**：

- 有压缩包就继续；
- 多分支不询问，按设置/上限展开；
- 每层有最大层数、每层内层包数量、密码候选上限；
- 候选分卷片有交界前租约，不能按普通过程物回收；
- `ShouldStopAtVolumeGroupMember` 遇到“还没凑齐的组的一员”时停止递归，留给交界；
- 失败/取消/部分完成 → 不发布最终内容，源包不动，工作区按设置保留。

### 9.2 手动“只解压”

- 只解当前一层；
- 不自动接手分卷组；
- 不按全递归跑；
- 源包规则与一键共用同一套最终校验，但不会等续解链；
- 分卷组不会被单层路径强行解开。

### 9.3 最终内容判决

`ContentGroupFinalizer`：

```text
owner 成功？
→ owner 输出树下取“ deepest 有内容物任务”
→ 产物非空
→ 输出校验 Passed
→ 清单逐条核对 ManifestCrossChecked
→ Verified；否则 Partial / Missing / Unknown
```

- `Verified`：组最终内容可证完整；
- `Partial`：有内容但未逐条核对/部分失败；
- `Missing`：没有最终内容；
- `Unknown`：还没走到可判阶段；
- 任务级 `Succeeded` 不得直接当 `Verified`；
- 组内过程任务不显示最终成功；
- 最终输出只有一个 `FinalOutputRoot`，不把过程任务目录当最终输出。

### 9.4 空目录清理

指定位置成功后：

- 组内过程任务的空输出壳（含空父目录）从 `PlacementRoot` 下删除；
- 只删空目录；
- 有任何文件/非空子目录就停手；
- 不删 `PlacementRoot` 本身；
- 不碰源目录、不碰最终内容目录。

这是“指定位置只剩一堆空文件夹”的直接修复。

### 9.5 源包处理

- 只有 `DeleteInPlace` 档才可能删源；
- 只有组 `FinalState=Verified` 才处理组内全部 `SourceRootIds`；
- `KeepInPlace` 一个字节都不动；
- 未证组/部分内容/取消/失败 → 源包全部保留；
- 删除按任务源清单，不按“目录里看着像过程物”；
- 删源日志带组 ID、证据、根路径；
- 组内多个源根全部一起处理，不再只删入口那一单。

## 10. 特定解压：独立管线

特定解压不进入普通第一/第二大步，不使用 `ContentGroup` 执行逻辑：

```text
SpecificBatchUnitBuilder
→ 每个外层包独立
→ SpecificExtractionRunner
→ 最多 3 层
→ 每层只认内容物 / 单一完整包 / 标准分卷
→ 内容物 → 输出根
```

关键规则：

- 标准分卷只按标准名/卷名归组；
- 中文后缀（`.001删` 等）在临时层生成标准名入口，不直接交给引擎；
- 输出根跟外层压缩包自己的父目录；
- 失败保留最后一层过程物；
- 成功链过程物随工作区清掉；
- 密码逐层不同；
- 不把特定解压的简单 2–3 层强行塞进普通组算法；
- 特定 10 份的 `recipe.targets` 是验收断言。

| 现象 | 不能报成 | 正确方向 |

## 14. 被本文明确废弃的旧说法

以下旧说法全部作废，不得再据此改代码或写测试：

1. “一个源文件 = 一个任务 = 一个最终结果”；
2. “任务 `Succeeded` 就是最终成功”；
3. “最终输出目录非空就算成功”；
4. “扫描期把同组分卷合并成一个任务”；
5. “第一大步可以解分卷成员”；
6. “分卷组完整与否按目录/名字猜”；
7. “`.002` 就是分卷，`.zip` 就是单卷”；
8. “ZIP 的 `VolumeMember` 一定说明它是分卷”；
9. “工作区可以落在盘根/程序目录/%TEMP%”；
10. “指定位置没有内容就回落到源目录”；
11. “跨盘时目标根不能硬链接，所以指定位置只能空”；
12. “过程任务和最终任务共用同一套成功显示/计数”；
13. “删源按每个 rootTask 的 OutputPath 分别判”；
14. “组内多个源根只删入口那一份”；
15. “指定位置跑完可以留下大量空过程目录”；
16. “50 份普通包一定是 25 指定 + 25 未指定”——**当前造包器实际是 24/26，必须修造包器，不能把 24 当 25**；
17. “造包备份目录可以当运行目录”；
18. “特定解压可以套普通组算法”。

## 16. 一句话总览

```text
造包：备份母本 → 复制到工作区 → 未指定在源树跑 / 指定在目标根跑
检测：文件内容卡 → 第一大步账本 → 交界组分族/完整性 → 第二大步解一层
      → 组最终内容 Verified → 才按源根处理源包
```

任何“看起来像成功”的任务状态，都不能替代这条链。
