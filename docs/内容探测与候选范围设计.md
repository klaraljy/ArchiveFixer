> 本文件是**设计稿**，不是已实现行为。用户确认前不改产品代码。

## 1. 不变量

1. UI 线程不做任何文件内容 I/O。
2. 单文件探测有界：固定头部/尾部窗口 + 超时。
3. 整批探测有预算；超预算降级为 `Unknown`，不阻塞。
4. 内容物只做浅层识别；深度分卷/归档解析只给候选。
5. 媒体前缀不能靠扩展名跳过；必须有界探测尾部/嵌入候选。
6. 第二大步只吃第一大步交接单和缓存卡；不递归扫输出/内容物树。
7. 判不出写 `Unknown`/未发现，不写“确定不是”。

## 2. 第一大步扫描分层

### A. 枚举（后台）

`FileScanService.ScanPathsAsync` 已在 `Task.Run`，保留。

只产出：

- 路径；
- 大小；
- 修改时间；
- 物理身份。

不读内容。

### B. 浅层（所有文件，有界）

每个文件最多：

- 头部 64 KiB；
- 尾部 64 KiB。

当前 `ArchiveDetectService` 是头部 34 KiB、尾部 256 KiB，之后对未知文件顺序扫最多 512 MiB。  
新设计保留头/尾窗口，但**取消无条件的 512 MiB 顺序扫**。

浅层结论：

```text
KnownArchive
Media
MediaWithPossibleEmbeddedArchive
ContentOnly
Unknown
```

### C. 媒体前缀

不能仅凭后缀/头部跳过。处理顺序：

1. 读头部；
2. 读固定尾窗；
3. 尾部有 EOCD/归档尾标记 ⇒ `MediaWithPossibleEmbeddedArchive`；
4. 只对尾部候选做嵌入偏移定位（`TailArchiveScanner` / `EmbeddedArchiveDetector`）；
5. 尾部无命中 ⇒ `ContentOnly` 或 `Unknown/未发现`；
6. 不再为了中段归档顺序扫完整份视频。

边界：

- MP4 前缀 + ZIP 尾：可发现；
- 普通 MP4：只读头尾；
- 媒体前缀、尾部无标记：如实写“有界尾窗未发现”，不是“确定不是归档”。

### D. 未知文件深度扫

非媒体、非归档未知文件：

- 允许有限顺序扫；
- 上限降为 8–16 MiB；
- 单文件超时（目标 2 秒）；
- 超时 ⇒ `Unknown`，继续下一个；
- 整批有总预算。

### E. 深度检查

`FileNature.Inspect` 只允许用于：

- 头部魔数像归档；
- 尾部有归档标记；
- 名字是卷名候选；
- 第一大步闸门已登记；
- 嵌入候选偏移。

内容物浅层结束，不进入深度检查。

## 3. 超时、预算、取消

- 并行 2–4；
- 单文件超时；
- 整批浅层预算 + 深度预算；
- 取消令牌贯穿；
- 同步 I/O 不能取消时，后台放弃该任务，UI 不等；
- 进度通过 `IProgress`，UI 只更新状态。

## 4. 第二大步候选范围

### 输入

只接受：

- `VolumeHandoffEntry` 路径；
- 交接文件所在目录的**顶层兄弟**；
- 第一大步缓存 `FileNatureCard`。

### 禁止

- `Tasks.OutputPath` 作为递归 root；
- 已解出内容物目录作为 root；
- 对 roots 全树 `SafeEnumerate`；
- 对目录全部文件调用 `FileNature.Inspect`。

### 组分析改动点

- `GroupAnalysis.Analyze` 接收 handoff 列表/路径集合；
- `CollectPieces` 候选集合在进入内容探测前定死；
- 跨层只从 `VolumeHandoffEntry.SourceLayer` 的已登记路径取；
- `OneClickCoordinator` 不再把 `Tasks.OutputPath` / `ParentOutputDirectory` 拼进组 roots。

### 当前应急修复

`CollectPieces` 的内容卡绕基名收片已限制为**种子自己的物理目录**。  
这只是止损，候选来源仍需按本节收口。

## 5. 变更清单（设计）

- `ArchiveDetectService`：头部/尾部窗口、深度预算、媒体前缀、超时；
- `FileScanService`/`ScanCoordinator`：进度、取消、批预算；
- `GroupAnalysis`：handoff-only 候选；
- `OneClickCoordinator`：移除输出目录 roots；
- 缓存：第一大步卡供第二大步复用；
- 测试：内容物大树、媒体前缀、超时、第二大步隔离、19 组形状。

## 6. 守门用例

1. 2000 个 PNG/MP4：不触发整文件顺序扫，UI 可响应取消。
2. MP4 前缀 + ZIP 尾：识别为嵌入候选。
3. 媒体前缀无尾标记：结果 `Unknown/未发现`，不是“确定不是归档”。
4. 单文件超时：整批继续。
5. 第二大步误传输出树 roots：不扫内容物，不产生 PNG 嗅探。
6. 19 组真机形状：进入组分析并写出组日志。
7. 缓存复用：同一文件第二大步不重复 `Inspect`。

## 7. 实施顺序

1. 第二大步候选收回交接单（先止 UI 卡死）；
2. 第一大步 512 MiB 顺序扫改为有界深度扫；
3. 媒体前缀尾部/嵌入候选；
4. 超时/预算/UI 响应；
5. 全量、format、刷 E。

## 8. 不动的边界

- P53/P55 判定口径不动；
- 删除/源包/其余物规则不动；
- 第一/第二大步业务顺序不动。
