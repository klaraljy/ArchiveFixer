# 打包功能（用户 2026-09-22 需求第 10 条）

> 这是**设计说明 + 实施记录**。用户原话（节选）：
> 「打包功能就做一个就行，因为打包很少见。文件夹 A 的内容 → 7z 分卷
> （≤1 GB → `.7z.001`+`.002`；>1 GB → `.001`/`.002`/`.003`），**密码必须有**；
> 把这些分卷放进文件夹 B → 把文件夹 B 压缩成一个**带密码的 rar**；结果 = 压缩包 B。
> 复杂的变体不要。」
>
> **2026-09-23 追加**（用户决定，本文件已按它更新）：外层**不再只有 rar**，改成
> **三选一 —— `rar`（默认）/ `7z` / 不做外层**；设置里加一格"自选 `Rar.exe` 路径"。
> 起因与许可依据见 §5.1。

本文件只写**这一个功能**：为什么这么做、判据是什么、哪些事不做。

---

## 1. 它做什么（一句话）

把**一个文件夹**变成一个**带密码的压缩包**：里面的内容是"该文件夹的 7z 加密分卷"。

```
A\（用户选的源文件夹，里面是要打包的东西）
        │  ① 7z 加密分卷（-mhe=on：连文件名一起加密）
        ▼
B\A名.7z.001, B\A名.7z.002, …        ← ② 分卷落在新建的文件夹 B 里
        │  ③ 按"外层容器"三选一压一层（都带密码、都连文件名一起加密）
        ├── rar（默认）: Rar.exe a -hp<密码> -r -ep1 "B.rar" "B"   → B.rar
        ├── 7z        : 7z.exe  a -t7z -mhe=on -mx=5 -p<密码> "B.7z" "B" → B.7z
        └── 不做外层   : 不产外层文件，结果就是 B 里的那组分卷
```

两层加密是**用户明确要求**的：外层容器是"运输容器"，内层 7z 分卷是"内容 + 分卷"。
"不做外层"那一档是 2026-09-23 补的出路（本机没装 WinRAR 时不必卡住，见 §5.1）。

---

## 2. 分卷大小：默认 512 MiB（两个例子都能对上）

用户给的两个例子是"≤1 GB → 2 个分卷、>1 GB → 3 个分卷"。它们同时成立只有一个解释：
**每个分卷有体积上限**，内容大了就多切一卷：

| 内容大小 | 每个分卷上限 512 MiB 时切出 | 与用户例子的对照 |
|---|---|---|
| 1 GB | `.7z.001` + `.002`（各 ~512 MiB） | ✅ 完全一致 |
| 1.5 GB | `.001` + `.002` + `.003`（各 ~512 MiB） | ✅ 完全一致 |
| 4 GB | 8 个分卷 | 用户没给这个例子（按同一规则推） |

- 默认值 **512 MiB**（= 用户那两句话的唯一自洽解），界面上是**一个数字框**（64 MiB – 4096 MiB），
  用户可以改 —— 这样"他其实想要别的体积"时不必改代码。
- 分卷**命名由 7z 自己产生**（`-v<size>` → `名字.7z.001/.002/…`），程序**不自己拼分卷名**：
  自己拼会在"内容物恰好等于整数倍"这种边界上多切一卷出来。
- ⚠ **不做**"按体积自动决定切几卷"（"必须切成 3 卷"这种）—— 那是把体积上限换成卷数上限，
  内容一大就会切出几十 GB 的单卷，与用户"空间紧张"的处境直接冲突。

## 3. 密码（必填，两层同一个密码）

- **必填**：两个密码框（可勾"外层 rar 用另一个密码"），默认两个都用同一个。
- 空密码 / 只有空格 → **拒绝开始**并说清"必须设密码"（用户原话："密码必须有"）。
- **绝不落盘**：密码只在内存里活到本次打包结束（不变量 5 —— 密码只存内存）。
  日志里一律写"已设置密码"，**不写密码本身**，也不写 `-p<明文>`（命令行里会带上，
  这是外部工具命令行的固有限制 → 与解压侧同一口径写进「已知限制」）。
- 打包结束后界面上提供"复制密码"按钮（用户自己也要用），**不进剪贴板历史之外的地方**。

## 4. 落点与命名

| 项 | 规则 |
|---|---|
| 源文件夹 A | 用户选（只打包**内容**，不含 A 这一层目录本身？ → **含 A 这一层**，见下） |
| 文件夹 B | 默认与 A 同级：`<A 的父目录>\<A 名>_打包`（用户可改） |
| 分卷 | `B\<A 名>.7z.001`、`.002`、… |
| 结果 rar | 默认 `B.rar`（与 B 同级）；**rar 里装的是文件夹 B 本身**（解出来就有 B 这一层） |
| 结果 7z | 默认 `B.7z`（与 B 同级，与 rar 一一对应）；**7z 里装的同样是文件夹 B 本身** |
| 不做外层 | 没有外层文件；结果就是 `B\` 里的那组分卷 |
| B 本身 | **保留**（用户可能要先检查分卷），界面上给一句"确认没问题后可以自己删掉 B" |

> ⚠ **绝不在源目录里写任何东西**（不变量 12）：分卷只写进 B，B 的默认位置在 A 的**外面**。
> 用户如果把 B 指到 A 里面 → 直接拒绝并说明（那会让"打包的内容"越打越多）。
> "外层容器落在哪"这一组判据（不能在 B 里、不能在 A 里、A 不能在 B 里）**按容器生效**：
> 不做外层时没有外层文件，那几条不适用；但"B 在 A 里"与"A 在 B 里"**照旧拒绝**
> —— 后者会让源文件与产物混在同一个目录里。

## 5. 外部工具：7z 一定在；Rar.exe 只能"用户自装"

| 外层容器 | 用什么 | 没有时怎么办 |
|---|---|---|
| **rar**（默认） | **`Rar.exe`（WinRAR 的**命令行**程序，共享软件）** —— 只检测、只调用、**绝不分发**（AGENTS.md §3.1） | **明确报错**（在切分卷**之前**）：需要本机已安装 WinRAR，并给出**三条**出路（见下） |
| **7z** | 内置 `tools\7zip\7z.exe`（LGPL，**随程序分发**） | 理论上不会没有；确实缺 → 报"没找到 7-Zip 程序"，并提示改设置或重新解压一份程序 |
| **不做外层** | 不需要任何额外工具 | —— |
| 建 7z 加密分卷（三步里都有） | 内置 `tools\7zip\7z.exe`（`a -t7z -mx=5 -mhe=on -p… -v512m`） | 同上 |

**没有 `Rar.exe` 时的三条出路**（`StatusText.PackThreeWaysOut`，界面与失败原因共用同一份措辞）：

1. 装好 WinRAR（带 `Rar.exe`）后重试；
2. 把「外层容器」改成 **7z** —— **无需额外安装**（7-Zip 是 LGPL，随程序分发）；
3. 选「**不做外层容器**」，这次就只出 B 里的 7z 加密分卷。

- ⛔ **绝不静默换容器**：用户选了 rar 而本机没有 `Rar.exe`，程序**不会**偷偷改成 7z ——
  那是替用户改主意（他要的可能是 `.rar` 这个后缀在别处能用）。换哪一种是**界面上用户自己点**的。
- ⛔ **绝不用 7z 假装做出 `.rar`**：7-Zip **不能创建 RAR**（RAR 的压缩算法是专有的）。
  文件名改成 `.rar` 是**伪造**，用户拿去用时会直接坏掉 —— 这属于"宁可报错也不撒谎"。
- ⛔ 也**不内置** `Rar.exe`（许可不允许随包分发，见 §5.1）。
- 定位沿用 `ToolLocator`（唯一来源）：`Rar.exe` 先找**用户自选路径**（设置 →「外部工具」里的那一格，
  2026-09-23 补的界面入口）→ 再找已装 WinRAR 目录 → 都没有就报上面那句话。

命令行（三条都在实现里写死参数模板，**只允许出现在 `Packing/` 内部**，与 §3.1 的"四条禁止项"同一口径）：

```text
# ① 加密分卷（-mhe=on 连文件名一起加密；-v512m 分卷；输出到 B）
7z.exe a -t7z -mx=5 -mhe=on -bsp1 -sccUTF-8 -y -p<密码> -v512m "<B>\<A名>.7z" "<A>\*"

# ②a 外层 rar（-hp 连文件名一起加密；-r 递归；-ep1 保留 B 这一层）
Rar.exe a -hp<密码> -r -ep1 -y "<B>.rar" "<B>"

# ②b 外层 7z（-mhe=on 连文件名一起加密；参数给的是 B 而不是 B\*：7z 会把 B 这一层带进归档）
7z.exe a -t7z -mhe=on -mx=5 -bsp1 -sccUTF-8 -y -p<密码> "<B>.7z" "<B>"

# ③ 校验（按容器走）
Rar.exe lb -p<密码> "<B>.rar"          # bare list：一行一个条目名
7z.exe  l -slt -sccUTF-8 -y -p<密码> "<B>.7z"   # 技术信息：一行一个「键 = 值」
```

> 为什么 7z 那一边用 `-slt` 而不是默认表格：默认输出是给人看的表格（列宽随内容变、带汇总行），
> 钉进代码等于把"某一版 7-Zip 的排版"当契约。`-slt` 的第一块描述**归档自己**，分隔线之后才是条目
> —— `PackingVerifier.ParseSevenZipSltList` 按分隔线切掉第一块，否则归档路径会被当成"计划外条目"，
> 产物校验会**永远不通过**（有单测钉住）。

### 5.1 许可依据：为什么 `Rar.exe` 不能随包，而"外层 7z"必须存在

用户 2026-09-23 问过"能不能随包发 `Rar.exe`（他不是商用、会完全开源）"。查 RARLAB 官方 EULA，**不能**：

| 条款 | 原文要点 |
|---|---|
| §3.1 | Nobody may distribute separate parts of the package, **with the exception of the UnRAR components**, without written permission |
| §3.2 / §3.3 | 不得放进任何其它软件包内；必须 pure and unpaired，**Any bundling is interdicted** |
| §10 | 不得分发 licensed software 的 **any subset**；也不得拿 RAR/UnRAR 二进制去重建 RAR 压缩算法 |

结论（边界不变）：`Rar.exe` / `WinRAR.exe` 只允许"**用户自装、自选路径、程序只检测与调用**"，
⛔ **绝不随包分发**；`UnRAR.exe`（RARLAB freeware，许可第 2 条明确允许随其它软件包分发）仍然可以内置。

正因如此，"本机没装 WinRAR"是**常态而不是异常**，所以外层容器必须有不依赖 WinRAR 的选项：
**7z 外层**（内置 7-Zip，LGPL）与**不做外层**。这不是"顺手加的功能"，
而是许可边界逼出来的产品决定。

## 6. 取消、失败与"不变量"

| 情形 | 行为 |
|---|---|
| 用户取消 | **杀掉自己启动的那个 PID 及其子进程**（绝不按名字杀 `7z.exe`/`Rar.exe`，不变量 10） |
| ① 失败 | 报错，**不留半个外层容器**；已经切出来的分卷**保留**并在日志里说明"分卷已生成，外层未生成"（重试时能接着用） |
| ②a 失败 | 分卷保留（同上）；明确说"外层 rar 没做成，原因：找不到 Rar.exe / 密码太短 / …" |
| ②b 失败 | 分卷保留（同上）；明确说"外层 7z 没做成（7-Zip 退出码 N）" |
| 成功 | 界面给出：**外层产物路径 + 容器类型 + 大小** + 分卷清单（名字 + 各自大小）+ "复制密码"；日志里同一条 |
| 校验 | 完成后**按容器**列一遍条目（`.rar` 用 `Rar.exe lb`，`.7z` 用 `7z l -slt`）：确认里面有 B 这一层且分卷数对得上；对不上就报"产物不对"，**不显示成功**（不变量 6 同一口径） |
| 空间 | 开始前算一次需求（有外层：内容 × 2.02；不做外层：内容 × 1.02）+ 32 MiB 余量，与目标盘可用空间比；不够就**不开始**，报"需要/可用/差"（与解压侧同一套 `SpaceGate` 口径） |

> "不显示成功"这句在结论里是**机器可判**的：`PackingResult.State` 只有 `Succeeded` 算成功，
> 而 `Describe()` 一定带容器类型与**实际**产物路径（`rar 外层 → B.rar` / `7z 外层 → B.7z` /
> `不做外层 → B 里的分卷`），用户不会看到一个光秃秃的"完成"。

## 7. 界面（只有一个入口，一个窗口）

- 入口：主界面菜单 **工具 → 打包文件夹为加密分卷…**（就这一个；不加按钮、不加第二处入口）。
- 窗口内容（一个屏，不要向导）：源文件夹 A（选择框）→ 输出文件夹 B（默认填好、可改）→
  分卷大小（默认 512 MiB）→ **外层容器三选一**（rar / 7z / 不做外层）→
  密码 + 确认密码（+ 勾"外层 rar 用另一个密码"）→
  **摘要行**（内容大小 / 预计分卷数 / 外层容器 / 输出路径 / 需要空间）→ 「开始打包」→ 进度条 + 当前步骤 →
  结果区（外层产物路径 + 容器类型、分卷清单、复制密码、打开输出目录）。
- 没有 Rar.exe 时：**开始按钮不禁用**，**三个外层容器选项也都一直可点**
  （"7z 外层"旁边直接写着"无需额外安装（7-Zip 是 LGPL，随程序分发）"）—— 让用户**看得见**发生了什么，
  而不是按钮灰着不解释；选 rar 而没有 Rar.exe 时在切分卷之前就明确报错并给三条出路。
- 设置 →「外部工具」里有 **`Rar.exe 路径`** 一格（+ 浏览按钮），文案写明许可边界；
  下面一行工具状态说明"当前用的是自选的那份还是已装目录那份"。

## 8. 不做（明确写下来，免得被"顺手加上"）

- 不做"打包后自动删除源文件夹"（危险动作，与危险模式那套闸门不是一回事）
- 不做 zip/7z 之外的格式选择、不做恢复记录、不做固实块调优、不做多文件夹批量打包
- 不做"分卷大小自动按目标网盘限制选"（没有联网功能）
- 不做打包历史/模板/计划任务

## 9. 验收判据（写完要能照着验）

1. `dotnet build` 0 错误 0 警告；`dotnet test` 全绿；`dotnet format --verify-no-changes` 通过。
2. 单测（不碰真 WinRAR 的部分必须有）：
   - 分卷规划：1 GB → 2 卷；1.5 GB → 3 卷；512 MiB 边界；内容为 0 / 超大（>4 GiB）时的行为。
   - 密码校验：空 / 纯空格 → 拒绝；两次输入不一致 → 拒绝；密码**不出现在任何日志行**里。
   - **外层容器三选一**（2026-09-23 补）：
     ① 容器 = 7z → 外层命令字面模板正确、产物名是 `B.7z`、按 `-slt` 校验通过；
     ② 容器 = 不做 → **只跑一次**（切分卷），一个外层文件都不产；
     ③ 容器 = rar 而没有 `Rar.exe` → 报错含**三条**出路、**假 runner 0 次调用**、一个文件都不产；
     ④ 容器 = 7z 而没有 `Rar.exe` → **照常成功**且 `Rar.exe` 一次都没被调用；
     ⑤ 自选 `Rar.exe` 路径：合法 → 解析用它；不存在 → 保存被拦下并说明改法；留空 → 回落已装目录。
   - 输出落在 A 里面 → 拒绝；B 非空 / 同名产物已存在 → 拒绝（不默认覆盖）。
   - 空间不够 → 不开始，报需要/可用/差；不做外层时按**一份**算（比两份少）。
3. **真 7z 端到端**（本机有内置 7z，必须真跑一次）：造一个小文件夹 → 分卷大小设 1 MiB →
   断言 `.7z.001`/`.002` 存在、`7z l -p<测试密码>` 能列出内容、不存在的密码列不出来。
4. **真 7z 外层容器端到端**（2026-09-23 补）：容器 = 7z → `B.7z` 存在、
   `7z l -slt -p<测试密码>` 能列出两卷、错密码列不出来。
5. 真机人工项：装没装 WinRAR 各试一次（`docs/人工测试清单.md` 加一节）；本机已装 WinRAR，
   "真 `Rar.exe` 端到端"那条用例会**真跑**（不是跳过）。

| `ArchiveFixer/Password/PasswordMasker.cs` | 补一条 `-hp<密码>` 的掩码规则 —— 打包要用 `-hp`，而原来的正则只认 `-p`，不补上 rar 的命令行会原样进日志 |

### 10.2 与设计稿的偏差（两处，都往"更保守"的方向）

1. **落点拒绝从两条加到四条**：除了"B 在 A 里面""rar 在 B 里面"，还拒了
   **"rar 在 A 里面"**（不变量 12：源目录一个字节都不许写）与
   **"A 在 B 里面"**（外层 rar 装的是整个 B，会把源文件原样再存一份）。
   后两条与设计稿点名的两条是同一类错误，只是方向不同。
2. **多两条启动前拒绝**：**B 已存在且不为空** → 拒绝（B 会被整个装进 rar，混进旧文件结果就不对；
   而且"静默删掉上一次的残留"是另一种不打招呼的破坏）；**同名 `.rar` 已存在** → 拒绝
   （与不变量 3"冲突不默认覆盖"同一口径）。

另外：没有 `Rar.exe` 的检查放在**切分卷之前**（设计稿只说"明确报错"，没说时机）——
先花十几分钟切出几十个分卷、再告诉用户外层做不了，等于让他最贵的那一步白等。

### 10.3 实测（2026-09-23，本机 7-Zip 26.03 + WinRAR 6.11）

- `dotnet build ArchiveFixer.slnx`：**0 错误 0 警告**。
- `dotnet test`：**1292 通过 / 0 失败 / 0 跳过**（本次新增 `PackingTests` **23 条**）。
- `dotnet format ArchiveFixer.slnx --verify-no-changes`：通过。
- 真机实测的几处：
  - 1 MiB 分卷 + 不可压缩内容 → `.7z.001`（正好 1048576 字节）+ `.7z.002`；对密码 `7z l` 退出码 0，
    错密码退出码 2（`Cannot open encrypted archive. Wrong password?`）；
  - `Rar.exe a -hp… -r -ep1 out.rar <B>` → `Rar.exe lb -p…` 列出的条目是 `B\xxx.7z.001`、`B\xxx.7z.002`、`B`
    （**`-ep1` 保留 B 这一层**，正是要的形态）；
  - Rar.exe 的输出是**控制台代码页**（本机 936），所以 `PackProcessRunner` 对 7z 用 UTF-8、
    对 Rar 用 OEM 代码页 —— 否则分卷名带中文时校验会认不出条目。
