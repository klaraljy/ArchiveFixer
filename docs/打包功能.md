# 打包功能（用户 2026-09-22 需求第 10 条）

> 这是**设计说明 + 实施记录**。用户原话（节选）：
> 「打包功能就做一个就行，因为打包很少见。文件夹 A 的内容 → 7z 分卷
> （≤1 GB → `.7z.001`+`.002`；>1 GB → `.001`/`.002`/`.003`），**密码必须有**；
> 把这些分卷放进文件夹 B → 把文件夹 B 压缩成一个**带密码的 rar**；结果 = 压缩包 B。
> 复杂的变体不要。」

本文件只写**这一个功能**：为什么这么做、判据是什么、哪些事不做。

---

## 1. 它做什么（一句话）

把**一个文件夹**变成一个**带密码的 rar**：里面的内容是"该文件夹的 7z 加密分卷"。

```
A\（用户选的源文件夹，里面是要打包的东西）
        │  ① 7z 加密分卷（-mhe=on：连文件名一起加密）
        ▼
B\A名.7z.001, B\A名.7z.002, …        ← ② 分卷落在新建的文件夹 B 里
        │  ③ 把 B 整个用 RAR 加密打包（-hp：连文件名一起加密）
        ▼
B.rar                                ← 结果（"压缩包 B"）
```

两层加密是**用户明确要求**的：外层 rar 是"运输容器"，内层 7z 分卷是"内容 + 分卷"。

---

## 2. 分卷大小：默认 512 MiB（两个例子都能对上）

用户给的两个例子是"≤1 GB → 2 个分卷、>1 GB → 3 个分卷"。它们同时成立只有一个解释：
**每个分卷有体积上限**，内容大了就多切一卷：

| 内容大小 | 每个分卷上限 512 MiB 时切出 | 与用户例子的对照 |
|---|---|---|
| 1 GB | `.7z.001` + `.002`（各 ~512 MiB） | ✅ 完全一致 |
| 1.5 GB | `.001` + `.002` + `.003`（各 ~512 MiB） | ✅ 完全一致 |
| 4 GB | 8 个分卷 | 用户没给这个例子（按同一规则推） |

- 默认值 **512 MiB**（= 用户那两句话的唯一自洽解），界面上是**一个数字框**（64 MiB – 4096 MiB），
  用户可以改 —— 这样"他其实想要别的体积"时不必改代码。
- 分卷**命名由 7z 自己产生**（`-v<size>` → `名字.7z.001/.002/…`），程序**不自己拼分卷名**：
  自己拼会在"内容物恰好等于整数倍"这种边界上多切一卷出来。
- ⚠ **不做**"按体积自动决定切几卷"（"必须切成 3 卷"这种）—— 那是把体积上限换成卷数上限，
  内容一大就会切出几十 GB 的单卷，与用户"空间紧张"的处境直接冲突。

---

## 3. 密码（必填，两层同一个密码）

- **必填**：两个密码框（可勾"外层 rar 用另一个密码"），默认两个都用同一个。
- 空密码 / 只有空格 → **拒绝开始**并说清"必须设密码"（用户原话："密码必须有"）。
- **绝不落盘**：密码只在内存里活到本次打包结束（不变量 5 —— 密码只存内存）。
  日志里一律写"已设置密码"，**不写密码本身**，也不写 `-p<明文>`（命令行里会带上，
  这是外部工具命令行的固有限制 → 与解压侧同一口径写进「已知限制」）。
- 打包结束后界面上提供"复制密码"按钮（用户自己也要用），**不进剪贴板历史之外的地方**。

---

## 4. 落点与命名

| 项 | 规则 |
|---|---|
| 源文件夹 A | 用户选（只打包**内容**，不含 A 这一层目录本身？ → **含 A 这一层**，见下） |
| 文件夹 B | 默认与 A 同级：`<A 的父目录>\<A 名>_打包`（用户可改） |
| 分卷 | `B\<A 名>.7z.001`、`.002`、… |
| 结果 rar | 默认 `B.rar`（与 B 同级）；**rar 里装的是文件夹 B 本身**（解出来就有 B 这一层） |
| B 本身 | **保留**（用户可能要先检查分卷），界面上给一句"确认没问题后可以自己删掉 B" |

> ⚠ **绝不在源目录里写任何东西**（不变量 12）：分卷只写进 B，B 的默认位置在 A 的**外面**。
> 用户如果把 B 指到 A 里面 → 直接拒绝并说明（那会让"打包的内容"越打越多）。

## 5. 外部工具：7z 一定在，Rar.exe 只能"用户自装"

| 步骤 | 用什么 | 没有时怎么办 |
|---|---|---|
| 建 7z 加密分卷 | 内置 `tools\7zip\7z.exe`（`a -t7z -mx=5 -mhe=on -p… -v512m`） | 理论上不会没有（程序自带）；确实缺 → 报"没有可用的解压引擎"那一套 |
| 建加密 rar | **`Rar.exe`（WinRAR 的**命令行**程序，共享软件）** —— 只检测、只调用、**绝不分发**（AGENTS.md §3.1） | **明确报错**：告诉他"这一步需要本机已安装 WinRAR（要 `Rar.exe` / `WinRAR.exe`）"，并给出**替代出路**：①装 WinRAR 后重试 ②先只做 7z 分卷（跳过外层 rar） |

- ⛔ **绝不用 7z 假装做出 `.rar`**：7-Zip **不能创建 RAR**（RAR 的压缩算法是专有的）。
  文件名改成 `.rar` 是**伪造**，用户拿去用时会直接坏掉 —— 这属于"宁可报错也不撒谎"。
- ⛔ 也**不内置** `Rar.exe`（许可不允许随包分发）。
- 定位沿用 `ToolLocator`（唯一来源）：`Rar.exe` 先找用户自选路径 → 再找已装 WinRAR 目录 →
  都没有就报上面那句。**"只做 7z 分卷"这一条出路必须是可点的**（不是让他自己去敲命令）。

命令行（两条都在实现里写死参数模板，**只允许出现在 `Packing/` 内部**，与 §3.1 的"四条禁止项"同一口径）：

```text
# ① 加密分卷（-mhe=on 连文件名一起加密；-v512m 分卷；输出到 B）
7z.exe a -t7z -mx=5 -mhe=on -p<密码> -v512m "<B>\<A名>.7z" "<A>\*"

# ② 加密 rar（-hp 连文件名一起加密；-r 递归；结果 B.rar 装的是 B 这一层）
Rar.exe a -hp<密码> -r -ep1 "<B>.rar" "<B>"
```

## 6. 取消、失败与"不变量"

| 情形 | 行为 |
|---|---|
| 用户取消 | **杀掉自己启动的那个 PID 及其子进程**（绝不按名字杀 `7z.exe`/`Rar.exe`，不变量 10） |
| ① 失败 | 报错，**不留半个 rar**；已经切出来的分卷**保留**并在日志里说明"分卷已生成，rar 未生成"（重试时能接着用） |
| ② 失败 | 分卷保留（同上）；明确说"外层 rar 没做成，原因：找不到 Rar.exe / 密码太短 / …" |
| 成功 | 界面给出：rar 路径 + 大小 + 分卷清单（名字 + 各自大小）+ "复制密码"；日志里同一条 |
| 校验 | 完成后**列一遍 rar 的条目**（`Rar.exe l` / `7z l` 读 rar）：确认里面有 B 这一层且分卷数对得上；对不上就报"产物不对"，**不显示成功**（不变量 6 同一口径） |
| 空间 | 开始前算一次需求（内容大小 × 1.02 + 内容大小（外层再存一份））并与目标盘可用空间比；不够就**不开始**，报"需要/可用/差"（与解压侧同一套 `SpaceGate` 口径） |

---

## 7. 界面（只有一个入口，一个窗口）

- 入口：主界面菜单 **工具 → 打包文件夹为加密分卷…**（就这一个；不加按钮、不加第二处入口）。
- 窗口内容（一个屏，不要向导）：源文件夹 A（选择框）→ 输出文件夹 B（默认填好、可改）→
  分卷大小（默认 512 MiB）→ 密码 + 确认密码（+ 勾"外层 rar 用另一个密码"）→
  **摘要行**（内容大小 / 预计分卷数 / 输出路径 / 需要空间）→ 「开始打包」→ 进度条 + 当前步骤 →
  结果区（rar 路径、分卷清单、复制密码、打开输出目录）。
- 没有 Rar.exe 时：**开始按钮不禁用**，而是把"只做 7z 分卷"作为一个显式勾选项
  （勾了就不做外层 rar，结果直接是 B 里的分卷）—— 让用户**看得见**发生了什么，而不是按钮灰着不解释。

---

## 8. 不做（明确写下来，免得被"顺手加上"）

- 不做"打包后自动删除源文件夹"（危险动作，与危险模式那套闸门不是一回事）
- 不做 zip/7z 之外的格式选择、不做恢复记录、不做固实块调优、不做多文件夹批量打包
- 不做"分卷大小自动按目标网盘限制选"（没有联网功能）
- 不做打包历史/模板/计划任务

## 9. 验收判据（写完要能照着验）

1. `dotnet build` 0 错误 0 警告；`dotnet test` 全绿；`dotnet format --verify-no-changes` 通过。
2. 单测（不碰真 WinRAR 的部分必须有）：
   - 分卷规划：1 GB → 2 卷；1.5 GB → 3 卷；512 MiB 边界；内容为 0 / 超大（>4 GiB）时的行为。
   - 密码校验：空 / 纯空格 → 拒绝；两次输入不一致 → 拒绝；密码**不出现在任何日志行**里。
   - 无 `Rar.exe` → 报错文案包含"需要本机已安装 WinRAR"，且**不产生** `.rar` 文件。
   - 输出落在 A 里面 → 拒绝。
   - 空间不够 → 不开始，报需要/可用/差。
3. **真 7z 端到端**（本机有内置 7z，必须真跑一次）：造一个小文件夹 → 分卷大小设 1 MiB →
   断言 `.7z.001`/`.002` 存在、`7z l -p<测试密码>` 能列出内容、不存在的密码列不出来。
4. 真机人工项：装没装 WinRAR 各试一次（`docs/人工测试清单.md` 加一节）。

### 10.2 与设计稿的偏差（两处，都往"更保守"的方向）

1. **落点拒绝从两条加到四条**：除了"B 在 A 里面""rar 在 B 里面"，还拒了
   **"rar 在 A 里面"**（不变量 12：源目录一个字节都不许写）与
   **"A 在 B 里面"**（外层 rar 装的是整个 B，会把源文件原样再存一份）。
   后两条与设计稿点名的两条是同一类错误，只是方向不同。
2. **多两条启动前拒绝**：**B 已存在且不为空** → 拒绝（B 会被整个装进 rar，混进旧文件结果就不对；
   而且"静默删掉上一次的残留"是另一种不打招呼的破坏）；**同名 `.rar` 已存在** → 拒绝
   （与不变量 3"冲突不默认覆盖"同一口径）。

另外：没有 `Rar.exe` 的检查放在**切分卷之前**（设计稿只说"明确报错"，没说时机）——
先花十几分钟切出几十个分卷、再告诉用户外层做不了，等于让他最贵的那一步白等。

### 10.3 实测（2026-09-23，本机 7-Zip 26.03 + WinRAR 6.11）

- `dotnet build ArchiveFixer.slnx`：**0 错误 0 警告**。
- `dotnet test`：**1292 通过 / 0 失败 / 0 跳过**（本次新增 `PackingTests` **23 条**）。
- `dotnet format ArchiveFixer.slnx --verify-no-changes`：通过。
- 真机实测的几处：
  - 1 MiB 分卷 + 不可压缩内容 → `.7z.001`（正好 1048576 字节）+ `.7z.002`；对密码 `7z l` 退出码 0，
    错密码退出码 2（`Cannot open encrypted archive. Wrong password?`）；
  - `Rar.exe a -hp… -r -ep1 out.rar <B>` → `Rar.exe lb -p…` 列出的条目是 `B\xxx.7z.001`、`B\xxx.7z.002`、`B`
    （**`-ep1` 保留 B 这一层**，正是要的形态）；
  - Rar.exe 的输出是**控制台代码页**（本机 936），所以 `PackProcessRunner` 对 7z 用 UTF-8、
    对 Rar 用 OEM 代码页 —— 否则分卷名带中文时校验会认不出条目。

### 10.4 遗留 / 待拍板

- `ToolLocator.CustomRarExePath`（用户自选 Rar.exe 路径）**还没有设置界面**：解析链已经支持，
  但没有 UI 去填它。当前实际只用"已装 WinRAR 目录"这一档。
- 退到 `WinRAR.exe`（GUI 版）时补了 `-ibck`（后台 / 托盘），**没有自动化验证过**：
  本机有 `Rar.exe`，跑那条路会在用户桌面弹出一个进度窗口 —— 按 `AGENTS.md` §13 不在自动化里碰。
  真正要验它得靠真机人工（把 `Rar.exe` 临时改名）。
- 取消发生在**第一步（7z 分卷）**时，B 里的分卷是不完整的；程序**不删**（设计稿：分卷保留），
  只在日志与提示里写明"可能不完整，重试前请先清空 B"。
