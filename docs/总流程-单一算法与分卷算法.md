# 总流程：单一算法与分卷算法（第一大步 / 第二大步 · 两道闸门）

> 这份是**流程总纲**：把「一轮 = 第一大步 + 第二大步」的完整逻辑写成一套，包含
> ① 底层能识别到的全部情况；② 单一专属算法（第一大步闸门的判据）；③ 分卷专属算法（第二大步的组分析+解压+收片）；
> ④ 两道闸门的输入/判据/成立与不成立的动作；⑤ 轮次模型（每轮重算入口包/工作区/落点）；
> ⑥ 与现有代码的对应与差距。
>
> 口径来源：`docs/第一大步与第二大步-流程与口径.md`、`docs/分卷专属算法-待校验.md`、
> `docs/需求变更.md`，以及 2026-10-22 用户对「闸门方向」「过程物定义」「媒体前缀」「7z/ZIP 分卷不归第一大步」的当面口径。

---

## 0. 一句话

**一轮 = 第一大步（把单一完整压缩包全部解开）+ 第二大步（把分卷只解一层）。**
第一大步闸门**留下**单一完整压缩包（第一大步处理），**放行**其余一切（非单一 / 判不出）；
放行的东西**原地不动**，它们就是第二大步的原包。

---

## 1. 术语

| 术语 | 含义 |
|---|---|
| 一轮 | 第一大步 + 第二大步；每到轮边界按盘上事实重新分类，不继承上一轮的角色 |
| 单一完整压缩包 | 内容可证"完整的单卷归档"：它自己就是一份能独立打开的归档（含媒体前缀，只在其前面垫了数据） |
| 分卷 / 组成员 | 内容可证"是某分卷组的一员"（首片 / 第 N 片），或判不出但属于卷族 |
| 第一大步闸门 | 判据 = 单一专属算法；**留下**单一包给第一大步，**放行**其余 |
| 第二大步闸门 | 判据 = 分卷专属算法里的组分析三道闸门（同组 / 卷号一对一 / 整组自洽） |
| 入口包 | 第二大步要"对谁输入密码"的那一片：内容卷号=1 / 首卷标记 / 大小最靠前 |
| 入口层 | 入口包所在的那一层；第二大步的工作区与解压都在这里 |
| `VolumeHandoffEntry` | 每份文件的事实登记（基名/族/大小/内容身份/卷号/首卷标记/所在层/来源） |
| 原包 | 用户导入的原件，或**通过闸门、未被打开过的片**（第二大步的原包） |
| 过程物 | **只有我们真的把它解开了、并且从它产出了内容物**的中间包，才叫过程物 |
| 判不出 | 内容层给不出结论；按规则**什么都不做**（不改名、不搬、不删、不下结论） |

## 2. 底层能识别到的全部情况（一张卡）

唯一出口：`Detection/FileNature.Inspect` → `FileNatureCard`（格式 / 分卷身份 / 卷号 / 首卷标记 / `BodyKind` / 名字线索 / 物理身份 / 媒体前缀偏移）。

### 2.1 正常单卷（第一大步的对象）

| 族 | 判据 | 卡上 |
|---|---|---|
| RAR5 | 签名 + 主归档头读到 + `Volume 位 = 0` | `SingleComplete` |
| RAR4 | 签名 + 主头 13 字节 CRC 通过 + `MHD_VOLUME = 0` | `SingleComplete` |
| ZIP | EOCD：盘号 0/0、非 split、中央目录偏移小于本文件 | `SingleComplete` |
| 7z | 起始头自述整包字节数（`32 + NextHeaderOffset + NextHeaderSize`）≤ 本文件 | `SingleComplete` |
| 其它格式 | 内容能自证才给结论；否则 `Unknown` | — |
| **RAR4 加密头（`-hp`）单卷** | 主头是**明文**（实测 flags=`0x0080`、CRC16 通过） | **`SingleComplete`** |
| **7z 加密头（`-mhe`）单卷** | 起始头明文，自述字节仍可读 | **`SingleComplete`** |

### 2.2 分卷（第二大步的对象，第一大步一律放行）

| 族 | 情况 | 底层读到 | 卡上 |
|---|---|---|---|
| RAR5 | 首卷 | `Volume=1`、无卷号字段 | `VolumeFirstPiece` |
| RAR5 | 第 N 卷 | `Volume=1` + 卷号字段 | `VolumePiece` + 卷号 |
| RAR4 | 首卷 | `MHD_VOLUME=1` + `MHD_FIRSTVOLUME=1` | `VolumeFirstPiece` |
| RAR4 | 中/末卷（有卷尾归档结尾块） | 结尾块 `EARC_VOLNUMBER`（绝对卷号 = 字段 + 1） | `VolumePiece` + 卷号 |
| RAR4 | 中/末卷（无卷尾块） | 主头证明是分卷，卷号缺 | 成员、卷号判不出 |
| RAR4 | 老式编号 `.rar` + `.r00` | 编号族=老式（本程序不改名、不猜） | 成员、卷号判不出 |
| ZIP | 跨盘末片 | EOCD 盘号 > 0 或中央目录偏移 ≥ 本文件 | `VolumePiece`（盘号+1） |
| ZIP | 跨盘中间片 | 无 EOCD，开头是四种 PK 签名之一 | 成员、卷号判不出 |
| ZIP | 裸切中间片 | 无 EOCD、开头也不是 PK | `Unknown` |
| ZIP | 通用分片首片 `.zip.001` | 本地头、可能带盘信息 | 成员或判不出 |
| 7z | 首片 | 起始头自述整包字节数 > 本文件，片数合理 | `VolumeFirstPiece` + 片数 |
| 7z | 中间/末片 | 无 7z 签名（裸字节流） | `Unknown` |
| RAR5 | **加密头（`-hp`）** | 第一个头 = 加密头（type=4）⇒ 卷位/首卷/卷号全部不可读（实测：单卷与首卷的卡一模一样） | `Unknown`（判不出） |
| 任何族 | 头坏了 / 截断 / 全零 | 读不出 | `Unknown` |
| 7z | 首片但自述字节荒谬 | 片数超合理性上限 | `Unknown`（不编） |

### 2.3 媒体前缀（前面垫 mp4/jpg/png，归档从某个偏移开始）

| 前缀 | 锚点（媒体结束） | 之后 |
|---|---|---|
| MP4 | 从 `ftyp` 起按 `size + type` 走顶层 box，第一个不合法 box 处 | 归档起点 |
| JPEG | 段头走到 `FFD9`（EOI） | 归档起点 |
| PNG | 块链走到 `IEND` 末尾 | 归档起点 |

定位之后再按格式做**自洽校验**（不猜）：
- ZIP：EOCD 声明的中央目录偏移 − 实际位置 = 前缀长度；
- 7z：`StartHeaderCRC` + `NextHeaderCRC` + `32+Offset+Size` 与文件剩余对账；
- RAR4：主头 13 字节 CRC16 + `MHD_VOLUME = 0`（分卷片一律不认）；
- 扫描窗口：快扫 = 文件尾 4 MB；深扫 = 从文件头到 512 MiB（与 ZIP 的顺序扫同一口径，**512 MiB 是窗口上限，不是文件大小上限**）；
- 深扫只对「后缀是媒体 + 媒体锚点解析成功」的文件触发，避免对普通大文件白扫。

RAR5 的媒体前缀：今天判不出（加密头 + vint 解析成本），按判不出处理（放行给第二大步）。

## 3. 单一专属算法（第一大步闸门的判据）

**它只回答一个问题：这一份是不是"单一完整压缩包"。**

输入：内容卡（格式 / 卷身份 / 卷号 / 首卷标记 / `BodyKind` / 媒体前缀偏移）。
输出（三档）：

| 输出 | 含义 | 闸门动作 |
|---|---|---|
| `SingleComplete` | 内容自证完整单卷（含媒体前缀、含"头完好的损坏包"） | **留下** ⇒ 第一大步处理 |
| `VolumeFirstPiece` / `VolumePiece` | 分卷组成员 | **放行** ⇒ 原地不动，第二大步原包 |
| `Unknown` | 判不出（RAR5 加密头、7z 中间片、裸切中间片、头坏/截断） | **放行** ⇒ 原地不动，第二大步原包 |

**判据只读内容，不看引擎能不能打开、不看后缀。** 引擎只在第一大步真正解压时参与；损坏在解压时由引擎如实报。

**边界（如实写）**：
- 头完好的损坏包（数据/条目坏）⇒ 仍判 `SingleComplete`，算第一大步的对象；
- 头本身坏了/截断 ⇒ 判不出 ⇒ 走放行那一侧（第二大步试开会报"损坏/缺卷"）；
- 7z 被截断的单卷与 7z 分卷首片，内容上无法区分 ⇒ 归判不出（放行）。

## 4. 第一大步流程

1. **统一预标记**：每一份文件先写 `VolumeHandoffEntry`（只记事实，不是拦截）。
2. **识别**：`FileNature.Inspect` 一张卡（含媒体前缀定位）。
3. **过闸门**（单一专属算法）：留下 / 放行。
4. **留下的**：
   - 媒体前缀 ⇒ 先按偏移把归档区间抠出来再解；
   - 全递归解压；**遇到分卷成员就停手**（⛔ 不在第一大步里开组、不写"分卷缺失"结论）；
   - 还原：把伪装后缀替换成规范形态（只动卷标记那一段、只改名、内容零改动、全成或全不成）；
   - 解完回到识别再判一次（回环）。
5. **三种结果**（只针对单一包）：
   - 成功 ⇒ 内容物落地；
   - 密码错误/候选试完打不开 ⇒ **失败**；包装留原处不动，从内容物里踢出（第二大步也救不了）；
   - 损坏但救回一部分 ⇒ 日志必须写「压缩包损坏」；不完整内容物留下；**最后一层过程物**按③页"删除操作"档。
6. **过程物删除**（定义见 §1）：
   - 被本链**真正打开过、且产出了内容物**的中间包 = 过程物 ⇒ 定稿+校验通过后当场永久删；
   - **没被打开过的片 = 原包**（第二大步的）⇒ 一个字节不动（不删、不搬、不进其余物）；
   - 用户导入的原件 ⇒ 永远按「源包处理」档，延期到整条链跑完。
7. **红线**：只碰自己产出的内层包副本；用户源目录一个字节不动；只改名不覆盖；判不出什么都不做；第一大步不许整批停。

## 5. 交接（轮边界）

- 交接 = 第一大步剩下的（放行的）交给第二大步；**没有"待交接内容物"这种中间态**，放行的东西就**原地不动**；
- 交接只写事实，不列族清单：建组只有一个出口（按卡的格式分派 RAR/7z/zip；判不出 ⇒ 什么都不做）；
- `VolumeHandoffEntry` 一行一份：`基名 / 族 / 大小 / 内容身份（首片·片+卷号·判不出）/ 名字卷号 / 首卷名 / 所在层 / 来源（用户原件 or 程序产出）`；
- 轮判定（唯一出口 `RoundProductClassifier`）按盘上事实重新分类：
  内容物 ⇒ 结束；单一压缩包 ⇒ 下一轮第一大步；分卷 ⇒ 下一轮直接第二大步。

## 6. 分卷专属算法（第二大步）

**顺序恒定：内容识别 → 名字识别 → 定槽位 → 规范改名 → 交给引擎试开。** 反过来（先改名再看）会出现"按它说的改完还是解不开"。

### 6.1 组分析（基石 = 基名 + 大小）

1. **同组**：基名逐字相同 + 族相同（唯一出口 `VolumeGroupDetector.Group` / `BelongsToSameGroup`）；
2. **大小**：除末卷外等大、末卷较小；定序时用作第二证据；
3. **内容身份**：RAR 卷号/首卷标记；ZIP 盘号/末片标记；7z 首片自述总字节（片数）；
4. **判不出**（7z 中间片、RAR5 加密头）：只按 基名 + 大小 定序；
5. 7z 大小异常：今天不做分析，先按基石判断。

### 6.2 第二大步闸门（三道，缺一不可）

| # | 闸门 | 不过的动作 |
|---|---|---|
| 1 | 同组：基名 + 族 | 整组不做 |
| 2 | 卷号一份对一份（同卷号两份候选 ⇒ 整组不做） | 整组不做 |
| 3 | 整组自洽：连成 1..N 无洞 + 尺寸规律 +（7z）字节守恒 | 缺卷如实写"缺哪几片"；判不出就不动 |

### 6.3 三步

1. **搬**：整组片搬进入口层。程序产出的片：同卷搬、跨卷建链接；用户导入的原件：只建零字节硬链接（源目录只读红线）；本单自己暂存目录里那份只建链接、绝不搬走。
2. **解**：在入口层**只解一层**（工作区 = 入口包那一层）。
3. **收**（必须在入口那一跑收尾时当场做，⛔ 不挪到批末）：
   - 成功（校验通过）⇒ 组片按过程物**全部删除**；
   - 失败/密码错/缺卷 ⇒ 组片**全部留在入口层**；
   - 用户原件 ⇒ 按「源包处理」档（留下 ⇒ 不动）。

### 6.4 各族细节

- **7z 分卷**：只有首片认得出（魔数 + 自述字节 + 片数）；中间/末片是裸字节流 ⇒ 名字+大小定序；字节守恒做最后校验。
- **RAR5**：卷号来自主头（字段 + 1）；第 1 卷没有该字段 ⇒ 1；加密头 ⇒ 判不出，靠基名+大小+试开。
- **RAR4 新编号**：主头 `Volume` 位 + 首卷标记；卷号来自卷尾归档结尾块（字段 + 1）；无结尾块 ⇒ 卷号判不出。
- **RAR4 老编号**（`.rar` + `.r00`）：认得出是分卷，但序号无法对应 `partN.rar` ⇒ 不改名、不猜（只按名字+大小处理）。
- **跨盘 ZIP**：末片 `X.zip` 是入口（`.z01` 只是第 1 片）；盘号决定顺序；单盘 ZIP 才是第一大步的对象。
- **ZIP 通用分片**（`.zip.001`）：入口 = `.001`；组内靠名字+大小定序。

## 7. 两道闸门对照表

| | 第一大步闸门 | 第二大步闸门 |
|---|---|---|
| 判据来源 | 单一专属算法 | 分卷专属算法的组分析 |
| 输入 | 内容卡（格式/卷身份/媒体前缀偏移） | 放行的片 + `VolumeHandoffEntry` |
| 成立 | `SingleComplete` | 三闸门全过（同组 / 卷号一对一 / 整组自洽） |
| 成立的动作 | **留下** ⇒ 第一大步全解压 | 搬进入口层 → 改标准名 → 只解一层 → 按结论收片 |
| 不成立 | **放行** ⇒ 原地不动，成为第二大步原包 | 一个字节不动 + 如实写一行（判据输入写清） |
| ⛔ 不许 | 用引擎"认不认"当判据；越界开组；按名字猜 | 判不出还搬/删/改名；先改名再识别 |

## 8. 轮次模型（R1 / R2 / R3）

- **R1（已落）**：轮判定进代码，一行轮结论；
- **R2（已落）**：第二大步只解一层（任务级事实位 `_volumeStepTasks` / `IsSingleLayerRecursion`）；
- **R3（未做）**：**每轮重算入口包 / 工作区 / 落点**：
  - 入口包：单一包 = 它自己；分卷组 = 组分析选出的那一片；
  - 工作区 = 入口包所在层；
  - 落点 = `GroupVolumeDirectory` + `PackageLayerRules`（最少两层；普通文件夹不摊平）；
  - ⛔ 不沿用上一轮的任务/路径；⛔ 不按任务表顺序选落点。
- 第二大步跑完如果剩下的仍是分卷 ⇒ 下一轮：第一大步**只做标记**（闸门不放行非单一），然后第二大步再解一层。
- 一轮最多 10 轮（唯一出口 `OneClickCoordinator.RoundLimit`）。

| 7z 大小异常 | 今天不做分析 | 先按基石（基名+大小） |
| 媒体前缀 RAR5 | 判不出 | 放行 |
| RAR4 老编号改名 | 不做（不猜） | 只按名字+大小处理 |

## 10. 与现有代码的对应与差距（如实）

| 环节 | 现状 | 差距 |
|---|---|---|
| 底层识别 | `FileNature.Inspect` 一张卡（已含 `BodyKind`、`EmbeddedOffset`） | 媒体锚点（MP4/JPEG/PNG）未实现；深扫已做（≤512 MiB） |

| 通过闸门的片 | `ExtractionCoordinator:5653` 把"组里的片"当过程物收走 | **判据错**：过程物 = 被打开且产出内容物；放行的片必须原地不动 |

| 组分析 | `VolumeGroupDetector` + `VolumeGroupUnit`（组事实）已有 | 需以"基名+大小"为基石补 7z/ZIP 判不出族的定序 |
| 第二大步 | `RarVolumeGroupBuilder` / `SevenZipVolumeGroupBuilder` / `TryBuildGroupUnitFromContentAsync` | 与交接表接线；`ApplySecondStepGroupPieceHandling` 收片已存在 |
| R3 | 未做 | 每轮重算入口包/工作区/落点 |

## 11. 验收判据（大测试按这五条判红绿）

| 判据 | 含义 |

```
用户导入

   ├─ 统一预标记：每份文件写 VolumeHandoffEntry（只记事实）
   │
```
