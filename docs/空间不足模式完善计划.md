# 空间不足模式完善计划

> 状态：已实现核心策略（SpaceTight 最大包跳过、失败不发布未完成内容、其余物保留、跨盘禁止复制、保留余量 64 MiB、20 份验收）；跨盘分卷组与硬链接别名回收仍需补真机用例
> 日期：2026-11-06
> 关联：`docs/空间不足造包器与20份测试计划.md`
> 目标：把空间不足从“普通删除档旁边的一组 if”升级成一套**批首冻结、覆盖策略、但绝不绕过安全闸门**的运行模式。

---

## 1. 结论先行

空间不足模式采用**覆盖制度**，不是在普通模式里分散加 `if`：

```text
批首解析一次
  → NormalPolicy（原行为，完全不变）
  → SpaceTightPolicy（覆盖源包/其余物/并发/排序/失败内容物）

后续只读批首策略；不再读实时 UI 开关
```

覆盖的是**策略选择**，不是安全闸门：

- 不覆盖“失败不删源”；
- 不覆盖“未验证的内容不发布”；
- 不覆盖“删源前必须过完整性/取消/归属/分卷完整/别名清理”；
- 不覆盖“跨盘不复制源包”。

---

## 2. 两种模式的定义

### 2.1 普通模式

- 源包保留（除非用户选 `DeleteInPlace`）；
- 解压成功的过程物自动删除；
- 盘上峰值约为：

```text
源包 + 内容物 + 过程物
```

- 空间门按“内容物 + 过程物”判断；源包已经在盘上，不从可用空间里重复扣；
- 不提前删源包，失败 / 取消源包不动。

### 2.2 空间不足模式

- 把源包当成**过程物**处理：某一层内容完整后，删除该层源包/整组分卷；
- 每层各自回收，不等整条链成功；
- 失败 / 中断 / 未完全解出：
  - 未完成内容物**不发布、不保留到成品**；
  - 该层源包作为**最后一层过程物**固定保留；
  - 用户可以自己拿过程物再解；
- 空间门按“内容物 + 过程物”判断；
- 排序按完整包/整组源包大小降序；
- 并发以用户选择的效率档为天花板；空间不足只能降低，不能抬高；
- 大包一开始放不下时直接记空间不足并退出队列，继续看后面的小包，不反复等待；
- 跨盘不复制源包；同盘硬链接不占数据空间，但删源前必须清掉组入口硬链接/别名。

---

## 3. 批首策略对象

批首生成一份冻结策略，所有组件只读它：

```text
SpacePolicy
  Mode                       Normal | SpaceTight
  SourceOnLayerSuccess       Keep | DeleteLayerSource
  SourceOnFailure            KeepAsLastProcess
  PublishPartialContent      false（SpaceTight 强制）
  RestOnFailure              KeepLastProcess
  RestOnSuccess              DeleteNonLastProcess
  Ordering                   SourceSizeDescending
  SkipUnfitAtStart           true
  ConcurrencyCap             UserN
  DynamicConcurrency         true
  SpaceDemand                ContentBytes + ProcessArtifactBytes
  CrossVolumeEntry           NoCopy
  AliasCleanup               BeforeSourceDelete
```

> `SpacePolicy` 是**设计名**，当前代码里还没有这个类；它指批首生成、后续只读的本次运行策略快照，不是新的用户设置。

### 3.1 普通模式

`NormalPolicy` 保持现有行为：

- 源包保留 / 用户删除档；
- 成功删除过程物；
- 正常排序与并发；
- 不启用“最大包跳过后不重试”的新规则。

### 3.2 空间不足模式

`SpaceTightPolicy` 覆盖：

| 维度 | 覆盖后的行为 |
|---|---|
| 源包 | 每层成功后删除该层源包/整组卷 |
| 失败 | 源包留作最后一层过程物；未完成内容物丢弃 |
| 其余物 | 最后过程物固定保留；其它成功过程物删除 |
| 并发 | `min(用户效率档, 空间可承载数)`；可动态升高，但不超过效率档 |
| 排序 | 源包/整组体积降序 |
| 放不下的大包 | 立即空间不足并退出，继续小包 |
| 空间判据 | 内容物 + 过程物 |
| 部分发布 | 强制关闭 |
| 跨盘入口 | 不复制源包 |
| 删源前 | 清组入口/别名；清不掉则不删源 |

## 4. 空间账本

### 4.1 单位

内部全部字节；显示 KiB/MiB/GiB。测试夹具统一用字节，不使用“看起来差不多”的 MB 字符串。

### 4.2 每个任务的账

```text
SourceBytes          源包整组（分卷求和）
ContentBytes         解压后内容物
ProcessArtifactBytes 本次额外过程物（内嵌副本 + 内层包净增量）
PeakBytes            Source + Content + Process（描述用）
FreeSpaceDemand      Content + Process（放行判据）
```

### 4.3 放行

```text
目标盘可用
- 已在跑任务的预留
- 本任务 FreeSpaceDemand
>= 保留余量
```

- 源包不加入放行需求：它已经在盘上；
- 保留余量不再固定 512 MiB：小说、TXT 这类小包实际可能远小于 512 MiB，固定 512 MiB 会把大量小任务误拦；
- 设计改为**可配置 + 按任务缩放**的保留余量：默认上限 64 MiB，下降到不小于 1 MiB，具体公式在空间单位/阈值讨论时最终定；
- 小包边界测试仍使用测试宿主注入：`SpaceReserveOverride` / `SpaceProbeOverride`，不改生产默认。

### 4.4 源盘 / 目标盘

- 同盘：源包删除会释放该盘空间，下一任务受益；
- 跨盘：源包在 E、目标 H 时，删除源包只释放 E，不会让 H 的可用空间变大；两个盘分别记录，不能把 E 的回收算成 H 的额度；
- 跨盘不复制源包；目标 H 只承担内容物 + 过程物。

## 5. 安全闸门

空间不足模式必须逐条通过现有安全闸门，只是**触发时点**可以提前到“每层成功”，不是绕过判据。

### 5.1 L1 启动前

不变：

- 源文件快照 / 源变化检测；
- 缺卷检查；
- 路径安全预检；
- 资源预算；
- 空间门；
- 取消令牌。

空间不足新增：

- 大包放不下直接 `SpaceBlocked`，不启动；
- 跨盘入口不复制；
- 排序和并发按空间策略。

### 5.2 L2 产物落点

不变：

- 产物不得越出目标根；
- 空产物 / 全 0 字节产物失败；
- 未完成内容物不进入最终目录。

空间不足新增：

- 失败层的内容物只留在工作区，不提交；
- 空间不足模式不允许“部分完成发布”；
- 失败后清理工作区未完成内容物，保留最后一层过程物。

### 5.3 L3 清单核对

不变：

- 有可信清单才逐条核对；
- 缺非空条目 / 总字节少 ⇒ 失败；
- 清单不可用 ⇒ 判不出。

空间不足可以提前删源包，但删源前必须有：

```text
本层定稿成功
+ 内容校验通过
+ 完整性不是 Incomplete
+ 未取消
+ 源包属于本任务
+ 分卷组完整
+ 硬链接别名已清理
```

> 只缺 0 字节条目的 `Undeterminable` 档：内容可发布，但**不删源包**；这是完整性升级后的统一口径，空间不足也不放宽。

### 5.4 L5 定稿

空间不足模式必须先完成后：

- 内容物提交；
- 输出校验；
- 落点复核。

再执行源包删除。

禁止：

```text
引擎成功 → 先删源包 → 再发现内容不完整
```

### 5.5 L6 删除源包

删除仍只走唯一出口 `SourceCleanupService`，空间不足只改变触发时点：

```text
单包：该层成功 + 校验通过 → 删除该包
分卷组：整组成功 + 整组完整 → 删除整组全部源片
嵌套链：哪一层成功，回收哪一层的输入包
失败 / 取消 / 未完成：不删源包，保留为最后一层过程物
```

删源前必须：

1. 清掉 group-entry 硬链接和别名；
2. 确认删除清单只来自本任务；
3. 确认没有“半套分卷”；
4. 删除失败时如实记录，不能把“部分删除”当成功；
5. 对分卷组，不能只删入口片，留下其它片。

---

## 6. 最后一层过程物

失败时固定保留，不受普通“删除其余物”档影响：

- 单包：保留原包本体；
- 分卷组：保留整组源片；
- 内层包：保留失败那一层的输入包；
- 未完成内容物：不发布、不留在最终目录；
- 日志和 recipe 记录最后过程物路径；
- 用户可手工再解。

---

## 7. 删源时机与风险

用户选择空间不足模式时，明确接受“源包可能先被删、后续失败无法回滚”的风险。

但删除仍然只在以下情况下发生：

```text
当前层内容已完整
+ 已提交
+ 已校验
+ 未取消
+ 源包归属明确
```

删除后如果后续层失败：

- 已删除的外层源包不回滚；
- 最后一层过程物保留；
- 未完成内容物丢弃；
- 任务如实标失败，不伪装成功。

---

## 8. 跨盘与硬链接

### 8.1 跨盘

- 源包在 E、目标在 H：引擎直接读 E，内容物写 H；
- 不复制源包；
- 目标 H 只承担内容物 + 过程物；
- 源包删除只释放 E，不得算作 H 的空间回收。

### 8.2 同盘硬链接

- 硬链接不复制数据，只多目录项；
- 组入口硬链接必须在删源前清掉；
- 清不掉别名 ⇒ 不删源包（避免“源文件没了、空间也没回来”）；
- 硬链接别名不参与“新写空间”需求。

### 8.3 跨盘分卷入口

如果引擎需要标准卷名，只能在**源盘**上建硬链接/临时入口；不能把分卷复制到目标盘。若源盘无法建入口，则：

- 优先直接使用原始源路径；
- 不允许退回“复制到目标”；
- 无法安全建组则不写盘、不改源。

---

## 9. 并发与排序

### 9.1 排序

```text
按单个完整包 / 整组分卷体积降序
```

### 9.2 放不下的大包

- 批首/轮到它时空间不足 ⇒ 立即记空间不足并退出，不进等待重试名单；
- 继续后面的小包；
- 大包不因为后面小包回收空间而自动重试；
- 源包一个字节不动。

### 9.3 并发

- 用户效率档是上限；
- 空间不足只收紧；
- 每完成一个任务，释放预留、刷新空间；
- 空间变宽时动态提高，但不超过效率档；
- 跨盘时只有目标盘空间影响“能不能写”，源盘释放不虚增目标额度。

---

## 10. 特定解压

特定解压也要读同一套 `SpacePolicy`：

- 空间预检：内容物 + 过程物 + 保留余量，不再只比 `free < sourceBytes`；
- 每个外层包/独立包按完整单位排序；
- 并发不超过用户效率档；
- 成功删源，失败保留最后一层过程物；
- 未完成内容物不发布；
- 多相同文件不再被当成“体积相同就能随便并行”，仍按空间额度准入。

---

## 11. 普通模式保持不变

- 源包默认保留；
- 用户选彻底删除才删源；
- 成功过程物自动删除；
- 普通并发/排序/其余物档不因空间不足代码改变；
- 空间不足策略只在批首覆盖，不做跨批持久化。

---

## 12. 日志与用户可见性

必须写清：

- 本次是普通还是空间不足；
- 覆盖了哪些策略、没有改设置；
- 排序结果；
- 哪个任务因空间不足被跳过、需要多少、差多少；
- 哪个任务成功删源、释放了多少；
- 哪个任务失败、最后过程物在哪；
- 跨盘时哪块盘承担了什么；
- 硬链接/别名清理失败时为什么没删源。

---

## 13. 验收要点

1. 大包放不下立即退出，小包继续；
2. 并发不超过用户效率档，空间充足时最多到效率档；
3. 成功层删源，失败/取消源包保留；
4. 失败不发布未完成内容物，最后过程物固定保留；
5. 跨盘不复制源包；
6. 硬链接别名清理后空间才真正回收；
7. 特定解压使用同一套空间判据；
8. 普通模式行为不变；
9. 只缺 0 字节条目的 `Undeterminable` 档不删源；
10. 20 份空间不足夹具全部按测试计划通过。

---

## 14. 待确认

- 保留余量的最终公式：设计方向是“不再固定 512 MiB；可配置 + 按任务缩放，默认上限 64 MiB、下限约 1 MiB”，最终数值待单位讨论确定；
- 空间不足模式是否保留“不删原包”测试安全档（建议保留，但默认关）；
- 跨盘源盘/目标盘是否需要分别显示两条空间曲线；
- 最后一层过程物是“原路径保留”还是集中到 `其余物`（建议原路径保留，避免同盘搬运不释放空间）。

### 已确认

- 大包空间不足后**允许用户手动重试**；只是不自动排队反复重试，避免无意义等待。
- 小包测试使用无头注入；真实盘不作为 20 份小包的边界测试手段。
