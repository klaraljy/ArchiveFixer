  **不是死锁**（sync-over-async 两处都有 `dispatcher.CheckAccess()` 保护），是**界面线程被喂满**。四个来源：
  1. 逐项 `Tasks.Add`（几百项 = 几百次集合变更）→ 已改批量替换（一次 Reset 通知）；

  3. 每行日志一次同步写盘 + 每行一次 `ScrollIntoView` 强制布局 → 滚动合并成"一个排空周期一次"；
  4. 改名预览窗每 Add 一项重算 6 个 O(N) 统计（≈3N²）→ 装载期间挂起、末尾算一次。
  **行虚拟化本来就是开的**（`App.xaml` 隐式样式里 `EnableRowVirtualization=True`，DataGrid 高度受约束、也没有分组），
  所以"开虚拟化"不是这次的修法；仍在待办里的是列虚拟化与 `Recycling` 模式（收益小，见 §6）。

### 6.2 与方案的偏差（逐条给理由）

1. **"落点模式（四种）"→ 两档**：方案 §1 表格里那句写在**第 13 条收敛之前**；第 13 条已把落点砍成两档
   （同名子文件夹 / 指定位置 + 同名子文件夹），本次照**第 13 条**落地，没有把删掉的档再放回来。
2. **保存设置的按钮在底栏，不在⑥页**：②③④⑥ 四页都会改设置，若把「保存」只放在⑥页，
   在②页改完就走的人会以为已经保存。底栏一个「保存设置」= 一处保存动作，四页通用；
   `SettingsViewModel` 的**保存前拦截**（工具路径不存在 / 危险模式没自测凭证）一行没改。
   界面上写明"不点它，改动只在本次运行内有效"。
3. **`OpenSettingsCommand` / `OpenPackingCommand` 不再有菜单入口**：它们原来打开的
   设置窗口 / 打包窗口已经退休，功能整页搬进了⑥ / ⑤。两个命令本身保留在 `MainViewModel` 上，
   语义改成"切到那一页"（`TabRequested` → 主窗口切选项卡），所以不是"命令丢了"。
4. **第 15 条的"无用物提醒开关"**：项目里**没有任何**现成的设置项（提醒一直是"每次运行弹一次 +
   弹窗里勾本次不再提示（只记内存）"）。按"界面上有的开关必须真的被读"这条规则，
   本次新增了 `AppSettings.RemindBeforeExtract`（默认开）**并顺手把它接通**
   （`ExtractionCoordinator.ConfirmBatchRemindersAsync` 第一道判断：关掉就不扫也不弹），
   开关落在③页；第 15 条真正要做的"导入文件夹后先提醒一次 + 列表删除入口"仍待做。
5. **"整页可滚"的实现方式**：②③④⑥ 用 `ScrollViewer` + `StackPanel`；⑤ 用
   `提示条(Auto) / 表单(*) / 操作栏(Auto)` 的星号行（表单内部再套 `ScrollViewer`），
   ①用 `列表(72*) / 分隔条 / 日志(28*)` —— 都是星号伸缩，没有固定高度堆叠（第 20 条）。
6. **打包页的密码不再"离页即擦"**：窗口版在 `OnClosed` 里擦内存，选项卡没有"关窗"这个时刻。
   密码仍然只存内存、不写设置、不记日志（不变量 5 的底线没变），只是存活时间变长。

**卡死诊断里发现、本轮没做的性能项（留给后续，按收益排序）**：

- 日志**文件**写入仍是"每行一次 open/write/close"（`LogService`）：改成后台写线程 + 有界队列收益最大，
  但要同时保证"写完立刻可读"（多处测试与排障都按这个前提读日志），所以单独做、单独验。
- 扫描/一键处理里逐任务的同步磁盘 I/O：`EmbeddedArchiveDetector` 的尾部读（每未知格式文件最多 256 KB）、
  `SourceFileSnapshot` 的 stat、排期阶段的 `TaskSpaceEstimate` stat、改名预览的逐项 `File.Exists` —— 都该进 `Task.Run`。
- 无用物扫描（`SourceJunkScanner`，最坏约 10 万条目录项）目前在界面线程上枚举；提醒那一步应整体挪到后台。
