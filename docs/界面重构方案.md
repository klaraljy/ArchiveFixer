## 3. 列表与选择（第 12 条）——**已实施**（2026-09-24）

- **一律只认勾选**：没勾 → 一键处理/只解压/清理类**什么都不做**，只提示"没有勾选任何任务"
  （已**取消**"退回当前点中的那一行"的兜底；判定处 `MainViewModel.ResolveCleanupTargets` 只剩"勾选 / 一个都没有"两种结果，
  提示语唯一来源 `StatusText.NoCheckedTaskPromptFormat`）。
  ⛔ 不要再把兜底加回来 —— 用户原话："你只需要操作我选中的文件，其他的不用管。"
- **点「添加文件 / 添加文件夹」= 清空整张表再加**（替换语义，用户 2026-09-24 补拍）；
  想往现有列表里加，走显式入口**菜单「文件 → 追加到列表」**（可追加文件 / 追加文件夹），
  界面提示（菜单 ToolTip + 导入日志）写明这件事。
  拖放一批新文件同样算"新的选择"，走替换语义；续解流程往列表里补内层包走 **Append**（`ImportMode.Append`，编译器强制每个调用点写出来）。
- **卡死（第 12 条"彻底卡死"、第 19.2"直接卡死机"）——只读诊断结论**：
  **不是死锁**（sync-over-async 两处都有 `dispatcher.CheckAccess()` 保护），是**界面线程被喂满**。四个来源：
  1. 逐项 `Tasks.Add`（几百项 = 几百次集合变更）→ 已改批量替换（一次 Reset 通知）；
  2. 逐项改勾选 → 每项触发一次全表汇总重算 + 38 条命令重查（O(N²)）→ 逐项循环全部套批量守卫；
  3. 每行日志一次同步写盘 + 每行一次 `ScrollIntoView` 强制布局 → 滚动合并成"一个排空周期一次"；
  4. 改名预览窗每 Add 一项重算 6 个 O(N) 统计（≈3N²）→ 装载期间挂起、末尾算一次。
  **行虚拟化本来就是开的**（`App.xaml` 隐式样式里 `EnableRowVirtualization=True`，DataGrid 高度受约束、也没有分组），
  所以"开虚拟化"不是这次的修法；仍在待办里的是列虚拟化与 `Recycling` 模式（收益小，见 §6）。

## 4. 落点规则（第 13 条，四种组合重定）

| 选中对象 | 有没有指定位置 | 期望落点（用户原话） |
|---|---|---|
| **文件**（`111\222.rar`） | 未指定 | `111\222\`（同目录同名子文件夹）——**不再**解到当前目录（他会问"以前那条解压到当前目录呢"：那条已被删掉，理由是他怕 `111` 里被弄乱） |
| **文件夹**（`111\222\`） | 未指定 | 就在 `222` **里面**就地解，**不往外面扔** |
| **文件**（`222.rar`） | 指定 `BBB` | `BBB\222\`（用去掉后缀的包名建子文件夹，**不弄乱 BBB**） |
| **文件夹**（`222\`） | 指定 `BBB` | `BBB\222\`（用选中的文件夹名建子文件夹，再在里面操作） |

一句话原则（用户原话）：**「我们解压绝对不能将原来的文件夹给弄混乱」**。
