# 最后一层过程物与最终组失败：实施计划

本文是执行计划，口径细节见 `docs/最后一层过程物的判定.md`。  
硬约束：禁止打补丁；禁止在 OneClick/任务收尾/链尾新增“扫 Pending、扫任务表、按文件存在性猜损坏”的兜底。

## 1. 当前已确认的代码事实

- `VolumeGroupService.TryCommitPrepared` 可以登记 `Missing/Unknown/SizeAnomaly` 组。
- `ZipBoundaryResolver.SizeAnomaly` 已保留 `Pieces` / `MissingNumbers`。
- `ContentGroup` 已有 `FailureKind`、`FailureEvidence`、`FinalLayerProducers`，但最后过程物尚未接线。
- `PartialPublishStep.PreserveStoppedLayerProcessArtifact` 处理的是**递归链停下来的那一层当前包**，Keep 建硬链接，Delete 不保留、随工作区清掉。
- `RestHandlingStep.ApplyRestHandlingAfterChainAsync` 对任务失败时的 Delete 有硬闸门：`task.Outcome != Succeeded` 直接拦下。
  因此失败档的当前过程物**不能**套 `RestHandlingStep` 的删除。

## 2. 造包器修复计划

失败样本不能再随机破坏最终文件，必须保持组身份：

```text
最终层固定单一族（ZipNumbered）
文件名固定标准名：aaa-L4.zip.001..005
不使用随机包装壳
不做随机受害者
```

5 个缺片：

```text
删除指定中间片，例如 .003
保留 .001/.002/.004/.005
断言：PreparedGroupState.Missing，缺失槽位精确
```

5 个坏片：

```text
五片全在
只翻转中间片 payload 的字节，不碰 header/卷标记/EOCD
断言：组 Complete，引擎解不出最终内容
```

每个失败样本的 recipe 写入：

```text
failure.stage = final-layer
failure.kind = missing|corrupted
failure.victim = 精确相对路径
```

成功 40 保持现有复杂形状、伪装、包装，不参与失败注入。

## 3. 当前过程物计划

不要记录“所有最终层直接产出者”作为保留对象。

唯一保留对象：

```text
CurrentProcessArtifact = 链停下来的这一层正在解的那个包/入口
```

对最终分卷组：

```text
CurrentProcessArtifact = group entry / 本层正在解的标准名入口
```

不是 `.001/.002/.003` 全部分片，不是所有上游包装。

### 位置判定

```text
1. 在当前递归工作区 / group-entry 工作区
   Keep   -> 用 PartialPublishStep 同语义留下
   Delete -> 不留下，随工作区清理

2. 在输出目录/其余物，且是程序过程物
   -> 既有其余物删除档处理

3. 是用户源包
   -> 源包身份优先，不按过程物删除

4. 判不出
   -> 不认定，不删除
```

### 失败组

```text
Missing 且无 group entry
=> 没有当前过程物
=> 不做过程物保留/删除
=> 源包保留

完整组解压失败
=> CurrentProcessArtifact = group entry
=> 按普通 Keep/Delete、空间不足档处理
```

普通档：

```text
Keep   -> CurrentProcessArtifact 存在
Delete -> CurrentProcessArtifact 不存在
空间不足 -> 释放当前过程物
源包   -> 两种档都保留
```

## 4. 测试计划

### 4.1 造包器测试

```text
最终层族 = ZipNumbered
片数/槽位正确
标准名正确
缺片样本只缺指定中间片
坏片样本五片全在、只有指定 payload 改变
recipe 与盘上事实一致
```

### 4.2 组事实与终态

缺片：

```text
ContentGroup.State = Missing
ContentGroup.FailureKind = Incomplete
Task.Outcome = Failed
Task.Reason = FinalGroupIncomplete
最终内容路径不存在
```

坏片：

```text
ContentGroup.State = Complete
ContentGroup.FailureKind = Corrupted
Task.Outcome = Failed
Task.Reason = FinalGroupCorrupted
最终内容路径不存在
```

密码错误：

```text
Task.Reason = PasswordExhausted
Task.Reason 不是 FinalGroupIncomplete / FinalGroupCorrupted
```

### 4.3 当前过程物与源包

逐条断言绝对路径：

```text
CurrentProcessArtifact 实际位置
Keep: 路径存在
Delete: 路径不存在
空间不足: 当前过程物释放
源包: Keep/Delete 两种都保留
最终内容: 不存在
落点: 指定位置 / 原位置准确
```

### 4.4 915 矩阵

```text
普通 50 = 40 成功 + 10 失败（5 缺片 + 5 坏片）
25 Specified / 25 Original
8 档每档 6/7
特定 10、异常 20、空间 20
总计 100
```

每条样本必须断言：

```text
落点
最终内容
任务终态
组事实
当前过程物
源包
```

不能只统计成功/失败数量。

## 5. 实施顺序

```text
1. 先改造包器并验证 5 缺片 + 5 坏片身份稳定
2. 写造包器/组事实/当前过程物测试
3. 组事实层接 CurrentProcessArtifact
4. 接 PartialPublishStep 的 Keep/Delete 语义
5. 接空间不足
6. 跑 50 普通、100 全矩阵
7. 全量、format、文档、绿色、setup
```

## 6. 禁止项

```text
禁止链尾扫 Pending
禁止扫任务表判组状态
禁止按文件存在性猜损坏
禁止全局改 VolumeMissing -> PartiallyCompleted
禁止失败时删除源包
禁止新增第二条删除路径
禁止为了矩阵通过改断言
```
