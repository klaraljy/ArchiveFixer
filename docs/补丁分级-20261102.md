# ArchiveFixer 补丁分级（A/B/C/D/E）

> 依据 `docs/补丁审计-20261102.md` 的 1,128 个发现点（去重约 950–1,000）。  
> 分级是**处理优先级**，不是“代码好坏”；同一模式的所有 `file:line` 都归入该级，完整位置见审计报告。  
> 所有结论均为静态审计，未取运行期证据；A/B 级动手前应先按 `archivefixer-unsafe-paths` 取运行期事实。

## 0. 分级标准

| 级别 | 定义 | 处理原则 |
|---|---|---|
| **A 必须立即改** | 可能直接造成用户数据永久丢失、删错源包/其余物/用户目录，或删源闸门被布尔/常量旁路 | 先修；每项先取证、加红检；不可逆路径改动按大改动跑全量 |
| **B 高，必须改** | 不必然立刻丢数据，但会导致系统性错误裁决：错组、错落点、错删资格、错终态、空清单当成功 | 排期修；优先收口到唯一事实源 |
| **C 中，应改** | 判据脆弱、顺序/阈值/回落/重复实现，当前多数方向安全或影响面有限，但会在新样本上复发 | 随对应模块重构一起收 |
| **D 低/维护性** | 死代码、兼容字段、过期注释、测试钩子、展示文案、日志/性能细节 | 清理即可；不影响功能正确性 |
| **E 可保留** | 有明确边界的防御性补丁、fail-closed 安全闸门、兼容 shim；保留的收益大于重构风险 | 不主动改；只补注释/测试，防止被误删或接错 |

**估算**：A 约 58、B 约 190、C 约 400、D 约 330、E 约 150（合计 1,128）。
