# ArchiveFixer 底层修复路线图（按功能/框架分段）

> 目标不是把 1,128 条补丁逐条改掉，而是**把产生补丁的旧框架换掉**，让新代码没有地方再长补丁。  
> 原则：一次只迁移一个功能模块；新框架先接一个入口，旧入口冻结；模块验收通过后删除旧实现。禁止一次性全改。

## 0. 当前进度（2026-11-02，阶段 0/1）

- 阶段 0 已落地：`IsVolumeComplete` 默认 false；`ArchivePathGuard` 无清单 `Known=false`；`ResourceBudget` 无清单按源包体积做最低空间检查；`OutputVerifier` 删源消费方要求 `Verified + ManifestCrossChecked`；`ContentKeepRules` 判不出文件名按保留；`RestVolumeCompletenessGate` 顶层读不动直接拦；按样本目录名递归删源已删。
- 阶段 1 已落地：`SourceCleanupDecision` 唯一删源裁决；`DeletionPlan` 接入源包/其余物；`CleanupExecutor.ExecuteDeletion` 是执行入口；`RestItemPurger` 解压侧只剩彻底删除；`force`/`ignoreDoneState`/`verified:true`/`enabled:true`/`cancelled:false` 已删；`MoveSourcePackageIntoRest`/`ExecuteSourcePackageMove`/`ApplySourceMoveResult` 已删。
- 待后续阶段：`SecondStepResidueState.Parked`、`AutoConcurrencyController`、`GroupAnalysis`、`VolumeNameRepair` 多套解析、`ProcessArtifactLayout` 旧路径、`TaskOutcome/RunSnapshot` 收口。

## 2. 目标架构（要建什么，不是只改哪一行）

### 2.1 事实层（不可变）

```
Detection/FileIdentity          唯一物理身份（路径/卷序列号/文件索引）
Detection/ArchiveFacts          格式/魔数/加密/内容结论（一次读盘产出）
Detection/VolumeFacts           族/卷号/槽位/自述片数/字节/是否首末片
Extraction/VolumeGroupUnit      由 VolumeFacts 构造的唯一组事实
Models/TaskOutcome + Reason     唯一机器终态 + 结构化原因
Models/RunSnapshot              本次运行的选项/勾选/批次开关（不可变）
Storage/WorkspaceRoot           已解析/未解析两态，不再回落
Storage/SpaceDecision           Enough/NotEnough/Unknown 三态
```

规则：
- `VolumeFacts` 只由 `FileNature/VolumeNumberFromContent/族 resolver` 产出；`VolumeGroupUnit` 只由 `VolumeFacts` 构造；`GroupAnalysis` 最多做诊断，不做裁决。
- `TaskOutcome` 只由终态收口写；`StatusText` 只做显示，不参与任何 `if`。
- `FileIdentity` 只保留一份 P/Invoke；所有“同名=同一份”的判据删除。

### 2.2 决策层（纯函数/计划）

```
Extraction/OutputPlan           落点+套层+内容物/其余物划分
Extraction/DeletionPlan         删什么/为什么/允许根/证据/取消令牌/档位
Extraction/SourceCleanupDecision 源包是否可删（读 VolumeGroupUnit+Outcome+档位+快照）
Extraction/BatchReport          批末统计/颜色/诊断（纯函数，不碰盘）
```

规则：
- 计划只产“事实与目标”，不执行 IO；执行器只认计划。
- `DeletionPlan` 不允许 `completenessEvidence/allowedRootEvidence` 这类可换证据参数；证据必须是本任务/本链的只读对象。
- `OutputPlan` 一旦生成，后续只读；`OutputPlacement` 不再“发现落点==源文件就改名 (1)”。

### 2.3 执行层（唯一出口）

```
CleanupExecutor                 唯一删除执行器（回收站/永久删/取消）
ExtractionAttempt               引擎调用的结构化结果（引擎/退出码/错误事实/产物）
PasswordAttemptLedger           “跳过/试过/不占次数”的唯一记账
FinalizeBatch                   独立批末阶段（删壳/恢复源名/别名清理）
```

规则：
- 所有 `File.Delete`/`Directory.Delete`/`File.Move` 必须经过执行器或 `FinalizeBatch`；代码审查禁止业务层直接删。
- 引擎结果只当输入；成功=产物校验通过，不是 `ExitCode==0`。
- `FinalizeBatch` 不允许藏在 `BuildSummaryLine`、`RefreshSummary`、`ToString` 等展示函数里。

### 2.4 兼容层（可保留但要隔离）

```
Legacy/LegacySettingsMigration   带版本/once 的迁移
Legacy/LegacyPasswordBook       旧编码/旧路径读取，只读
Legacy/LegacyVolumeNames        旧名字容错只输出 Confidence，不直接改名
```

兼容代码不能出现在主决策链；调用点必须显式 `Legacy...`，并有删除条件（版本号/最后支持版本）。

## 3. 迁移方式：绞杀者，不是大爆炸

每一步固定五件事：
1. **建立新类型**（不改变行为，只做适配）；
2. **选一个入口接新类型**（其余入口冻结，不允许新增调用）；
3. **写红检**：撤掉新逻辑必须红；
4. **定向测试 + 受影响链路**；跨删源/落点/分卷/终态的改动再跑全量；
5. **删除旧入口/旧类型**；删不掉就标 `[Legacy]` 并登记删除阶段。

禁止：
- 同时改两个模块的判据；
- 在旧入口里再加条件“先让它对”；
- 用新的布尔参数兼容两条路；
- 为了通过测试改旧守门用例（先确认是不是“改错了层”）。

## 4. 分段路线（按模块，顺序有依赖）

### 阶段 0：安全闸门 + 事实类型落地（不改主流程）

**目的**：先停止“空清单=安全、读失败=没有、状态串=机器结论”的伤害。

- 新增 `TaskOutcome.Reason`、`FileIdentity` 单例、`WorkspaceRoot`、`SpaceDecision` 值对象。
- 修 fail-open 闸门：
  - `ResourceBudget.Allowed`：无清单 → `Unknown`，不是 true；
  - `ArchivePathGuard.IsSafe`：空清单 → false/Unknown；
  - `OutputVerifier`：空清单 → `Verified=false + Known=false`；
  - `ArchiveTask.IsVolumeComplete`：默认改为 false/Unknown；
  - `ContentKeepRules`：判不出 → 保留（fail-closed）；
  - `RestVolumeCompletenessGate`：读不动 → 拦。
- 删掉“按样本目录名递归删源”的两处（`DeferredVolumeDeficitStep:1223-1265`、`VolumeRepairStep:278-334`）和三个 `Contains("大测试...")`。

**退出标准**：以上每条有红检；全量通过；没有新增行为路径。

### 阶段 1：删除框架（M1+M2）

**新框架**：
- `DeletionPlanBuilder`（输入：任务、链、`VolumeGroupUnit`、`TaskOutcome`、`RunSnapshot`、目标、证据）；
- `CleanupExecutor` 只执行计划；
- `CleanupLedger` 记录 `UserSource/LayerInput/RestArtifact/Workspace` 的 FileIdentity。

**替换**：
- 四套删源入口 → `SourceCleanupDecision` + `DeletionPlan`：
  - `SourceCleanupService.CleanupVerified`
  - `SourceCleanupService.CleanupAcceptedRisk`
  - `Source.cs` 的 `PurgeLayerSourcePackage`
  - `SettleSucceededGroupSourcesAtChainEnd`
- 删除参数：`verified:true`、`enabled:true`、`ignoreDoneState`、`force`、`cancelled:false`、`includeRestAliases`。
- `RestItemPurger` 只保留六道门槛 + 计划输入；删 `completenessEvidence/allowedRootEvidence` 的“可换证据”语义。
- `RestHandlingStep` 的 `Permanent` 写死、RecycleBin 分支、keepLast 整体 Purge、四路猜组名、`EndsWith("其余物")` 全部删。

**旧框架删除**：
- `MoveSourcePackageIntoRest` 整条（无调用点）；
- `RecycleBin` 枚举/分支/文案；
- `ProcessArtifactLayout.LiftOutOfProcessArtifactDirectory` 路径改写（改为返回“不可用”事实）；
- `PieceAdoptionStep` 的“不查链接数删唯一副本”。

**退出标准**：所有删除只经 `CleanupExecutor`；失败/取消/空间不足/同名别名/半套分卷/唯一副本红检全绿。

### 阶段 2：分卷事实（M3）

**新框架**：
- `VolumeFacts`（族/卷号/槽位/声明片数/字节/首末片/Confidence）；
- `IVolumeResolver` 只产 `VolumeFacts`；`VolumeGroupUnit` 只由 `VolumeFacts` 构造；
- `LegacyVolumeNames` 只输出候选名 + Confidence，不直接改名。

**先修确定性缺陷**：
- `SpannedZipIndex` ZIP64 8 字节读取；
- `VolumePiecesFromCards` 正则/枚举顺序/名先于内容；
- `VolumeGroupResolver` AnchorPath/Variant 漏抄、凭空造槽；
- `GroupAnalysis` 字节配对覆盖 resolver、子集删组。

**替换**：
- `GroupAnalysis` 退出裁决，只保留诊断；
- 删除 `SecondStepResidueState.Parked`，把第二大步入口接回；
- 删除 `VolumeNameRepair` 纯名字改名/建链接两档，名字只进 `LegacyVolumeNames`；
- `VolumeProbeVerifier` 端口补 family/testVolumes/passwordCandidates；
- `VolumeGroupService` prepared 组必须产 `NamePlan`，否则不进收片。

**退出标准**：同一组只由 `VolumeGroupUnit` 裁决；`Parked` 删除后第二大步测试全绿；ZIP64 >4 GiB、名字容错、非等大切分红检。

### 阶段 3：落点/定稿/发布（M5）

**新框架**：
- `OutputPlan`（落点/套层/内容物/其余物/身份）；
- `FinalLayoutPlan` 由 `ResultFinalizer` 一次生成；
- `OutputVerifier` 三态：`Verified/Known/ManifestCrossChecked`；
- `PartialPublisher` 只按计划发布。

**替换**：
- `OutputPlacement` 只产计划，不执行改名/不落盘；
- 删“落点==源文件 ⇒ 名字(1)”、`Lift` 换根、`ToLegacyFlags`；
- `ResultFinalizer` 删形状反推、三处最里层闸门、`wrapperName` 防御；
- `SpecialExtractionRules` 整体下线（UI/日志/默认值一起删）；
- `ExtractionWorkspace` 发布按逐文件结果，`Success=errors.Count==0 && expected==moved`。

**退出标准**：落点只由 `OutputPlan` 决定；失败/部分发布不把半成品当成功；特殊解压规则不再出现在 UI/日志。

**收口状态（2026-11-02）**：
- `OutputPlan` 已接入路径服务；`FinalLayoutPlan` 已并入唯一 `FinalizePlan`，`ResultFinalizer` 有 `OutputPlan` 重载。
- 旧特定解压规则注册表/UI/设置/定稿参数全部删除；特定解压只保留独立开关，不删源包、不直删最后一层过程物。
- 发布结果按 `expected == moved` 判成功；验证增加 `Known` 闸门。
- `ToLegacyFlags` 已删，落点新写入只写 `AppSettings.PlacementMode`；旧布尔只读迁移。
- 全量 3002 通过 / 13 跳过 / 0 失败；构建 0 错 0 警；format 通过。


### 阶段 4：任务终态/批末（M7）

**新框架**：

## 5. 每个阶段怎么防止“又长补丁”

1. **一个事实一个 owner**：`FileIdentity`、`VolumeGroupUnit`、`TaskOutcome`、`DeletionPlan`、`OutputPlan` 各自唯一，消费方只读。
2. **公共 API 禁止布尔旁路**：`verified:true`、`enabled:true`、`force`、`allowFallback`、`ignoreDoneState`、`requireRecognizedCandidates` 这类参数不允许出现在新接口。
3. **删源只走执行器**：`DeletionPlan` 之外禁止 `File.Delete`；`CleanupExecutor` 是唯一执行体。
4. **判不出 = 停手**：所有不可逆路径默认 fail-closed；Unknown 不参与“可删/可发布”判定。
5. **旧框架有死亡日期**：每个 `[Legacy]` 类型/入口登记删除阶段；阶段 7 不清完不算完成。
6. **测试只守行为，不守文案**：状态/日志用枚举/原因，不断言中文串；展示文案单独测试。
7. **一次只改一个模块**：跨模块改动必须拆成“事实层→消费方”两次提交。
