# 120 批造包器最终口径

本文件记录已确认的口径，作为新造包器唯一依据。

## 1. 输出位置

造包器只写不可变备份：

```text
H:\BaiduNetdiskDownload\困难大测试\大测试备份位置\<SeedBase>-120批次-备份
```

例如：

```text
SeedBase = 917000000
输出 = H:\BaiduNetdiskDownload\困难大测试\大测试备份位置\917000000-120批次-备份
```

测试时复制备份：

```text
H:\BaiduNetdiskDownload\困难大测试\大测试\<SeedBase>\
```

备份目录本身测试时只读，不直接跑，不删除、不改名、不移动。

造包器不生成测试输出：

```text
不生成 大测试\<SeedBase>\
不生成 大测试指定位置\<SeedBase>-指定位置\
```

这些由测试夹具复制/创建。

## 2. 目录结构

每份样本：

```text
<sample>\
  原包\
  recipe.json
```

普通、特定、异常、空间 C/B 都统一这个结构。

不生成：

```text
本地成品\
.build\
大测试\
指定位置\
```

```text
50 + 20 + 25 + 15 + 10 = 120
```

```text
不随机破坏族身份
```

```text

```


## 6. 异常 25

```text

```

现有 20 形状保留，新增 5 个真正不同的异常：

```text

```

## 7. 空间 25

```text
C01-C15  普通空间
B01-B10  特定解压空间
placement = Original
```

C 保持最新空间矩阵结构：

```text
packages[].fileName / sourceBytes / contentBytes / format / shape / corrupt / expected
space.freeBytes / reserveBytes / concurrency
expected.blocked[] / failed[]
```

B 保持特定解压形状，并补：

```text
expectedTaskFileName
expectedTaskFileNames
```

B 没有 contentBytes，只有 contentFiles；期望字节由 contentFiles 计算。

## 8. 落点规则

### Original

输出跟随源包实际父目录：

```text
源包在：
  <测试根>\<sample>\原包\aaa.zip

输出在：
  <测试根>\<sample>\原包\aaa\内容物
```

不是固定在大测试根，也不是复制出另一套固定输出根。

recipe 记录：

```text
sourceRelative
expectedOutputRelative
```

其中 `expectedOutputRelative` 相对于源包父目录，不能写死 `大测试\<SeedBase>`。

测试断言：

```text
源包父目录 + expectedOutputRelative
```

### Specified

固定输出根：

```text
H:\BaiduNetdiskDownload\困难大测试\大测试指定位置\<SeedBase>-指定位置
```

recipe 的 `expectedOutputRelative` 相对于这个根。

## 10. 旧脚本与合并

保留：

```text
E:\AF\大测试-造困难包.ps1
E:\AF\大测试-造特定解压包.ps1
E:\AF\大测试-造异常包.ps1
E:\AF\大测试-造空间不足20矩阵.ps1
```

淘汰：

```text
E:\AF\大测试-造空间不足包.ps1
```

旧脚本文件保留，可独立运行；新脚本不调用旧脚本，必须把最新四个脚本的函数/造包逻辑真正合并进：

```text
E:\AF\造120批.ps1
```

原物只在：

```text
H:\BaiduNetdiskDownload\困难大测试\原物\困难内容
H:\BaiduNetdiskDownload\困难大测试\原物\生成的媒体
```

不复制、不移动、不生成第二份原物。


## 14. 对拍判据

四个旧脚本是唯一基线。同一 seed 跑旧脚本一份、新脚本 `-Mode Single -Section <类> -Only N` 一份，
用 `E:\AF\对拍.ps1` 比。绿的条件：

```text
原包下相对路径集合一致
recipe 的 scenario / layers(kind+format+inputs+outputs) / files(wraps+mediaPrefix+suffixMethods) / validation.wrapCounts 一致
单文件字节差 <= 128
```

允许字节差的原因（实测）：7z 与 rar 都是 AES 加密 + 随机 IV，同一输入两次产出的密文不同，
压缩头长度会差几字节。实测 rar/7z 两次 SHA256 不同、长度相同；zip 不加密则两次完全相同。

造包器把输入文件修改时间固定为 `2020-01-01 00:00:00`，去掉时间这一路变化。

## 15. 普通 recipe 额外口径

```text
expectedSourceKeep    成功 = scenario.sourceHandling 是 KeepInPlace；失败恒为 true
expectedProcessKeep   成功 = false（成功自动删过程物）；失败 = scenario.contentHandling 是 Keep
expectedProcessPaths  恒列出最终层全部片的 finalRelative
expectedFinalContentPath  成功 = content-N.bin，失败 = ''
expectedContentBytes  成功 = 实际写入字节，失败 = 0
expectedGroupState    缺片 = Missing；坏片与成功 = Complete
```

recipe 同时保留旧造包器的结构字段：`layers[]`、`files[]`（含 wraps / mediaPrefix / suffixMethods）、`validation`。

未定项：普通成功样本的最终内容落点目录名由产品决定（多层递归展开后套几层包名目录），
取不到运行期证据前 `expectedFinalContentPath` 只写文件名，不写死路径。

## 16. 落地时的口径修正（实现以本节为准）

异常 25：旧 20 个里已经包含「空归档」和「内层分卷缺最后一卷」，所以 §6 列的这两条不算新增。
实际新增 5 个：

```text
ZIP EOCD 截断
RAR 分卷头冲突
7z 起始头 CRC 损坏
ZIP 中央目录偏移越界
同基名不同族强锚点
```

空间 B：旧矩阵脚本只出 B1–B5（无零填充）。新造包器按 §3 统一成 B01–B10；
B01–B05 与旧五批一致（类型 ample/largest/allblocked/corrupt/ample），B06–B10 为新增
（类型 largest/allblocked/corrupt/ample/largest，包数 5/6/5/6/5）。

特定 11–20 的实际结构：

```text
11 直接单包（1 层 7z）
12 外层即 7z 分卷（.001/.002/.003）
13 两层单包（外 7z → 内 7z）
14 三层单包（外 rar → 中 zip → 内 7z，三层三个密码）
15 三层中间分卷（外 7z → 中 7z 分卷 → 内单包）
16 最后一层落在文件夹（目录名与包基名不同）
17 跨盘 ZIP（WinRAR -afzip -v1m，产 .z01/.z02/.zip）
18 内层密码不在密码本（expectedOutcome = Failed，expectedReason = WrongPassword）
19 空归档（0 条目）
20 同一形状在两个父目录各一份
```

对拍补充：

```text
空间样本内容用随机数生成，两次运行字节必然不同 ⇒ 只比包名/格式/形状/损坏标记/expected，不比字节
largest 档的 blocked 取本批最大包，依赖随机体积 ⇒ 只记不比
B 的旧脚本 ID 是 B1–B5，新口径是 B01–B10 ⇒ 比较时去零填充
第 5 号异常目录名带随机 GUID ⇒ 比较时归一化成 <guid>
```
