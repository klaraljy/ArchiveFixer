# 全量测试中的旧框架痕迹审计（2026-11-02）

> 结论先说：`用例1_根源包成功而内层包失败_彻底删除档下其余物真被删` **测的是新行为，不是旧框架**；它让人疑惑是“文档/名字混了两个时代”，不是断言错了。全量偶发红是测试隔离问题，已用 `[Collection("ArchiveFixerGlobalState")]` 修掉。

## 1. 这个用例为什么看起来矛盾

`ChainRestHandlingSettingTests` 的类注释原来写：

- 旧：“根源包成功 + 内层失败 + 彻底删除 ⇒ **其余物真被删**（源包也随之按设置消失）”；
- 但用例正文断言：`outer.7z` **还在**、`其余物` 目录为空、源包删除名单不包含 `outer`。

这是两个时代的口径叠在同一段注释里：

- 旧框架（2026-10-04 之前）：整链必须成功，才允许动链尾其余物/源包；
- 新口径：内层失败只让**那一单**失败，根源包那一层成功 ⇒ 其余物按③页设置处理；失败/部分完成 ⇒ **源包永不动**。

所以这个用例真正钉的是：

1. 内层失败确实发生（`TaskOutcome.Failed`）；
2. 根源包那层的内容物 `layer1.txt` 在；
3. `outer.7z` **保留**（失败/部分完成不删源）；
4. 其余物按“彻底删除”清空；
5. 删除执行器没有对 `outer.7z` 发起 Permanent/Recycle 调用。

**结论**：断言是新的；类注释第 34 行“源包也随之按设置消失”是旧残句，已改成“源包按失败原包永不动保留”。用例名只描述“其余物真被删”，没有说源包被删。

## 2. 全量偶发红的原因

`ChainRestHandlingSettingTests` 原来**没有** `[Collection("ArchiveFixerGlobalState")]`，但它构造 `MainViewModel`，会写两个进程级静态：

- `RecursiveExtractor.ConfiguredWorkspaceRoot`；
- `ToolLocator.Default` 的内置 7z 路径。

同集合里 87 个真 7z/全局状态测试是串行的；它却可能和它们并行跑，于是工作区根/工具路径被别的用例改写，表现为“单跑绿、全量偶发红”。已加集合属性；加完后全量 **3019 通过 / 13 跳过 / 0 失败**。

这是**测试隔离的旧框架**（用进程级静态共享状态），不是产品判据问题。

## 3. 测试里的旧框架清单

| `DeleteOptionsClarityTests` 类注释 | 仍写“三档”（含回收站），同文件 `:66` 又写“已两档” | 统一成两档；删除旧用户原话里的第三档描述 |

| `AuditFixVerificationTests` 的反射“类已删”检查 | 不是旧行为，是防止旧类复活的守门 | **保留**，这是反旧框架的守卫 |

### 3.2 不是旧框架、不要误删

- `PackingCleanupTests` / `PackingOptionsTests` 的 `MoveToRest`：**打包功能**的源包档仍真实存在，与解压侧无关。
- `CleanupSelectionScopeTests` 的 `DeleteMode.RecycleBin`：**手动清理**仍可走回收站；只有解压侧“其余物=回收站”下线。
- `RestVolumeCompletenessGateTests` 的 `requireRecognizedCandidates:false`：当前链尾删源包那一档的刻意口径，不是旧代码；但应改成显式策略对象，避免默认值危险。
- `Item37SafetyTests` 的 `ChainCompletionGate`：只在注释里回顾旧闸门，**没有旧测试体**。
- `DeleteOptionsClarityTests.已取消/失败/部分完成不删`：新红线，保留。
- `SpaceTightModeTests.空间不足模式_定稿校验通过后立刻删源包`：新红线里的**成功**路径，保留。
- `SourceDeleteAfterVerifyTests`：名字旧，但如果正文只测“可证完整才删”，改名为 `SourceCleanupEvidenceTests` 即可，不删。

## 4. 建议的测试清理顺序

1. 先修 `ChainRestHandlingSettingTests` 的集合隔离（已做）和类注释（已做）→ 全量稳定。
2. 再清 `DeleteOptionsClarityTests` 的 RecycleBin 用例与“三档”文档；与 `RestItemPurger` 删分支同一提交。
3. 重写 `SourcePackageRestMoveTests` 头部/类名；删除 `MoveToRest` 残留描述。
4. 删除 `AutoConcurrencyController` 与它的测试（生产无实例化）。
5. 分卷事实收口时，重写 `GroupAnalysis*Tests`；不要保留两套组裁决测试。
6. 最后保留 `AuditFixVerificationTests` 这类“防旧类复活”的反射守卫。

> 原则：测试名/注释必须描述**当前唯一行为**；旧口径只放在“历史/红检”注释里，且明确标旧。不要用旧测试证明新行为，也不要用新断言继续养旧类。
