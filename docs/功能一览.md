# 功能一览

> 这份是**详细版**：README 里只留一行一条，想细看就翻这里。
> 内容与 README 同源（2026-09-26 从 README 搬来），改动请两边一起改。

## 现在能做什么

- **格式识别**：读文件头魔数判真实格式，不信扩展名。覆盖 ZIP / 7Z / RAR4 / RAR5 / GZIP / BZIP2 / XZ / TAR /
  CAB / ARJ / LZH / Z / Zstandard / LZ4 / RPM / ISO。
- **双面文件 / 内嵌归档**（2026-09-24 放宽判据 + 新增**直读**；2026-09-25 第 38/39/40 条补齐三种形状）：
  前面是视频 / 图片等数据、后面拼着一个完整归档的文件（真实资源包常见形态），后缀状态显示「**内嵌归档**」。
  三种形状都认：**①`视频 + 尾部 ZIP`**（读尾部 256 KB 反推起点，走**直读**）、
  **②`图片 + 尾部 RAR / 7z`**（RAR / 7z 的目录结构不能从尾部反推起点 —— 实测前缀超过约 1 MB 后
  7-Zip 与 UnRAR 自己都报"不是归档"，所以**从头扫签名**定位起点、抠出 `[起点, 终点)` 交给引擎）、
  **③`ZIP 不在文件末尾`**（前后都垫了数据 → 顺序扫一遍找 EOCD，逐个自洽校验后给出精确区间）。
  一键处理**优先直读**（只认 ZIP）：直接从原文件的 `[起点, 归档终点)` 流式解出条目，
  **不再产生那份等大的临时副本**（ZIP 段实测 487 MB–2.4 GB；原来必须先整段抠出来才能交给 7-Zip，
  峰值空间约等于包大小的 3 倍）。直读不支持时**自动回落**到"抠取 + 7-Zip"并在日志里写明原因
  （RAR / 7z / bzip2 等方法 / ZIP64 字段缺失 / 中央目录对不上 / 递归模式）。
  改成 `.zip` 没用：7-Zip 只容忍 8 MiB 以内的整体偏移。
  判据是**逐个 EOCD 候选自洽校验**（要求"算出来的中央目录位置真有 `PK 01 02`"且
  "算出来的归档起点真有 `PK 03 04`"），于是：**EOCD 之后允许还有别的数据**
  （真实文件就有 14,350–17,424 字节，那截**不属于归档**，抠取与直读都按 `EOCD + 22 + 注释长度` 截断）、
  **支持 ZIP64 收尾**（56 字节 ZIP64 EOCD + 20 字节 locator）。
  反过来，凑不出这两条签名的普通 MP4、自解压安装器**不会被误报**成内嵌归档；
  ZIP 里正好装着 `.rar` 文件时，结论仍是**外层那个 ZIP**（自洽校验过的证据强于一个 7 字节魔数）。
- **后缀分析**：后缀正常 / 缺失 / 不匹配 / 多重后缀疑似伪装 / **内嵌归档** / **分卷后缀** / **格式未知**
  （分卷单独归类，不会被误当成伪装）。两条优先级的来由：「**内嵌归档**」排在一切后缀结论之前
  （这种文件没有可修正的后缀，报成"不匹配"会把人引向改名那条死路）；「**分卷后缀**」排在「**格式未知**」之前
  （后续卷 `x.7z.002` 的文件头本来就没有归档魔数，报"格式未知"会把"缺首卷"这件事藏起来）。
- **批量改名**（①「任务」页 →「手动操作」那一栏）：**智能修正选中后缀** / **改名…**（模式下拉里含 *改后缀*：
  添加 / 替换最后一个 / 删除最后一个，以及 *按文字替换*：在整个文件名上查找替换、全部出现都换、区分大小写）
  —— **一律先生成预览**，预览里可手工改新文件名。
  分卷文件受保护：**改后缀那几档一律不碰分卷名**（`FileNameHelper.IsVolumePartFileName`）；要修被改坏的卷名有三条入口 ——
  **「修复分卷名并重试」**（只改名字、先确认、改完核字节数）、**「智能修正选中后缀」**（只修"名字被改坏的**第 1 卷**"，
  其余分卷照样跳过）、以及「改名…」里的**按文字替换**（打包者往每一卷都塞了同样的字时，一起去掉正是修法；预览逐行看得见）。
  同一栏还有 **解压到当前文件夹**（2026-09-27 加：内容物不建包名那一层，直接落在包自己所在目录，
  ⛔ 只对这一颗按钮生效；一键处理/批量永远套一层）、**看内容 / 试密码**（2026-09-26 加，**一个字节都不写盘**）
  与 **打开源目录**。
- **任务列表的勾选（2026-09-22 按用户要求重做；2026-09-24 第 12 条收紧为"只认勾选"）**：**一次点击即切换**
  （勾选框铺满整格，点击这一列的任何地方都算；以前点在格子空白处只会选中行，看起来"点了没反应"，得再点一次）；
  **全选 / 全不选 / 反选**按钮就在列表正上方；列表**右键菜单**里也有「全选（Ctrl+A）/ 全不选（Ctrl+D）」一份；键盘是 `Ctrl+A` / `Ctrl+D` / `Ctrl+I`（`Ctrl+A` 由窗口的 `PreviewKeyDown` 接管 —— DataGrid 自己会吃掉它）；
  右键还有「**只勾选这一个**」—— "一整个文件夹都被勾上了、这次只想解其中一个"从"逐个点掉"变成**一个动作**。
  勾选一变，汇总里的「选中：N」与「只解压」的可用性立刻跟着走；
  **勾选那一排右边还有一句「已勾选 N 项 · 合计 X」**（2026-09-27 加），列表里**紧跟文件名**的那一列是「**大小**」——
  勾之前先看得见"这一行多大、这次一共多少"。
  ⚠ 「**移除勾选的**」是**纯列表操作**（2026-09-27 第二次修；**判据 2026-09-29 修正过**）：有勾选就移除勾选的；
  **一个都没勾（含空列表）时这颗按钮是灰的、点不动**（与旁边「全选 / 全不选 / 反选」同形："没有可作用的对象就不亮"），
  鼠标放上去的提示会说清为什么；它**处理中（跑批中途）只要勾着就照样能点** ——
  真机上他"点中一行 + 点按钮"什么都没发生（旧实现只认勾选框、还绑了"处理中不可用"），看起来就是按钮坏了。
  ⚠ **判据只问"有没有勾选"，不看忙闲**（合成口径 = `Tasks.Any(IsSelected)`，⛔ 不许再加"闲着"那一半）；
  代码里"没勾就按高亮那一行办"那一段仍在，但**界面已经点不到那种状态**（按钮灰着），只是兜底网。
  移除只动列表：源文件 / 输出目录 / 日志一个字节都不动，移除错了再添加一次就回来
  （⛔ "没勾就按高亮行办"这条**只作为这颗按钮的兜底存在**，且现在不可达；一键处理 / 只解压 / 清理那些**动磁盘**的命令仍然只认勾选 —— 用户 2026-09-24 第 12 条）。
  **除「移除勾选的」（纯列表操作）之外，动磁盘的命令一律只认勾选**：一键处理 / 只解压 / 智能修正 / 清理类
  一个都没勾就**什么都不做**，只提示"没有勾选任何任务" ——
  ⛔ 那几类命令**没有**"没勾就按当前点中的那一行办"这回事。
- **导入语义（2026-09-24 第 12 条）**：点「**添加文件 / 添加文件夹**」（以及拖放一批新文件）= **先清空整张任务列表**
  再加入这次选的内容；想**追加**到现有列表后面，用菜单「**文件 → 追加到列表**」（追加文件 / 追加文件夹）。
- **分卷**：**一组分卷 = 一个任务**，只从第一卷启动；缺卷时直接报"缺哪几个"并拒绝开始。
  认五种命名：`.001` / `.z01` / `.r00` / `.partN.rar` / 本体（`x.zip`、`x.rar` 就是第一卷）。
  另外还认两种"名字不那么干净"的：**卷标记后面粘着垃圾**（网盘给每卷缀的 `giu910.7z.001删除` 照样算分卷，
  垃圾尾巴记下来、缺卷提示里带着同样的尾巴）与**容错档**（干扰字符塞进卷号内部、还夹了字母的
  `amb909.7sz.00c1`，删掉少量非纯数字字符后能对上标准卷标记就认，认不出就照旧不猜）。
  ⛔ 老口径不许回退：另起一段的后缀（`x.7z.001.txt` / `x.001.bak`）与纯数字尾巴（`0012`）照旧**不算**分卷。
- **缺卷时去"认不出的兄弟文件"里找**（2026-09-29）：第一卷第名字被改烂、同目录里躺着一个**认不出格式**的
  文件（它其实是**裸的续卷**）时，程序会把这类文件当**候选续卷**，靠**名字里的短数字尾巴**
  （`.01` → 1、`.2` → 2）或**体积规律**（第一卷正好是切分上限 = 满片）排出顺序，
  再用**硬链接试开**验证这一组真能打开 —— 验过了才走既有的整组改名（只改名字、绝不覆盖），然后解压；
  **验不过就什么都不做**（不改名、不猜）。两卷（第一卷满片 + 第二卷是余量）与三卷都支持。
- **密码**：统一密码、本次运行手动输入一个密码（**整批共用、只对本次运行有效、不落盘**）、
  密码本（**列表式**一行一个 + **映射式** `名称:密码`，按归档名命中）、
  最近成功密码优先；**本批已经试成功的密码排在最前**（有这种密码时**空密码不进候选**）；
  同一层里按**历史成功次数**从多到少排（次数跨重启落盘记住，次数相同的保持你排的顺序）；
  可显式开启从**压缩包同目录的说明文件**里提取候选。**支持多本密码本**（导入过的每一本都被记住，
  启动时按记住的顺序逐本合并，设置里能逐项移除）。**解压这一侧**的日志、报告、剪贴板里永远只有脱敏形态
  （⑤「打包」页那颗「复制密码」是另一个出口，见下面「打包」那条）。
- **密码列表跨重启保留**（2026-09-24）：列表的**内容 / 顺序 / 启用状态 / 手工条目 / 备注**按本机
  **DPAPI（机器范围）**加密存在 **`<数据根>\password-list.dat`**（跟 Windows 账号无关、不弹框）。
  **数据根 = 程序目录下的 `data`**；⑥页设过「缓存根目录」时数据根就是你填的那个目录，
  记忆文件随之变成 `<那个目录>\password-list.dat`。口径是"**绝不写漫游目录**（`%AppData%` / `%APPDATA%`
  那类会被漫游同步的位置一律不碰），**跟着安装目录走**" —— ⚠ 官方安装包默认装到 `%LOCALAPPDATA%\ArchiveFixer`，
  所以**默认安装下 `data` 也在系统盘**（那是安装位置决定的，不是程序往 C 盘塞缓存）；
  要挪就在⑥页设「缓存根目录」（那条硬规则只管你手填的那个根，管不到安装目录本身）。
  删除与清空记**墓碑**（重启不从密码本复活）；设置项「记住密码列表」**默认开**，可整个关掉（关掉 = 既不写也不读）。
  ⚠ 代价：同机任何本机用户都可能解开、换机器 / 重装系统解不开 —— 那时**忽略并提示**，不崩，原件只被读过、不会被搬走或删掉：
  程序先把读不出来的那份**原样另存一份备份**（同目录，名字形如 `password-list.dat.unreadable-<时间戳>.bak`，
  提示里**点名这个备份文件名**；万一连备份都没做成，也如实说"它随时可能被新的记忆覆盖"），
  出路是拿这份备份换回原来的机器 / 系统，或者用「写回密码本」把当前列表带走 ——
  ⚠ 启动时那一轮落盘是**替换式**的，原来那份之后就不在了，能指望的就是这份备份。
  解压侧的日志、报告、剪贴板同样只有脱敏形态。
- **密码尝试上限**：每一层最多真的试 `MaxPasswordAttemptsPerLayer` 个候选（设置里可改，缺省 10，范围 1~1000）；
  到上限的状态是**达到密码尝试上限**，不是"密码错误" —— 候选没试完不等于密码本里就没有。
- **批量解压**：并发数按设置 `MaxParallelExtractCount`（1~8，**默认 4**；②「解压方式」页另有 1/2/3/4/8 的下拉 +
  「按空间算建议」）；**"停止后续" = 停止所有的东西**（2026-09-27 口径）：不再启动新任务，**正在跑的那一个也在下一个安全点停下**
  （密码候选之间、写完当前文件之后 —— 真机上他点了停止，程序还去试第 10 个密码，白等 32 秒）；要**立刻掐断**用"取消当前"，
  两套语义各自独立（不变量 9 不变：停止后续 ≠ 强杀当前）；
  解压前做**条目路径预检 + 资源预算**，解压后做**落点校验 + 结果校验（条目数/总大小）**。
  产物一旦越出目标根目录（含"产物目录里混进了目录联接点 / 符号链接"）就是**失败结论**：
  不归集、不处理源包，原因写进任务状态与错误信息 —— 不会只留一行日志却照样报"解压成功"。
- **"解不完整"不许说成"密码错"（2026-09-27 真机）**：引擎解出了东西、只是比清单少几个文件时，
  若清单里**没有加密条目**（或连着两个候选的结果**完全相同**），就不再换密码 —— 结论落「**解压失败**」
  （⚠ 状态本身没有"产物不完整"这一档，那句话只出现在**错误信息的尾巴**上：已试几个候选、为什么说问题不在密码上）。
  空密码就解出来的包在界面上标「**不需要密码**」（这是界面实际用的文案）。同理，**"仅大小写不同"的同名条目**在 Windows 上只能落地一份，
  预期数按"后写覆盖先写"折算（真机 `rar-android-722.132.apk`：1271 条 → 1238 个，字节数与盘上逐字节吻合）。
- **空间门（解压之前就判，不足就不启动）**：每个任务启动前算一次峰值需求 ——
  **源包（分卷整组）+ 内容物 + 本次会额外产生的过程物（内嵌归档中间件、内层包再展开的增量）**，
  三者按路径与类别**去重**，并保留 512 MiB 余量。装不下就**不启动**该任务，
  状态落「**磁盘空间不足**」（**状态本身**与"解压失败"分开：归档没问题，只是一个字节都还没写；
  ⚠ 但在**汇总统计**里它被算进"失败"那一档 —— ①页那几档与一键处理的批末汇总都是这个口径），
  错误信息里给出**需要 X / 可用 Y / 差 Z** 与建议动作（清 `其余物` / 换输出盘 / 降并发 /
   开①页的「空间不足」模式，让程序边解边回收空间）。
   取不到可用空间时**不拦**（不把"探测失败"说成"空间不足"），只写一条 WARN。
- **「空间不足」模式（①页主操作栏、「一键处理」左边那个黄色勾选框，2026-09-27 拍板）**：
   盘快满时用它。它是一个**运行期**开关 —— ⛔ 不写设置、不记忆，程序一关就没了（下次启动是关着的）。
   开着时四件事一起变：① **并发自己定**（「全速」不生效：很多个体积相近的小包最多 5 个、
   其余最多 3 个，再与"按空间算出的建议并行数"取小；**②页的并发档仍然有效，但只许往下压** ——
   你把它调得比模式自己算出来的更低时，就按更低的那个跑，模式的上限不会被它抬高）；
   ② 按**净占用**（解完真正留在盘上的字节数）从小到大排序，先解"解完占地最少"的；
   ③ 每个包**定稿 + 校验通过后立刻永久删除它的源包**（不进回收站、不进其余物 —— 同盘搬进其余物
   一个字节都不会回到可用空间）；⚠ **多层（嵌套）包是"每一层各删各的"**（2026-09-29 第 1 条）：
   最外层是你给的包，续解出来的内层包在**它自己那一层**跑完时就被收走 —— 不在链尾一起删，
   所以四层链的峰值是"当前层 + 下一层"（≈ 两倍单层），不是"四倍单层"；
   ④ 其余物（过程物 / 内层包）任务成功后**彻底删除**（链尾按既有口径处理）。
   ⚠ 它会删你的源包，所以动手前一键处理那个确认框里有一条**红字**、②③页各有一条覆盖提示，
   日志里也逐条写明"这一批覆盖了什么、没写设置"。
   ⚠ 交付边界（如实说）：**第一个包必须自己装得下**（那时还没有东西可回收）；
   回收只发生在"删除的那一刻"；工作区默认跟输出盘走，算在这块盘的账里。
   ⚠ **某一层失败只影响那一层**（2026-09-29 第 4 条）：那一层的源包留着，
   **已经收走的更外层不回滚** —— 用户明确接受"原包已经没有了但留下的不会破"。
- **多层 + 空间小：动手前就说，不在中途才报**（2026-09-29 第 2 条）：
   本批允许解多层（②页「最大嵌套层数」> 1）**且各包加起来要新写的量超过目标盘可用空间**时，
   ① 批首日志写一条黄色提醒（最多几层 / 要新写多少 / 可用多少 / 差多少），
   ② 点「一键处理」时那个**唯一确认框**里写同一句话并点明去开①页「空间不足」模式
   （判据与措辞都只有一处：`Storage/MultiLayerSpaceRiskRules` + `StatusText.MultiLayerSpaceRiskFormat`）。
   ⚠ 它**只是提醒**：不拦任务、不改设置、不改勾选。
   中途真撞上空间不足时（那一单不启动、整批照跑）**一键档弹一次纯提示**：非模态窗口、一个按钮、
   **不阻塞后续任务**、同一批只弹这一次（合并计数落在批末日志与汇总框里），措辞给出三条出路
   （清理「其余物」/ 换更大的输出盘 / 开「空间不足」模式）；手动档照旧只写日志。

  删前删后各写一条日志，删失败只记 WARN、**不会**让已经成功的任务变成失败。

## 设计边界（对用户的承诺）

下面五条是**承诺**，不是"目前还没做"。它们决定了这个工具是什么、不是什么 ——
与 WinRAR 这类"压缩管理器"的能力边界差别，逐条理由见 `docs/WinRAR功能参考.md`：

| 承诺 | 含义 |
|---|---|
| **不修改 / 不回写已有归档** | 已有归档一律**只做"读 + 解压"**：不改注释、不改分卷、不锁包、不回写。⚠ ⑤「打包」是**新建**归档（那正是它的职责）。识别出后缀被改坏时，改的是**你自己选中的文件名** —— 手动档先出预览，一键处理档按你的要求自动改（旧名 → 新名逐条写进日志） |
| **检出产物越界即整包失败** | 产物一旦越出目标根目录（含"产物目录里混进了目录联接点 / 符号链接"），就是**整包失败结论**：**不归集、不处理源包、其余物不生成**，原因写进任务状态与错误信息 —— 不会只留一行日志却照样报"解压成功" |
| **失败 / 部分完成 / 取消时源包原地不动** | 只有"内容物已定稿 + 输出校验通过 + 未取消 + 属于本任务分卷组"四条同时成立，才可能按你选的档位动源包（默认 `KeepInPlace` —— **一个字节都不搬**；选了"放入其余物当中"才搬，再按「删除操作」决定那份其余物的下场） |
| **绝不默认覆盖** | 同名一律走"跳过或自动重命名"（默认 `AutoRename` → `名字(1)`）；即使选了覆盖，也是"先挪到临时名 → 落位成功 → 再删旧的"，不做"先删后移" |
| **不联网、不写漫游目录** | 不自动下载任何引擎、不上传任何东西；配置 / 日志 / 临时文件都在 **`<数据根>\`**（默认 = 程序目录下的 `data`；⑥页设过「缓存根目录」就是你填的那个目录），而**解压工作区默认落在这一单的目标目录里面**（`<目标目录>\.ArchiveFixer.work`，2026-09-30 用户明确指示：不在盘根另开一个顶层目录、目录带隐藏属性、批末连空壳一起收掉；目标目录与工作区同一棵树 ⇒ 定稿走同卷改名）。硬规则是"**绝不写漫游目录**（`%AppData%` / `%APPDATA%` 那类一律不碰）、**跟着安装目录走**"；⚠ 官方安装包默认装到 `%LOCALAPPDATA%` —— 那种装法下 `data` **本来就在系统盘**（安装位置决定的），要挪就在⑥页设「缓存根目录」 |
