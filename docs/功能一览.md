## 现在能做什么

- **格式识别**：读文件头魔数判真实格式，不信扩展名。覆盖 ZIP / 7Z / RAR4 / RAR5 / GZIP / BZIP2 / XZ / TAR /
  CAB / ARJ / LZH / Z / Zstandard / LZ4 / RPM / ISO。
- **双面文件 / 内嵌归档**（2026-09-24 放宽判据 + 新增**直读**；2026-09-25 第 38/39/40 条补齐三种形状）：
  前面是视频 / 图片等数据、后面拼着一个完整归档的文件（真实资源包常见形态），后缀状态显示「**内嵌归档**」。
  三种形状都认：**①`视频 + 尾部 ZIP`**（读尾部 256 KB 反推起点，走**直读**）、
  **②`图片 + 尾部 RAR / 7z`**（RAR / 7z 的目录结构不能从尾部反推起点 —— 实测前缀超过约 1 MB 后
  7-Zip 与 UnRAR 自己都报"不是归档"，所以**从头扫签名**定位起点、抠出 `[起点, 终点)` 交给引擎）、
  **③`ZIP 不在文件末尾`**（前后都垫了数据 → 顺序扫一遍找 EOCD，逐个自洽校验后给出精确区间）。
  一键处理**优先直读**（只认 ZIP）：直接从原文件的 `[起点, 归档终点)` 流式解出条目，
  **不再产生那份等大的临时副本**（ZIP 段实测 487 MB–2.4 GB；原来必须先整段抠出来才能交给 7-Zip，
  峰值空间约等于包大小的 3 倍）。直读不支持时**自动回落**到"抠取 + 7-Zip"并在日志里写明原因
  （RAR / 7z / bzip2 等方法 / ZIP64 字段缺失 / 中央目录对不上 / 递归模式）。
  改成 `.zip` 没用：7-Zip 只容忍 8 MiB 以内的整体偏移。
  判据是**逐个 EOCD 候选自洽校验**（要求"算出来的中央目录位置真有 `PK 01 02`"且
  "算出来的归档起点真有 `PK 03 04`"），于是：**EOCD 之后允许还有别的数据**
  （真实文件就有 14,350–17,424 字节，那截**不属于归档**，抠取与直读都按 `EOCD + 22 + 注释长度` 截断）、
  **支持 ZIP64 收尾**（56 字节 ZIP64 EOCD + 20 字节 locator）。
  反过来，凑不出这两条签名的普通 MP4、自解压安装器**不会被误报**成内嵌归档；
  ZIP 里正好装着 `.rar` 文件时，结论仍是**外层那个 ZIP**（自洽校验过的证据强于一个 7 字节魔数）。
- **后缀分析**：后缀正常 / 缺失 / 不匹配 / 多重后缀疑似伪装 / **分卷后缀**（分卷单独归类，不会被误当成伪装）。
- **批量改名**（①「任务」页 →「手动操作」那一栏）：**智能修正选中后缀** / **改名…**（模式下拉里含 *改后缀*：
  添加 / 替换最后一个 / 删除最后一个，以及 *按文字替换*：在整个文件名上查找替换、全部出现都换、区分大小写）
  —— **一律先生成预览**，预览里可手工改新文件名。
  分卷文件受保护：**改后缀那几档一律不碰分卷名**（`FileNameHelper.IsVolumePartFileName`）；要修被改坏的卷名有三条入口 ——
  **「修复分卷名并重试」**（只改名字、先确认、改完核字节数）、**「智能修正选中后缀」**（只修"名字被改坏的**第 1 卷**"，
  其余分卷照样跳过）、以及「改名…」里的**按文字替换**（打包者往每一卷都塞了同样的字时，一起去掉正是修法；预览逐行看得见）。
  同一栏还有 **看内容 / 试密码 / 打开源目录** 三颗（2026-09-26 加；前两颗**一个字节都不写盘**）。
- **任务列表的勾选（2026-09-22 按用户要求重做；2026-09-24 第 12 条收紧为"只认勾选"）**：**一次点击即切换**
  （勾选框铺满整格，点击这一列的任何地方都算；以前点在格子空白处只会选中行，看起来"点了没反应"，得再点一次）；
  **全选 / 全不选 / 反选**按钮就在列表正上方；列表**右键菜单**里也有「全选（Ctrl+A）/ 全不选（Ctrl+D）」一份；键盘是 `Ctrl+A` / `Ctrl+D` / `Ctrl+I`（`Ctrl+A` 由窗口的 `PreviewKeyDown` 接管 —— DataGrid 自己会吃掉它）；
  右键还有「**只勾选这一个**」—— "一整个文件夹都被勾上了、这次只想解其中一个"从"逐个点掉"变成**一个动作**。
  勾选一变，汇总里的「选中：N」与「只解压」的可用性立刻跟着走。
  **所有批量命令（一键处理 / 只解压 / 智能修正 / 移除选中 / 清理类）一律只认勾选**：一个都没勾就**什么都不做**，
  只提示"没有勾选任何任务"。⛔ 没有"没勾就按当前点中的那一行办"这回事（那是错的，已删除）。
- **导入语义（2026-09-24 第 12 条）**：点「**添加文件 / 添加文件夹**」（以及拖放一批新文件）= **先清空整张任务列表**
  再加入这次选的内容；想**追加**到现有列表后面，用菜单「**文件 → 追加到列表**」（追加文件 / 追加文件夹）。
- **分卷**：**一组分卷 = 一个任务**，只从第一卷启动；缺卷时直接报"缺哪几个"并拒绝开始。
  认五种命名：`.001` / `.z01` / `.r00` / `.partN.rar` / 本体（`x.zip`、`x.rar` 就是第一卷）。
- **密码**：统一密码、单任务密码、密码本（**列表式**一行一个 + **映射式** `名称:密码`，按归档名命中）、
  最近成功密码优先；可显式开启从**压缩包同目录的说明文件**里提取候选。**支持多本密码本**（导入过的每一本都被记住，
  启动时按记住的顺序逐本合并，设置里能逐项移除）。日志、报告、剪贴板里永远只有脱敏形态。
- **密码列表跨重启保留**（2026-09-24）：列表的**内容 / 顺序 / 启用状态 / 手工条目 / 备注**按本机
  **DPAPI（机器范围）**加密存在 `<程序目录>\data\password-list.dat`（跟 Windows 账号无关、不弹框、不写 C 盘），
  删除与清空记**墓碑**（重启不从密码本复活）；设置项「记住密码列表」**默认开**，可整个关掉（关掉 = 既不写也不读）。
  ⚠ 代价：同机任何本机用户都可能解开、换机器 / 重装系统解不开（**忽略并提示**，不崩不覆盖不删；
  出路是「写回密码本」）；日志、报告、剪贴板永远只有脱敏形态。
- **密码尝试上限**：每一层最多真的试 `MaxPasswordAttemptsPerLayer` 个候选（设置里可改，缺省 10，范围 1~1000）；
  到上限的状态是**达到密码尝试上限**，不是"密码错误" —— 候选没试完不等于密码本里就没有。
- **批量解压**：并发数按设置 `MaxParallelExtractCount`（1~8，**默认 4**；②「解压方式」页另有 1/2/3/4/8 的下拉 +
  「按空间算建议」）；"停止后续"与"取消当前"是两套独立语义；
  解压前做**条目路径预检 + 资源预算**，解压后做**落点校验 + 结果校验（条目数/总大小）**。
  产物一旦越出目标根目录（含"产物目录里混进了目录联接点 / 符号链接"）就是**失败结论**：
  不归集、不处理源包，原因写进任务状态与错误信息 —— 不会只留一行日志却照样报"解压成功"。
- **空间门（解压之前就判，不足就不启动）**：每个任务启动前算一次峰值需求 ——
  **源包（分卷整组）+ 内容物 + 本次会额外产生的过程物（内嵌归档中间件、内层包再展开的增量）**，
  三者按路径与类别**去重**，并保留 512 MiB 余量。装不下就**不启动**该任务，
  状态落「**磁盘空间不足**」（与"解压失败"分开：归档没问题，只是一个字节都还没写），
  错误信息里给出**需要 X / 可用 Y / 差 Z** 与建议动作（清 `其余物` / 换输出盘 / 降并发 /
  把③页「删除操作」改成「彻底删除」，让程序成功后自己回收空间）。
  取不到可用空间时**不拦**（不把"探测失败"说成"空间不足"），只写一条 WARN。
- **空间感知的调度**：一键处理按空间需求**从小到大**排序（用户点名的反例"一开始就去解 5G+6G"因此不成立）；
  并发时账本记着"已经在跑的任务占了多少"，只有 `已经在跑的 + 我 ≤ 可用 − 余量` 才启动；
  装不下的**跳过它、先做后面装得下的**，批末**逐个点名**报告"谁被跳过、需要多少、差多少"（绝不静默跳过）；
  ②「解压方式」页的「按空间算建议」会显示"当前可用 X，建议并行 N 个"（与真正调度同一段实现）。
- **「删除操作」三档（③「清理与删除」选项卡，2026-09-25 第 32 条按你自己的口述重做）**：
  `不动其余物`（**默认**）/ `移入回收站`（可还原）/ **`彻底删除`**（直接省空间；字号红，
  选中之后下面常驻一条**不能关掉**的红色提示）。后两档在「内容物已定稿并按落点策略排好 + 输出校验通过 +
  未取消」之后处理那一份**定稿时记下来的** `其余物`（源包 + 中间件，不进回收站）——
  这是它唯一能解决"空间不够"的原因。**失败 / 部分完成 / 取消的任务一个字节都不删**（不变量 1 的红线）。
  ⚠ 一键处理把这一档**留到整条续解链跑完**（任务收尾那一刻 `其余物` 里还躺着下一层要解的内层包，
  当场删会把链断掉），手动「只解压」是单层路径、**当场**按档处理；两种情况下日志都写明
  "这一批 / 这一单的其余物会怎么处理"，跑完你看到的和日志写的一致。
  ⛔ **原来那套独立的"危险模式"（红按钮 + 自测凭证 + 常驻红横幅）的界面入口与红横幅已整块删除**（同一批退役）：
  它正是过去"明明选了彻底删除、其余物却还在"的原因（凭证不在时静默按"不动其余物"走）——
  现在这一档**没有任何前置仪式**，选了就生效。
- **解压前的提醒（每次批量解压前最多弹一次，两段合并）**：① **可能的"无用物"** ——
  与本批压缩包同目录、不属于本批任务、而且**魔数认不出是压缩包**的说明/网址/工具类文件
  （`.txt` / `.url` / `.exe` / `.bat` / `.jpg` 等），提醒里写明**程序一个都不会动它们**，删不删由你决定；
  ② **需要密码但当前没有可用候选的包** —— 说清继续大概率会以「密码错误」或「达到密码尝试上限」结束
  （**不是**成功、也不是损坏），并给出"先去补密码本 / 先把它们取消勾选"两条出路。
  ⚠ 判据刻意窄：**伪装包绝不算无用物**（复用同一套魔数识别，不另写一份）；两段都为空时**不弹**；
  「本次运行不再提醒」只记在内存里，**绝不写设置文件**。
- **打包（⑤「打包」选项卡；2026-09-26 第 46 条按用户口述整体重做）**：整条路只有五步 ——
  **选一个文件夹（或一个文件）→ 填密码（两层一样就一个框，默认）→ 点「打包…」→ 弹一个小窗
  （**落点只显示** —— "默认（源旁边）"还是"指定位置"是在⑤页选的 + 原包操作 + 其余物操作）→ 确认之后才动任何字节**；
  ⛔ **点「取消」= 服务一次都没调、盘上一个字节都没多**（有自动化用例钉着）。
  内部：程序用内置 7-Zip 生成**带密码的 7z 分卷**（`-mhe=on`：连文件名一起加密）**直接落在落点目录里**（不再套文件夹），
  再压一层加密外层 —— 有 `Rar.exe` 用 **rar**（`-hp`），**没有就自动改用 7z**（`源名.7z`，日志/结果/弹窗都写明），
  ⛔ **绝不静默伪造 `.rar`**（7-Zip 造不出 RAR）。
  **分卷按卷数**（用户拍板）：内容 <1 GiB → 目标 **2 卷**、≥1 GiB → 目标 **3 卷**，每卷上限 = ⌈内容÷卷数⌉ 向上取整到整 MiB；
  ⛔ **不承诺"平均分"**（`7z -v` 是前面装满、最后一卷拿零头，实际卷数如实报）。
  **命名以源名为准**：分卷基名 `源名.7z`（撞名 → `源名(1).7z`）、最终产物 `源名.rar`（**没装 WinRAR 时产物是 `源名.7z`**；撞名让位成 `源名(1).rar`，⛔ 绝不覆盖）。
  **单文件**（如 `111.mp4`）会在旁边建同名文件夹把它**硬链接**进去（跨盘才复制、先查空间），那个文件夹算**其余物**。
  **清理只在外层容器生成 + 校验通过之后**：其余物默认**彻底删除**、原包默认**不动**；
  失败 / 取消一个字节不动；危险组合（原包移入其余物 + 其余物要删）**弹窗里当场红字警告**。
  这三档设置与 ③「清理与删除」页那两档**完全独立、各存各的**（用户原话"两者绝对不能同步"）。
  开始前判一次空间（不够不开始，报需要/可用/差），完成后**按实际容器校验产物**
  （`.rar` 用 `Rar.exe` 读、`.7z` 用 `7z l -slt` 读），对不上不显示成功。
  **②「解压方式」页 → 引擎**里有 **`Rar.exe 路径`** 一格（+ 浏览按钮），文案写明许可边界、留空 = 自动用已装目录那份。
  完整设计（含 EULA 依据）见 `docs\打包功能.md`。
- **需要你处理的窗口"叫得住人"**（**只在它没能出现在最前面时**）：警告 / 错误 / 询问 / 密码输入 / 密码本
  这些窗口出现之后会先判一次"它是不是已经在最前面"——
  **已经在最前面（你刚点出来的那种）→ 一声不响、一下不闪**；**没能出现在最前面**（躲在大窗口后面、
  或你正在别的程序里而这一批被它卡着）→ 把窗口从后面**拎到最前面** + **任务栏一直闪（闪到你点它为止）**
  + 连响三声提示音（普通信息只响一声）。以前它们是**每一个**都又闪又响 —— 用户 2026-09-26 原话：
  "这个提醒的作用是什么，如果我现在的小窗没关闭导致我大窗口不能操作才需要这样的提醒，而不是现在的每时每刻提醒"。
  两种结论都写进日志（`窗口提醒：…已经在最前面，安静显示` / `…没能出现在最前面 → 拎到前面 + 闪 + 响`）。
  音量上限就是 Windows 的提示音音量（见 README「已知限制」）。
- **递归解压**：三种模式 —— **只解当前层（默认）** / 单链自动展开（只有一个内层包时才继续）/ 展开所有分支；
  多分支**必须问你**；层数、文件数、总大小、展开比、密码尝试次数都有硬上限，到顶停下并说清停在哪一层。
解压前那四条上限（单文件 / 总大小 / 文件数 / 展开比）是**可改的设置项**
（⑥「设置」页 →「安全上限」，默认 64 GiB / 512 GiB / 20 万 / 1000 倍）——
它们只拒绝解压、不删任何东西；被拦下时失败清单会写清是哪个条目、哪个上限、去哪儿调。
  内层包同样要过安全预检与落点校验，越界即失败（与单层同一口径）。
- **其余物（原「过程物」）**：为得到内容物而产生、用户不需要的东西**集中一处** `其余物\` ——
  内层归档、分卷、抠出来的中间 ZIP（**只在直读不支持时才产生**）、纯壳文件夹，**以及源包本身**。
  每包一个目录的落点就是 `111\222\其余物\`；多个包共用同一个输出目录时（"添加文件夹 + 指定位置"那一档的 `BBB\222\`）
  按包名分层 `111\其余物\222\`，不会互相撞名。老版本留下的 `过程物\` 仍然认（删除功能能清掉它）。
- **源包处理（两档；一键处理与手动「只解压」同一套规则）**：在"内容物已定稿 + 输出校验通过 +
  未取消 + 属于本任务分卷组"四条同时成立之后，按①「源包操作」处理源包 ——
  `KeepInPlace`（**默认**，"原来的位置不动"，一个字节都不搬）/ `MoveToRest`（整组移入 `其余物\`，
  同名加 `(1)` 绝不覆盖，跨盘先复制成功再删原件）。
  要连源包一起删，就把②「删除操作」选成「移入回收站」或「彻底删除」（两档组合，见上一条）。
  搬不动（只读 / 被占用）时任务标「部分完成」并写明"内容物已好，源包未能移入其余物"，内容物结论不受影响。
  ⚠ **手动「只解压」也照这两档走**（用户 2026-09-22 版本二：早先"地基路径永远不动源包"的说法已被推翻）；
  失败 / 部分完成 / 取消时源包一律原地不动、`其余物` 不生成。想要"传统解压器"语义就保持默认的 `KeepInPlace`。
- **解压引擎（两个，按格式与优先级自动分派）**：RAR / RAR4 / RAR5 → **UnRAR**（RARLAB 官方免费件，
  已内置 `tools\unrar\UnRAR.exe`，7.23 稳定版；缺卷时它直接点名缺哪一卷、加密文件名有显式标志）；
  zip / 7z / tar / iso 等其余格式 → **7-Zip**（已内置 26.03）。
  顺序由设置项 `EnginePriority` 决定（默认 `winrar → sevenzip`），规则是**先按能力筛、再用优先级做先后**，
  **不可用的引擎直接跳过** —— 没装 UnRAR、把内置关掉、或把它从优先级里去掉，RAR 仍然由 7-Zip 正常解开。
  每个任务在详情/失败清单里记的是**它实际用的**引擎名 + 版本（不是"当前设置里的第一个"）。
- **同名冲突（`ConflictAction` 一处设置、两处生效）**：输出目录已存在且非空、定稿搬运时同名、以及改名预览里的同名，
  都按同一档处理 —— `Skip` / `Overwrite`（走"先挪到临时名 → 落位 → 再删旧的"两阶段，绝不先删后移）/
  `AutoRename`（**默认**，新产物落成 `名字(1)`，绝不覆盖）/ `Ask`。
  `Ask` 是**真的会问**，而且**两条路径都问**：
  ① **解压落位**第一次撞上同名时暂停该任务、弹一次聚合询问（覆盖 / 跳过 / 自动重命名，勾上
  「对后面所有同名冲突都照此办理」就对整批生效，本批不再问第二次；关掉窗口 = 取消本批）；
  ② **改名冲突在改名预览表里逐条确认** —— 撞名的行出现「冲突选择（询问档）」下拉
  （自动重命名 / 跳过 / 覆盖），没选就不放行（也可以点「冲突全部自动重命名」一次处理完）；
  **不选或直接关掉预览窗口都按保守档自动重命名，绝不覆盖**。没有界面宿主时也降级为"自动重命名 + 写日志"。
  真正覆盖前先写日志留痕（列出被顶掉的落点）。
- **「修复分卷名并重试」（2026-09-25 用户第 41 条，他当场同意加）**：一组分卷的**第一卷**名字被改坏时
  （`X.7z(删掉.001`），程序只能报「分卷缺失」+ 给标准改名建议 —— 源文件它自己一个字节都不动。
  ①「任务」页 →「手动操作」里那颗按钮让**用户显式点一下**：程序只 `File.Move` 改名
  （⛔ 不覆盖 / 不删除 / 内容一个字节不动，改完核字节数）→ 重新识别（重拍快照）→ 按「只解压」
  同一条路重试。七种情况**当场拒绝并说清为什么**（源文件不在 / 名字里没卷号 / 不是第 1 卷 /
  同目录没有后续卷 / 推不出标准名 / 名字本来就标准 / 目标名被占），拒绝时磁盘上一个字节都不动。
- **收尾**：结果可**归集**到统一目录（同名自动改名不覆盖）；源包怎么处理见上面那两档
  （①「源包操作」+ ②「删除操作」，手动档与一键档读**同一套**设置 —— 用户 2026-09-25 第 32 条明确
  "手动档的操作就和选项卡里面的一致"，原来那个"手动只解压成功后删源包"的独立开关已退役）；
  删除仍然只在"解压成功 + 校验通过"之后才发生；失败清单可复制或导出成 txt。
- **其余物 / 空文件夹清理（多任务只问一次）**：勾了 N 个任务时**不再逐个弹预览 + 逐个确认**
  （勾 5 个 = 5 次点击，用户明确说这是冗余）——先一次预览**全部**目标，合成**一个**确认框：
  逐个列出**每个任务的作用范围（哪个目录）**、**合计**条目数 / 字节数、以及**哪些任务含源包**
  （含就点名，删了要重新下载）；确认**一次**，默认移入回收站，勾「改为彻底删除」走激进档
  （红色 + 二次确认，整批也只来这一次）；之后**逐个执行**，**单个任务失败不中断整批**，
  最后给**一次**汇总：成功 N / 失败 M（各自原因）/ 释放字节数 —— 有任何一项没删掉就**不会**显示成全部成功。
- **一键处理**：识别 → 修正伪装后缀（**自动执行，不弹预览** —— 用户 2026-09-25 第 32 条：
  "这个一键处理自己会自动改名自动解压，为什么遇到这种改名的压缩包还要我两次确认"）→
  按密码本解压 → **自动续解本轮新出现的内层包**（轮数 = ②页「最大嵌套层数」，**默认 5**、
   天花板 10；达到上限会明说"还剩 N 个内层包没解"并给出「继续解」按钮）→ 一行汇总
  （成功 / 失败 / 跳过等分项**互斥且可加**，合计恒等于任务总数，不会一个任务被算两次）。
  ⚠ **"这一层还有没有下一层"只看内容，不看名字**（2026-09-25 第 33 条）：内层包的名字被塞字
  （真机上是 `222.ra删除r`）、后缀被改成 `.jpg`、或者干脆是"假 MP4 头 + 尾部完整 ZIP"的双面文件，
  一样会被认出来并接着解；每轮还会在日志里逐条写清"认出谁（按什么判据）/ 跳过谁（为什么）"，
  以及这次定稿产出了哪些文件 —— 出问题**看日志就能定位**，不用去翻目录。
  没有任何需要改名的任务时，改名这步整个跳过，真正零确认；按下「停止后续」后不再续解。
  改名预览仍然属于**手动档**（"智能修正"那条路依旧是先预览再改）。
  源包默认**留在原地不动**（①「源包操作」的默认档），想让程序替你整理就选"放入其余物当中"，
  再按②「删除操作」决定那份其余物留着、进回收站还是彻底删掉。
- **进度可见（不再是"处理中/完成"两态）**：任务列表的状态列显示**百分比**（`解压中 45%`，不新增列），
  任务详情多一行**当前正在解哪个条目**（`45% · payload 08 数据.bin`），**耗时**跟着进度实时走；
  进度来自两台引擎自己的输出（7-Zip `-bsp1` / UnRAR 的百分比），归一化成同一个进度对象、
  **最多 250ms 上报一次**（否则会把界面刷爆）；只会在**跨过 10% 档位**时写一行日志（最多 10 行）。
  ⚠ 超过 **90 秒没有任何引擎输出**时：写一条 WARN + 在任务上挂「长时间无响应」提示
  （`解压中 45% · 长时间无响应`，详情里也有一条），**只提示、不杀进程** ——
  要不要中止由你点「取消当前」决定（"取消当前"与"停止后续"仍是两套独立语义）。
  任务一收尾百分比立刻消失（失败的包绝不会显示"解压失败 100%"）。
- **一键处理 · 本次选项面板**：点「一键处理」时**先问一次**这一次怎么跑 ——
  **本次落点**二选一 / **指定位置** / **终端落法** / **1 源包操作**（原来的位置不动（默认）/ 放入其余物当中）/
  **2 删除操作**（不动其余物（默认）/ 移入回收站 / **彻底删除**，红字 + 选中后那条关不掉的红提示），外加
  ☐「把本次选择存为默认」与 ☐「以后不再询问，直接按设置走」。
  整批**只问这一次**（50–200 个包不会逐个问）；面板上的每一项默认值都取设置里的当前值，
  所以"直接点开始"与"没有面板"的行为完全一致 —— **面板里改的那一档这一次就算数**
  （包括「删除操作」：正文那一行也会跟着改口）。
  ⚠ **不勾「存为默认」时 `appsettings.json` 一个字节都不会改**（有回归测试钉住文件字节哈希）；
  勾了才把这一组选择写进设置。**无界面宿主**（自动测试 / 控制台）下不弹窗、不死等，直接按设置值继续。
  本次实际用的落点会写进**日志**、**任务详情**（失败清单第二级与「复制任务信息」），
  所以"这次为什么解到这里"事后能回答。落点仍然只有一处实现（`OutputPlacement`），面板只是运行期覆盖。
- **特定解压（用户 2026-09-24 拍板：一键处理旁边一个开关 + ②「解压方式」页一栏"可以往上加的规则"）**：
  ①「任务」页「一键处理」右边那个「**特定解压**」开关（**默认关**）+ ②「解压方式」页「特定解压」那一栏里逐条挑规则。
  **关掉总开关 = 与没有这个功能逐字相同**（规则清单里写着什么都不参与运算）。
  ⛔ 界面**按注册表渲染**（`Extraction/SpecialExtractionRules.cs`），一条规则都没写死在 XAML 里；
  **加第二条规则 = 加一条描述 + 一个效果（`ResolveEffect` 分派）+ 它的实现，界面骨架一个字都不用动**。
  第一条规则 = 「**每个包只留一层内容**」（Id `SingleContentLayer`，默认勾上）：
  包名那一层永远保留（`222\1111\`），只把它里面多套的那一层去掉 ——
  规则关 `222\1111\内容文件夹\内容物` → 规则开 `222\1111\内容物`。
  **不塌的三种情况**（各自写一条 WARN 说清原因，绝不静默）：总开关/规则没开、包内有**两个及以上并列文件夹**、
  落点是**多个包共用的成品目录**（"添加文件夹 + 指定位置"那一档）。
  **其余物位置不变**（`<成品目录>\其余物\`）、**同名冲突口径不变**（默认自动改名 `名字(1)`，绝不覆盖）；
  日志、任务详情（`task.RunOptionsNote` / 失败清单）与一键处理确认框正文里都能看到"这次用了哪条特定规则"。
- **日志按级别上色**（2026-09-26 用户要求：「用不同颜色的字体，就比如说用红色、黄色、黑色字体，表示危险、警告、正常的操作」）：**红 = ERROR / 黄 = WARN / 黑 = INFO**，①页日志区与「日志放大」窗口同一份实现（`StatusToBrushConverter`）。设置没存下去（某项不合法）、填的数字被夹回、写盘失败这类事都走**黄色 WARN**；界面上不再有专门的提示框。
- **可恢复**：中间产物放在**工作区**（默认 = `<输出盘>\.ArchiveFixer.work`，跟着输出盘走，
  见 `docs/设置项.md`；填过 `CacheRootDirectory` 时是 `<它>\work`）。
- **失败 / 取消不留残留（2026-09-25 用户第 25 条追加）**：任务以**失败 / 取消 / 部分完成**收尾时，
  默认把这一单**自己的任务工作区整份删掉** —— 含暂存目录、抠出来的内嵌归档副本、已解出的中间件，
  以及**递归解压的逐层工作区**（`<工作区>\recursive\<任务号>\`，双层大包失败时留下的正是最大的一份）；
  **零文件空壳无论如何都删**。删前写一条 INFO（几个文件 / 多大 / 去哪儿改主意），删不掉只写 WARN + 路径、
  **绝不改任务结论**。"为什么失败"照样看得到：列表里的状态与错误信息 + 「导出失败清单」。
  「导出日志（本次）」（①页结果区与⑥设置页都有，2026-09-25 第 38 条）导的是**最近一次操作**那一份 ——
  从 `======== 本次操作开始：<名字> ========` 那行往后，不掺历史；⑥设置页另有一颗**显式**的
  「导出全部历史日志」把 `data\logs` 里每一份按时间拼起来（带分隔头与合计）。
  导出的文件**开头有 6 行头**（2026-09-25 第 44 条追加之二）：时间范围 / 任务数（按各任务的最终状态数）/
  引擎名 + 版本 / 本次输出位置 / "细节在哪看" —— 这份 txt 的用途就是发出来排查，头部只写**机器事实**、
  不含任何密码内容，而且**不算进弹窗里报的"N 行"**（那个数字只数正文）。
  想要"成功任务的**全过程**"：⑥设置 →「日志」→ 勾上**「详细日志（排查用）」**（默认关）再跑一次；
  ⚠ 它只影响**成功**的任务，失败 / 取消的那些永远话多（那才是线索）。
  要留现场排查的人在 ③「清理与删除」页 →「工作区残留」里打开**「失败时保留中间产物（排查用）」**；
  打开之后留下的东西会列在那一组里（名字 / 体积），随时可以点「清理工作区…」清掉。
  所以默认档下**只有两种情况**会在盘上看到工作区残留：打开了这个开关，或者程序被强杀 / 断电来不及收尾。
  ⚠ 第三种情况：工作区里含**目录联接点（junction / 符号链接）**时 Windows 会拒绝整个递归删除，
  那一单的工作区会留下来（日志有 WARN + 完整路径，③页也能扫到、能手动清）。
  **刻意不做**"先删掉其余内容、只留那个联接点"—— 联接点不是我们造的，顺着它删可能把删除动作引到工作区之外，
  宁可留下并如实报路径。
- **中间工作区不留垃圾（成功路径，口径一个字没改）**：任务**成功且产物已经发布**之后，两处工作区都会被清掉 ——
  本任务抠出来的内嵌归档（`<工作区>\<任务名>\`，双面文件动辄几百 MB；**走直读时根本没有这一份**）
  与**递归解压的逐层工作区**（`<工作区>\recursive\<任务号>\`，成功一次同样可能是几百 MB）；
  删前删后各写一条日志，删失败只记 WARN、**不会**让已经成功的任务变成失败。
  ⚠ 这条与上面那条是**两套判据**：成功路径按"校验通过"清，没成功那一支按"默认不留现场"清（可关）。

## 设计边界（对用户的承诺）

下面五条是**承诺**，不是"目前还没做"。它们决定了这个工具是什么、不是什么 ——
与 WinRAR 这类"压缩管理器"的能力边界差别，逐条理由见 `docs/WinRAR功能参考.md`：

| 承诺 | 含义 |
|---|---|
| **不修改 / 不回写已有归档** | 已有归档一律**只做"读 + 解压"**：不改注释、不改分卷、不锁包、不回写。⚠ ⑤「打包」是**新建**归档（那正是它的职责）。识别出后缀被改坏时，改的是**你自己选中的文件名** —— 手动档先出预览，一键处理档按你的要求自动改（旧名 → 新名逐条写进日志） |
| **检出产物越界即整包失败** | 产物一旦越出目标根目录（含"产物目录里混进了目录联接点 / 符号链接"），就是**整包失败结论**：**不归集、不处理源包、其余物不生成**，原因写进任务状态与错误信息 —— 不会只留一行日志却照样报"解压成功" |
| **失败 / 部分完成 / 取消时源包原地不动** | 只有"内容物已定稿 + 输出校验通过 + 未取消 + 属于本任务分卷组"四条同时成立，才可能按你选的档位动源包（默认 `KeepInPlace` —— **一个字节都不搬**；选了"放入其余物当中"才搬，再按「删除操作」决定那份其余物的下场） |
| **绝不默认覆盖** | 同名一律走"跳过或自动重命名"（默认 `AutoRename` → `名字(1)`）；即使选了覆盖，也是"先挪到临时名 → 落位成功 → 再删旧的"，不做"先删后移" |
| **不联网、不写系统盘** | 不自动下载任何引擎、不上传任何东西；配置 / 日志 / 临时文件都在 **`<程序目录>\data\`**，而**解压工作区默认跟着输出盘走**（`<输出盘>\.ArchiveFixer.work`，2026-09-24 用户拍板：残留不堆在程序盘上、定稿走同盘改名）。`%AppData%` 与 C 盘缓存都已被明确否掉 |
