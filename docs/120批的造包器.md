# 120 批造包器修改计划

目标：把现在分散的造包脚本合并成一个入口脚本，一次生成 120 份唯一样本，并把每份样本的期望事实写进 recipe。

本计划只定造包器，不改产品代码。

## 1. 最终数量

```text
普通：50
  40 成功
  10 失败：5 缺片 + 5 坏片
  25 Specified / 25 Original
  8 档每档 6/7

特定解压：20
  现有 10
  +10 个新形状

异常：25
  现有 20
  +5 个边界异常

空间不足：25
  15 普通 C
  10 特定 B (B1-B10)
```

合计：

```text
50 + 20 + 25 + 25 = 120
```

## 2. 合并为一个脚本

新增唯一入口：

```text
E:\AF\造120批.ps1
```

五个旧脚本全部保留，⛔ 不删除、不移动、不改名、不归档：

```text
E:\AF\大测试-造困难包.ps1
E:\AF\大测试-造空间不足20矩阵.ps1
E:\AF\大测试-造空间不足包.ps1
E:\AF\大测试-造特定解压包.ps1
E:\AF\大测试-造异常包.ps1
```

新脚本不是从零重写，而是按五个旧脚本的现有代码块升级合并：

```text
旧脚本继续可独立运行
新脚本复制其函数、命令、目录结构、recipe 字段
只改 100 -> 120 的数量、分组和新增形状
不改变旧脚本行为
```

旧脚本作为回退路径和对照基线保留；新脚本验证失败时直接回旧脚本，不需要恢复文件。

统一参数：

```text
-SampleRoot H:\BaiduNetdiskDownload\困难大测试\大测试备份位置
-SeedBase 915000000
-Force
-Section All|Normal|Specific|Abnormal|Space
```

统一目录：

```text
<SampleRoot>\915000000-备份\<sample>\原包
<SampleRoot>\915000000-备份\<sample>\recipe.json

<SampleRoot>\915100000-特定解压-备份\<sample>\原包
<SampleRoot>\915200000-额外异常-备份\<sample>\原包
<SampleRoot>\915300000-空间不足-矩阵-备份\C01..C15\原包
<SampleRoot>\915400000-特定解压-矩阵-备份\B01..B10\原包
```

## 2.1 按旧脚本升级的来源映射

| 新脚本部分 | 来源旧脚本 | 保留内容 | 只改什么 |
|---|---|---|---|
| 普通 50 | `大测试-造困难包.ps1` | 8 档、40 成功 + 10 失败、包装/伪装/指定位置结构 | 失败样本固定标准名、补 recipe expected |
| 特定 20 | `大测试-造特定解压包.ps1` | 单包、两层、三层、最后文件夹、分卷、密码 | 10 -> 20，补 10 个形状和 expected |
| 异常 25 | `大测试-造异常包.ps1` | `extraKind` 分派、20 个异常形状、recipe | 20 -> 25，补 5 个边界异常 |
| 空间 C 15 | `大测试-造空间不足20矩阵.ps1` | `C01-C15`、space.freeBytes/reserveBytes、expected.blocked/failed | 只换 seed 和 recipe 补 expectedTaskFileName |
| 空间 B 10 | `大测试-造空间不足20矩阵.ps1` 的 B 段 + `大测试-造空间不足包.ps1` 的造包函数 | B1-B5 结构、特定解压形状、空间 recipe | B5 -> B10，补 B6-B10 和任务名映射 |
| 文件/工具/日志 | 三个通用脚本里的同名函数 | `Write-Log`、`Fail`、`Invoke-Tool`、`New-Archive`、`Copy-OrLinkTree` | 只去重，不改语义 |

不采用的做法：

```text
不自己另写一套压缩逻辑
不改旧脚本的参数默认值
不复制旧脚本后又改旧脚本
不删除旧脚本里的安全标记/覆盖检查
```

## 2.2 新旧兼容验证

新脚本完成后先做兼容检查：

```text
普通 50：与旧困难包脚本同一 seed 的样本数、目录结构、recipe 顶层字段一致
特定 10：与旧特定解压脚本同一 seed 的样本数、形状、recipe 字段一致
异常 20：与旧异常脚本同一 seed 的 extraKind 列表一致
空间 15+5：与旧空间矩阵 C01-C15/B1-B5 的 recipe 字段一致
```

允许新脚本新增 `expected` 字段；不允许把旧脚本已有字段改名或删掉。

旧脚本继续可以重跑；新脚本失败可直接用旧脚本生成基线，不需要回滚代码。

## 3. 公共函数

一个脚本内集中实现，不再各脚本复制：

```text
New-WorkTree
New-Archive
New-VolumeGroup
Copy-OrHardLink
Write-Recipe
Write-Manifest
Assert-FileBytes
Assert-StandardNames
Assert-FailureInjection
Assert-SpaceRecipe
```

禁止：

```text
按样本名写产品分支
按固定文件名猜结果
随机受害者
失败样本破坏族身份
```

## 4. 普通 50

### 成功 40

保持现有 8 档组合，每档 6/7 份：

```text
25 指定位置
25 原位置
```

其中失败 10 份：

```text
41-45 缺片
46-50 坏片
```

失败样本最终层固定：

```text
族 = ZipNumbered
标准名 = <stem>-L4.zip.001..005
不做包装壳
```

缺片：

```text
固定删中间片 .003
```

坏片：

```text
固定破坏中间片 payload
不改 archive header / 卷头 / EOCD
```

recipe 必须写：

```text
failure.stage
failure.kind
failure.victim
expected.reason
expected.outcome
expected.finalContent
```

## 7. 空间不足 25

### 普通 C 15

```text
C01-C15
```

recipe 保留：

```text
space.freeBytes
space.reserveBytes
space.concurrency
packages[]
  fileName
  sourceBytes
  contentBytes
  format
  shape
  corrupt
  expected
expected.blocked[]
expected.failed[]
```

### 特定 B 10

```text
B01-B10
```

现有 B1-B5，新增 B6-B10。

B 的 recipe 必须补：

```text
packageId
sourceFiles[]
expectedTaskFileName
expected.blocked / expected.failed
expected.sourceKeep
```

现在 B1-B5 的 `blocked/failed` 和任务文件名对不上，测试不能按包名猜；必须补映射。

新增 B 覆盖：

```text
直接单包 + Delete
两层 + Keep
三层 + Delete
分卷 + Keep
指定位置 / 原位置
```

## 8. 每份 recipe 的公共期望字段

所有样本统一加：

```text
sampleId
category
placement
expected.outcome
expected.reason
expected.sourceKeep
expected.processKeep
expected.processPaths
expected.finalContentPath
expected.contentBytes
expected.groupState
```

空间 B 额外：

```text
expectedTaskFileName
```

没有这些字段，后面的检测只会退回“看总数/看任务名”，又会变成猜。

## 9. 生成后的自检

脚本最后必须断言：

```text
普通 50
  成功 40
  缺片 5
  坏片 5
  25 Specified / 25 Original
  8 档每档 6/7

特定 20
异常 25
空间 25
  普通 C 15
  特定 B 10

总计 120
```

并检查：

```text
失败样本最终层是单一 ZipNumbered 标准名
缺片样本只缺指定中间片
坏片样本五片都在，只改指定 payload
每个 recipe 必有 expected 字段
每个空间 B 必有 expectedTaskFileName
没有 data/、日志、密码本、临时目录进入备份
```

## 11. 实施顺序

```text
1. 先合并公共函数
2. 接普通 50
3. 接特定 20
4. 接异常 25
5. 接空间 25（C15 + B10）
6. 补 recipe expected
7. 跑 120/120 自检
8. 旧脚本保留，不做归档/删除/改名
```

禁止为了凑 120 复制同一份样本
