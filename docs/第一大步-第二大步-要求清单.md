## A0. 两步的**业务流程**（用户原话，⛔ 这是"流程"口径，不是操作规范）

### 第一大步（程序内部的三道工序，顺序不可颠倒）

| 工序 | 用户原话 / 判据 | 出处 |
|---|---|---|
| ① **识别底层** | 「这个读取**底层**的情况」；「首先第一步就是**识别底层文件找出伪装文件**」；按**魔数**认出底层（**认不出 ⇒ 什么都不做**） | `需求变更.md:5259`、`:5273` |
| ② **还原** | 「**将伪装去掉就行了**」；把伪装后缀改成规范形态（**替换、⛔ 不是追加**；**基名一个字不动**） | `需求变更.md:5259`、`:5273` |
| ③ **再匹配** | 「**再接着匹配**」；⛔「**不是说你要直接用这个伪装文件去匹配**」；还原后**才回到第 1 层**用该族专属证据重判一次（"回环" = 照旧走 `CollapseSameGroupVolumes`） | `需求变更.md:5259`、`:5274` |
| — | 「**我们要改的话就要系统化的改，而不是针对一个例子**」 | `需求变更.md:5261` |

**第一大步的范围与边界**（`需求变更.md:5991-5993`）
1. **能解压的统统解压**；剩下的才是分卷缺失的，**先跳过**；
2. ⛔ **不在第一大步里写"分卷缺失"结论**（「没有到最后一步都是先跳过」）；
3. **简单改名允许**（"就是删除中文字符的操作"）；被推迟的只有**缺卷结论**与**组卷归位**；
4. 「**最后的文件全放在一起**我们就能看到了」。

**第一大步的红线**（`需求变更.md:5278-5288`）
- **只碰我们自己产出的内层包副本**；**用户源目录一个字节不动**（那一档归批首「修正后缀」）；
- **只改名、全成或全不成、绝不覆盖**（目标名被占 ⇒ 整组一个都不改 + WARN）；
- **判据只准转调既有两把尺子**（骨架化 / 归档体还原），⛔ 不新造第三把；
- **判不出 ⇒ 什么都不做**。

### ⛔ 本轮复现出的违规点（对着上面流程判）

`111.rar` 解出的入口包被**接片落地到落点层**（= 第一大步的产物，本该到此收手），
**同一批的续解扫描又把它当成"待解的内层包"** ⇒ 给它算落点 `…\111\111\111`，
而该目录已存在且非空 ⇒ 改写成 `…\111\111\111(1)`（日志逐字）。

⇒ 违反 **③ 再匹配** 的后半句（「⛔ 不是说你直接用这个伪装文件去匹配」）与
第一大步红线「**只碰我们自己产出的内层包副本**」—— 程序在**重复解自己的产物**。
⇒ 这也正是"**最后的文件全放在一起**"没做到的机制（产物被分散到 `111(1)` 那一层）。
