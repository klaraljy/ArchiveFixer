## 0. 产品要替掉的那套手工劳动（来自 bat 考古）

用户过去在 `111/222/` 里放几十到 200+ 个包，然后依次跑：

| 原脚本 | 干了什么 | 产品化后对应 |
|---|---|---|
| `解压7z分卷文件1.bat` | 对当前目录每个 `*.7z.001` 执行 `7z x … -y`（**静默**），按原结构解压到当前目录 | 「一键处理」的解压引擎（已具备，改造为**先入独立目录**） |
| `删除7z分卷文件.bat` | `del *.7z.0??` 删掉所有分卷 | §9.5 清理源包（已有，默认关） |
| `移动文件夹1.bat` | 把所有**第二层**子文件夹搬进一个扁平 `11111` | 「过程物集中」（§3.2） |
| `移动文件夹2.bat` | 仅当第一层子文件夹里**只有一个子文件夹且没有其它文件**时，把那个子文件夹提上来 | 「单链塌缩」（§3.3 情形 3） |
| `删除空文件夹.bat` | 删掉"任意层级都没有文件"的第一层子文件夹 | **空文件夹清理**（新功能，§5） |

**一句话**：用户真正要的不是"解压"，而是**"把一堆包变成一堆干净的内容物文件夹"**。

> ⚠️ 隐私红线：bat 里写着明文解压密码。**任何代码、日志、文档、提交信息、测试数据都不得包含该密码**（§8）。
> 密码只能来自密码本 / 用户输入，且只存内存。

## 1. 目标根目录解析（用户诉求第 2 点："输出在哪，疯狂完善"）

### 1.1 三种落点模式（互斥，设置项 `OutputPlacementMode`）

| 模式 | 枚举值 | 源包 `111\222.rar` 的产物落点 | 说明 |
|---|---|---|---|
| 同名子文件夹（**默认**） | `PerArchiveSubfolder` | `111\222\内容物` | 与 WinRAR 默认一致：地基不能丢 |
| 当前目录 | `SourceDirectoryFlat` | `111\内容物` | 用户明确要的第 2 种 |
| 自定义位置 · 单独建文件夹 | `CustomRootPerArchive` | `<自定义根>\222\内容物` | 用户明确要的第 3 种（前半） |
| 自定义位置 · 直接解到该目录 | `CustomRootFlat` | `<自定义根>\内容物` | 用户明确要的第 3 种（后半） |

**硬要求**：`CustomRootPerArchive` 与 `CustomRootFlat` 必须是**两个独立可选项**，不能只做一个（用户原话："这个也要有单独的文件夹和解压到此目录之分"）。

### 1.2 路径推导公式（唯一实现处）

```
destRoot  = 模式 ∈ {PerArchiveSubfolder, SourceDirectoryFlat} ? dir(源包) : 自定义根
destDir   = 模式 ∈ {PerArchiveSubfolder, CustomRootPerArchive}
              ? destRoot \ SafeName(源包基名)      // 去掉所有后缀：222.rar / 222.7z.001 / 222.part1.rar → 222
              : destRoot
```
- `SafeName` 必须走既有 `FileNameHelper` 清洗（Windows 保留名、结尾空格/点、非法字符）——复用，不要新写。
- 分卷组：**基名取整个分卷组**（`222.7z.001` → `222`），不是 `222.7z`。已有 `VolumeGroupDetector` 的结果可直接用。
- 冲突处理沿用不变量 3：默认"跳过或自动重命名"，**不得默认覆盖**。
- `SourceDirectoryFlat` 下若 `111/内容物` 与已有文件冲突，一样走冲突策略（不是往 `111/222` 里塞）。

### 1.3 与现有设置的关系
现在的 `ExtractToOriginalDirectory`（布尔）+ `CustomOutputDirectory` + `KeepArchiveNameFolder` **表达不了上面四种**，
按 1.1 重构为单一枚举（旧布尔组合迁移到新枚举：`true`→`PerArchiveSubfolder`、`false`+空根→`PerArchiveSubfolder`、
`false`+有根→`CustomRootPerArchive`），旧配置必须能平滑迁移，不得让用户升级后行为突变。

## 2. 一键处理的两阶段模型（用户诉求第 2.4 点）

用户原话：**"一键处理先解压到单独的文件夹，然后就是在文件夹内处理"**；现状被批"多弄了四个文件夹、分卷文件被解压到外面来了、文件一多根本分不清"。

### 2.1 阶段一：入仓（stage）
- 每个任务在**私有暂存目录**里完成所有中间动作：抠内嵌归档 → 解第一层 → 解内层分卷 → …
- 暂存目录：`<dataRoot>\work\<taskId>\`（已存在，且**不得落 C 盘**）。
- **暂存期间绝对不往源目录写任何东西**：分卷中间件、部分产物、临时文件全部留在暂存区。
  （现状缺陷：分卷被解到用户可见的目录里，用户"分不清"。）

### 2.2 阶段二：定稿（commit）
- 只有当"最终内容物已确定 + 输出校验通过"时，才把结果**一次性**落到 §1 算出的 `destDir`。
- 定稿是**搬运**（同盘 move，跨盘 copy+delete），不是"原地解压"。
- 定稿完成后：① 按 §3 归置内容物；② 按 §3.2 集中过程物；③ 按既有规则决定是否清源包。
- **失败/取消时**：`destDir` 里不得留下半成品（要么没有，要么完整）；暂存区保留供排查（不变量 12/13）。

## 3. 从尾巴倒着判定落点（用户诉求第 3 点，核心）

思路：**先看最终内容物长什么样，再决定目录结构**，而不是"解到哪算哪"。

设解压链的**终端内容物**（最后一层归档里的东西）为 `T`，任务目标目录为 `D`（= §1 的 `destDir`）：

### 3.1 判定表（必须按顺序判，先命中先返回）

| # | 终端形态 | 落法 | 例子（源包 `111\222.rar`） |
|---|---|---|---|
| 1 | `T` = **单个文件**（如一个 mp4） | 直接放 `D\` 下；`D` 的名字就是包名（`222`） | `111\222\666.MP4` |
| 2 | `T` = 多个文件 / 多个文件夹 / 自带一层文件夹 | 在 `D\` 下**套一层**，文件夹名取"最后一层归档内最外层那个文件夹名"，没有就取终端归档基名 | `111\222\666\多数内容物` |
| 3 | `T` 被**多重空目录嵌套**包裹（`…/999/内容物`，中间层只有空目录/仅一层文件夹） | 把**最后那个有意义的文件夹**提上来当 `D` 的直接子层 | `111\222\999\内容物` |
| 4 | 终端归档本身**只有一条单链**（每层都只有一个文件夹、没有别的文件） | 塌缩为最深层那个文件夹名（等价于原 `移动文件夹2.bat` 的规则） | `111\222\<最深名>\内容物` |

**用户可选项（`TerminalLayoutMode`）**：
- `KeepLastFolder`（默认）：`111\222\666\内容物` —— 保留最后一层文件夹名；
- `UseArchiveName`：`111\222\内容物` —— 用包名当最后一层，少一层点击。
两种都必须保留 `111\222\过程物`。

### 3.2 过程物（用户诉求第 3.5 点）
- **定义**：为得到内容物而产生的、用户不需要的东西 —— 内层归档文件、分卷、抠出来的中间 ZIP、纯壳文件夹、以及对不上内容物的杂物。
- **位置**：**集中一处** `D\过程物\`，保持它们之间的相对结构（不要"东放放西放放"）。
- **命名**：固定叫 `过程物`（写进 `StatusText`/常量，不要散落字面量）。
- **体积**：通常较小，但可能很大（分卷）→ 详情的日志要报总大小。
- **清理**（用户明确两档）：

| 档 | 行为 | 安全要求 |
|---|---|---|
| 默认 | 移入**回收站** | 操作前**必须让用户确认**（列出路径数量与总大小）；回收站不可用时降级为"不删 + 明确告知" |
| 激进 | **彻底删除** | ① 必须在界面上用**红色**标识；② 必须二次确认（输入确认或勾选"我知道不可恢复"）；③ 每次删除写日志（路径+理由+总大小）；④ 取消/部分完成时**一律不删** |

- **绝不允许**：把过程物和内容物混在同一层、或把过程物散落在源目录/内容物目录里。

### 3.3 批量场景（用户诉求第 4 点，产品初衷）
- 场景 A：`111\222\` 下有 50–200+ 个包（大多结构相同，少量是更新的）→ 逐个产出 `111\222\<包名>\内容物`。
  → 直接由 §1.1 默认模式 + §3 判定表得到，**不需要额外规则**。
- 场景 B：`111\222\<名字>\<名字>.rar`（数百个子文件夹，每个里一个包）→ 产出 `111\222\<名字>\内容物`。
  → 注意：这里 `destDir` = 包子文件夹所在目录 + 包基名 = `111\222\<名字>\<名字>`，
    与用户期望 `111\222\<名字>\内容物` 差一层。**规则**：当"包基名 == 其所在目录名"且该目录下只有这一个包时，
    `destDir` 取父目录（即塌缩掉重复的一层），产物落在 `111\222\<名字>\内容物`。此规则必须可关（设置项），默认开。
- 两场景都必须**单任务失败不中断整批**、结果可追溯（不变量 9/14）。

## 4. 地基（用户强调："一定不能少"）
- **WinRAR 式基础解压必须始终可用**：选一个包 → 解压到同名子文件夹 → 完事。这条路径不得被"智能整理"挡住或变慢。
- 增强项（定稿整理、过程物集中、自动续解）都必须是**可关的**，关掉后行为 == 传统解压器。
- 默认值取"最不意外"：`PerArchiveSubfolder`（同名子文件夹）+ 终端落法 `KeepLastFolder` + 过程物集中**开**。

---

## 5. 空文件夹清理（原 `删除空文件夹.bat`）
- 规则：删除"**任意层级都没有文件**"的目录（只剩空目录树的目录）；只要任意层级有文件就保留（与原 bat 一致）。
- 默认**关**；执行前二次确认；**移入回收站**；删除前写日志。
- 作用于"本次任务的目标根目录"内，**禁止越出**（走 `ArchivePathGuard.IsInsideRoot`）。
- 与过程物清理是两个独立动作，不得合并成一个开关。

---

## 6. 不变量（本模型新增/强调）
1. 暂存期间不往源目录写任何东西。
2. 定稿前 `destDir` 不得出现半成品。
3. 过程物只允许出现在 `D\过程物\` 一处。
4. 彻底删除必须红色标识 + 二次确认 + 写日志；回收站不可用时不删。
5. 基础解压路径（同名子文件夹）永远可用且是默认。
6. 输出根解析只有一处实现（`OutputPlacement`），禁止在别处再拼路径。

## 8. 已定位的历史根因（来自 bat + 旧代码考古）

1. **"分卷被解压到外面、多弄了四个文件夹"**：
   - 旧 `FileNameHelper.GetArchiveBaseName` 只去**最后一个**后缀 → `a.7z.001` → `a.7z`、`001.part1.rar` → `001.part1`；
   - 旧 `ArchiveDetectService` / `FileScanService` **通篇没有分卷组概念**（一卷 = 一个任务），
     于是每个分卷各自解压、各自建目录。
   - **当前仓库仍有前半段**：`GetArchiveBaseName` 只处理 `.tar.gz/.tar.bz2/.tar.xz`，其余只去最后一个后缀。
     **证据**：2026-09-21 端到端产物里出现的目录就是 `17274362.7z\岳母交换计划 1.mp4`（应为 `17274362\`）。
   - 修法：`OutputPlacement.ResolveArchiveBaseName` 成为唯一实现；`FileNameHelper.GetArchiveBaseName` 改为转调或补上分卷后缀处理（由 R2/R3 的负责人接线）。
2. **"四个文件夹"的后半段**：续解把内层包当成**独立任务**、各自拿自己的输出目录 →
   必须合并成"一个源包 = 一个最终目录"（§2.2 / R3）。
3. **`ExtractionWorkspace` 已有 90%**：`layer-NNN/output`、`Publish`、`Cleanup`、`WriteReport` 都在，
   缺的只是 `final/` 与 `process/` 两个子目录 —— 阶段化改造优先复用它，不要另造工作区。
4. **回收站 API**：`Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile/DeleteDirectory`
   （`RecycleOption.SendToRecycleBin`）与 `SHFileOperation` P/Invoke 都不是 NuGet 依赖，两种都可行；
   实现时按"能测、失败可降级"选一种，并在 README 的已知限制里写明网络盘/策略禁用时不可用。
