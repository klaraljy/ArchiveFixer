## 0. 一页速览：WinRAR 在这件事上的设计骨架

如果只看一段，看这段。WinRAR 的解压设计可以归纳成 6 条：

1. **解压是"一条命令 + 一组开关"，不是一堆对话框**。GUI 只是开关的可视化外壳，
   每一个勾选框都能在 `Rar.txt` 里找到等价开关（帮助里几乎每条都写了"界面模式对等参数是…"）。
   → 反面：它的 GUI 也因此塞进了 60+ 个开关，绝大多数用户一辈子用不到。
2. **默认值全都取"最不破坏数据"的那一档**：解压默认"覆盖前询问"、损坏文件默认删掉但可关、
   删除源包默认"永不"、路径越界默认拒绝、`-ep3`（按原盘符落盘）默认关闭并配三重警告。
3. **每个"危险动作"都有一个显式的代价说明**。`-ep3` 的帮助原文意思就是"只有你完全确认包里没有
   恶意文件才用，它能覆盖你机器上任何位置的文件，包括系统文件"。"额外的参数"输入框也写明
   "错误使用会干扰 WinRAR 的功能，甚至导致数据丢失"。
4. **多档案批处理靠"路径推导公式"而不是"智能猜测"**：`-ad` / `-ad1` / `-ad2` 三个开关把
   "每个包解到哪"讲得毫不含糊（详见 §1.1），并且**承认 `-ad1/-ad2` 会忽略目标目录参数**。
5. **进度、错误、报表三件事分得很清**：进度窗口管当下（可取消/可暂停/可后台），诊断信息窗口管错误，
   "生成报告"管事后清单。三者互不兼任。
6. **它自己也留下了一堆"我们不该照抄"的历史包袱**：配置文件（Profiles）对解压完全无效、
   密码明文存注册表、`-e` 摊平会撞名、GUI 里塞命令行参数输入框、靠 `-ri` 手工调优先级。

**对 ArchiveFixer 最重要的一句结论**：WinRAR 在"**单包、交互式、用户全程盯着**"这个前提下打磨得极好；
我们的前提是"**200 个包、不想盯着、结果必须可追踪**"。所以它的**默认值思路**（不破坏数据）值得抄，
它的**交互形态**（逐个询问、逐卷插盘、配置文件存一组压缩选项）大多不能照抄 —— §2 逐条给了结论。

## 1. 解压相关的功能清单（WinRAR 怎么做）

### 1.1 "解压到"的语义：它其实有 **5 种**入口，默认各不相同

这是最容易看错的一节。WinRAR **没有一个统一的"解压到"默认值**，取决于从哪进：

| 入口 | 界面命令 / 开关 | 产物落点 |
|---|---|---|
| 不确认直接解压 | 命令菜单 Alt+W，等价命令行 `x` | **压缩包所在文件夹**；若"路径设置"里填了"解压文件的默认文件夹"，则以它为基准，**再按"附加压缩文件名到路径"选项决定是否追加包名子文件夹** |
| 解压到指定文件夹 | Alt+E，弹出"解压路径和选项"对话框；等价 `x` | 对话框里"目标路径"，**默认值也是压缩包所在文件夹** |
| 对话框"选项"页 · 解压到（4 选 1） | `-ad` / `-ad1` / `-ad2` / 目标路径 | 见下表 |
| 资源管理器右键"解压到 \<文件夹名\>" | 无对话框 | **以压缩包名命名的同名子文件夹** |
| 命令行的目标路径参数 / `-op<path>` | `x arc.rar file c:\dest\` 或 `x -opdest arc.rar` | 指定目录 |

"解压到"4 选 1 的**精确语义**（来自帮助的"解压缩归档到"选项组，外加 `Rar.txt` 的 `-ad` 说明）：

| 选项 | 等价开关 | 语义 | 目标目录参数是否生效 |
|---|---|---|---|
| 目标路径 | （命令行里的 `path_to_extract\`） | 所有产物放同一个指定目录 | 就是它自己 |
| 目标路径中的子文件夹 | `-ad` | 在**目标目录**下，为每个压缩包各建一个基于包名的子文件夹 | 生效 |
| 归档文件夹中的子文件夹 | `-ad1` | 在**每个包自己所在的目录**下，为它建一个子文件夹 | **被忽略** |
| 归档文件夹 | `-ad2` | 把产物**直接放进包自己所在的目录**，不建子文件夹 | **被忽略** |

边界行为：

- **目标路径不存在就自动创建**。`-op<path>` 相对命令行尾部的 `dest\` 参数"友好一些"：
  它接受**不带尾部分隔符**的路径（`-opdest` 等价 `-opdest\`）。这个细节是 6.10 才补的
  （`WhatsNew` 明确写"与 `<path_to_extract\>` 不同，此参数还接受没有尾随路径分隔符的路径"）。
- 对话框目标是"文件夹树 + 路径输入框"双通道：输入路径后**延迟约 0.5 秒**自动在树里定位；
  定位可能因为路径在慢盘上而被中止，所以配了一个"**显示**"按钮强制立即定位。
  路径不存在时，选中"它的上级"或"最相似的"节点。
- 树里可以直接 `F2` 重命名 / `Del` 删除 / `F5` 刷新 / "新建文件夹"。
- 对话框可以拖动改变大小，**WinRAR 会记住新尺寸**。
- **"保存设置"按钮**：把对话框"常规 + 高级"两页的当前状态存为下次的默认值，
  但**明确不保存目标路径** —— 默认目标目录统一由"设置 / 路径 / 解压文件的默认文件夹"管。
- 目标路径有**历史下拉**；6.00 起把 `folder` 与 `folder\` 视为同一路径，历史里只留一条。

**"从解压路径移除多余的文件夹"**（设置 / 路径）是一个很容易被忽略但很有意思的开关：

- 只在**右键菜单的"解压到 DestName\"命令**下生效，且必须满足"压缩包只有一个根目录、
  该根目录下只有一个文件夹、没有别的文件"。
- 生效时，把"基于包名生成的那一层"从解压路径里去掉：包 `Pictures.rar` 里全是 `Samples\…`，
  关着得到 `Pictures\Samples\…`，打开得到 `Samples\…`（省一次点击）。
- 帮助**自己写明了代价**："会导致解压开始有额外的延迟，因为 WinRAR 需要扫描压缩文件并分析
  文件夹的结构"，并且"在关联菜单中显示纠正的文件夹会导致在右键点击和显示关联菜单间潜在的
  烦人延迟"。
- 它还说明一个构造性事实：即使解压时要去掉那一层，**右键菜单里显示的名字仍然是包的文件夹名**。

> 对照我们的模型：这一条与"从尾巴倒着判定落点"是同一个问题。WinRAR 只覆盖了判定表里的
> **情形 4（单链塌缩）**，而且只在右键菜单那一个入口、还要额外扫一遍包。我们的判定表有 4 种情形、
> 可关、且预检本来就要 list（见 §2 A7、§3 第 4 条）。

### 1.2 更新模式与覆盖模式：两个独立的 3 选 1 / 4 选 1

"解压路径和选项"对话框**常规页**把这两件事分开放在两个组里 —— 这个划分值得记住：

**更新模式（3 选 1，靠时间判据决定"要不要解"）**

| 选项 | 语义 | 等价开关 |
|---|---|---|
| 解压和替换文件（**默认**） | 全部选定文件都解 | — |
| 解压并更新文件 | 解压后只复制"目标里不存在"或"比解压出来的旧"的 | `-u` |
| 仅刷新已存在的文件 | 只覆盖"目标里已存在且比包内旧"的；**目标里没有的直接跳过** | `-f` |

- `-u` 与 `-f` 的差别被写得很清楚：`-f`（刷新）**不会**解出目标里没有的文件；`-u`（更新）**会**。
- 两者都**只支持 RAR 和 ZIP**，别的格式用不了。

**覆盖模式（4 选 1，靠"已存在怎么办"决定"怎么落"）**

| 选项 | 语义 | 等价开关 |
|---|---|---|
| 覆盖前询问（**解压默认**） | 逐个提示 | `-o` |
| 覆盖但不提示 | 直接覆盖 | `-o+`（**更新压缩包时的默认值**） |
| 忽略已存在的文件 | 已存在的不覆盖 | `-o-` |
| 自动重命名 | 已存在时**给解压出来的文件改名** | `-or` |

**它到底改哪一侧的名字？——改"解压产物"（目标侧），不改包内条目、不改源包。**
命名规则：`filename(N).txt`，`N` 从 1 递增（`filename.txt` 是原始名）。

**"覆盖前询问"对话框的 6 个出口**（这是它的交互设计精华）：

> 覆盖（是） / 跳过（否） / **重命名** / **全部重命名** / 覆盖全部文件（全部皆是） / 跳过全部已存在的文件（全部皆否），外加 取消。

关键在"**全部重命名**"这一档：批量时用户可以一次决定"这一批全部走改名"，不必点 N 次。
选择"全部重命名"后，后续所有冲突都按 `filename(N).txt` 自动处理。

另外两种**改名**语义要注意区分：

- `-or`：解压时的**目标侧**自动重命名（上面这个）。
- `-ver[n]`：**压缩包内部的版本控制**，更新已存在的归档时旧版本被存成 `filename;n`。
  解压时默认只解"最新版本"（名字里不带数字后缀的那个）；`x arcname file.txt;5` 才能取第 5 版；
  `x -ver5 arcname` 只解第 5 版并去掉版本号。**这是归档内部的事，不是我们场景里的解压冲突。**

### 1.3 时间判据的完整形态

WinRAR 的时间不只是"更新模式"，它在**压缩/解压两侧**都有一套完整的时间开关：

| 开关 | 语义 |
|---|---|
| `-ta[m,c,a,o]<日期>` | 只处理**指定日期之后**修改的文件（含当天，`YYYYMMDDHHMMSS`，可插 `-`/`:` 并省略尾部） |
| `-tb[m,c,a,o]<日期>` | 只处理**指定日期之前**修改的文件（**不含**当天） |
| `-tn[m,c,a,o]<时间>` | 处理"距今多久之内"的新文件，如 `-tn15d`、`-tn2h30m` |
| `-to[m,c,a,o]<时间>` | 处理"距今多久之前"的旧文件 |
| `-ts[m,c,a,p][+,-,1]` | **保存/恢复文件时间**（下面单列） |
| `-tk` / `-tl` | 修改归档时**保留原归档时间** / 把归档时间设为包内最新文件的时间 |

- `m/c/a` 修饰符分别指定用**修改时间 / 创建时间 / 上次访问时间**做判据，不写默认 `m`。
- 多个时间过滤参数之间是 **AND**；加了 `o` 修饰符的那个改走 **OR**。
- 这套判据同时作用于**压缩**（选哪些文件进包）和**解压**（选哪些条目出包）。
  界面上的对等物是压缩对话框"时间"页的"待处理文件"选项（5.70 起支持创建/访问时间，
  之前只有修改时间）。

### 1.4 解压前 / 解压后的动作

**解压前测试：WinRAR 没有这个开关。** 这是一个必须说清的事实：

- `t` 是**独立命令**（"测试压缩文件"，Alt+T），它做一次虚拟解压、不写任何数据；
- `-t` 是"**压缩后**测试文件"（配合 `m` 移动命令时很有用：只有测试通过才删源文件）；
- 解压对话框里**没有**"解压前先测试"的勾选框。
- 它的替代设计是：**解压在写出数据的同时校验校验和**，校验失败的产物默认被删掉
  （`-kb` 可保留，见下）；发现的错误进"诊断信息"窗口。
- 唯一带"解压前动作"的地方是 **SFX 自解压模块**的预设：`解压前先删除文件`、
  `指定解压前运行的程序`（这是安装器语义，不是通用解压器语义）。

**保留损坏的文件（`-kb`）**：默认"解压后删除校验和错误的文件"，`-kb` 关掉这个删除动作。
界面等价物是解压对话框常规页的"保留受损的文件"。
帮助给的理由是"您可以试着从坏掉的文件中保存部分的信息"。

**完成后的动作**：
- 解压对话框**选项页**的"完成时"（6.10 新增）：可以选**关机 / 休眠 / 睡眠 / 重启**。
  等价开关 `-ioff` / `-ioff1`（关机）、`-ioff2`（休眠）、`-ioff3`（睡眠）、`-ioff4`（重启）。
  两个边界写得很明确：① 操作系统必须支持对应电源管理功能；② **"如果在诊断消息窗口中显示错误，
  则忽略用来关闭 WinRAR 的选项"**；③ 多开时"由最后结束的那一份来关机"。
- 常规页"杂项"里的"**在资源管理器中显示**"：解压完成后打开资源管理器并定位到目标文件夹。

**删除压缩包**（高级页，与"完成后动作"并列）：

| 选项 | 语义 |
|---|---|
| 永不（**默认**） | 不删 |
| 询问确认 | 删前问 |
| 总是 | 不问就删 |
| 移动到回收站 | 删进回收站而不是彻底删 |

**触发条件极其严格**（原文意思）："**仅在无错误解压后，并且压缩文件中所有文件都被选择解压时**"
才删；解压多卷时**所有卷一起删**。帮助还加了一句提醒：
"要小心使用'询问确认'尤其是'总是'模式。删除解压过的压缩文件使用不当会导致数据丢失。"

**属性与安全数据（高级页）**：

- 文件时间：设置**修改 / 创建 / 最近访问**三种时间（默认只恢复修改时间；在包里存了另外两种
  也必须在这里勾上才会恢复）。可用性取决于格式，有些格式不支持。
- 属性：`不解压路径名称` / `清除"存档"属性`（`-ac`，为备份设计） /
  `设置文件安全`（`-ow`，NTFS 所有者/组/ACL/审计，**只有 RAR 支持**，需要特权，
  帮助说"大多数情况下家庭用户不需要"） / `设置"压缩"属性`（`-oc`，NTFS 压缩属性，只有 RAR 支持）。
- `-ai`：忽略包里存的属性，保留操作系统给新文件的属性（Windows 下影响存档/系统/隐藏/只读）。

### 1.5 后台解压 / 低优先级（对应用户抱怨过的"卡死"）

WinRAR 在这件事上有**四个互相独立的机制**，值得分开看：

| 机制 | 开关 / 设置 | 语义 |
|---|---|---|
| 低运行优先级 | 设置 / 常规 / **系统 · 低运行优先级**；`-ri<p>[:<s>]` | `<p>` = 0–15，**0 = 默认优先级，1 = 最低，15 = 最高**；`<s>` = 每次读写之后"还给系统"的休眠毫秒（0–1000）。帮助的建议是"通常常规优先级是最优选择，但如果你常与其它程序合用并把 WinRAR 放后台运行，可能希望用较低的优先级" |
| 线程数 | 设置 / 常规 / 系统 · 线程；`-mt<参数>` | 限制压缩等模块的最大 CPU 线程数；帮助写明"有时活动线程的实际数量可能超过指定的值" |
| 后台运行 | 解压对话框"后台解压"；`-ibck` | **语义只是"开始时最小化到任务栏/通知区"**，不是降低优先级、也不是并行 |
| 与其它副本排队 | 解压对话框"如果其它的 WinRAR 副本正在活动则等待" | 等别的 WinRAR 任务完成/暂停后再开始；理由是"队列执行能帮助减少磁盘定位的次数并提高整体性能"；**不支持 7z**；可在进度窗口点"继续"强制忽略 |

进度窗口本身提供三件事：**取消**（立即中断）、**后台操作**（最小化到任务栏，完成后自动复原）、
**暂停 / 继续**。

一个历史教训（6.02 修）："以前的版本**忽略了 `-ri` 参数**，并在存在 `-ibck` 参数的情况下
设置了较低的优先级。" —— 即"两个调节旋钮互相打架"是真实踩过的坑。

### 1.6 配置文件（Profiles）：**只作用于压缩，对解压完全无效**

这是本节最需要写清楚的一条，因为它直接影响能不能抄：

- 它叫"压缩配置"（Profiles），可以是**用户定义**的，也可以从"压缩设置"里"创建默认值"
  （后者固定叫"默认配置文件"）。
- 能存的东西：压缩格式、分卷大小、压缩方式等等**一组压缩选项**；外加元参数：
  `配置文件名`（可含 `%arcname%` 变量）、`保存压缩文件名`、`保存选定的文件名`、
  `设置为默认配置文件`（同时只能有一个）、`立即运行`（选中即开跑，不再确认）、
  `在桌面上创建快捷方式`、`添加到关联菜单`。
- 选择方式：压缩对话框的"配置文件"按钮 + 弹出列表；命令行是 `-cp<名称>`；
  还有"管理配置"对话框（改名/删除/上移下移/设默认）。
- **密码可以存进配置文件**，但"以不安全的格式存储在注册表中"，所以 5.50 起会出现主密码提示，
  可以给"配置文件中保存的密码"单独设一个主密码。
- ⛔ **决定性的一条**（帮助原文意思）："**解压不使用默认压缩配置的任何选项**"。
  也就是说：**WinRAR 的 Profiles 解决不了"解压选项一键复用"这个问题**。
  它自己在 6.00 才给解压对话框加了"保存设置"按钮，而且那个按钮**不保存目标路径**。

> **对"批量整理"场景的启发其实是否定的**：WinRAR 用 20 年时间证明的是
> "把一组压缩选项打包命名"这件事对解压没用。真要一键复用，正确形态是
> "**把上一次这次操作的所有选项存成默认值**" + "**一次操作级的临时覆盖**"，
> 而不是引入一个独立的命名配置实体。

### 1.7 掩码 / 排除 / 只解压指定文件

| 开关 | 语义与边界 |
|---|---|
| `-n<掩码>` | **附加**包含过滤器（不替换命令行上的普通文件掩码）。可多次指定。只处理匹配的文件 |
| `-n@<列表文件>` | 从文件读包含掩码 |
| `-x<掩码>` | 排除指定文件或文件夹，可多次指定 |
| `-x@<列表文件>` | 排除列表文件里列出的文件；`-x@` 不带文件名时从**标准输入**读 |
| 位置参数 | `x docs.rar *.txt c:\docs\` —— 指定解压哪些条目（也支持 `@列表文件`） |

`-x` 的语义细节（**这些是最容易踩的坑**，值得记住它的设计）：

- **含通配符**的掩码**递归**作用于当前目录及其子目录；**不含通配符**的掩码**不递归** ——
  `filename` 只排除"当前目录里的 filename"，解压时只排除"包根目录下的 filename"。
- `*\filename` 排除**所有目录**里的 `filename`。
- `路径\文件名` 只排除那个特定副本；**解压时这里的"路径"必须是包内路径，不是解压后磁盘上的路径**。
- **目录排除掩码必须尾随一个路径分隔符**：`*tmp*\` 排除所有匹配的目录，`*\tmp\` 排除所有 `tmp` 目录。
  只有掩码里含通配符时，才必须靠这个尾随分隔符把它和"文件排除掩码"区分开。
- 文件夹排除掩码**只支持 RAR 和 ZIP**。

`-e` vs `-x`（**这一对是命令行最容易搞混的**）：

| 命令 | 语义 | 后果 |
|---|---|---|
| `x` | **带路径**解压（保留目录结构） | 结构完整；产物是一个目录树 |
| `e` | **不带路径**解压，所有文件都创建到同一个目标目录 | **多个同名文件会撞在一起**，所以 `e` 几乎总要配 `-or` 用。帮助的示例就是 `rar e -or html.rar *.css css\`，并特意注明"多个文件有相同的名称时自动重命名解压的文件" |

路径加减开关（压缩/解压两侧都可用）：

| 开关 | 语义 |
|---|---|
| `-ep` | **从名称中排除路径**：解压时忽略包内路径，全部落到同一目标目录（= GUI 的"不解压路径名"） |
| `-ep1` | **从名称中排除主文件夹**：不存储/不还原命令行里输入的那段前缀路径（`x -ep1 data images\* dest\` 会把 `images\` 从产物路径里去掉） |
| `-ep2` | 压缩时存"完整路径（不含盘符和根反斜杠）" |
| `-ep3` | 压缩时存"**含盘符**的完整路径"（冒号被换成下划线）；解压时还原到**原始目录和磁盘**，并且**用户指定的目标路径会被忽略** |
| `-ep4<path>` | 名称开头若匹配该路径则从包内名称里去掉（压缩）/从包路径里去掉（解压） |
| `-ap<路径>` | 给包内名称加一层路径（压缩），或解压时从条目名里去掉这一段（`x -apDOCS release DOCS\ENG\*.*`） |
| `-cl` / `-cu` | 解压/添加/更新时把文件名全转小写 / 全大写（跨大小写敏感系统搬运时用） |

> `-ep3` 帮助里的警告值得单独抄下来当"红线反面教材"：
> "**小心使用 `-ep3` 参数，只有您确认压缩文件不包含任何恶意文件。……此参数允许覆盖在您的计算机上
> 任何地方的任何文件，包括重要的系统文件和通常仅用于备份和恢复的目的。**"

### 1.8 目录结构：默认永远保留

- 默认（`x`）保留目录结构；`e` / `-ep` / "不解压路径名"才会摊平。
- 高级页的"文件路径"是 4 选 1：`解压相对路径`（**默认**）/ `解压完全路径` /
  `不解压路径名` / `解压绝对路径`。
  - "解压相对路径"的含义很细：**如果你在 WinRAR 里已经进了包的某个子文件夹再解压，
    那一段当前子目录会从产物路径里去掉**（在 `Backup\MyData` 里解 `Images` → 得到 `Images`，
    而不是 `Backup\MyData\Images`）；但如果你在包根目录、或从右键菜单启动，它就等价于"解压完全路径"。
  - "解压绝对路径"是 `-ep3` 的界面等价物，**只被 RAR 和 ZIP 支持**，帮助照例配了
    "如果你不是完全确认压缩文件不包含恶意文件则不要设置此选项"。

### 1.9 分卷 / 多卷

| 主题 | WinRAR 的做法 |
|---|---|
| 启动 | **必须从第一卷开始**（RAR 是 `.rar` 扩展名的那个；ZIP 是 `.zip` 那个，其余是 `.z01/.z02…`） |
| 位置 | 解压前**必须把所有卷放在同一个文件夹里**。RAR 卷在硬盘上可以分散（它会提示插盘），但 ZIP 卷"需要同时访问所有卷"，所以**不可能跨多个移动磁盘解压 ZIP 卷** |
| 缺卷时 | 弹提示："**请插入磁盘 \<下一个分卷名\>。确定/取消**"，用户可以插入或指定正确的卷再继续 |
| 命名 | 默认 `volname.partNNN.rar`；RAR 4.x 可用 `-vn` 改用 `.rar` + `.r00…r99`；**RAR 5.0 不支持 `-vn`**。ZIP 是 `volname.zip` + `volname.z01/z02…` |
| 卷号 | 3.40 起卷号存在卷内，"显示信息"对话框顶端能看到 —— 原始卷名丢了需要手工纠正文件名时有用 |
| 只能只解部分吗 | 不支持"只解已有部分"这一概念；缺卷就是解不下去。**但**从**固实卷**里解**一部分文件**有专门优化（6.00）：会从头跳过卷、从最接近指定文件的卷开始解压并重置固实统计，不再无脑从第一卷重来 |
| 自动回退 | 6.00 起，用户没从第一卷启动时，**只有第一卷到指定卷之间的所有卷都可用**才自动回退到第一卷 |
| 恢复卷 | `-rv[N]` 建 `.rev`；`rc` 命令或解压时找不到下一卷且 .rev 数量够，会**自动尝试重建**丢失/损坏的卷；损坏的原始副本重建前先改名 `*.bad`（如 `volname.part03.rar` → `volname.part03.rar.bad`） |
| 不可修改 | 已存在的分卷**不能**添加/更新/删除文件；`d/u/f/a` 都不能用于分卷（`a` 只能新建卷组） |
| 卷数上限 | RAR 4.x ≤255，RAR 5.0 ≤65535；恢复卷数必须 < RAR 4.x 卷数、≤ RAR 5.0 卷数的 10 倍 |
| 内存 | RAR 5.0 起"如果卷号字段宽度允许"，卷名用 `part01` 而不是 `part001`（与 RAR4 恢复卷对齐） |

### 1.10 密码

| 主题 | WinRAR 的做法 |
|---|---|
| 密码存哪 | **会话内存**：文件菜单"设置默认密码"设的那个全局密码一直有效到关闭 WinRAR（钥匙图标变红）；重启即清。压缩对话框里直接输入的密码**只对那一次操作有效，完成后自动删除** |
| 提示时机 | **遇到加密文件才提示**，不必事先输入。"用于所有压缩文件"把这一次输入的密码应用到本批全部包（只处理一个文件时该选项无效） |
| 无人值守 | "**空密码 + 用于所有压缩文件**" = 解压和测试命令**跳过所有加密的文件和压缩包**（此时状态栏钥匙图标不显示）。6.10 起有专用开关 `-mes`（跳过加密文件），它取代了旧的 `-p-` |
| 密码本 | "管理密码"对话框：每条记录含 `密码文本`（必填）、`密码标签`、`用于压缩文件`（**只写名字/掩码，不含路径**，空格分隔，含空格要加引号）、`无需询问`。解压时若包名匹配掩码就**自动选中**该密码；"无需询问"关着则只作为默认值、用户仍可改 |
| 标签 | 可以用标签代替真密码（定义了 `home` 就可以输 `home`）；**标签只在密码对话框里有效，不影响命令行 `-p`**；标签大小写不敏感且必须唯一 |
| 自动完成 | 只在"显示密码"启用时工作；密码被隐藏则自动完成也禁用；有标签时只补标签不补密码 |
| 主密码 | 5.50 起可为密码管理器设主密码加密这些记录；**输入空主密码即取消加密**；主密码一次输入在关闭 WinRAR 前一直有效；输错则当普通密码处理 |
| ⚠ 安全 | 帮助**自己承认**："保存的密码被以**未加密格式的纯文本存储在注册表**中。这样所有能访问您的计算机的人都可以看到它们。……如果密码所保护的信息是敏感保密的，或者避免使用此功能，或者保护您的计算机免遭非法访问。" |
| 加密文件名 | RAR 专有：`-hp[密码]` / 界面"加密文件名"。**数据+文件名+大小+属性+注释全部加密，没密码连文件列表都看不了**。ZIP 不支持 |
| 算法 | RAR 5.0 = AES-256-CBC，密钥派生基于 HMAC-SHA256 的 PBKDF2；RAR 4.x = AES-128-CBC；ZIP 默认 AES-256，可切"ZIP 传统加密"兼容老工具 |
| 长度 | 密码最大 127 字符，超长**截断**（6.10 起截断会警告，之前静默截断） |
| 错误密码 | 6.02 起，**解压文件的名称会被包含进错误密码警告里** —— 对一个"内部文件用了不同密码"的非固实包，这很有帮助。5.60 起输错密码会**建议重输**而不是直接中止 |
| 固实/加密头限制 | 固实 RAR 和加密文件名的包，**整个包只能有一个密码**；非固实且未加密文件名的 RAR 和 ZIP 可以有不同密码 |

### 1.11 路径与安全

**非法/不兼容文件名（`-oni`）—— 默认就清洗，且清洗规则和我们几乎一样**：

- 默认行为：**删掉文件名结尾的空格和小数点**；对**已保留的设备名**（如 `aux`）
  **在开头插入下划线**。
- `-oni`（界面"允许潜在的不兼容名称"）才"按原样解压"，帮助明确警告"可能会带来兼容性
  甚至安全隐患"。
- 6.11 补了一个平台差异：Windows 11 会把 `aux.txt` 这类"带扩展名的保留名"当常规文件，
  所以这类名字**不需要**上面两个开关也能原样解出；但**不带扩展名的设备名仍然需要**。

**绝对路径 / `..` 的防护**：

- 默认拒绝：不主动按绝对路径落盘。
- 符号链接：`-ol` 把 NTFS 符号链接/分析点存成链接，解压时还原（**需要管理员权限**）；
  解压时**默认忽略**指向目标文件夹之外的链接、链接目标含绝对路径、或含**多余数量的 `..`**、
  或其它潜在危险的链接参数；`-ola` 才放开（"仅当您确认压缩文件内容是安全的（如您自己的备份）时"）。
  `-oh` 把硬链接存成链接；`-os` 保存 NTFS 数据流（不保存 NTFS 加密文件）。
- **安全公告类的演进**：`WhatsNew` 里记录了两次真实的严重问题 ——
  ① 第三方 UNACEV2.DLL 的漏洞"可以在解压缩 ACE 归档时在目标文件夹内部或外部的任意文件夹中
  创建文件"（触发点是路径穿越，之后 WinRAR 直接**去掉了 ACE 支持**）；
  ② 6.01 "我们已经阻止解压格式异常的压缩文件中的内容"；
  ③ 6.11 "已实施防止提取不安全链接的额外措施"。
  → **结论：这个领域的能力是"被漏洞推着长出来的"，不是一开始就设计好的。**

**名称编码**：`选项 / 名称编码`（Ctrl+E）可手选代码页；默认"默认"由 WinRAR 按系统语言和
格式知识自选；含 Unicode 名字且能可靠检测时**忽略手选值**；"保存当前"才持久化。
命令行等价 `-sc<字符集>[对象]`：`U`=UTF-16、`F`=UTF-8、`A`=本机单字节、`O`=OEM；
对象 `G`=错误日志、`L`=列表文件、`C`=命令文件、`R`=重定向/管道消息。

**长路径**：RAR/ZIP 一直支持长路径；**7z 归档的路径上限 5.80 起提到 2048 字符**
（之前限制在 260 左右）。

**`-dh`（打开共享的文件）**：允许处理被其它程序以写方式打开的文件。帮助自己标为
"**此参数是有危险性的**，因为它允许添加文件到压缩文件，而文件可能正由其它应用程序进行修改中"。

**`-w<路径>`（工作目录）**：为归档修改操作产生的临时文件指定目录。
另有"临时文件夹 / **仅用于可移动磁盘**"选项：在慢的外部磁盘上，先在硬盘建好临时文件再复制过去
可能更有效率。

### 1.12 注释、恢复记录、锁定、时间戳、文件属性

| 能力 | WinRAR 的做法 | 边界 |
|---|---|---|
| **归档注释** | `c` 命令添加（**上限 256 KB**）、`-z<文件>` 从文件读注释、`cw` 写出到文件；处理归档时显示；可在文件列表右侧显示注释窗口（宽度可拖） | 非 RAR 格式不一定支持；GUI 里还有一个"压缩文件注释"命令 |
| **恢复记录** | `-rr[N]`，RAR 5.0 用 Reed-Solomon，大小按**百分比**（不写默认 **3%**，最大 1000%）；RAR 4.x 按区块数（512 字节/块，最多 524288 块，≤256 MB） | 修复走两阶段：① 有恢复记录 → 产出 `fixed.arcname.rar`；② 只重建结构（校验失败的文件救不回）→ 产出 `rebuilt.arcname.rar`。**加密文件名的包只有存在恢复记录时才能修**；"修复"命令**不修恢复记录自身**的损坏块 |
| **锁定归档** | `k` 命令 / `-k`：锁定后 **WinRAR 无法修改**该归档；帮助明确"此命令不旨在或不能阻止其他工具或第三方有意进行修改。它仅针对 WinRAR 引起的意外数据变更实行安全措施" | 试图修改锁定归档 → **退出码 4** |
| **时间戳** | 默认只存/恢复**修改时间**（最高精度）；`-tsm/-tsc/-tsa` 分别管修改/创建(Unix ctime)/访问时间，`+` 最高精度、`1` 秒级、`-` 不保存；不写修饰符等于 `+`；`-tsp` 额外保留**源文件的原始访问时间**（"可以防止打开一些没有该参数也能打开的文件"） | 解压时 Windows 能设三种时间，Unix 只能设修改+访问。RAR 5.0 允许**完全不带时间**（产物用当前系统时间）；RAR 4.x 至少保留 2 秒精度的修改时间 |
| **文件属性** | `-ai` 忽略、`-ac` 清存档属性、`-ao` 只加带存档属性的文件、`-e[+]<属性>` 按属性掩码排除/包含（可用 `D/S/H/A/R` 符号代替数字掩码）、`-ow` 安全数据、`-oc` NTFS 压缩属性、`-os` NTFS 数据流、`-ol/-oh` 链接 | `-ow`/`-oc`/`-os`/`-oh` **只有 RAR 支持**；`-ao`/`-ac`/`-oi` 仅 Windows；`-oi`（把完全相同的文件存为引用）是压缩侧优化 |

### 1.13 命令行的 `x` 与 `e`：差别与坑（单列）

- **`x` = 带路径解压（保留目录结构）**；**`e` = 不带压缩路径解压（全部摊平到同一目录）**。
- `e` 的坑是**必然撞名**：包里 `a\readme.txt` 和 `b\readme.txt` 摊平后是同一个 `readme.txt`。
  所以 WinRAR 自己的 `e` 示例永远配着 `-or`（自动重命名）。**不配 `-or` 的 `e` 会静默丢文件**
  （后写的覆盖先写的，或按覆盖模式询问）。
- 帮助在 `e` 的描述里直接点明"如果您要解压完整路径名，请使用 `x` 命令"。
- 摊平的合法用途是**筛出来的少量文件**（`e -or *.css css\`），不是"整包解压"。
- 相关：`-ep`（排除路径）与 `e` 在解压侧效果相近；`-ep1`（排除主文件夹）是"只去掉一层"的
  温和版本 —— 这三者的层次感是 WinRAR 命令行设计里比较讲究的一处。

### 1.14 日志 / 报表 / 诊断

**三套互不兼任的东西**：

| 名称 | 开关 / 入口 | 内容与边界 |
|---|---|---|

### 1.16 其它值得知道的边界（不成体系，但真实）

- `--`：停止参数扫描（文件名以 `-` 开头时必须用）。
- `-@[+]`：`@` 开头的参数默认当"文件列表"，如果磁盘上真有个叫 `@home` 的文件就产生歧义；
  `-@` 让之后的参数都当文件名，`-@+` 都当列表。
- `-y`：所有询问都回答"是"（**批量脚本里最危险也最常用的一档**）。
- `-cfg-`：忽略默认配置和环境变量（排障用）。
- 命令限制：`d/u/f/c/cf` 不能用于分卷；`a` 不能更新分卷、只能新建。
- 卷数防护：GUI 里创建到 **500 个卷**会提示，让用户决定继续或停止
  （理由是"防止在错误输入卷大小的情况下创建数千个卷"）。
- 同名重复：`-as`（同步，删掉不在列表里的旧成员）、`-oi`（存为引用）等是压缩侧的事，
  与解压无关，此处只登记。
- 界面细节：常规设置里有"**任务栏进度条**"（Win7+ 在任务栏图标显示总进度）、
  "启用声音提示"、"显示压缩文件的注释"、"总在最上"、"重复使用现有窗口"、
  "在对话框中显示历史记录"（**明确提示"多用户环境下这样的功能会有安全问题"**）、
  以及"清除历史记录"命令。
- 5.80 改过一个细节：进度窗口里过长的文件名**以前从末尾截断，导致扩展名看不见；
  现在只删除中间的路径**（即"中间省略、保留首尾"）。

## 4. 明确不学的（6 条）

> 选取标准：**要么撞我们的非目标，要么撞不变量，要么是它自己都在警告的坑。**

1. **捆绑、默认依赖、自动探测安装、安装包、自更新**
   即 `AGENTS.md §2` 的"WinRAR 特指捆绑/默认依赖/自动探测安装这种适配不做"与"安装包 / 自动更新"。
   我们的位置是"用户自装、自选路径、只检测与调用"（§3.1）——
   **这个位置已经落地了**：`Engines/ToolLocator.cs` 会探测用户已装的 WinRAR 目录
   （`%ProgramFiles%\WinRAR\UnRAR.exe` 等），但**只取其中的免费件 `UnRAR.exe`**，
   绝不复制、绝不调用同目录的 `Rar.exe` / `WinRAR.exe`（共享软件，见 §5）。
   额外一层理由：WinRAR 的许可证**本身就禁止捆绑**（§5 第 6 条），
   所以"想捆也捆不了"—— 这条不是取舍，是硬边界。RAR 侧的第二引擎见 §6 更正记录第 2 条。

2. **资源管理器右键菜单 / "发送到"菜单 / 下载目录监控 / 任务模板 / 文件清单导出**
   `AGENTS.md §2` 的整条非目标，逐字对应 WinRAR 的"集成设置 / 关联菜单 / 配置文件进右键菜单 /
   生成报告"。理由：这些能力的共同点是"**把工具挂到系统上**"，
   而我们的定位是"打开它、丢一批包进去、拿到结果、关掉"；
   挂进系统还会引入注册表写入、卸载残留、多用户冲突等一整类问题（WinRAR 的
   "WinRAR.ini 重定向注册表 / Global\Integration=0" 就是这类问题的症状）。

3. **密码的持久化与"主密码"体系**
   即 `AGENTS.md §6 不变量 5`（密码只存内存）。WinRAR 的密码管理器 + 密码标签 + 主密码 +
   "配置文件中保存密码"是一整套成熟设计，但它的基石是**把密码明文存进注册表**，
   帮助里两次承认"所有能访问您计算机的人都可以看到它们"。
   我们保留的出口只有一个：用户**显式**导出密码列表时（`Models/PasswordItem.cs:14` 已写明）。

4. **一切"按原样落盘"的危险逃生舱**：`-oni`（不兼容名称）、`-ola`（越界符号链接）、
   `-ep3` / "解压绝对路径"（按原盘符落盘）。全部撞 `AGENTS.md §6 不变量 4`。
   理由不是"我们用不到"，而是"**一旦提供，用户为了解开一个包点了它，代价会转移到别的程序里**"：
   保留名和结尾空格会在资源管理器/播放器/脚本里出各种怪问题，而用户不会联想到是解压时点的那个勾。

5. **GUI 里的"额外命令行参数"输入框 / `rar.ini` 式的按命令默认参数**
   即 `AGENTS.md §2` 的"CLI 前端"非目标 + 规格 §6 不变量 6（选项只有一个来源）。
   理由：这类设计的本质是"**把 CLI 的表达力泄漏进 GUI**"，后果是"这次行为为什么不一样"
   在界面上无法回答。WinRAR 自己给它配了三重警告（"错误使用会干扰功能，甚至导致数据丢失"）。

6. **不可逆或"脏手法"的自动化**：`-vd`（建卷前清除磁盘内容）、`-dw`（用 0 字节覆盖再删文件）、
   启动时自动清理超龄临时文件、以及**挂起外部进程实现的"暂停"**。
   - 前两个：撞"不可逆操作"红线；`-dw` 它自己承认"可能无法覆盖固态磁盘上的原始文件数据"（SSD 磨损均衡），
     即**成本真实、收益不确定**。
   - 自动清理超龄临时文件：撞 `AGENTS.md §6 不变量 13`（清工作区必须先经用户确认）+
     规格 §2.2（失败/取消时暂存区**必须保留**供排查）。它自己都写着"如果不确认临时文件是否仍被
     外部应用程序使用着"就删 —— 也就是可能删掉正在用的东西。
   - "暂停"：只有挂起 7z 进程才能实现，会让管道/句柄半死、超时与取消语义混乱。
     我们有更好的替代：**取消当前（工作区保留）+ 稍后重跑** —— 语义干净、可测试、可收干净
     （不变量 10）。

### 6.1 ⚠ `-kb` 只对 UnRAR 加，7-Zip 没有这个开关（**原建议被实测推翻**）

- **原文建议**（§2 C 组，本文件早期版本）：*"加 `AppSettings.KeepBrokenFiles`（默认关）+
  `SevenZipProcessRunner.BuildExtractArguments:807` 里条件加 `-kb`"*。
- **实测结果**（2026-09-22，随包内置的 7-Zip **26.03**）：

  ```
  > 7z x -kb a.zip -o<目录>
  Command Line Error:
  Unknown switch:
  -kb
  （退出码 7 = 错误的命令行选项）
  ```

  → `-kb` 是 **RAR / UnRAR** 的开关（"保留受损的文件"），7-Zip 不认。
  按原建议接线的话，用户一打开这个设置，**每一次 7-Zip 解压都会失败**（而且是命令行错误，
  看起来像程序坏了）。
- **落地口径**：`AppSettings.KeepBrokenFiles`（默认关）+ 设置界面一行；
  参数侧只在 `UnRarProcessRunner.BuildExtractArguments` 里条件加 `-kb`，
  `SevenZipProcessRunner` **永远不加**。7-Zip 本来就保留校验失败的半成品，
  所以这一档对它是"无事可做"，不是"漏了"。
- **边界（未变）**：保留受损文件**只决定半成品留不留**，任务状态仍由退出码与错误分类决定，
  仍然是"失败 / 部分完成"，绝不显示成功（不变量 6）。回归测试：
  `保留受损文件默认关_只对RAR引擎加_kb` + `保留受损文件不影响成败判定`。
- **顺带更正本文一处措辞**：§1.4 里"解压前测试：WinRAR 没有这个开关"仍然成立；
  我们自己的 `TestBeforeExtract`（解压前跑 `7z t`）是**我们多出来的**能力，不是照抄它。

### 6.2 `ToolLocator` 不再"只认 7z"：第二引擎（RARLAB UnRAR）已内置并接线

- **原文写法**（§4 第 1 条、§5.3 补充第 1 条、§2 的几处"现状"）：*"`Engines/ToolLocator.cs`
  只认 7z，源码里没有任何 rar/unrar 探测"*、*"第一版连调用都还没做"*。
- **现在的事实**（2026-09-22 落地）：
  1. **已内置** `src/ArchiveFixer/tools/unrar/UnRAR.exe`（RARLAB 免费件，**7.23 稳定版**，
     SHA256 / 来源 / 许可摘录见 `src/ArchiveFixer/tools/unrar/README.md`；许可第 2 条明确允许随包分发）；
  2. **已实现** `Engines/WinRar/UnRarEngine`（`IArchiveEngine` 的 probe / list / test / extract），
     能力位**如实只登记 RAR**（zip / 7z / tar 一律声明不支持，交给 7-Zip）；
  3. **引擎优先级** `AppSettings.EnginePriority` 默认 `winrar → sevenzip`
     （用户 2026-09-22 指示："先是 winrar、7z、然后就是后面的引擎"）；
     规则是**先按能力筛、再用优先级做 tiebreaker**，不可用的引擎直接跳过；
  4. **UnRAR 来源顺序**：用户自选路径 → 用户已装的 WinRAR 目录 → 内置 `tools\unrar\`；
  5. **已接进真实流程**：`MainViewModel` 交给流水线的不再是裸的 `SevenZipEngine`，
     而是按格式与优先级分派的门面（`ViewModels/MainViewModel.cs` 的 `EngineRouter`）。
- **未变的两条硬边界**：⛔ `Rar.exe` / `WinRAR.exe`（共享软件）**绝不分发、绝不复制**，
  只允许"用户自装、我们检测与调用"；⛔ 只解压、绝不改包（许可第 4 条禁止用其重建 RAR 压缩算法）。
