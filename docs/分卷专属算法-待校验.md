## 0. 三条不可动摇的前提

1. **内容优先，改名在识别之后。** 任何一份文件的第一步永远是"内容读数"两个出口：
   - `Detection/VolumeContentInference.SniffFormat` —— 认格式（魔数，不信后缀）；
   - `Detection/VolumeNumberFromContent.Read` —— 读分卷身份/卷号（只读头尾若干字节）。
   名字只在内容给不出答案时才参与，且只参与"定序"这一件事。你新加那段里写的「改名绝对是放在底层识别后面」「底层识别要特别借助基名和大小，这是我们第二大步的基石」，落成代码就是这条顺序。
2. **判不出 ⇒ 什么都不做。** 不改名、不搬、不删（连"顺手的清洗"也不做）。所有族的兜底一律落在这里。
3. **名字类改动全成或全不成。** 只动卷标记那一段（基名、族、卷序、内容一个字节不动），绝不覆盖已存在的文件；干净的名字永远不许改成脏名字；失败要倒序改回原名。

## 3. 分类树：先判"这一份是什么"，再谈处理

```
这一份是什么？
├─ 内容认得出归档格式（7z / RAR / ZIP）且内容说自己是分卷成员或判不出
│   ├─ 名字自报第 1 卷（或内容首卷标志成立）→ 它是一组的"入口"
│   └─ 名字自报后续卷 / 判不出 → 它是"跟班卷"或"待定片"
├─ 内容认得出归档格式、但内容可证它是单卷（`NotVolumeMember`）
│   → 单一完整压缩包（第一大步的活）
├─ 内容认不出格式，但名字是"标准卷名形状"（如 `aaa.7z` 认不出）
│   → 跳过，留到第二大步（你文档案例 4）
└─ 内容认得出是"别族的分卷"（如 `444.zip` 里其实是 RAR 分卷）
    → 一个字节都不动，留到第二大步（你文档案例 5）
```

## 4. 第一大步：单一完整压缩包（你说的"底层都能识别，所以这一步不需要专属算法"）

### 4.1 名字被改坏的 6 种形态与处置

| # | 真机名字（30 份普查里的实例） | 内容读数 | 处置 |
|---|---|---|---|
| 1 | `打包111-W1-1.png`、`资源222-W0-0.pdf` | 媒体前缀 + 尾部归档（不是单一格式） | 走媒体前缀那两级兜底（§4.2） |
| 2 | `333-W1-0`、`111-W1-0`、`aaa-L2-976` | 无后缀，魔数认得出 | 基名 = 原样那串 ⇒ 直接补规范后缀 |
| 3 | `222-W0-0.r$0_ar`、`111-W1-0.7=_8z`、`打包111-W2-0.z中文ip` | 后缀段被改坏 | 基名 + 内容族 ⇒ 换成 `.rar` / `.7z` / `.zip` |
| 4 | `aaa.7z` 但内容认不出 | `Fail = NotAnArchive` | **跳过**，留第二大步（案例 4） |
| 5 | `444.zip` 但内容是 RAR 分卷 | 别族分卷 | **一个字节不动**，留第二大步（案例 5；这条已落地：`RenameService.cs:1210` 的两族并集闸门） |
| 6 | `111-L2.part1.r删除ar`、`222-W0-0.删除rar` | 认得出 + 名字里夹中文/删除字样 | 找基名 ⇒ 换标准名 ⇒ 再谈密码（案例 6） |

**这一步的判据全是"内容说了算"**：格式未知 ⇒ 不改（`ExtensionHelper` 与 `RenameService` 两处闸门）；末尾纯数字 ⇒ 那是卷号不许当后缀；分卷成员 ⇒ 交给第二大步。

### 4.2 媒体前缀伪装（`mp4/jpg/png` 在前、归档在后）

两级兜底，顺序不能调换：

1. **尾部 256 KB 找 EOCD** —— 快，覆盖"尾部就是 zip 结尾"的绝大多数；
2. **顺序扫，上限 512 MiB** —— 同时找 RAR/7z 魔数 + ZIP 的 EOCD 候选；ZIP 候选还要过"中央目录签名 + 局部文件头"两条位置校验；
3. 命中 ⇒ 按偏移抠出来（结果带偏移/长度/条目数）。

⚠ 必须写清的语义：**512 MiB 是"扫描窗口上限"，不是"文件必须小于 512 MB"**。超过这个窗口、尾部又不是 ZIP 结尾的包，今天抠不出来（会落到"判不出 ⇒ 什么都不做"）。你新加那段写「小于 512 MB 都没有问题」——按这个读法是对的，我按这个写进算法。

### 4.3 第一大步末尾的三种情况（你刚确认的口径）

| 情况 | 单包自己那一格 | 批末汇总 |
|---|---|---|
| 密码错误（候选试完仍打不开） | **失败**（单独标记） | 整批还有内容物 ⇒ 部分完成（橙）；整批一个内容物都没有 ⇒ 失败（红） |
| 损坏压缩包（引擎明说损坏，但救回一部分） | 日志必须写「压缩包损坏」；不完整内容物留下；要不要删那一层过程物看③页档位 | 部分完成（橙） |
| 顺利完成 | 成功 | 成功 |

唯一出口 `TaskOutcomeClassifier.FromProducedContent`（有内容物 ⇒ `PartiallyCompleted`，没有 ⇒ `Failed`），盘上那一半还要过 `ProducedContentGate`（`MinimumFiles = 2`，只留一个文件是"错密码签名"，不算解出了内容物）。

**第一大步不许整批停**：单个包失败只影响它自己那一行，其他单、以及第二大步照常往前。这一条和现在代码一致（缺卷那几单在批首只记缺口、等这一批跑完再补判）。

## 5. 第二大步：分卷专属

- 入口层 = 「对哪个包输入密码，就在哪个地方设工作区」那一层 ⇒ 第一件事是**认出入口那一份**（名字自报第 1 卷 / 内容首卷标志）。
- 顺序恒为：**内容识别 → 名字识别 → 定槽位 → 规范改名 → 交给引擎试开**。⛔ 反过来（先改名再看）会出现"按它说的改完还是解不开"。
- 三族共用三条闸门（缺一不可，全部通过才允许定序/改名）：
  1. **同组**：基名逐字相同 + 族相同（唯一出口 `VolumeGroupDetector.Group` / `BelongsToSameGroup`）；
  2. **卷号一份对一份**：同一卷号上冒出两份候选 ⇒ 整档不做；
  3. **整组自洽**：连成 1..N 无洞 + 尺寸规律（除末卷外等大）+ （7z）字节数守恒。
- 只有"可证完整"才允许搬走或删源包（`RestVolumeCompletenessGate` / 六道门槛）。

## 6. 各族专属算法

### 6.1 7z 分卷（`基名.7z.001`…`基名.7z.00N`）

**内容给什么**：只有第 1 片认得出（魔数 + 起始头自述整包字节数 + 片数）；中间/后续片是裸字节流，一个字段都没有。

**算法**：

1. **认第 1 片**：`SniffFormat = SevenZip` 且起始头读得出 ⇒ 它是入口。（真机实例：`222-L2.%%%%%7z`，71,300,398 B —— 后缀段整个烂掉、名字里没有卷号，内容照样认得出。）
2. **算片数 A**：`A = ceil(自述整包字节数 ÷ 这一片的字节数)`。⚠ 这是旁证，不是权威（见第 3 步）。
3. **字节数守恒（权威）**：`手上这几片的字节数之和 == 自述整包字节数` ⇒ 这一组齐了、槽位也定得下来；`和 < 自述值` 且**洞只有一个**且**恰好一份候选的字节数等于差额** ⇒ 那一份就是那个洞。真机实例 `10101010`：`.001` 卡 = `DeclaredTotal=62919013 / DeclaredVolumeCount=3`，而 26214400 + 26214400 + 10490213 = 62919013，逐字吻合（已落地：`VolumeNameRepair` 的「唯一填平」档，今天只对 7z 开）。
4. **定末卷**：除末卷外都是满片 ⇒ 末卷**不比满片大**。⚠ 不写成"末卷最小"当唯一权威：整包恰好等于满片 × N 时末卷也等于满片，大小分不出谁在后 ⇒ **此时不做决定**。真机实例：`111-L2.7z.00_!63`(10,478,484) 明显小于 25 MiB 满片 ⇒ 它极可能是末卷。
5. **定中间片**：`A - 2` 片，全部是满片（真机满片 = 26,214,400 = 25 MiB 整）。
6. **规范名**：`BuildStandardNames(stem, SevenZipNumbered, A)` ⇒ `基名.7z.001`…`基名.7z.00A`；基名走唯一出口（`222-L2.%%%%%7z` 的基名是 `222-L2`，`%%%%%` 属于后缀段）。
7. **兜底**：守恒对不上、或洞不唯一、或尺寸规律不成立 ⇒ 整档不做（一个字节都不改）。

**缺口**：多个洞（缺 2 片以上）时今天什么都不做；你新加那段要求再加一档「后缀相似匹配 + 高概率猜测（缺什么补什么）」——我建议写成"**只补一个洞 + 补完必须连成 1..N 且守恒成立**"，多洞仍然不做（原因见 §7）。

### 6.2 RAR5（`基名.partN.rar`）

**内容给什么**：主头 `MHFL_VOLUME 0x0001` ⇒ 是成员（没置位 ⇒ 可证不是成员）；卷号是**绝对**的（字段值 + 1；第 1 卷没有该字段 ⇒ 1）。

**算法**：内容读卷号 ⇒ 按卷号排 ⇒ 连成 1..N 即完整；缺号即缺卷、如实报缺哪几号。**不需要后缀相似匹配**（卷号是硬证据）。真机实例：`111-L2.part1.r删除ar`(26,214,400) / `aaa-L2.part0788839中文1.rar`(26,214,400) —— 名字里的数字都不标准，内容照样给得出卷号。

**缺口**：无（这是七族里最省事的一族）。

### 6.3 RAR 1.5–4.x 新编号族（RAR4，主头带 `MHD_NEWNUMBERING`）

**内容给什么**：成员身份能证；**卷号只有卷尾归档结尾块里的原始字段**，基数（0 起还是 1 起）文档没写 ⇒ 卡上 `Number` 为空、`RawVolumeField` 有值；首卷标志 = 主头 `MHD_FIRSTVOLUME 0x0100`。

今天在真机样本 `4444` 上的实测（探针逐字，三份都在窗口里）：

```
[片] bbb-L2.part1.rar | IsMember=True | Number=null | Fmt=Rar
[片] bbb-L2.txt       | IsMember=True | Number=null | Fmt=Rar
[片] bbb-L2.jpg       | IsMember=True | Number=null | Fmt=Rar
```

⇒ 结论：**光靠 `Number` 永远修不了 RAR4**，必须用 `RawVolumeField`。

**算法（含「新增」一档，用已有字段，不写新解析器）**：

1. **认入口**：主头 `MHD_FIRSTVOLUME` 置位的**那一份**就是第 1 卷 —— 由内容给出，不靠名字（这一点对你那份样本是关键：`aaa-L2.part0788839中文1.rar` 里的那个 `1` 埋在 8 位随机数后面，纯名字算法会翻车）。名字只能当旁证。
2. **锚定基数**：第 1 卷的 `RawVolumeField = raw₁` ⇒ `基数 = raw₁ − 1` ⇒ 其余片 `绝对卷号 = RawVolumeField − 基数`。
   ⚠ 闸门（四条全过才采信）：① 同基名 + 同族；② 各片 `RawVolumeField` 互不相同；③ 换算结果全部 ≥ 1；④ 换算结果连成 1..N 且**洞的个数唯一可判**（缺 1 片可判，缺 2 片以上不做）。任何一条不成立 ⇒ 判不出 ⇒ 什么都不做（这正是既有 `GroupBaseAmbiguous` 那一档的口径）。
3. **末卷**：`MHD_FIRSTVOLUME` 未置位且**没有"还有下一卷"标记**的那一份 = 末卷；配合"末卷不比满片大"复核。
4. **定中间片**：满片 + 卷号顺序。
5. **规范名**：`BuildStandardNames(stem, RarPart, N)` ⇒ `基名.part1.rar`…；补零宽度按 N 的位数（10 卷以上才补零）。
6. **兜底**：raw 字段读不出 / 基数两解都成立 / 洞不唯一 ⇒ **整档不做**；此时**不改名**，让引擎按原话报"缺卷"。

**现状**：`GroupBaseAmbiguous`（基数两解）与 `RarFirstVolumeMismatch`（首卷标志与推出来的卷号打架）两档检测已经在代码里（`VolumeNumberFromContent.cs:68`、`:980`、`:995`）。
**缺口**：`Number` 为空时，**目前没有把 `RawVolumeField` 换算成绝对卷号的那一步**（今天 4444 就是死在这里：三片都进了窗口、都判出是成员，却没有号 ⇒ 池子里只剩入口一片 ⇒ 期望基名推不出来 ⇒ 整档不做）。

### 6.4 RAR 1.5–4.x 老编号族（`基名.rar` + `基名.r00`、`.r01`…）

**内容给什么**：能证成员；卷号读不出（`Fail = RarOldNumbering`）。

**现状口径（不猜）**：本程序只认 `partN.rar` 这一族，遇到老编号族**直接判"卷号读不出"**，什么都不做。
**你新加那段要求**：RAR4 新老都走「去中文 + 后缀相似匹配 + 高概率猜测」。⇒ 这是**口径变更**，需要你点头，理由：
- 老编号族的"卷序"在名字里是 `.rar` = 第 1 卷、`.r00` = 第 2 卷、`.r01` = 第 3 卷（**不是**数字直接对应），所以它天生没有"数字卷号"可匹配，只能靠这套约定 + 顺序推；
- 本机 30 份真机样本里**一份老编号族都没有**（我普查过，见 §8），改了也无法用真样本验收，只能用合成夹具。

⇒ 我的建议：**这条先不做**，写成"识别得出、如实报'老式编号族，本程序不猜'"，等真机出现样本再做（否则就是拿没样本的算法去动不可逆路径）。

### 6.5 跨盘 ZIP（`基名.z01`…`基名.z0N` + 末片 `基名.zip`）

**内容给什么**：末片（含 `X.zip` 与 `.zip.00N` 的末片）EOCD 盘号 ⇒ `总片数 = 盘号 + 1`；头不一定是 PK（从数据中间切开）⇒ 靠 EOCD 判；**中间片**没有 EOCD，只能靠消去法定位。

**算法**：

1. **认末片**：EOCD 盘号 > 0 ⇒ 跨盘成员；盘号 + 1 = 总片数 B。两个盘号都是 0 ⇒ 可证是单盘 zip（不是这一族）。
2. **认中间片**：头是四种 PK 签名之一 + 名字自报 `.z0N`；`B` 已知 ⇒ 中间片只能取 `1..B-1`，**一份对一个**。
3. **第 1 片是 `.z01`，不是 `.zip`**（`.zip` 是末片）—— 这条要写死在算法里，本项目在这个反向上踩过坑。
4. **端到端核对**：认出来的片数 == B，且盘号唯一 ⇒ 定序完成；数量对不上 ⇒ 判不出（`ZipPartsMissing`）。
5. **规范名**：`BuildStandardNames(stem, ZipSpanned, B)` ⇒ `基名.z01`…+ `基名.zip`。
6. **兜底**：片数 ≥ 3 且中间片顺序定不下来 ⇒ 不做。

**真机实例**：`111-L2.00000z01`(26,214,400) / `111-L2.z4056075366中文02`(26,214,400) / `222-W2-0.中文zip`(10,479,398) / `111-W1-0.z删除ip`；`23232323` 那一组实测 26,214,400 + 26,214,400 + 10,490,420 ⇒ 末片确实更小，但**权威是盘号**，大小只是旁证。

**缺口**：`ZipTooManyDisks`（≥3 片时中间片定不下来，`VolumeNumberFromContent.cs:74`）——你新加那段要求把它补上（用基名 + 大小 + 后缀相似匹配定中间片）。这条我按 §7 的共用规则写。

### 6.6 ZIP 通用分片（`.zip.001` 这一族）

**定义（用户 2026-10-16 拍板 = A）：对归档再分片** —— `X.zip.001 + X.zip.002 + …` 是**同一个 zip 的连续字节段**，
拼回去必须是一份合法 zip，EOCD 落在最后一片的尾部。真机实例：`111-L2.zip.0@@@@@@01`、`222-L2.zip.00%$3`、
`资源222-L2.zip.--p002`、`资源222-L2.zip.00删除3`。

**内容给什么（恰好 3 片时可以纯内容定序）**：

| 位置 | 内容事实（`VolumeNumberFromContent.Read` / `FileNatureCard`） |
|---|---|
| 第 1 片 | 开头是本地文件头 `PK\x03\x04`；⚠ WinRAR/网盘那种跨盘器还常在偏移 0 先写 4 字节**跨盘标记** `PK\x07\x08`，本地头跟在它后面（`HasZipLocalHeader` 今天只认偏移 0 ⇒ 这一档要按"跨盘标记 + 本地头"两个事实一起认） |
| 中间片 | 裸字节流（从数据中间切开）⇒ 既没有 EOCD、也没有本地头 ⇒ 内容只能给"它不是首片也不是末片" |
| 末片 | 尾部有 EOCD，且 **中央目录偏移 ≥ 本文件长度** ⇒ 中央目录起在更早的片里 ⇒ `ZipEndRecordMeansSplit = true` |

⇒ 恰好 3 片时：EOCD 那片 = 3、本地头那片 = 1、剩下那片 = 2（唯一，⛔ 不猜）。多于 3 片 ⇒ 中间片顺序内容判不出，
不补（交给"槽位 + 尺寸规律"那两道闸门）。

**命名族分水岭（2026-10-18 运行期定案，唯一出口 `VolumePiecesFromCards.ResolveNamingFamily`）**：
`ZipEndRecordMeansSplit` 只说明"中央目录起在这一份之前"，**两族都成立**，⛔ 不能拿它单独判"通用分片"。
真正分开两族的是**带 EOCD 那一片自己的盘号（`Membership`）**：

- 通用分片：单盘 zip 被字节切开 ⇒ EOCD 盘号 **0/0** ⇒ `Membership != VolumeMember` ⇒ `ZipNumbered` ⇒ 规范名 `X.zip.001…`；
- 跨盘 ZIP：归档器写的多盘 zip ⇒ EOCD 盘号 **> 0** ⇒ `Membership == VolumeMember` ⇒ `ZipSpanned` ⇒ 规范名 `X.z01…X.zip`。

**真机事故（`15151515` 组合 6 —— 这一条就是为它写的）**：旧代码把"层里有 `ZipEndRecordMeansSplit`"直接归纳成
`ZipNumbered`（`ExtractionCoordinator` 里自己写了一份族判定，与检测层两套并行）⇒ 打分分配把第 1 片补成
`aaa-L2.zip.002`；而这一组真名是 `aaa-L2.z01/.z02/.zip` ⇒ 引擎按数字分片找不到 `.z01` ⇒ ① ② 双红。
改后同一现场补成 `aaa-L2.z01`，再解开 `content-60mb.bin`（62,914,560 字节）。**同一现场的第二处冲突**：
扫描"同一份物理文件两条名字只算一个内层包"原来留**先出现的**那条 ⇒ 留下脏名 `aaa-L2.z00000000ip`、
把规范名 `aaa-L2.zip` 当重复跳掉 ⇒ 第二轮拿脏名开组 ⇒ 同样红。⇒ 去重规则补一条：
**两条名字里优先留"内容卡自证的规范名"那条**（`CanonicalVolumeName` 与文件名逐字相同；判不出 ⇒ 照旧留先出现的，
⛔ 不比名字长短/干净程度的观感）。

### 6.7 统一算法（额外引擎 / 未知族）

**你的原话**：「这个一般是应用到额外引擎上面的，我们也不能落下」。
**我的建议写法**：不是第五套判据，而是把第 6.1–6.6 的**证据来源做成可插拔**：一族 = 「成员判据 + 卷号来源 + 片数来源」三件套；新引擎（或没有魔数的族）只要能提供这三件里的任意几件，就复用同一套"闸门 + 定槽位 + 规范名 + 全成或全不成"的执行层。⇒ 请确认这是你要的意思。

### 6.8 内容与名字的合流（唯一判据出口，2026-10-18）

> 用户口径：「底层识别永远是重中之重，名字的修改只是来辅助底层识别的，这两条路要合成一条。」

一条判据只回答一个问题，每个问题只有一个出口：

| 问题 | 唯一出口 | 内容先说 | 名字只在什么时候说话 |
|---|---|---|---|
| 这一份是什么格式 | `FileNature.Inspect`（`VolumeContentInference.SniffFormat`） | 魔数 / EOCD / 起始头 | 永不（后缀不参与） |
| 它是不是分卷组的一员 | `FileNatureCard.Membership`（`ClassifyMembership`） | RAR Volume 位 / 跨盘 ZIP 盘号 / 7z 只能"判不出" | 判不出时才由名字的卷标记兜底 |
| 它是不是这一组的第一片 | `BodyKind` + `Membership` | 7z 起始头自述、RAR5 卷号=1、RAR4 首卷标志、跨盘 ZIP 跨盘标记 | 判不出才看名字"第 1 卷" |
| 这一组是哪一族 | `VolumePiecesFromCards.ResolveNamingFamily` | 带 EOCD 那一片的盘号（`Membership`） | 内容判不出才按名字样本 |
| 这一片是第几槽 | `VolumePieceFacts.ResolveSlotIndex` | 内容卷号 / 首片标志 | 内容给不出才用名字卷号 |
| 这一槽叫什么规范名 | `VolumePieceFacts.ResolveCanonicalName` + `BuildStandardNames` | 族 + 槽位 | 族判不出才照名字样本拼 |
| 同一份字节两条名字留哪条 | `OneClickCoordinator.IsContentCanonicalName` | 卡的 `CanonicalVolumeName` 与文件名逐字相同者优先 | 判不出 ⇒ 留先出现的 |

**四条硬纪律**：

1. **内容一旦给出正面证据，名字那一格全部作废**（`ContentProvesNotAVolumePiece`：单盘 ZIP 名字里的 `.932` 不是卷号）。
2. **内容"判不出" ≠ "可证不是"** —— 判不出才轮到名字，⛔ 不许把判不出当否证（7z 中间片、跨盘 ZIP 中间片都在这一档）。
3. **同一个事实不许两处各判一遍**：命名族只许走 `ResolveNamingFamily`；槽位只许走 `ResolveSlotIndex`。
   2026-10-18 的回归就是 `ExtractionCoordinator` 自己写了一份"只看 `ZipEndRecordMeansSplit`"的族判定 ⇒ 与检测层冲突。
4. **可证完整才动手**：改名 / 搬 / 删仍只由既有的"全成或全不成"与六道门槛执行；判据层只输出结论与证据，不做动作。

## 7. 全族共用的四条硬约束（写进算法的护栏）

1. **「去中文字符」只清洗卷标记/后缀那一段，⛔ 不许整名去中文。** 真机反例（我普查到的）：`111-W0-0.中文zip`、`资源222-L2.zip.--p002`、`打包111-W2-0.@@@@@@@7z` —— 基名里的中文是真基名，整名去中文会把基名改错。
2. **「高概率猜测（缺什么补什么）」最多补一个洞**，且补完必须连成 1..N、并通过本族的守恒/自洽闸门；多洞 ⇒ 谁先谁后判不出 ⇒ 整档不做。
3. **「末卷最小」= 末卷不比满片大**，恰好全等时不做决定（不做决定 ≠ 失败，就是"这一档不做"）。
4. **改名在识别之后、且全成或全不成**：目标名被占 ⇒ 整组不动；中途失败倒序改回原名；改完同步全表任务路径 + 快照。
