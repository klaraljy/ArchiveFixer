# 重构方案：源根到最终内容

> 状态：已实施并验收。
> 基线：`8742d2e`（备份标签 `backup-before-content-graph-20261102`）。
> 约束：先改完一个阶段再验证；不以任务级“解压成功”代替最终内容成功；禁止盘根兜底、提前删候选片、按样本名打补丁。

## 1. 要解决的问题

当前程序把“一个源文件 = 一个任务 = 一个最终结果”作为隐含前提，导致四个真实错误：

1. 一个内容组由多个源根共同产出时，组内每个根任务各自判成功、各自删源，最终内容却只落在其中一个根目录。
2. 包装包解出的内层分卷片被当成“过程物”提前回收，交界处只看到残余片，组被判缺片。
3. 任务级 `OutputPath` 被续解任务复用/分裂，出现空输出目录、重复输出路径和 `(1)` 目录。
4. 工作区在找不到合法落点时回落到盘根，产生 `E:\.ArchiveFixer.work`、`H:\.ArchiveFixer.work`。

这些错误的共同原因不是某个判断写错，而是缺少“源根 → 产出物 → 内容组 → 最终内容”的归属关系。

## 2. 目标模型

### 2.1 SourceRoot

与现有 `ArchiveTask` 一一对应，只表示“用户导入的一份源包/源片”。

新增或派生：

```text
RootTaskId
PlacementKey
SourceSelectionRoot / SourceSelectionKind
SourceHandling
```

`PlacementKey` 在导入时确定：

- 未指定位置：选中文件夹根；选中文件时用其父目录；
- 指定位置：用户指定根。

组内成员必须共享 `PlacementKey`。跨 `PlacementKey` 不做自动合并，落为冲突。

### 2.2 ProducedArtifact

第一层及后续层解出的每个文件都登记，不再依赖“任务收尾时看目录”。

```text
Path
FileIdentity
BaseName / VolumeNumber
ProducedByTaskId
OriginRootId
ArtifactRole
CandidateLease
```

`ArtifactRole`：

```text
CandidateVolumePiece  可能是分卷的片，交界前不得删
InnerArchive          普通内层归档
ProcessArtifact       已确认的过程物
Content               最终内容候选
```

`CandidateLease` 在交界前保护候选片：逐层回收、失败清理、临时目录清理都不得删除被租用的片。

### 2.3 ContentGroup

交界屏障之后建立，键为：

```text
PlacementKey + 第二大步基名 + 族/卷事实
```

字段：

```text
PlacementKey
BaseName / Family
MemberArtifacts
SourceRootIds
EntryArtifact
WorkspaceRoot
EntryRoot
State
MemberEvidence
FinalOutputRoot
FinalOutputs
```

状态：

```text
Resolving   已有候选，仍可能来片
Complete    成员齐、入口确定
Missing     有明确缺号/缺片
Unknown     证据不足，不猜
```

### 2.4 FinalContentOutput

只有真正产出内容物才建立：

```text
OutputPath
IsFinal
VerificationEvidence
FileCount / TotalBytes / Hash
OwningGroupId
```

`VerificationEvidence` 沿用现有 `OutputVerifier`、清单交叉校验和检验等级，不允许只用“目录非空”。

## 3. 生命周期

### 3.1 导入

```text
FileScanService 一文件一任务
→ 每个任务生成 SourceRoot
→ 记录 PlacementKey / SourceHandling
→ 不预分组
```

保持现有硬链接输入按 `FileIdentity` 去重。

### 3.2 第一大步

```text
每个根任务解第一层
→ 每个产出文件登记 ProducedArtifact
→ 可能是分卷的片立即加 CandidateLease
→ 根任务不得在这一步宣布最终成功
```

内层片仍可继续递归，但回收逻辑必须先看租约；没有租约才允许按现有过程物规则处理。

### 3.3 交界屏障

这是唯一交界入口：

```text
本批第一大步全部结束
→ 所有 ProducedArtifact 注入 FirstStepFileLedger
→ 按 PlacementKey + 基名归组
→ 生成 ContentGroup
→ 只对 Complete 组建第二大步入口
```

`FirstStepFileLedger` 继续作为唯一候选来源，不另建平行判据。账本项增加：

```text
OriginRootId
ProducedByTaskId
ArtifactRole
CandidateLease
PlacementKey
```

`VolumeBoundaryPipeline` 只在屏障之后调用。缺片/Unknown 组保留全部候选，不建入口、不删源。

### 3.4 第二大步

```text
Complete 组：
  在 ContentGroup.EntryRoot 建标准名入口
  只解一层
  产出登记为下一层 ProducedArtifact
Missing/Unknown：
  保留片
  记录缺什么
  不发布
```

### 3.5 最终内容判决

新增 `ContentGroupFinalizer`，由组统一判：

```text
组是否有最终内容
最终内容是否通过现有校验
证据等级是什么
```

结果：

```text
FinalContentVerified
FinalContentPartial
FinalContentUnknown
```

只有 `FinalContentVerified` 才：

- 回写所有贡献 `SourceRoot` 为最终成功；
- 允许按档处理该组源包；
- 计入批末最终成功。

### 3.6 源包删除

删除依据从“逐 rootTask 检查 OutputPath”改为“按 Complete 组检查最终内容”。

删除前检查：

- 该组是否 `FinalContentVerified`；
- 该源根是否还被其他未完成组引用；
- 是否仍有 `CandidateLease` 未释放；
- `SourceHandling` 是否允许删除；
- 删除路径是否在受保护路径之外。

`SourcePackageMove` 保留为显示/兼容字段，不再作为唯一决策依据。

## 4. 工作区和输出

### 4.1 工作区

唯一来源：

```text
ContentGroup.WorkspaceRoot\.ArchiveFixer.work
```

`WorkspaceRoot` 由 `PlacementKey` 决定。禁止：

```text
Path.GetPathRoot(sourcePath)
程序目录
%TEMP%
源卷根
```

`VolumeGroupEntryDirectory` 不再提供盘根兜底；拿不到合法根就返回失败，组落 Unknown，不建目录、不删源。

### 4.2 输出

一个内容组只有一个最终输出根：

```text
ContentGroup.FinalOutputRoot
```

过程任务只写：

```text
FinalOutputRoot\.ArchiveFixer.work\...
```

最终内容才进入 `FinalOutputRoot`。同名冲突在组层做一次稳定改名，不在每个任务上产生 `(1)`。

## 5. 列表和汇总

`ArchiveTask.Outcome` 只表示任务层执行结果，不再表示最终交付结果。

新增显示字段：

```text
UnitId
UnitRole：SourceRoot / ProcessTask / FinalTask
UnitState：Resolving / ProcessOnly / FinalVerified / Failed
FinalContentPath
```

规则：

- 只有 `FinalVerified` 显示最终成功；
- 过程任务显示“已并入组/过程任务”；
- 空最终内容不得显示成功；
- 同一组不重复显示多个最终成功；
- 批末按 `ContentGroup` 统计，不按 `ArchiveTask` 统计；
- 日志同时打印组成员、来源根、证据等级。

## 6. 特定解压

保持独立：

```text
SpecificBatchUnitBuilder
SpecificExtractionRunner
最多 3 层
标准名分卷 + 简单中文后缀
输出根 = 压缩包父目录
```

不接入普通 `ContentGroup` / `VolumeBoundaryPipeline` 的执行逻辑，只接统一显示和最终内容状态。

## 7. 分阶段实施与验收

每个阶段必须自身闭环：代码、定向测试、构建 0 错 0 警、格式通过，才允许进入下一阶段。阶段未闭环不得切换问题、不得开下一阶段。

### 阶段 1：账本与源根

改动：

- `FirstStepFileLedgerEntry` 增加源根、产出任务、角色、租约、PlacementKey；
- `FirstStepFileLedger` 增加按源根/租约查询；
- 导入时登记 `SourceRoot`；
- 不改删除、不改输出、不改 UI。

验收：

- 现有账本测试全绿；
- 同一物理文件多路径仍只算一份；
- 未登记的产出不会进入第二大步；
- 新增测试覆盖源根→账本项归属。

### 阶段 2：候选产出登记与租约

改动：

- 第一大步及递归层产出登记为 `ProducedArtifact`；
- 候选分卷片加 `CandidateLease`；
- 逐层回收、失败清理、工作区清理尊重租约；
- 交界前不删被租用片。

验收：

- 包装包解出的内层片在交界前仍存在；
- `aaa-L4` 类样本能看到全部片，而不是只剩 2 片；
- 普通内容物不会被误标为候选；
- 定向测试覆盖“内层片被回收”回归。

### 阶段 3：交界屏障与内容组

改动：

- 第一大步结束后统一把产出注入账本并归组；
- 组键包含 `PlacementKey`；
- `VolumeBoundaryPipeline` 只在屏障后调用；
- 缺片/Unknown 保留候选。

验收：

- 一个组由多个源根贡献时只生成一个 `ContentGroup`；
- 包装包外层名不会覆盖内层基名；
- 缺片组不建入口、不删源；
- 新增“多源根同组”和“包装包内层片”测试。

### 阶段 4：最终内容判决

- 回写 `SourceRoot` 最终状态；

## 8. 禁止事项

- 不在导入时预建内容组；
- 不用 `VolumeHandoffEntries`、`extraGroupSeeds` 等旁路替代账本；
- 不按样本名、目录名、特定文件名加分支；
- 不用“目录非空”代替最终内容校验；
- 不在未最终验证时删除源包；
- 不提前删除带租约的候选片；
- 不用盘根、程序目录、`%TEMP%` 兜底工作区；
- 不把特定解压并入普通组执行管线；
- 不用全量测试代替阶段定向验证，也不在阶段未闭环时切换目标。
