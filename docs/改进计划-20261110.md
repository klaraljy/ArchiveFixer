## WP1 目录枚举：`Directory.GetFiles` → `EnumerateFiles`

### 现状（14 处，逐条）

| 文件:行 | 调用 | 风险 |
|---|---|---|
| `VolumeSlotFillStep.cs:388` | `GetFiles(root, "*", AllDirectories)` | **高**：递归全量，目录大时一次性分配 |
| `VolumeSlotFillStep.cs:828` | `GetFiles(scanRoot, "*", AllDirectories)` | **高**：同上 |
| `RestVolumeCompletenessGate.cs:465` | `GetFiles(directory, "*", AllDirectories)` | **高** |
| `ExtractionCoordinator.RecursionOutcomeStep.cs:360` | `GetFiles(...AllDirectories).Length == 0` | **高**：只为判空却枚举全部 |
| `VolumeContentInference.cs:763` | `GetFiles(directory, "*", TopDirectoryOnly)` | 中 |
| `VolumeNameRepair.cs:196` | `GetFiles(directory, "*", TopDirectoryOnly)` | 中 |
| `VolumeNameRepair.cs:3384` | `GetFiles(directory)` | 中 |
| `RestVolumeCompletenessGate.cs:441` | `GetFiles(directory)` | 中 |
| `ExtractionCoordinator.VolumeHandoffStep.cs:465` | `GetFiles(directory, "*", TopDirectoryOnly)` | 中 |
| `ExtractionCoordinator.VolumeGatherCollectStep.cs:664` | `GetFiles(directory)` | 中 |
| `ExtractionWorkspace.cs:865` | `GetFiles(sourceDirectory)` | 中 |
| `RecursiveExtractor.cs:4916` | `GetFiles(directory!)` | 中 |
| `SidecarPasswordReader.cs:402` | `foreach (GetFiles(directory))` | 低 |
| `MaintenanceCleanupService.cs:934` | `AddRange(GetFiles(directory)...)` | 低 |

### 改法

```text
只为判空        → EnumerateFiles(...).Any()（不进数组）
只遍历一次      → foreach (EnumerateFiles(...))
需要快照/排序    → EnumerateFiles(...).ToArray()（语义不变，但明确写出物化）
含 AllDirectories → 优先改成"边枚举边判"，避免整棵树进内存
```

### 风险与验证

- 风险：低。唯一语义差异是"枚举期间目录变化"——现有代码都在快照语义下工作，改成物化/边枚举需要逐个看调用点。
- 验证：`VolumeGroup` / `VolumeNameRepair` / `RestVolume` / `RecursionOutcome` 相关定向测试；改动 4 处 AllDirectories 时再加一次 `--no-incremental` 构建。

```text

SpecialExtractionPipelineTests:224  UiBindingReachabilityTests:281

```

问题：夹具/前置条件不在时直接 `return`，xUnit 记成 **passed**。"跳过"和"真的验过"在报表上无法区分。

### 改法（先确认能力，再动）

1. 查 `xunit` 版本是否支持运行时跳过（v3 的 `Assert.Skip`；v2 没有）。
2. **能真跳过** → 统一走 `FixtureGate.Require(path)`，缺失时走跳过通道。
3. **不能真跳过** → 统一走 `FixtureGate.Require(path)`，缺失时：
   - 用 `ITestOutputHelper` 打一条 `SKIPPED: 夹具缺失 …`；
   - 跑批脚本统计 `SKIPPED` 条数，汇报里单列，**不许混进通过数**。

### 风险与验证

- 风险：低（不碰断言，只碰"前置条件缺失时的出口"）。
- 验证：把夹具临时改名，确认对应用例产出 `SKIPPED` 而不是 passed；恢复后全绿。

## WP3 `FileOperations.cs:47` 删除重试里的 `Thread.Sleep(100)`

### 现状

```csharp
for (int attempt = 0; attempt < 3; attempt++)
{
    try { ClearReadOnlyAttributes(extended); Directory.Delete(extended, true); return true; }
    catch (Exception ex) { last = ex; Thread.Sleep(100); }
}
```

最坏 300ms 阻塞。**先确认它在哪个线程上跑**（这条不许猜）。

### 改法

```text
在 UI 线程   → 改 async + Task.Delay(100, ct)，失败重试逻辑不变
在后台线程   → 保留 sync 形态，但把 sleep 换成可取消等待，避免取消后还要白等 300ms
```

### 风险与验证

- 取证手段：调试器断点停在 `catch` 里，看 `Thread.CurrentThread.ManagedThreadId` 与是否有 SynchronizationContext。
- 验证：删除失败注入（只读文件/占用文件）复现重试；取消场景确认能提前退出。
