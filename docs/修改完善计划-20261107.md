# ArchiveFixer 修改完善计划（2026-11-07）

> 基线：`97d592e Record final UX verification count`  
> 现有体验计划：`docs/UX完善计划.md`  
> 状态：阶段1（记忆兼容）已落地；阶段2 已做底栏进度/高对比度补充；阶段3/4 待做  
> 原则：先保护用户记忆，再修行为和功能；不做视觉大改；不可逆路径先取证。

## 1. 本轮目标

把目前散落在 UI、记忆、分卷、加密、安装里的问题收成一条可执行顺序，避免“今天修窗口、明天修记忆、后天又回退”。

优先级只按三条：

1. **会丢用户数据/隐私的**：记忆格式、迁移、密码本、旧目录。
2. **会让用户以为程序坏了/没反应的**：窗口、托盘、反馈、核心功能失败。
3. **只在发布前才需要的**：安装包、签名、更新、许可证。

## 2. 已确认口径（不再反复问）

- 发布物：**self-contained setup.exe**，自带 .NET 运行时，不做便携版。
- 覆盖安装：主程序、`tools\`、`docs\` 整体按新版覆盖，旧版不再发布的引擎文件清理；
  `%LOCALAPPDATA%\ArchiveFixer` 与旧 `data\` 不动。
- 更新：只发 GitHub Release，用户手动下载 setup.exe 覆盖；**不做内置联网更新**。
- 暗色主题：**不做**。
- 视觉：当前 UI 不再大改，只修行为/反馈/可访问性。
- 无障碍：**键盘 + 高对比度 + 主要控件 Narrator 基本可读**，不追求完整认证。
- 代码签名：发布前再做，现在不做。
- 密码复制：**不自动清空剪贴板**。
- 开源许可证/专利：先不讨论，代码问题收完再定。
- 安装包：等 F 和人工验证收完再做。
- `H:\.ArchiveFixerSrcProtect`：确认清理；以后 Source protection 只在工作区。

## 3. 工作流总览

```text
阶段 0  取证 + 备份 + 记忆迁移矩阵
```

阶段 1 不依赖阶段 2；阶段 3 的大功能不要和 UI 提交混在一起。

## 4. 阶段 0：取证、备份、迁移矩阵

目的：在改任何迁移代码前，先知道现实数据长什么样。

### 4.1 只读取证

- 盘点 `%LOCALAPPDATA%\ArchiveFixer`：
  - `appsettings.json`
  - `passwords.txt`（DPAPI 头）
  - `passwords.txt.bak`
  - `passwords.meta.json`
  - `password-list.dat`
  - `password-book.path`
  - `window-placement.json`
  - 任何旧迁移标记/日志/temp
- 盘点旧位置：
  - `%APPDATA%\ArchiveFixer`
  - 旧安装目录 `data\`
  - `C/E/H:\.ArchiveFixerSrcProtect`（只读，不删）
- 对当前用户数据做**只读副本**到安全位置，记录文件数、大小、SHA256、修改时间。

### 4.2 不做什么

- 不直接删除旧目录。
- 不拿真实用户数据跑迁移脚本；先复制到临时根再跑。
- 不把 `passwords.txt` 明文内容写入日志、报告、提交。
- 不根据“看起来像残留”判断目录可删；硬链接可能是最后一份数据。

### 4.3 产出

- 一张迁移矩阵（见阶段 1）。
- 一份“当前真实数据长什么样”的证据记录。
- 一份旧目录清理清单，标出：
  - 可重建；
  - 含用户独有数据；
  - 含硬链接/源包；
  - 不确定 ⇒ 不删。

## 5. 阶段 1：记忆格式与迁移（P0）

### 5.1 固定文件职责

| 文件 | 职责 | 保护级别 |
|---|---|---|
| `appsettings.json` | 用户设置 | 高；未知字段不能静默丢 |
| `passwords.txt` | 密码值 + 顺序（DPAPI 当前用户加密） | 最高；不可丢、不可明文 |
| `passwords.txt.bak` | 上一次保存的恢复副本 | 最高；同样加密 |
| `passwords.meta.json` | 启用状态、备注 | 高；与值对齐 |
| `password-list.dat` | 旧版记忆（机器范围 DPAPI） | 迁移来源，不是主存储 |
| `password-book.path` | 旧版单本路径 | 旧兼容 |
| `window-placement.json` | 窗口位置/大小 | 低；损坏/屏幕外可丢 |

### 5.2 格式约定

- `passwords.txt`：
  - 明文旧格式继续可读；
  - 加密格式固定版本头；
  - 写入原子化：临时文件 → 替换；
  - 保存前备份，备份也加密；
  - 解不开时**不覆盖、不清空、不回落旧记忆**；
  - 显式导出只写副本，内部文件不移动、不删除。
- `passwords.meta.json`：
  - 先读旧内容，按密码值匹配；
  - 元数据里有、密码列表没有的条目不能直接删；
  - 密码列表有、元数据没有的条目按默认启用/无备注；
  - 写入前备份。
- `appsettings.json`：
  - 先取证当前保存是否会丢掉未知键；
  - 如果会丢，方案是保留未知字段或迁移到显式扩展字段；
  - 任何字段删除必须能说清“旧值去哪了”。
- `password-list.dat`：
  - 只在 `passwords.txt` 不存在时作为迁移来源；
  - 迁移后保留原文件，不删；
  - 机器范围解不开时明确提示“换机器/换用户”，不用空列表覆盖。
- 旧位置：
  - 继续只补目标不存在的设置/密码；
  - 不覆盖当前文件；
  - 迁移标记可重入；
  - 日志/temp 不迁移。

### 5.3 迁移矩阵（必须逐项有测试）

| 来源/形状 | 目标 | 策略 | 失败时 |
|---|---|---|---|
| 旧明文 `passwords.txt` | 新加密 `passwords.txt` | 读取后加密写，备份旧值 | 不覆盖，保留明文并告警 |
| 新加密 `passwords.txt` | 新加密 | 原样读 | 解密失败 ⇒ 禁止写，提示恢复 |
| `passwords.txt` 丢失 + `.bak` | 主文件 | 从加密 `.bak` 恢复 | 不回落旧记忆 |
| 旧机器范围 `password-list.dat` | `passwords.txt` | 仅在主文件不存在时迁移 | 解不开 ⇒ 提示，不覆盖 |
| 旧 `%APPDATA%` / 安装 `data\` | LocalAppData | 只补缺失文件 | 不覆盖、不删除旧源 |
| `passwords.meta.json` 与值不一致 | 元数据 | 按值对齐，保留孤儿条目 | 不静默清空 |
| `appsettings.json` 含未知键 | 设置 | 保留或显式迁移 | 失败保留原文件 |
| `window-placement.json` 损坏/屏幕外 | 窗口 | 回默认，删除无效值 | 不影响启动 |

### 5.4 验收

- 用当前真实数据的**副本**跑一遍：条数、顺序、启用状态、备注前后一致。
- 文件在磁盘上搜不到任何密码明文（含 `.bak`）。
- 每个失败场景都不会清空/覆盖原文件。
- 迁移可重入：跑两遍结果一致。
- 旧位置迁移后不产生重复/孤儿文件。
- 相关定向测试 + 全量测试 0 失败。
- 文档写明“怎么备份、怎么恢复、为什么换机器要导出”。

## 6. 阶段 2：UI 行为（P1，不改视觉）

### 6.1 F：反馈与状态

- 主窗口进度显示当前任务名/百分比/剩余，而不是只有不确定进度条。
- 失败/取消/空间不足/部分完成的颜色、图标、文案统一。
- 错误信息可复制、脱敏；长路径可选中。
- 继续清点旧系统 `MessageBox`，统一自绘对话框。
- 对话框按钮语义一致：危险确认默认“取消”，Esc 可退出。
- 密码列表导出/导入后提示“内部密码本仍在”，不能让人以为文件被移走。

### 6.2 D：可访问性

- 键盘：
  - Tab 顺序、焦点可见、Enter/Esc、菜单访问键；
  - 主流程“导入 → 一键处理 → 查看失败 → 退出”可全程键盘。
- 自动化名称：
  - 选项卡、主按钮、密码框、显示/隐藏、日志、失败/取消、危险操作。
- 高对比度：
  - 系统高对比度下关键背景/文字/边框/按钮可读；
  - 不只靠颜色表达成功/失败。
- 200% 文本缩放：
  - 密码页、任务列表、日志、打包确认、密码列表、子窗按钮。
- Narrator：
  - 主要控件名称/角色/状态可读；
  - 弹窗标题/正文可读；
  - 不承诺完整认证。

### 6.3 B/C/E 只做验证

- 窗口：1366×768、125/150/200%、双屏/拔屏、Snap、屏幕外恢复。
- 托盘：空闲 X 退出、忙碌 X 收托盘、首次提示、托盘退出确认。
- 密码：真实数据升级、导出/导入、旧 `.bak` 恢复。
- 只有验证失败才改代码；不把“没验证”写成“通过”。

## 7. 阶段 3：功能 backlog（按严重度排）

### 7.1 7z 及其他分卷“异常大小”

- 先只读取证：哪些族、什么形状、引擎原话、当前判据。
- 明确“异常”定义：声明的整包字节数、卷长、末片大小、缺片/多片。
- 优先保证：判不出 ⇒ 不动源包；不能把缺片当完整组。
- 需要产品确认的边界：报错、继续试、还是提示用户补片；不先猜。

### 7.2 加密头 RAR5 / 7z / ZIP

- 先整理支持矩阵：能识别、能列出、只能报“需要密码”、完全打不开。
- 不承诺“全部能解”；先把“识别 + 如实报错 + 不误判为损坏”做好。
- 需要新算法时按既有 Detection 框架接入，不另起一套。

### 7.3 手动解压 / 特定解压改造

- 先画清与“一键处理”的关系：
  - 手动选择包；
  - 特定输出/特定层；
  - 失败后的保留/清理；
  - 与分卷组、工作区、源包删除的边界。
- 这是产品交互改造，先出流程图/状态表，再动代码。

### 7.4 说明选项卡 / README / 术语

- 在说明页用例子解释专有名词：
  - 源包、过程物、其余物、工作区、落点、分卷组、骨架、入口层、第一/第二大步。
- README 与使用说明同步，不再维护两份互相矛盾的话。
- 保留“普通用户能照着做”的步骤，不写开发术语堆砌。

### 7.5 其他

- `EngineRoutingTests` 单跑 flaky：单独排查，不把它混进 UI 提交。
- `H:\.ArchiveFixerSrcProtect`：确认后只清理旧盘根目录；以后只允许工作区内。
- 引擎切换验证：确保切换引擎不影响已有任务/结果。
