## 4. 共同根因

1. **没有独立 finalize 阶段**：展示/汇总/删除/改名混在一起；链尾靠多个布尔判断。
2. **“本次运行快照”没有建模**：设置、选择、删除档、源包身份在 UI 状态与全局设置之间来回写。
3. **同一事实多真值源**：分卷族/槽位/完整/源包身份/其余物归属各自判一遍。
4. **布尔旁路代替证据**：force、ignoreDoneState、allowFallback、suppress、completenessEvidence、allowPartNumberedSkeleton。
5. **fail-open 与 fail-closed 混用**：完整默认 true、卡读失败照旧搬、快照异常当不存在；删除路径上不可接受。
6. **兼容/迁移代码没有退出条件**：旧字段、旧路径、旧方法、旧 UI 协议长期存活。

## 7. 建议的清理顺序

1. 先修不可逆删除：`SourceCleanupService.AddRestAliases`、`CleanupAcceptedRisk`、`RestItemPurger` 证据旁路、`ArchiveTask.IsVolumeComplete` 默认值。
2. 再统一删除入口：`DeletionPlan` 唯一执行器、删除前 FileIdentity 校验、fail-closed。
3. 再收分卷：一个 `VolumeFacts` 模型，族 resolver 只产出事实；名字容错输出置信度，消费方不接受低置信。
4. 再收落点：入口包/内容根/内层包是否打开改为显式 fact，不再按树形/名字反推。
5. 最后收 UI/设置：运行快照与默认值分离，确认面板不可被持久静默；迁移只在首次加载执行并清零。

### 8.1 新增最高风险（按不可逆后果）

1. `Extraction/VolumeNameRepair.cs:542-567` 与 `:4864-4889`：同一份“FileNatureCard 只剔除可证不是成员”的实现逐字两份；喂给 `FileNature.Inspect` 的是虚拟路径（`:5024-5036`）或裸文件名（`:4850-4852`），空卡 `Membership` 默认 `VolumeMember`，所以过滤条件恒不成立。该闸门是“卡优先”承诺的支点，`:5172` 的搬移计划会真的 `File.Move` 别的组的文件。
