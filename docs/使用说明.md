## 1. 这是什么

一个 Windows 桌面小工具，专门对付**来源不明、后缀被改坏、加密、分卷、还可能一层套一层**的压缩包。

它做四件事：

1. **认出真实格式** —— 读文件头判断，不看你那个后缀（后缀叫 `.mp4` 的其实可能是 7z）；
2. **修正伪装后缀** —— **一键处理**自动改（点了就是"自动改名自动解压"），**手动「智能修正」先给你看一遍预览**，
   你点确认才改；
3. **按密码本自动试密码并解压** —— 分卷当一组处理，解不动的会告诉你为什么；
4. **把结果整理干净** —— 内容物放到该放的地方；要整理的话，把剩下没用的（包括源包本身）
   集中到 `其余物\`，你再按 ③页那一档决定留着、进回收站还是删掉。

**它不会做的事**：不改你的压缩包内容、不联网、不写注册表、不往 C 盘 `%AppData%` 里塞东西、
**不自动删你的源文件**（默认档就是"源包原来的位置不动"；只有你显式把 ③页那一档选成
「放入其余物」+「彻底删除 / 移入回收站」时，程序才会在"解压成功 + 校验通过"之后动它）。

## 2. 怎么拿到、怎么开始用

### 2.1 两个版本，选一个

| 版本 | zip 名字里有 | 体积（约） | 目标电脑需要什么 |
|---|---|---|---|
| **框架依赖版** | `-框架依赖` | 小（几 MB） | 需要装 **.NET 8 桌面运行时（Desktop Runtime，x64）** |
| **独立版** | `-独立` | 大（约 100–200 MB） | **什么都不用装**，解压就能跑 |

- 不确定对方电脑上有没有 .NET 8 → 直接给**独立版**。
- 自己这台已经装过 .NET 8（或装过 .NET 8 SDK）→ 用**框架依赖版**就够了，体积小、传起来快。
- 缺运行时的时候，双击 `ArchiveFixer.exe` 会弹一个英文对话框，写着需要
  "Microsoft Windows Desktop Runtime" —— 那就是缺运行时。
  到 <https://dotnet.microsoft.com/download/dotnet/8.0> 下载
  **Desktop Runtime 8.x（x64）**装上即可（认准 "Desktop"，不是 "Console"）。

### 2.2 安装？不需要安装

**解压到一个你找得到的目录就能用** —— 这就是"绿色版"的意思：

1. 把 zip **完整解压**出来（不要只在压缩包里双击 exe，那样 `tools\` 里的引擎会找不到）；
2. 解压后得到**一个文件夹**，里面有 `ArchiveFixer.exe`；
3. 双击 `ArchiveFixer.exe` 就开了。

> ⚠ 请放在**你自己可写**的目录里（例如 `D:\Tools\ArchiveFixer\`）。
> **不要**放进 `C:\Program Files\`：那里需要管理员权限，程序的日志和临时文件会写不进去。
> 正常使用**不需要管理员权限**。

### 2.3 目录里都是什么

```
ArchiveFixer-<版本>\
  ArchiveFixer.exe        ← 双击这个
  使用说明.md             ← 就是本文（docs\ 里还有一份同样的）
  README.md               ← 给开发者看的说明
  LICENSE                 ← 本软件的许可证（MIT）+ 第三方组件声明
  appsettings.json        ← 默认配置模板（第一次启动时程序会拿它生成你自己的配置）
  docs\使用说明.md         ← 本文
  tools\7zip\             7z.exe / 7z.dll / License.txt / README.md   ← 内置的通用解压引擎
  tools\unrar\            UnRAR.exe / license.txt / README.md         ← 内置的 RAR 解压引擎
  （第一次启动后，程序会自己建一个 data\ 目录，见下）
```

**第一次启动**之后，程序会在自己旁边建一个 `data\`：

```
data\
  appsettings.json   ← 你的设置
  logs\              ← 日志（每次运行一个文件，里面**不含**密码明文）
  temp\              ← 临时文件
```

- **"卸载"就是删掉整个文件夹**（想连设置和日志一起清掉，就把 `data\` 一起删）。
- 想把这些挪到别处（例如挪出 C 盘）：**⑥「设置」页 → 缓存与工作区目录 → 缓存根目录**。
- ⚠ 换新版本时，可以把旧目录里的 `data\` 整个拷到新目录里，设置和日志就跟着走了。

> **解压工作区默认不在 `data\` 里了**（2026-09-24 起）：它跟着**输出盘**走 ——
> 在输出盘的根目录下建一个 `.ArchiveFixer.work`（点开头的隐藏目录）。
> 这样失败 / 取消留下的中间产物不会再堆在程序所在的那块盘上，定稿（从工作区搬到成品目录）
> 也变成**同盘改名**（快，而且不需要两份空间）。详见 §12 与 §15。
> 你在「缓存根目录」里填了路径的话，工作区就回到 `<那个路径>\work`（以你的设置为准）。
>
> **2026-09-25 起，失败 / 取消默认不再留下任何中间产物**（这个目录用过就清掉，见 §14 Q9）；
> 要留现场排查的人在 ③「清理与删除」页打开「失败时保留中间产物」。

> 如果你以前用过更早的版本（配置文件放在程序目录或 `%AppData%\ArchiveFixer\`），
> 新版本第一次启动会**自动把旧配置搬过来**，不用重新配一遍。

## 3. 30 秒上手

### 第 1 步：把文件拖进来

打开程序，把**压缩包**（或装着压缩包的**文件夹**）直接**拖到窗口里**。

- 拖文件夹进去会扫描里面的文件；文件夹里还有子文件夹也扫不扫，由
  **⑥「设置」页 → 扫描与识别 → 递归扫描文件夹**决定（默认扫）。
- 也可以点①任务页左上角「**添加文件**」「**添加文件夹**」。
- 拖进来后程序**自动识别**（读文件头，不信后缀），列表里每一行都会显示
  **检测格式**（真实格式）和**后缀状态**（后缀正常 / 后缀缺失 / 后缀不匹配 / 多重后缀疑似伪装 / 分卷后缀 / 内嵌归档）。

### 第 2 步：勾上要处理的任务

最左边一列是**勾选框**（点这一列的任意位置就切换，不用精准点那个小方块）。

- 顶部有「**全选**」「**全不选**」「**反选**」三个按钮；
  **全不选**之后再点一行 = 只处理那一个。
- 也可以在某一行上**右键 →「只勾选这一个」**（一次点击，其它全部取消勾选）。
- 键盘：`Ctrl+A` 全选 / `Ctrl+D` 全不选 / `Ctrl+I` 反选。

### 第 3 步：点「一键处理」

1. 点右上角绿色的「**一键处理**」；
2. 会先弹出一次「**一键处理 · 本次选项**」面板 —— 这一次解到哪、源包怎么处理，
   在这里临时选一下就行（**只对这一次生效**，不改你的设置）。不想每次都被问，就勾
   「以后不再询问，直接按设置走」；
3. 点「**开始处理**」。

程序接着自己跑完：识别 → 修正伪装后缀（**先弹预览给你确认**）→ 按密码本试密码解压 →
自动续解里面的内层包 → 最后给一行汇总。

### 结果在哪？

| 想看什么 | 在哪看 |
|---|---|
| 解出来的内容物 | 就在**源包旁边**（默认是 `111\222.rar → 111\222\` 这个文件夹），点右上角「**打开输出目录**」直接跳过去 |
| 这次成功几个、失败几个 | 窗口最下面「**汇总**」那一行；日志栏还有逐条的中文日志 |
| 某个包为什么失败 | 列表里的「**状态**」「**错误信息**」两列；点底部「**导出失败清单**」存成 txt |
| 那个包用了哪个引擎解的 | 右键任务 →「**查看任务详情**」；导出失败清单里也有 |

> **第一次用建议先拿一个不重要的小包试一次**，看清楚产物落在哪、`其余物\` 里是什么，
> 心里有数了再放大批量。

## 5. 输出位置：内容物到底会落在哪

**2026-09-24 起只剩两条规则**（用户亲自拍板删掉了"解压到当前目录"与"直接解到指定目录"两档：
"我怕如果 222 里面有很多的子文件夹，我们 111 里面就彻底乱掉了"）。**②「解压方式」页 → 落点**里**二选一**
（点「一键处理」时也能临时改）；**2026-09-25 起①「任务」页也能直接选**（在「添加文件夹」与「全选」中间那一格）——
两处**改的是同一个值**：在哪一处改，另一处立刻跟着变。

| 你选的是 | 有没有指定位置 | 产物落在哪 | 举例 |
|---|---|---|---|
| **一个压缩包**（添加文件 / 拖放） | 没指定 | 包旁边新建一个**同名文件夹** | `111\222.rar` → `111\222\内容物` |
| **一个文件夹**（添加文件夹） | 没指定 | 就在**这个文件夹里面**，每个包各一层 | `111\222\` 里的 `a.rar` → `111\222\a\内容物` |
| **一个压缩包** | 指定 `BBB` | `BBB` 里新建一个**包名**文件夹 | `222.rar` → `BBB\222\内容物` |
| **一个文件夹** | 指定 `BBB` | `BBB` 里新建一个**和所选文件夹同名**的文件夹 | 选 `222\` → `BBB\222\内容物` |

> **①页那一格怎么读**：`输出位置：` 后面显示的就是当前的选择 —— 没指定时直接写
> 「（未指定：产物落在每个包自己的目录）」；指定了位置时显示路径，**太长的路径中间会省略**
> （`E:\DeepSeekProjects\ArchiveFixer\...\net8.0-windows\ref`，保留开头一段与最后两段），
> 鼠标停上去看**完整路径**，右键「复制完整路径」可以整条复制走。旁边的「未指定位置」开关
> 就是上表里的"有没有指定位置"。
>
> ⚠ 选位置**只是记住一个地址**，程序**不会**在那一刻建目录 —— 那个目录只在真的要往里放内容物
> （定稿）时才创建；挑错了、又改了主意，盘上不会多出一个空文件夹。

一句话原则（用户原话）：**「我们解压绝对不能将原来的文件夹给弄混乱」**。

- **未指定位置那两档**：源目录里**只会多出新出现的产物子文件夹**，别的什么都不多 ——
  不会凭空多出 `111\222\222\` 这种同名层，更不会把产物扔到上一层去。
- **"添加文件夹 + 指定位置"那一档**：同一个文件夹里的包**都落进 `BBB\222\` 这一层**
  （用户原话"再里面操作"）。⚠ 所以那个文件夹里若有好几个包，它们的内容物会放在一起，
  同名条目按「同名冲突处理」办（默认自动重命名 `名字(1)`，绝不覆盖）。
- **分卷组 / 伪装后缀 / 双面文件**都取对名字：`222.7z.001` → `222\`、`222.rar.jpg` → `222\`、`222.mp4`（内嵌归档）→ `222\`。
- 旧版本设置里的"解压到当前目录"会**自动迁移**成"同名子文件夹"那一档（不会报错，也不会把你的东西摊进源目录）；
  "指定位置 + 直接放该目录下"迁移成"指定位置 + 同名子文件夹"（位置保留，但会多一层包名文件夹）。

### 5.1 「内容物最后那一层」是什么

内容物本身可能自带文件夹。程序按"**从最里面往外看**"的规则决定最后长什么样：

| 情况 | 结果（以 `111\222.rar` 为例） |
|---|---|
| 包里就**一个文件**（比如一个 mp4） | `111\222\666.MP4`（不再多套一层） |
| 包里有**多个文件 / 多个文件夹** | 默认**保留包内那一层名字**：`111\222\666\内容物`；<br>想少点一层，就在设置里选「多文件时用压缩包名当最后一层」，变成 `111\222\内容物` |
| 包里套着多层**空目录/单层文件夹** | 把最后那个有意义的文件夹提上来，不会给你一串没用的空壳 |
| 每一层都只有一个文件夹（单链） | 塌缩成最深层那个文件夹名（省掉重复的一层） |
| 包名和它所在文件夹同名（`111\222\222.rar`） | 默认合并掉重复的那一层：`111\222\内容物`（可在设置里关掉） |
| 用「添加文件夹」选了 `111\222`，而里面只有 `222.7z.001` 这一组卷 | 合并掉重复的一层，产物就落在你选的那个文件夹里：`111\222\内容物` |

### 5.2 输出目录已经存在 / 同名冲突怎么办

由 **⑥「设置」页 → 扫描与识别 → 同名冲突处理**决定，**默认「自动重命名」= 新产物叫 `名字(1)`，绝不覆盖**：

- `自动重命名（默认，绝不覆盖）`
- `跳过（不动已存在的文件）`
- `覆盖（先挪到临时名，落位成功后才删旧的）`
- `询问（第一次冲突时暂停任务问一次）` —— 选这个之后：解压落位第一次撞名会**暂停并弹一次**询问
  （覆盖 / 跳过 / 自动重命名，可勾"对后面所有同名冲突都照此办理"）；改名预览里撞名的行会多出一个
  「冲突选择（询问档）」下拉让你逐条选，**不选就直接关掉预览 = 按自动重命名，绝不覆盖**。

### 5.3 特定解压：让内容物"只留一层"（**可加的**规则）

> 用户 2026-09-24 拍板：「我是想在一键解压旁边弄一个特定解压开关……在解压方式里面就可以去添加一个
> 特定解压这一栏，**也就是以后可能会经常加的东西，因为每个人的特定的解压方式不同**」。

**怎么用（两步）**：

1. **①「任务」页**：「一键处理」按钮**右边**把「特定解压」那个开关勾上（**默认是关的**）；
2. **②「解压方式」页** → 最上面「特定解压（可以往上加的规则）」那一栏里，挑要按哪几条跑。

**关掉①页那个开关 = 与没有这个功能完全一样**（②页挑了什么都不算数）。所以你想"这次按老规矩来"，
把①页那个勾去掉就行，不用去②页改。

**第一条规则：每个包只留一层内容**

| | 产物长什么样（源包 `222\1111.rar`，包内是 `内容文件夹\内容物`） |
|---|---|
| 规则**关** | `222\1111\内容文件夹\内容物`（老行为：保留包内那一层的名字） |
| 规则**开** | `222\1111\内容物` ← 把多套的那一层去掉，内容物直接落在包名那一层里 |

- **包名那一层永远保留**（`222\1111\`）：内容物外面必须有一层文件夹，绝不把东西摊到 `222\` 去。
- **其余物位置不变**：还是在 `222\1111\其余物\` 里（源包 + 中间件），一键清理的用法完全一样（§6）。
- **同名冲突也不变**：撞名按⑥页的「同名冲突处理」办，**默认自动重命名 `名字(1)`，绝不覆盖**（§5.2）。

**什么时候"不塌"（不会按这条规则走）** —— 这三种情况它会**照老规矩套一层**，并在日志里写清楚为什么：

1. ①页那个总开关没勾，或者②页这条规则没勾；
2. 包里**有两个或更多并列的文件夹**（去掉一层就分不清哪个才是内容物了）；
3. 你选的是「添加文件夹 + 指定位置」那一档（几个包**共用**同一个成品目录 `BBB\222\`）——
   那一档下"包名那一层"就是程序套出来的那一层，去掉它会把几个包的内容物混在一起。

> ⚠ 不想让它生效时的**兜底**：①页那个总开关关掉即可（②页的勾选会原样留着，下次打开开关还按它跑）。

## 6. 「其余物」是什么，怎么一键清理

### 6.1 它是什么

**除内容物之外剩下的东西**，程序把它们**集中到一个叫 `其余物` 的目录里**，包括：

1. **过程物**：为拿到内容物而产生的中间件 —— 内层归档、分卷、抠出来的中间 ZIP（**只在直读不支持时才产生**，见 §10.2）、纯壳文件夹；
2. **源包本身**（含整个分卷组）。

也就是说：**整理完，一个目录里只剩"内容物 + 其余物"两样东西**，你看一眼就知道哪些是要留的。

```
111\
  内容物A        内容物B        内容物C
  其余物\
        222\      ← 222 这个包的：源包 + 分卷 + 内层归档
        333\      ← 333 这个包的：同上
```

- 如果包本来就有自己的文件夹（默认模式），就是 `111\222\其余物\`；
- 如果多个包摊在同一个目录（"解压到压缩包所在目录" / "直接放在指定目录"），
  就会**按包名分层**：`111\其余物\222\`、`111\其余物\333\`，不会互相撞名。

### 6.2 为什么源包也在里面

这是**故意**的：你原来的做法是"解压完再把一堆 `*.7z.001` 手动删掉"。
把源包和过程物放一起，你就只用做一个动作 —— **确认删掉 `其余物`**。
源包还在 `其余物` 里，所以在删之前你随时能把它捞回来。

改动源包有**四个前提，缺一不可**：内容物已经整理好 + 输出校验通过 + 你没取消 + 它属于本任务的分卷组。
**失败 / 只完成一部分 / 被取消 → 源包一个字节都不动，`其余物` 也不会生成。**

⚠ **默认档是"原来的位置不动"**（2026-09-25 你自己定的默认）：程序**一个字节都不碰你的源包**。
想让程序替你整理，就在 **③「清理与删除」页 →「1 源包操作」**里选「**放入其余物当中**」，
再按 **「2 删除操作」**决定那份 `其余物` 的下场（不动 / 移入回收站 / 彻底删除，见 §12.3）。

- 想保持"传统解压器"的语义 → 「1 源包操作」保持**原来的位置不动**（默认就是它）；
- 只对某一次生效 → 点「一键处理」时在确认框的折叠区里把**源包处理**改成「留在原地」。

### 6.3 怎么清理

**③「清理与删除」页 →「其余物删除」**里有三个（原来在「工具」菜单里）：

| 按钮 | 作用范围 |
|---|---|
| **删除其余物…** | 删**勾选**的每个任务自己那一份 `其余物`（一个都没勾就什么都不做，只提示） |
| **删除本目录全部其余物…** | 删目标任务输出目录下的**全部**其余物 —— 会影响同一个目录里的**其它包**，确认框里会点名影响几个包 |
| **清理空文件夹…** | 清掉输出根目录下"**任意层级都没有文件**"的空文件夹（有文件的目录一律保留） |

流程都是：**先给你看预览**（哪些目录、多少条目、多少字节、**里面有没有源包** —— 有就点名），
再**只确认一次**（勾了 5 个任务也不会问你 5 遍），然后逐个执行，最后给一次汇总。

**回收站 vs 彻底删除：**

| 档 | 怎么用 | 行为 |
|---|---|---|
| **移入回收站**（默认） | 什么都不用勾，直接确认 | 从回收站可以还原 |
| **彻底删除** | 在确认框里勾上「**改为彻底删除，不进回收站**」 | **不可恢复**；确认框会变红，还要再勾一次「我知道彻底删除不可恢复，这些内容不会进回收站」才真的删 |

> 那个勾选框永远表示"**切到另一档**"：如果你把默认档改成了"彻底删除"，它就变成
> 「改为移入回收站（可恢复）」，勾上反而更安全。

- 想改默认档：**③「清理与删除」页 → 其余物删除 → 默认档**（默认仍是回收站）。
- 回收站不可用时（网络盘、组策略关掉了回收站）程序**不会硬删**，会明确告诉你没删成。
- 每次删除都写日志（删了哪些路径、为什么、释放多少字节）。

## 7. 密码：怎么给、存在哪

程序试密码的顺序是（2026-09-24 起多了第二档）：

```
空密码（可关）→ 本批已成功的密码（复用）→ 本任务/本层最近成功过的密码 → 密码本里按包名命中的那条 → 统一密码 → 密码本列表 → 手动输入
```

**「本批已成功的密码」是什么**（用户 2026-09-24 要求："只要测到一个成功了就不要去再尝试了……
如果是密码本里面的第 5 个，如果是 200 个压缩包，那你岂不是要尝试 1000 遍"）：
同一次运行里，只要某个包用某条密码解开了，这条密码就会被**提到后面每个包的候选最前面**，
日志里会写明「复用本批已成功的密码」。200 个同源包的总尝试次数因此从 O(N×k) 降到 O(N)。

- ⛔ 它只是**提前**，**不是替换**：原来的候选一条都不会少 —— 不同包的密码可能确实不同，
  复用的那条不对时，程序照旧把它自己的密码试出来。
- **密码本内部按"用得多"排**（用户原话："密码本里面的优先级差不多就是使用次数的频繁程度"）：
  哪条密码成功解开过更多次，它就排在同层级候选的更前面（次数相同就保持你排的顺序）。
  这个次数跟着密码列表一起**按本机加密保存**（见 §7.6），所以重启后优先级照样在。
- 空密码不算"一条密码"，不参与上面的记账与复用（它本来就是每个包的第一步）。

### 7.1 三种给密码的方式

| 方式 | 在哪 | 说明 |
|---|---|---|
| **统一密码** | **④「密码」页 →「统一密码」框** | 所有任务都用这一个。勾上「使用统一密码」才生效 |
| **密码列表管理** | **④「密码」页 →「密码列表管理…」**（导入 / 编辑 / 写回都在那个窗口里） | 导入 / 编辑密码本 |
| **单任务密码** | 开始前程序会问一次「要不要手动输一个密码」（只对本次运行有效），或右键任务 → 查看任务详情 | 只给这一个包用 |

### 7.2 密码本怎么导入

**④「密码」页 →「导入密码本…」** → 选一个 `.txt` 文件（UTF-8 最好，GBK 也认）。两种写法都支持：

```
# 这是注释，以 # 开头
# ① 列表式：一行一个密码，按顺序逐个试
<示例密码1>
<示例密码2>

# ② 映射式：用"名称:密码"，按压缩包文件名去命中（中英文冒号都认）
资源包A:<示例密码3>
资源包B：<示例密码4>
```

- **映射式命中优先**：包名匹配上了就先试它，不用把整张表遍历一遍。
- 导入后主界面会显示密码本摘要（多少条、来自哪个文件）。
- 程序**只记住密码本文件的路径**，下次启动时如果文件还在就自动重新读一遍；
  **不会复制、不会修改**你的密码本文件。

### 7.2.1 「写回密码本…」：为什么它仍然重要

密码列表**默认会按本机加密保存**（见 §7.6），所以手动加的密码、手动调的顺序**关掉程序也不会丢**。
但那份加密记忆有两条天生的短板：**换机器 / 重装系统解不开**，**关掉「记住密码列表」就没有**。
真正带得走、也永远不会被程序碰的载体，是你**自己那份密码本 txt** —— 点「**写回密码本…**」：

| 它会做什么 | 说明 |
|---|---|
| 写前先备份 | 原文件旁边生成 `<你的密码本>.bak-年月日-时分秒`；**备份失败就不写** |
| 只追加到末尾 | 已有内容一个字节都不改、不重排；编码（UTF-8 / UTF-8 带 BOM / GBK）与换行风格都保持原样 |
| 按值去重 | 文件里已经有的密码不会再写一遍 |
| 空密码跳过 | 空密码写进去没有意义，会跳过并在结果里说明跳过了几条 |
| 写完自检 | 立刻用密码本解析器重新读一遍，确认新写的都能读回来；读不回来就报失败并告诉你备份在哪 |

窗口里**手动添加、值还不在任何一本已记住的密码本里**的条目会带一个小标记（备注列「手动添加 · 未写回」）。
标记的判定是**按值、以文件为准**的：

- 标记消失 = 这个值**确实躺在某一本已记住的密码本文件里**了（程序会**重新读一遍文件**来判定）；
  所以**写回成功之后重启，标记仍然消失**（用户 2026-09-24 第 21 条报的就是"重启又显示未添加"，已修）；
- 改动过某条密码的值，标记会重新出现（新值还没写进去）；
- **一本已记住的密码本都没有、或者书读不到**（被搬走 / 改名 / 权限不足）时，标记**保持** ——
  程序不会假装已写回；
- 你在设置里**移除**掉某本密码本之后，只在那本书里的值也会重新显示"未写回"（它已经不在任何一本被记住的书里了）；
- 这个标记是**纯显示**的：不影响候选顺序，也不影响尝试上限。

### 7.2.2 候选顺序与「每层尝试上限」的关系（加了密码却没被试用时看这里）

程序试密码的顺序是固定的：

```
空密码（可关）→ 本批已成功的密码（复用）→ 本任务/本层最近成功过的密码 → 密码本里按包名命中的那条 → 统一密码 → 密码本列表 → 手动输入
```

「每层尝试上限」（**④「密码」页**，默认 10）限制的是"**这一个包最多真的试几个候选**"。
**写回是追加到密码本末尾**，所以密码本条目一多，排在后面的候选就会被上限截断——
这时状态显示「**达到密码尝试上限**」，**不是**「密码错误」，看着就像"我明明加了密码，它却没识别到"。
（复用的那条密码会占用一个候选位，但它同时也是最可能命中的那一条。）

该改什么（任选，也可都做）：

1. 把「每层尝试上限」**调大**（1~1000，改完当场生效）；
2. 改用 **`名称:密码` 的映射式**写法——映射命中排在"遍历整张列表"**之前**，条目再多也不会被挤到后面；
3. 或者在任务详情里对那一个包**手动输入密码**。

### 7.3 密码存在哪、日志里会不会有

- **日志、报告、剪贴板、任务详情、异常信息里一律只有脱敏形态**（`******`）：程序只记"试了哪个来源、成功没有"，
  **绝不记内容**（`PasswordMasker` 统一处理）。
- **唯一会落盘的密码数据是密码列表记忆**（见 §7.6）：一份**按本机加密**的文件 `data\password-list.dat`，
  连文件名一起加密，用记事本打开是乱码；可以整个关掉。
- ⚠ **已知限制**：调用命令行引擎解压时，密码必须写在参数里（`-p密码`），所以**任务管理器里能看到**。
  这是 7z / UnRAR 命令行的固有限制，程序不假装解决了。
- 密码本文件、密码列表记忆都属于**隐私**：程序**完全不联网**，不会把它们发到任何地方。

### 7.4 「达到密码尝试上限」不是"密码错误"

**④「密码」页 → 每层尝试上限**（默认 10）限制的是"这一个包最多真的试几个候选"。
试到上限就停下，状态显示「**达到密码尝试上限**」——它的意思是
"候选**还没试完**就按上限停了，正确密码可能在更靠后的位置"，**不代表密码本里没有**。

想继续试：把上限调大（1~1000，改完当场生效）、改用映射式写法、或者在任务详情里**手动输入密码**
——三条出路的取舍见 [§7.2.2](#722-候选顺序与每层尝试上限的关系加了密码却没被试用时看这里)。

### 7.5 从包旁边的说明文件里找密码（默认关）

有些资源包会把密码写在旁边的 `.txt` / `.bat` 里。**④「密码」页 →**
**从压缩包同目录的说明文件里提取密码候选**（默认**关**）。开了以后：
只读同一个目录、有大小上限、提取到的只是**候选**（照样走上面的顺序），
结果里会标明"这个密码是从说明文件里来的"。

### 7.6 记住密码列表（默认开）+ 多本密码本

**用户 2026-09-24 拍板的方案。** 以前列表只在内存里，重启由密码本 txt 重建 —— 于是
手动加的条目、手动调的顺序重启就丢，导入第二本密码本还会把"自动加载哪一本"顶掉（第一本的条目全不见）。
现在：

| 项 | 行为 |
|---|---|
| **存哪** | `<程序目录>\data\password-list.dat`（**绝不写 C 盘**，跟程序其它数据同一个 `data\`） |
| **怎么加密** | Windows 自带的 **DPAPI，机器范围**（`CryptProtectData` + `CRYPTPROTECT_LOCAL_MACHINE`）+ 一段固定的应用标识 |
| **跟 Windows 账号有关吗** | **无关**：同一台机器上换谁登录都能用，**不弹任何框** |
| **存了什么** | 列表的**内容 / 顺序 / 启用状态 / 手工条目 / 备注**、记住的**多本**密码本路径、"你删掉过哪些值"（重启时不许它们从密码本里复活），以及**每条密码成功解开过多少次**（用户 2026-09-24 第 14 条：重启后"用得多排前面"照样成立） |
| **开关** | **④「密码」页 →**「**记住密码列表（加密保存在程序目录，跟 Windows 账号无关）**」，**默认开** |
| **关掉会怎样** | **既不写也不读**那个文件（磁盘上已有的那份**不会被删**）：列表回到"只在本次运行内有效"，重启由密码本 txt 重建 |
| **换机器 / 重装系统** | 解不开 → **忽略并提示**（不崩、不覆盖、不删文件）；主界面摘要会挂一句提示，密码列表窗口里给完整说明。出路：在本机用「**写回密码本…**」把列表写进你自己的 txt，再带走 |

**多本密码本**：导入过的每一本都会被记住，启动时**按记住的顺序逐本合并** ——
只补列表里还没有的密码（已有的顺序与启用状态不动），删掉过的值不会被补回来。
**④「密码」页 →**「**已记住的密码本**」里能逐项**移除**（只是不再自动加载它，**磁盘上的文件一个字节都不会动**；
一本都没有时那一组会写明"启动时不会自动加载任何密码本"）。

密码列表窗口顶部会显示一行 **「当前列表：N 条（其中启动时由记忆恢复 M 条）＋ 记住的密码本 K 本」**，
一眼能看出这份列表现在是靠什么活着的。

**代价（如实说明，用户已知并接受）**：机器范围意味着**同一台机器上任何本机用户都可能解开它**；
它保护的是"别人拿到这个文件也看不懂"，**不是**"防住这台机器上的其他账号"。
要更强，只有一个办法：别把密码留在列表里，用「写回密码本…」放进你自己的 txt。

## 8. 解压引擎：WinRAR 与 7-Zip 是怎么回事

程序自己不实现解压算法，它调用现成的命令行工具。**包里已经内置了两个**，所以**你什么都不用装**：

| 引擎 | 是什么 | 归谁 | 我们怎么用它 |
|---|---|---|---|
| **7-Zip 命令行**（`7z.exe`，26.03） | 自由软件（LGPL），能解 zip / 7z / tar / iso / gz 等一大堆格式 | 7-Zip 项目 | **内置**在 `tools\7zip\`，随包分发，带它的许可文本 |
| **UnRAR 命令行**（`UnRAR.exe`，7.23） | RARLAB 官方**免费的解压专用**工具，RAR 格式支持最正 | RARLAB | **内置**在 `tools\unrar\`，随包分发，带它的许可文本 |

### 优先级：默认先 UnRAR、再 7-Zip

**②「解压方式」页 → 引擎**里能看到顺序（默认 `1. UnRAR … / 2. 7-Zip …`，可以「上移 / 下移」）。
规则是"**先看这个引擎能不能干这活，能干的里面再按你排的顺序挑**"：

- **RAR 包** → 默认给轮到前面的 UnRAR（它报错更准：缺哪一卷直接点名、加密文件名有明确标志）；
- **zip / 7z / tar / iso 等** → 7-Zip。

### 没装 WinRAR 会怎样？

**完全不受影响。** 说明白两件事：

1. **WinRAR（`WinRAR.exe` / `Rar.exe`）是共享软件，我们绝不打包、绝不复制它。**
   程序只会**只读地看一眼**你机器上如果装了 WinRAR，那个目录里有没有免费件 `UnRAR.exe`，有就用它。
   你**从头到尾没装过 WinRAR**，程序也照样能解 RAR —— 它用的是**内置的那份** `UnRAR.exe`。
2. 就算某个引擎不可用（路径被删了、被你在设置里改错了），程序**不会傻在那儿**：
   它会**跳过不可用的引擎**，用剩下的那个干；两个都不可用才会报
   「**没有可用的解压引擎**」（如果是 7z 那一格指错了，报的是「7z不存在」）。

想指定自己的版本：**②「解压方式」页 → 引擎** → 「7z.exe 路径」「UnRAR.exe 路径」；**留空 = 用内置的**。
填了一个不存在的文件时，点「保存设置」会被拦下来并告诉你该怎么改。

**打包要用的 `Rar.exe` 是另一格**（**②「解压方式」页 → 引擎** →「Rar.exe 路径」，带「浏览…」按钮）：
它指向的是**你自己安装 / 下载的 WinRAR** 里的那一份，程序只检测与调用，**绝不随包分发**（共享软件）。
留空 = 自动用本机已装 WinRAR 目录里的那一份；没装 WinRAR 也可以用「外层容器 = 7z」（见 §13.3）。

## 9. 分卷压缩包

分卷就是被切成好几个文件的压缩包（`xxx.7z.001`、`xxx.7z.002`…）。

- **一组分卷 = 一个任务**：列表里只出现**第一卷**（`xxx.7z.001`），不会一卷一行；
- 认这几种命名：`.001`、`.z01`、`.r00`、`.part1.rar` / `.part01.rar`，以及"本体就是第一卷"（`x.zip` / `x.rar`）；
- 列表里「**分卷**」那一列会显示这一组有几卷。分卷的产物落点和普通包一样
  （按其所在目录 + 包名算）。

### 缺卷怎么办

**程序不会硬着头皮解**，会直接报「**分卷缺失**」，并在错误信息里说清**缺哪几个**、已找到哪些。
处理办法：把缺的那几卷找回来放到同一个目录里，再重新扫描（右键该任务 →「重新扫描此文件」）。

> 打包时**只删了中间某一卷**的包是解不开的 —— 这不是程序的限制，是分卷格式本身的要求。

## 10. 嵌套包与「内嵌归档」

### 10.1 包里有包

**②「解压方式」页 → 嵌套与覆盖** → 「嵌套压缩包」三选一：

| 选项 | 行为 |
|---|---|
| **只解当前这一层**（默认） | 只把外面那层解开，里面的包原样留在 `其余物\` 里，你自己决定下一步 |
| **单链自动展开**（推荐） | 如果里面**只有一个**内层包就继续解，一层层往下；遇到**多个包**会停下来问你 |
| **展开所有分支** | 内层有多个包也全部解开 |

安全垫：层数、文件数、总大小、展开比、密码尝试次数都有**硬上限**，到顶就安全停下，
并告诉你"停在第几层"。解内层包同样要过安全检查，越界就判失败。

**解压前那四条上限是可改的**（**⑥「设置」页 →「安全上限（解压前预算）」**，默认值是给真实资源包留足余量的）：

| 项 | 默认 | 含义 |
|---|---|---|
| 单文件上限 | **64 GiB** | 归档里**最大的那一个文件**解压后超过它 → **不解这个包** |
| 总大小上限 | **512 GiB** | 清单声明的解压后总量超过它 → 不解这个包（永远不小于单文件那一档） |
| 文件数上限 | **200000** | 条目数超过它 → 不解这个包 |
| 展开比上限 | **1000 倍** | 解压后总大小 ÷ 压缩包体积（体积未知时不判），超过按"疑似压缩炸弹"拒绝 |

- 这四条**只拒绝解压，不会删任何东西**；填了 0 / 负数 / 过大的数会被夹回合法区间，
  并在保存时告诉你"已按 X 生效"。
- 它和"目标盘空间不够就不启动"是**两道独立的闸门**：空间不够那句**不会**建议你去调上限
  （那件事该做的是清盘或换盘）。
- 上限拦下时，失败清单会写清**是哪个条目、哪个上限、以及去哪儿调**。
  日志每批开头也有一条 `安全上限（解压前预算）：单文件 … / 总大小 … / 文件数 … / 展开比 …`，
  事后翻日志就能对上"当时设的是多少"。

### 10.0 密码是**先试后解**的（不会拿一个可能不对的密码去跑整包）

- 每换一个候选密码，程序会**先用它只解包里最小的那个文件**（≤16 MiB 的说明文件/小图）来验证：
  解不开就是"这个候选不对"，**整包一个字节都不动**；解开了才去解整包。
- **包里没有小文件也没关系**：程序还会**只读第一个条目"解密后的开头 64 字节"**
  （做法是让 7-Zip 把内容流出来、读够就立刻掐掉那个进程）——
  密码对，这几十字节就是文件真正的开头（7z/zip/rar/mp4… 的魔数）；密码错，就是随机字节。
  **代价与包多大无关**（一个 5 GiB 的条目也只要零点几秒），一个字节都不落盘。
  看不出开头的候选**不会被丢掉**，只是排到最后再试（有些真实文件本来就没有魔数）。
- 说句实话：7z 的 AES **没有密码校验位**，所以"只验密码、一个字节数据都不读"在格式上做不到 ——
  手工工具试密码时同样是"读一点数据来判断"，区别只是它读得足够少。程序现在读的是**最省的那么一点**。
- **加密的包不会试"空密码"**：7-Zip / WinRAR 都造不出"用空密码加密"的包，试它必然白跑一整包
  （以前真机上就是这里花了十分钟）。
- 如果你要排查问题：**①「任务」页 →「导出全部日志」** 会把 `data\logs` 里**所有**日志合并成一个 txt
  （每一份都有分隔头，密码一律脱敏），比失败清单更适合发给我看。
### 10.1.1 一组分卷的**第一卷**名字被改坏时

打包者常干一件事：把一组分卷的**第一卷**改个名字（塞几个字、吃掉一个字符），让解压工具按名字找不到
后面的卷。这种情况程序会判「**分卷缺失**」并告诉你：

- 这一卷是"一组分卷的第一卷"，但名字被改坏了；
- 引擎只会把它当成一段**通用分片**（解出来是一个与它等大的垃圾文件，**不是**包里的内容），所以**不开始**；
- 同目录里像后续卷的那几个文件叫什么，以及**把这一卷改成什么名字**就能解开（例如 `X.7z(删掉.001` → `X.7z.001`）。

⛔ 程序**不会自己**改源文件：要它改，就**勾上这一行**点①「任务」页 →「手动操作」→「**按建议改名并重试**」。

- 它只做三件事：**把这一卷改成程序给出的那个标准名**（`File.Move`，⛔ 不覆盖、不删除、**内容一个字节都不动**，
  改完还会核一遍字节数）→ 重新识别（顺手重拍源文件快照）→ 按「只解压」同一条路**重试一次**；
- 点之前会弹确认框，逐条列出 `旧名 → 新名`；
- 目标名已经被别的文件占了、同目录里没有后续卷、从后续卷推不出标准名、这一卷的名字本来就是标准的 ——
  这些情况它**当场拒绝**并说清为什么（宁可不动，也不乱改）；
- 只改你**勾选的**那些任务，一次一个名字，改完按钮自己熄灭（问题解决了就不该再亮着）。

也可以自己按日志里给的名字改好，然后右键 →「重新扫描此文件」。

> 名字**正常**、卷也齐全的一组（`X.001` + `X.002`）不受影响 —— 那种情况下"把分片拼起来"正是你要的东西。

### 10.1.3 日志现在"话很少"（第 44 条）

- **成功的任务只留一行**：`X：解压 100% ｜ 解压成功 ｜ 校验通过 ｜ → …\包名 ｜ 用时 1.4 s`
  （"开始解压"与收尾摘要**合成一行**）。进度、落点、入仓目录、空间门、结果校验、定稿、工作区清理
  这些**过程细节不再逐任务往日志里灌**；
- **失败 / 取消 / 部分完成的细节一个字都不少**（含进度与全部路径）—— 那才是排查要的东西；
- **其余物处理**：逐任务一行（`彻底删除：…（N 项 / 4.6 MiB）`）+ **批末一条汇总**；
  理由与"不可恢复"的提示在批首一条 + ③页那条常驻红提示里；
- 「导出日志（本次）」里的**完整绝对路径**改成了"末两段"（满屏几百字符的路径最占地方）——
  要看完整地址请用任务详情（右键「复制任务路径 / 复制任务信息」）或①页「输出位置」。

**要更细的日志：⑥设置 →「详细日志（排查用）」（默认关）**

勾上之后**成功的任务也把全过程写进日志**（落点 / 入仓目录 / 空间门 / 候选密码 / 结果校验 / 定稿 /
工作区清理……），排查**单个**包时用它；取消勾选并保存就回到"一行"。⚠ 两点：

- **失败 / 取消的任务不受这个开关影响** —— 它们永远保留全部细节；
- 打开之后日志会明显变大（几十个同形包时可能就是"一包十几行"），**平时关着**。

**导出的文件现在有"头"**（点「导出日志（本次操作）」之后，文件开头那 6 行）：

```
================ ArchiveFixer 日志导出 ================
时间范围：… → …（用时 …）
任务数：N（成功 x / 失败 y / 跳过 z）
引擎：7-Zip 命令行 <版本>（优先级：…）
输出位置：<本次的输出位置>
细节在哪看：①页任务行的「详情 / 右键复制任务信息」… ；「导出失败清单」… ；③页「工作区残留」…
================ 以下是日志正文 ================
```

- 头部**不算进**弹窗里报的"N 行"（那个数字只数正文）；
- 头部只写**机器事实**（任务数按任务的最终状态数、引擎名与版本、这次的位置），**不含任何密码内容**；
- 头里那行「细节在哪看」就是上表那几个入口 —— 排查时不用再猜"去哪找更细的"。
### 10.1.2 一批包共用输出目录时，**每个包一层自己的目录**（第 43 条）

"添加文件夹 + 指定位置"导入一整批包时，那一层"同名子文件夹"用的是**你选的文件夹的名字**
（例如 `CCC\SJA佳爷…\`）—— 它不区分是哪个包。所以每个包必须**再有自己的包名目录**：

```
CCC\SJA佳爷…\055\内容物      ← 055.7z 这一条链的产物（含它里面内层包解出来的东西）
CCC\SJA佳爷…\056\内容物      ← 056.7z 的，与上面互不干扰
```

- 外层包里**只有内层包、没有内容文件夹**时（真机上 68 个包都是这样），这一层以前**不会被建出来**，
  于是所有包的内容物全倒进共用根、几千个同名文件被自动改名成 `(1)(2)…` —— 这是 2026-09-25 修掉的缺陷；
- 包名取自**事实**：内层包当时躺在哪一层（`其余物\055\…` 里的 `055`），不是"扫描归到谁头上"的任务名；
- 想更少一层可以在②页把落点改成"选文件 + 指定位置"（那样每个包直接落 `<指定位置>\<包名>\`）。

**容器里装着的就是这一组的第一卷时**（`封面.jpg` 里是 `set.7z.001`，`set.7z.002/.003` 在容器外面）
程序会判「分卷缺失」，原因里除了引擎那句原话，还会跟一条 **`更正引擎那一句`**：

- 说清**首卷就在这个容器里**（引擎那句"这是后续卷、缺少首卷"说反了）；
- 点名外面那一组缺首卷的分卷叫什么、以及它**应该**有的首卷名（例如 `set.7z.001`）；
- 说清引擎为什么找不到它们 —— 它按**文件名**在**同一个目录**里找同组的卷，而抠出来的那一段
  既不在那个目录、名字也不带卷号。

**要"全自动"：②页打开「容器里装的是分卷第 1 卷时，自动接上同目录的后续卷」（默认关）**，再重跑这一单：

- 程序在**工作区**里接出一套"名字成套、同在一个目录"的卷：首卷 = 从容器里抠出来的那一段
  （改成标准首卷名 `set.7z.001`），后续卷 = 同目录里的 `.002/.003`…；
- **同一块盘**：只"接名字"（硬链接）—— **不复制字节、不占额外空间、也不改你的源文件**；
  **跨盘**：只能真复制，所以**先查空间**，不够就**不做**（照旧报「分卷缺失」并说清为什么）；
- 接完**先让引擎自己验一次**：它认了才用这一套解压；认不了就退回原路（结论一个字不变）；
- 判不准时**一律不动**：同目录里**同一族**有两组以上都缺首卷（7z 分卷与 RAR 分卷算不同族，
  所以"目录里分卷多"通常不影响），或者认不出容器里那一段是什么格式 —— 这时照旧只把话说清；
- 你的源目录**从头到尾一个字节都不变**：源文件只读，接出来的东西都是工作区里的中间件，跑完即清；
- 日志里看得见：那一单的摘要行会带 `接上分卷（硬链接 N / 复制 M，X MB）`。

> 为什么要你手动开：它要读你的源目录、并在盘上造名字（跨盘时还会复制卷）。
> 默认关 = 程序对你的盘**只读**；你确认过那种形状之后再打开。
### 10.2 双面文件 / 内嵌归档

有些文件是"视频 + 尾部塞了一个 zip"（俗称双面文件）。
程序识别出这种文件时，后缀状态那一栏会显示「**内嵌归档**」。

- 请**不要**把它的后缀改成 `.zip`：它前面那截数据远超普通解压工具能容忍的偏移量，改了也打不开，
  只会让你误以为修好了；
- 正确做法是让程序按偏移把尾部那段归档解出来（一键处理会自动做这件事）；
- **程序会优先"直读"**：直接从原文件的 `[起点, 归档终点)` 这一段流式解出条目，
  **不产生那份等大的临时副本**（几百 MB–2 GB 的包，以前必须先拷一份出来才能交给 7-Zip）。
  此时空间核算里**不预留**这笔副本，日志里会写明"本次不需要那份等大的临时副本"；
- **直读不支持时自动回落到"抠出来 + 7-Zip"**（加密条目、bzip2 这类不常见压缩方法、
  ZIP64 字段缺失、中央目录与收尾对不上等），日志里会写明"直读不支持（原因 X），已回落到抠取"。
  这条路抠出来的中间件会放进 `其余物\`，空间核算也照旧把那笔副本算进去；
- 递归模式（§10.1 选了"单链自动展开 / 展开所有分支"）下第 0 层仍交给 7-Zip 处理，
  所以那种设置下**还是会抠一份**，日志里会说明。

**归档不一定正好在文件最后**（2026-09-24 修正）。真实资源包就是这么封的：
`[视频][完整 zip][十几 KB 正常数据]` —— 那十几 KB 在 ZIP 的收尾记录（EOCD）**之后**，
不属于归档。程序按 `EOCD + 22 + 注释长度` 算出**归档终点**，抠取与直读都按终点**截断**，
尾巴上的数据一个字节都不会混进产物（实测那些尾巴有 14,350–17,424 字节）。
带 **ZIP64** 收尾（56 字节 ZIP64 EOCD + 20 字节 locator，大文件才会有）的包同样支持。

识别靠的是**自洽校验**（不猜内容）：从文件尾部**从后往前**逐个试 EOCD 候选，
要求"算出来的中央目录位置真的有 `PK 01 02`"**并且**"算出来的归档起点真的有 `PK 03 04`"，
两条同时成立才算数。所以普通视频、自解压安装器这类"尾部凑巧有几个像 ZIP 的字节"的文件
**不会被误报** —— 凑不出来就还是「格式未知」，**宁可漏报也不给你一个错偏移**。

> 反过来说：文件被截断、EOCD 与中央目录位置对不上的，仍然认不出来（这是有意的）。
> 边界见 §15 已知限制。

**三种"藏在别的文件里"的形状，程序都认**（2026-09-25 第 38 / 39 / 40 条补齐）：

| 形状 | 长什么样 | 程序怎么做 |
|---|---|---|
| **视频 / 图片 + 尾部 ZIP** | `movie.mp4`、`photo.jpg` 后面直接拼一个完整 ZIP | 读文件**尾部 256 KB** 反推 ZIP 起点 → 走**内置直读**（只碰归档那一段，前缀一个字节都不读）；这就是他常说的"`.jpg` 伪装和 `.mp4` 一样" |
| **图片 + 尾部 RAR / 7z** | `封面.jpg`（前缀可以到几百 MB）后面拼一个 `.rar` / `.7z` | RAR / 7z 的结构**不支持**从尾部反推起点，程序**从头扫签名**定位起点 → **抠出 `[起点, 终点)` 交给引擎**。这类**不走**内置直读（直读只解 ZIP）。⚠ 实测：前缀超过约 **1 MB** 之后，7-Zip 与 UnRAR 自己都打不开这种文件（"不是归档"），所以必须由程序定位起点 |
| **ZIP 不在文件末尾**（前后都垫了数据） | `图片 + ZIP + 别的数据` | 顺序扫一遍找 ZIP 的收尾记录（EOCD）→ 逐个做自洽校验 → 给出**精确区间** → 直读或抠取 |

- 三种形状下**归档终点都按归档自己的结构算**（ZIP 按 `EOCD + 22 + 注释长度`，RAR / 7z 取到文件末尾 ——
  两者都能容忍结束标记之后的少量尾巴）：后面垫的数据一个字节都不会混进产物；
- 这些路**只在"文件头认不出来"时才会走**：正常包只读 34 KB 文件头；
  认不出来才读 256 KB 尾部；再认不出来才**顺序扫一遍**（扫到就停，上限 512 MiB）；
- ⛔ 你的原文件在任何情况下都不会被改名 / 搬走 / 删除（除非你自己在 ③「清理与删除」页选了那些档）。

## 11. 手动操作：只改后缀、只解压、停止、取消

不想一键处理时，可以分步做：

1. **智能修正选中后缀** —— 只改后缀，改之前一定弹预览：勾上的行才会改，
   「新文件名」那一列可以**双击直接改**；有冲突的行会显示冲突状态。
   - 点「**确认改名**」= 真改磁盘上的文件名；点「**取消**」= 什么都不做（**不会**默默改一半）。
2. **只解压（不改后缀）** —— 跳过改后缀直接解压（**不改名的包也能直接解**，这是设计上就支持的）。
3. **停止后续** —— 当前任务**继续跑完**，只是不再开始新任务。
4. **取消当前** —— **立刻中止当前任务**（会结束这次解压进程），工作区和日志保留下来供排查。

> 「停止后续」和「取消当前」是**两件独立的事**，不会互相影响。
> 一个任务失败**不会**中断整批，剩下的照样跑。

**改名有没有风险？** 只改你**选中的那个文件名**，绝不碰压缩包里面的任何东西，
而且永远先预览。分卷文件受保护，「智能修正」不会把分卷链切断。

## 12. 空间不够怎么办（并行档 / 空间门 / 「删除操作」三档）

这一节讲的是**"盘快满了，还有一堆包要解"**这种情况。三种做法，从安全到激进排：

### 12.1 先说程序会自动做什么

**① 开跑之前先算账，装不下就不启动。**
每个任务在启动前都会算一次"这一次一共要占多少盘"：

```
峰值需求 = 源包（分卷整组） + 内容物 + 本次会额外产生的过程物
```

- **源包**：解压期间它一直在盘上（选"放入其余物"之后也只是**同盘移动**，不释放空间）；
- **内容物**：解压后的大小（能读到内容清单时用真实数字；读不到时按源包体积估，并标明"估算"）；
- **过程物**：内嵌归档抠出来的中间件（**直读时这一项是 0**，见 §10.2）+ 内容物里的内层包
  **再展开**的增量；
- **去重**：同一个文件只算一次 —— 分卷各卷只算一次，内层包自身已经在"内容物"里，
  这里只算它展开后多出来的那一份。

**峰值算在哪块盘上（2026-09-24 起口径）**：工作区默认就跟着**输出盘**
（`<输出盘>\.ArchiveFixer.work`），所以暂存的内容物与最终的成品是**同一份字节** ——
定稿走的是**同卷改名**，内容物在峰值里**只算一份**（不会算成两份）。
⚠ 只有"工作区被指到另一块盘"时（你在「缓存根目录」里填过路径 / 拿不到盘回落程序目录）定稿才是
"复制 + 删原件"：那时成品盘会多出一份内容物，而**工作区那块盘另外还要留得下 内容物 + 过程物** ——
这一半**不在空间门的账面上**（已知限制，批首日志里会写一条 WARN 说明）。

还要留 **512 MiB** 余量。装不下就**不启动**这个任务，状态显示
「**磁盘空间不足**」，错误信息里写清**需要多少、可用多少、差多少**，并给出建议动作。
**它跟"解压失败"是两回事**：归档本身没问题，只是一个字节都还没开始写。

**② 一键处理按"空间需求从小到大"排序。**
绝不会一上来就去解最大的那几个（那样并行两个都跑不动）。排在最前面的一定是塞得进去的小包。

**③ 并发时把"已经在跑的任务"也算进去。**
两个任务同时看到"还剩 10 G"就一起开跑，是并发把盘写满的典型路径。
所以程序记着一本账：**已经在跑的任务占了多少**，新的任务要看"剩下的够不够我"。

**④ 全部排不下时如实报告。** 日志里会逐个点名"谁被跳过、需要多少、当时可用多少、差多少"，
绝不会静默跳过。

### 12.2 三种做法

| 做法 | 怎么做 | 代价 |
|---|---|---|
| **① 先清 `其余物`** | **③「清理与删除」页 →「删除其余物…」**（默认移入回收站，可还原） | 最安全。上一个包的源包与中间件清掉，空间立刻回来 |
| **② 换输出盘 / 换落点** | **②「解压方式」页 → 落点 →「指定位置」**选一个空间更大的盘 | 安全。产物落到别的盘，源盘压力立刻减半 |
| **③ 让程序成功后自己删** | **③「清理与删除」页 →「2 删除操作」→「彻底删除」**（红字那一档，选中后下面常驻一条红色提示） | **源包与中间件会被永久删除**，见 §12.4 的风险与边界 |

另外，**②「解压方式」页 →「并发与空间」**里还有一个「**并发档**」输入框（`1 / 2 / 3 / 4 / 8`，**默认 4**，
也可以直接填 1~8 的任意数）和一个「**按空间算建议**」按钮：点一下会算出"按当前可用空间，最多能并行几个"
（例如"当前可用 10 GB，建议并行 2 个"）。
**并发越高，同时在盘上的峰值越大** —— 盘紧张时把它调小。

> 默认 4 是实测出来的：并发 1→4 快 **3.08 倍**，而 4→8 只再快 **1.9%**，
> 却把单个包的耗时拉长了一倍（这台机器是 6 物理核，8 个并发已经超订）。
> 界面上这一项旁边会写「**建议不超过物理核心数（当前检测到 N 核）**」。

### 12.3 「删除操作」这三档分别是什么（③「清理与删除」页）

2026-09-25 之后，"要不要动源包"和"要不要动其余物"是**两个独立的选择**（你自己定的那一版）：

**1 源包操作**：
- **原来的位置不动**（**默认**）—— 程序一个字节都不碰你的源包；
- **放入其余物当中** —— 成功且校验通过之后，源包（分卷则整组）被移进成品目录的 `其余物\`。

**2 删除操作**（决定 `其余物` 的下场）：
- **不动其余物**（**默认**）—— 源包与中间件都留着，你自己看过再决定；
- **移入回收站** —— 可还原；空间要等你清空回收站才真正释放；
- **彻底删除** —— **直接省空间**（这正是它存在的意义：净占用基本不变）。这一档**字号是红的**，
  选中之后下面会出现一条**常驻的红色提示**，而且**关不掉** —— 选了它就一直摆在那儿。

触发点只有一句话：**"内容物已定稿并按落点排好 + 输出校验通过 + 没有取消"之后**才动手。
它**不会**做这些事：

- **失败 / 部分完成 / 取消的任务，一个字节都不删**：源包原地不动、`其余物` 不生成；
- 校验没通过的任务同样不删（内容物可能不全，那时最不该动源包）；
- 只处理**本任务自己那一份** `其余物`，不碰同一个目录里其它包的。

> ⚠ **两种路径的时机不一样（但判据完全一样）**：
> **一键处理**会**留到整条续解链跑完**再处理 —— 因为任务刚收尾那一刻，`其余物` 里躺着的正是
> **下一层要解的内层包**，当场删掉后面就解不出来了。
> **手动「只解压」**是单层路径，没有链可等，**当场**按你选的档处理。
> 两种情况下日志都会写明"这一批 / 这一单的其余物会怎么处理"，跑完你看到的和日志写的一致。

### 12.4 「彻底删除」这一档的风险与边界（点之前请逐条看）

1. **源包与中间件会被永久删除**（不进回收站、无法还原，只能重新下载）。
2. 删除发生在「内容物已排好且校验通过」之后，但**校验不等于你确认过内容** ——
   程序只保证"该解出来的都解出来了"，不保证"内容就是你想要的那一份"。
3. 中途断电 / 蓝屏 / 程序被强杀时，可能停在「**其余物已删、内容物未完成**」的状态：
   那时这一份只能重新下载。
4. **只在你确实没有空间时才用它**；正常情况请用默认档（不动其余物），
   或者退一步用「移入回收站」（能还原，代价是空间要等清空回收站才回来）。

> ⚠ 这一档**没有任何前置仪式**（不需要自测、不需要凭证）：以前那套独立的「危险模式」
> （红按钮 + 自测 + 凭证 + 常驻红横幅）已经在 2026-09-25 整块删除 ——
> 它正是过去"明明选了彻底删除、其余物却还在"的原因（凭证不在时程序静默按"不动其余物"走）。
> 现在它就是 ③页上的一个单选项，选了就生效；代价与边界仍如实写在上面这四条里。
>
> 换句话说：**这一档的唯一保护就是"失败一个字节都不删"那条硬规则 + 你自己的选择**。
> 想稳一点，先用「移入回收站」跑几天看看手感。

## 13. 打包：把文件夹变成带密码的压缩包

**⑤「打包」选项卡**（**就这一个入口**，整页都在那儿，没有向导）。

它做的事只有一件：**把一个文件夹 A 变成"压缩包 B"**——

```
A\（你选的源文件夹，里面是要打包的东西）
      │ ① 切成 7z 加密分卷（-mhe：连文件名一起加密）
      ▼
B\A名.7z.001、B\A名.7z.002、…        ← ② 分卷落进新建的文件夹 B
      │ ③ 按你选的外层容器压一层（三选一，都带密码）
      ├─ rar（默认）→ B.rar     ← 需要本机已装 WinRAR 的 Rar.exe
      ├─ 7z         → B.7z      ← 用随程序分发的 7-Zip，无需额外安装
      └─ 不做外层    → 没有外层文件，结果就是 B 里那组 .7z.001/.002/…
```

页面上从上到下就这几样：**源文件夹 A → 输出文件夹 B（默认填好）→ 分卷大小 →
外层容器（三选一）→ 密码 → 摘要行**，然后「开始打包」；下面是进度条 + 当前步骤，
跑完在同一屏显示结果（**外层产物路径 + 容器类型** + 分卷清单 +「复制密码」「打开输出目录」）。

### 13.1 分卷大小（默认 512 MiB）

| 内容大小 | 切出来 |
|---|---|
| 1 GB | `.7z.001` + `.002`（各约 512 MiB） |
| 1.5 GB | `.001` + `.002` + `.003` |
| 4 GB | 8 个分卷 |

默认 **512 MiB**，界面上是一个数字框，可以改成 **64 – 4096 MiB**（整数 MiB）。
实际切几卷取决于**压缩后**的体积，所以摘要里的"预计几卷"是**上界**（内容压得很小的时候会少切几卷）。
分卷名字由 7-Zip 自己产生，程序不自己拼 —— 免得在"正好是整数倍"的边界上多切一卷。

### 13.2 密码（必填，两层默认同一个）

- **密码必须有**：空密码、只有空格的密码都不接受，直接拒绝开始。
- 默认**两层用同一个密码**；勾「外层 rar 用另一个密码」可以把它们分开。
- 密码只在**内存**里活到这次打包结束：不写设置文件、不进日志（日志里只写"已设置密码"）。
- 跑完可以用结果区的「**复制密码**」把它复制到剪贴板 —— 程序自己没有别的地方能把它还给你，
  **请自己存好**。

### 13.3 外层容器：rar / 7z / 不做外层（三个都一直可点）

| 选项 | 结果 | 需要装什么 |
|---|---|---|
| **rar**（默认） | `B.rar`（`-hp`：连文件名一起加密） | 本机已装的 WinRAR（`Rar.exe`）。**程序只检测与调用，绝不随包分发它** |
| **7z** | `B.7z`（`-mhe`：连文件名一起加密） | **什么都不用装** —— 用随程序分发的 7-Zip（LGPL） |
| **不做外层** | 没有外层文件，结果就是 `B\` 里的 `.7z.001/.002/…` | 什么都不用装；也**不需要多一份空间**（空间只要分卷那一份） |

> **为什么 rar 那一项需要你自己装 WinRAR**：`Rar.exe` / `WinRAR.exe` 是**共享软件**，
> RARLAB 的许可（§3.1 / §3.2 / §3.3 / §10）明确禁止把它放进任何别的软件包里分发
> —— 原文就是 **Any bundling is interdicted**。所以程序**不会**替你装、**不会**复制、**不会**随包发。
> 你自己装了 WinRAR，程序就**只读地**看一眼、在打包时调用它。

**没装 WinRAR 时**程序会**在切分卷之前**就明确报错，并给你**三条出路**：

1. 装好 WinRAR（带 `Rar.exe`）后重试；
2. 把「外层容器」改成 **7z**（**无需额外安装**）；
3. 选「**不做外层容器**」，这次就只出 B 里的 7z 加密分卷。

> ⛔ **程序绝不拿 7-Zip 假装做出一个 `.rar`。** RAR 的压缩算法是专有的，7-Zip 建不了它；
> 改个后缀名是伪造，你拿去用的时候会直接坏掉。这里宁可报错，也不骗你。
> ⛔ 也**不会**偷偷把你的选择换成别的容器 —— 换哪一种是你在上面三个选项里自己点的。

**WinRAR 装在别的地方？** **②「解压方式」页 → 引擎**里有 **`Rar.exe 路径`** 一格（带「浏览…」按钮）：
填你自己安装 / 下载的 WinRAR 里的 `Rar.exe` 即可。填了一个不存在的文件时，点「保存设置」会**被拦下**并告诉你
怎么改；**留空 = 自动**用本机已装 WinRAR 目录里的那一份。那一格下面还有一行状态，
写着"当前用的是自选的那份还是已装目录那份"。

### 13.4 落点与"不显示假成功"

- **B 必须是空文件夹或还不存在**：B 会被整个装进外层容器，混进旧文件结果就不对了。
  上一次留下的残留会让程序拒绝开始，并告诉你先清空它。
- **B 不能放在 A 里面**（分卷会落进正在打包的目录，越打越多）；
  **外层容器不能放在 B 里面**（它会把自己装进去）；**A 也不能在 B 里面**。
  （选了「不做外层」时没有外层文件，中间那条自然不适用。）
- 已经存在的同名 `.rar` / `.7z` **不会被覆盖**：程序会让你先改名或换位置。
- 开始之前会算一次空间（有外层：分卷一份 + 外层再存一份 + 32 MiB 余量；不做外层：只算分卷那一份），
  不够就**不开始**，并写明**需要多少 / 可用多少 / 差多少**。
- 做完之后程序会**按容器**自己列一遍条目核对（`.rar` 用 `Rar.exe`，`.7z` 用 7-Zip；
  里面有 B 这一层、分卷数与 B 里一致）。**对不上就不显示成功** ——
  你会看到"产物校验不通过"，而不是一个绿色的"完成"。
- 取消或失败时：**不留半个外层文件**（没做完的会被清掉），已经切出来的分卷**会保留**，
  日志里会写明"分卷已生成、外层未生成"；重试前请先清空 B。
- 打包**不会**动源文件夹 A 里的任何东西（不删、不改名、不搬走），
  也**不会**自动删除 B —— 确认结果没问题之后，B 你可以自己删。

> **已知限制**：调用命令行工具时必须把密码写在参数里（`-p密码` / `-hp密码`），
> 所以**任务管理器 / 进程列表里能看到它**；这与解压侧是同一条固有限制（见 §15 表格的第一行），
> 程序不假装解决了。日志、结果区、失败原因层面都已脱敏。

## 14. 常见问题

**Q1：为什么提示「文件名已加密」？**
这种包（RAR 的 `-hp` / 7z 的 `-mhe`）把**里面的文件名也加密**了，不给密码连"里面有几个文件"都读不出来。
所以程序没法判断它坏没坏 —— 它**可能完全正常，只是需要正确密码**。
把正确密码加进密码本（或手动输入）再解一次就行。⚠ 它不是"成功"，也不算"文件损坏"。

**Q2：为什么非得让我先勾选任务？**
所有批量动作（一键处理、只解压、智能修正、移除选中、删除其余物、清理空文件夹）都**只认勾选** ——
这样你不用一个个点开，也不会"点了个按钮把整表都处理了"。
**一个都没勾时程序什么都不做**，只提示你"没有勾选任何任务"（绝不会退而求其次去动你点中的那一行）。
想只处理一个：右键那一行 →「**只勾选这一个**」。

**Q2.1：我重新选了一批文件，为什么列表里还有上一次的？**
不会再有这种事了：点「**添加文件 / 添加文件夹**」= 先把整张列表**清空**再加入这次选的。
要把新选的**追加**到现有列表后面，用菜单「**文件 → 追加到列表**」（追加文件 / 追加文件夹）。

**Q3：我只想处理其中一个包，怎么做？**
点「**全不选**」（或 `Ctrl+D`），然后**点一下那一行**的勾选列；或者直接在那行右键 →
「**只勾选这一个**」。然后再点「一键处理 / 只解压」。

**Q4：提示「分卷缺失」怎么办？**
程序已经告诉你缺哪几卷了。把缺的卷找回来放到同一个目录，右键该任务 →
「**重新扫描此文件**」，再处理。**缺卷时程序不会开始**（避免白跑一趟还留一堆半成品）。

**Q5：状态里那个「长时间无响应」是什么意思？**
解压时超过 **90 秒**没收到引擎的任何输出，程序就在那一行挂一个提示
（`解压中 45% · 长时间无响应`）。
它**只是提示、不会杀进程、也不改结论** —— 大文件、加密包、慢硬盘上都可能出现。
要不要中止由你决定：点「**取消当前**」就停，让它继续就继续等。
新的一有输出，这个提示会自己消失。

**Q6：进度条为什么只有一个百分比？**
7-Zip 和 UnRAR 给的就是"整包累计百分比 + 当前正在解哪个条目"，
没有"第几个文件 / 还剩多少时间"这种数字。程序**不会编一个数字给你看**，
所以不要把它当成卡住的证据 —— 真正的卡住判据是上面的「长时间无响应」。

**Q7：为什么有的包改完后缀还是打不开？**
先看「后缀状态」那一栏：
- 显示「**内嵌归档**」→ 见 §10.2，改后缀没用，要用"按偏移解出来"的方式（程序优先直读）；
- 显示「文件损坏」或解压失败 → 包本身可能就缺数据；
- 显示「**达到密码尝试上限**」→ 不是密码错，是候选没试完（见 §7.4）。

**Q8：任务显示「部分完成」是什么意思？**
解出来了一部分，但中途因为上限 / 密码 / 损坏停了，**或者内容物好了但源包没能搬进 `其余物`**
（比如源包只读、被别的程序占着）。任务详情里会写明是哪一种。**它不等于成功。**

**Q9：我关掉了程序，会不会有半成品留在外面？**
不会。解压缩过程中间的东西都放在**工作区**里（默认 = 输出盘根目录下的 `.ArchiveFixer.work\`，
你在「缓存根目录」里填过路径的话是 `<那个路径>\work\`），只有"内容物已定好 + 校验通过"才一次性搬到输出目录。
中途取消 / 失败：输出目录里**不会**有半成品，**源包原地不动**，`其余物` 不生成。

**2026-09-25 起：失败 / 取消也不再留中间产物**（用户原话："我不希望有这么多的失败残留……
如果解压 40G，两层，解压失败有 80G 的卸载残留，用户不得气死……失败了就失败了，成功了就成功了"）。
没成功的任务会把**它自己这次的工作区整份删掉**（包括暂存目录、抠出来的内嵌归档副本、已解出的中间件，
以及嵌套解压逐层用的那一份），日志里写一行
「已清理工作区：N 个文件 / X（这次没成功；要留现场请在 ③ 页打开「失败时保留中间产物」）」。
所以**什么都不会留在盘上**，失败原因照样看得到（列表里的「失败信息」列 + 「导出失败清单」）。

- 要**留现场排查**：③「清理与删除」页 →「工作区残留」那一组 → 勾上「失败时保留中间产物（排查用）」。
  打开之后失败 / 取消留下的东西会列在那一组里（名字 / 体积），随时可以点「清理工作区…」清掉。
- **一个文件都没解出来的空壳**：不管这个开关开没开，收尾都**当场删掉**（没有东西可留）。
- 只有这两种情况会在盘上看到工作区残留：① 你打开了上面那个开关；② 程序被强杀 / 断电，来不及收尾。

**Q10：程序会不会偷偷上传什么？**
不会。它**完全不联网**：不自动下载引擎、不上传任何东西、不检查更新。

**Q11：输出目录里那个 `其余物` 删了还能恢复吗？**
默认走**回收站**，可以还原。只有你在确认框里勾了「改为彻底删除，不进回收站」才是真的没了
（那一档确认框会变红，还要再确认一次）。

**Q12：为什么我改了设置却没生效？**
绝大多数设置改完**立刻生效**。两个例外：
- **低运行优先级**：要**重启程序**才生效（启动时读一次）；
- 任何**手改** `data\appsettings.json` 的动作：改完要重启程序。

**Q13：状态显示「磁盘空间不足」，是包坏了吗？**
**不是。** 那说明程序在**动手之前**就算出"这次解压要占的盘比现在空着的还多"，
于是这个任务**一个字节都没开始写**。归档本身可能完全正常。
错误信息里有三个数字（需要多少 / 可用多少 / 差多少）与建议动作，见 §12。
处理办法：清 `其余物`、换输出盘、把并发调小，或者把 ③页「2 删除操作」改成「彻底删除」
（成功后程序自己回收空间）。

**Q14：为什么有的包一上来就被跳过了，而不是排在后面？**
一键处理按"空间需求从小到大"排序。装不下的任务会被跳过并**逐个点名报出来**（日志里），
剩下的照跑。跳过的任务不会被静默丢掉 —— 它们的状态是「磁盘空间不足」，也会进失败清单。

**Q15：我选了「彻底删除」，为什么有些任务没删其余物？**
因为那一条是红线：**只有「解压成功 + 输出校验通过 + 你没取消」的任务才会删**。
失败 / 部分完成 / 取消的任务一律不删 —— 源包原地不动、`其余物` 不生成。
日志里会写清每个任务"删了"还是"没删、为什么没删"。
另外两条容易误会的：**一键处理是等整条续解链跑完才删**（中途删会把后面几层要用的内层包一起删掉），
所以你在第二批续解跑完之前看到 `其余物` 还在是正常的；而**「源包操作」选了"原来的位置不动"**时，
源包本来就不进 `其余物`，那一档只处理中间件。

**Q16：我改回「不动其余物」，之前删掉的源包能回来吗？**
不能。「彻底删除」那一档是**永久删除、不进回收站**（要能还原就用「移入回收站」那一档）。
改回默认档只是"以后不再这么干"。
（顺带说一句：这一档现在**没有**任何自测或凭证 —— 以前那套"危险模式"已经在 2026-09-25 整块删除，
它正是"明明选了彻底删除、其余物却还在"的原因。）

**Q17：为什么每次解压前都弹一个「解压前的提醒」？那些文件能不能删？**
这个框把两件事合在一起说，**都不是错误**，也不会改变解压结果：

- **① 可能的「无用物」**：源文件夹里那些 `.txt` / `.url` / `.html` / `.htm` / `.lnk` / `.exe` / `.bat` / `.cmd` /
  `.ps1` / `.vbs` / `.js` / `.jpg` / `.jpeg` / `.png` / `.gif` / `.bmp` / `.db` / `.ini`，以及 `Thumbs.db`、
  `.DS_Store`，**很可能是打包者附带的**说明、网址、工具或广告（引诱你点、诱导你装东西的那种）。
  程序只按文件名猜了个大概，**不保证**它们真没用，所以：
  **本程序一个都不会动**（不删、不改名、不搬走）—— 解压完成后你可以自己看一眼，再决定要不要删。
  判定刻意收窄：属于本次要处理的包（含分卷）不会列进来；**凡是魔数能认出是压缩包的，一律不算** ——
  后缀写着 `.jpg`、里面其实是压缩包的伪装包绝不会被叫成无用物（那正是本程序最擅长的情况）。
  上限：每个目录最多扫 2000 个文件、最多列 10 条（多出来的写"还有 N 个"）、最多扫 50 个目录。
- **② 需要密码、但当前一个可用候选都没有的包**：密码本里没有、映射式没命中、也没设统一密码。
  继续跑的话，它们大概率会以「**密码错误**」或「**达到密码尝试上限**」结束 —— 既不是成功，也不是文件损坏。
  两条路：点「**先不处理**」回到列表，把它们从勾选里去掉（或先把密码补上）再重跑；
  点「**继续处理**」就照常开始（程序紧接着还会问你要不要手动输一个密码）。
- 想让它别再弹：勾「**本次运行不再提示这类提醒**」—— **只在本次运行内有效**（关掉程序重开还会提醒），
  程序**不会**把这个勾写进任何设置文件。整批只弹这一次。
- 想**永久**关掉这一条提醒：**③「清理与删除」页 →「解压前的提醒」**里取消勾选（默认开）。
  关掉之后这一遍扫描与弹窗都不做，直接开始解压。

**Q18：为什么报「源文件已变化」？我该怎么办？**
程序在**识别（扫描）那一刻**记下了每个源包（分卷则整组）的**大小**与**修改时间**。
真正开始解压之前它会再对一遍：对不上就**不启动引擎**，状态落「源文件已变化」，错误信息里点名
**是哪一个文件、哪一项变了**，形如：

```
源文件已变化：222.7z（大小 1.2 GiB → 1.3 GiB）。识别结果作废，本次没有开始解压
（引擎没有被调用，源包一个字节都没动）。请右键该任务 →「重新扫描此文件」重新识别后再处理。
```

- 常见触发：你（或别的工具）在扫描之后**换了 / 改了 / 删了**那个包；分卷组里动了**任意一卷**（会点名是哪个卷）。
- **怎么办**：右键该任务 →「**重新扫描此文件**」（与「分卷缺失」给的是同一条出路），再处理即可。
- 这一拦**什么都没做**：引擎一次都没被调用、源包原地不动、`其余物` 不生成、输出目录里不会有半成品。
- ⚠ 判据只有**大小 + 修改时间**，不比对内容哈希（见 §15）。所以"只是被别的工具摸了一下时间戳"
  （甚至被某个程序打开过一次）也会触发 —— 宁可多问一次，也不拿旧识别结果去解新文件。

## 15. 已知限制（如实说明）

这些是"已知且记录在案"的，不是没想到：

| 限制 | 说明 |
|---|---|
| **密码会出现在进程列表里** | 调用命令行引擎时必须把密码写在参数里（`-p密码`），所以**任务管理器里能看到**。日志、报告、清单层面都已脱敏，但这一条是命令行工具的固有限制，**程序不假装解决了** |
| **密码列表记忆是"机器范围"加密** | 按本机 DPAPI（机器范围）加密存在 `data\password-list.dat`（用户 2026-09-24 选定）。**同机任何本机用户都可能解开它** —— 它保护的是"文件被别人拿到也看不懂"，**不是**防住这台机器上的其他账号。**换机器 / 重装系统解不开**：那时程序**忽略并提示**（不崩、不覆盖、不删文件），出路是在原来的机器上用「写回密码本…」把列表写进你自己的 txt 再带走。不想要这份记忆就在设置里关掉「记住密码列表」（关掉 = 既不写也不读，磁盘上已有的那份不会被删） |
| 进度只有"整包一个百分比" | 引擎只报这么多信息（见 Q6） |
| **压缩炸弹拦不住已经写出去的那一次** | 程序能"解压前按清单拦 + 解压后按实测量拦并停止后续"，但引擎往磁盘写的那一刻我们看不见 |
| 落点校验只看得见目标目录**里面** | 引擎绕过程序直接写到别处的话，事后发现不了（两道防线只能覆盖"产物目录内可观察"的越界） |
| 可疑条目**只提示、不阻断** | 会统计"这个包里有多少个可执行 / 脚本类条目"写进详情，但**不会**因此拦下解压（安装器、补丁本来就常是内容物）。这只是提示，**不是**杀毒判定 |
| **源文件变化检测只比"大小 + 修改时间"** | 扫描时记下大小与修改时间，解压动手之前对一遍，对不上就报「源文件已变化」并**不启动引擎**（见 Q18）。⚠ **不比对内容哈希** —— 全量读一遍几百 GB 的分卷组是不可接受的代价。所以边界有两条：① 被别的工具"摸"了一下时间戳（甚至只是被某个程序打开过）也会触发；② 反过来，如果文件被换成**大小和修改时间都恰好一样**的另一份，检测不出来 |
| 符号链接条目看不出来 | 归档里的链接指向哪，条目列表里看不到；靠"解压后落点校验"发现（**发现即判失败**，但拦不住那一次写入） |
| 外接盘 / 网络路径未专门适配 | 只保证不写死盘符、不在源目录建工作区；盘符变了、拔盘断连的恢复不做 |
| **WinRAR 本体不能随包分发** | 它是共享软件（RARLAB 许可明文 **Any bundling is interdicted**），程序绝不捆绑也不复制，只保留"你自己装了、程序检测并调用"这个位置。所以打包的**外层 rar** 需要你自己装 WinRAR；不想装就把外层容器改成 **7z**（内置 7-Zip，无需额外安装）或选**不做外层**（见 §13.3） |
| **打包的外层容器产物名跟着容器走** | rar → `B.rar`、7z → `B.7z`、不做外层 → 没有外层文件。结果区与日志都会写明**容器类型 + 实际产物路径**，不会只报一句"完成" |
| **打包取消 / 失败会留下不完整的分卷** | 按设计保留已切出的分卷（重试可能还要用），只保证**不留半个外层文件**；提示里写明"重试前先清空 B" |
| RAR 侧引擎也不是万能的 | 两个引擎都解不开的畸形包仍然会失败（这时报的是**失败**，不会显示成功） |
| **绿色版必须放在可写目录** | 设置 / 日志 / 临时文件都在程序目录下的 `data\`。放进 `C:\Program Files\` 之类需要提权的位置会写不进去（日志会退化，不会崩） |
| **空间门按"输出盘"算** | 它探的是**输出目录所在的那块盘**（开了结果归集时是归集目标盘）。默认档下工作区就在这块盘上，所以账面是完整的（见下一行）。如果你在「缓存根目录」里把工作区指到了**另一块盘**，那块盘不重复核算 —— 它写满时仍然会由引擎报错兜底（那时是「解压失败」，不是「磁盘空间不足」），程序会在批首写一条 WARN 把这件事说明 |
| **工作区与成品同卷时，内容物只算一份** | 默认档下工作区就在输出盘上（`<输出盘>\.ArchiveFixer.work`），暂存的内容物与最终的成品是**同一份字节**（定稿走同卷改名），所以峰值 = 源包 + 过程物 + 内容物**各一份**，不会算成两份。⚠ 工作区被指到**另一块盘**时（缓存根目录 / 拿不到盘回落程序目录）定稿那一步是"复制 + 删原件"：成品盘会多出一份内容物，而**工作区那块盘另外还要留得下 内容物 + 过程物** —— 这一半**不在空间门的账面上**（已知限制，批首日志里会写明） |
| 空间需求是**估算**，不是保证 | 内容物能读清单时用真实数字；读不到（加密头 / 引擎拒绝列目录）时按源包体积估，并标明"估"。估算**宁可高估**，所以偶尔会拦下本来勉强能跑的任务 —— 那时清理 `其余物` 或换盘即可 |
| **取不到可用空间时不做空间门判断** | 盘没就绪、路径异常、网络盘取不到大小时，程序**不会**拦（不敢把"探测失败"说成"空间不足"），只会写一条 WARN。这种情况下磁盘写满仍然由引擎报错兜底 |
| **「彻底删除」这一档不可逆** | ③「清理与删除」页「2 删除操作」选它之后，成功任务的那一份 `其余物`（源包 + 中间件）会被**永久删除**（不进回收站）。风险与边界见 §12.4。想能还原就选「移入回收站」，想什么都不动就保持默认的「不动其余物」 |
| **删东西只发生在"成功后"** | "失败 / 部分完成 / 取消 → 一个字节都不删"是硬规则（程序内部有五道门槛钉着它）。它保护不了的是"成功之后你自己发现解错了" —— 那时已经删了 |
| **一键处理删其余物的时机是"链尾"** | 续解链跑完之前 `其余物` 会一直在（里面还有下一层要解的内层包）。所以你看到 `其余物` 暂时还在是正常的；日志里每个任务收尾都会写明它最后的下场 |
| **改回"不动其余物"** ≠ 找回文件 | 改档位只停止后续删除，**不会**恢复已经删掉的东西 —— 要能还原请在删之前就选「移入回收站」 |
| **提醒音的音量由系统决定** | 需要你处理的窗口（警告 / 错误 / 询问 / 密码输入 / 密码本）会**闪任务栏**（一直闪到你点它）并**连响三声**。响度上限就是 Windows 的提示音音量 —— 程序不能也不该超过它；觉得轻就调"系统 → 声音 → 音量合成器 / 提示音音量"。**静音时只有闪烁、没有声音**（这是系统设置，程序不会绕过它） |
| **「无用物」只是按文件名猜的** | 解压前那条提醒里的清单只看**文件名 + 魔数体检**（用来排除真压缩包），**不读内容、不判断有没有用**；判据刻意收窄（只报打包者常放的那几类），所以**漏报很正常**，数量与清单也**不是**杀毒或"可删"的判定。程序对这些文件**只提示、绝不删除**，删不删由你自己决定 —— 拿不准就先留着 |
| **内嵌归档（双面文件）只认"自洽"的证据** | 判据两条同时成立才算：① 算出来的中央目录位置处真的有 `PK 01 02`；② 算出来的归档起点处真的有 `PK 03 04`。因此 **EOCD 之后允许还有别的数据**（那不参与归档，抠取与直读都按 `EOCD + 22 + 注释长度` 截断）、**ZIP64 收尾也支持**。两条路找 EOCD：先读**尾部 256 KB**（ZIP 收在末尾时够用），不够时**顺序扫一遍**（上限 **512 MiB**，扫到就停）—— 所以"ZIP 在文件中间"也认得出来。而"自洽"始终是**必要条件**：文件被截断、只有一个孤儿 EOCD、中央目录位置对不上的，仍然显示「格式未知」并**不会**乱指一个偏移去抠（宁可漏报，不可误报）。同理，**超过 512 MiB 之后**才出现的归档仍然认不出来 |
| **内嵌归档的"直读"也有它的边界** | 直读只认 **ZIP**（RAR / 7z 一律走"抠出来 + 引擎"），而且只在"中央目录声明偏移 == 从 EOCD 反推的实际起点"、方法 ∈ {stored, deflate}（**AES 加密条目自己解**，见 §10.2 与 `ZipAesCrypto`；老式 ZipCrypto 仍回落）、ZIP64 字段齐全时才走。任一条不成立就**回落到"抠出来 + 7-Zip"**，日志里写明原因 —— 那是"这条路走不通"，不是"这个包坏了"。递归模式下第 0 层仍交给 7-Zip，所以那种设置下照样会抠一份副本 |

## 16. 出问题了怎么反馈

反馈的时候带上这几样，对方一眼就能定位：

1. **`data\logs\` 里最新那个日志文件**（**⑥「设置」页 → 日志 →「导出日志」**可以直接导出）；
2. **失败清单**（点「导出失败清单」存成 txt）——里面有每个失败包的原因和它实际用的引擎；
3. 任务的**状态**和**错误信息**两列的文字（也可以右键 →「复制任务信息」）；
4. 能重现的话：你做了什么、点了哪个按钮、看到什么。

> ⚠ **别把真实密码贴进反馈里。** 日志里本来就不含密码明文，你也不用补上。
> 需要说明"是加密包"时，写"加密包，密码在密码本里"就够了。
