# 引擎与外部工具（能用哪些、以及许可证边界）

> **本文性质**：工程说明书 + 边界记录，**不是**需求、不是规格、不是法律意见。
>
> 依据：`AGENTS.md` §2（非目标）/ §3.1（多引擎架构与 WinRAR 位置保留）/ §6（不变量）/ §12 第 3 条（LICENSE 未定），
> 以及 `docs/WinRAR功能参考.md` §4–§5（对 WinRAR 分发条款的阅读理解，来源是本机 `C:\Program Files\WinRAR\`
> 的 `License.txt` / `Rar.txt` / `ReadMe.txt` 与解出的帮助主题）。
>
> ⚠ **本文不代表"已经接线"**：第二引擎（RARLAB 的 `UnRAR`）在本版**没有任何调用代码** ——
> `Engines/ToolLocator.cs` 目前只认 7z，源码里没有任何 rar / unrar 探测。
> 本文是给**将来真接第二引擎**时用的说明书：先说清"能用什么、绝不能分发什么"，再动手。
>
> ⚠ **许可证结论一律以原文为准**。这里只做工程判断（"能不能随包放、能不能调"），
> 正式对外分发前必须逐条复核原文，并请人复核。

## 0. 一页速览：能分发什么、不能分发什么

| 工具 | 谁提供 | 能不能随包分发 | 能不能调用 | 本版状态 |
|---|---|---|---|---|
| **`7z.exe` + `7z.dll`**（7-Zip 26.01） | **我们内置**在 `ArchiveFixer/tools/7zip/` | ✅ 可以（LGPL：未修改 + 随包带许可文本 + 说明如何取得对应源码） | ✅ 当前**唯一**引擎 | **已接线**（`Engines/SevenZip/SevenZipEngine`） |
| **`UnRAR.exe` / `UnRAR.dll`**（RARLAB 官方解压件） | 用户自装（将来也可随包分发，届时**带其许可文本**） | ⚠ 免费可用于**解压**；分发要带许可文本，且**不得**用于造一个 RAR 压缩器 | ✅ 可作为"用户自装的第二引擎" | **未接线**（本版只留位置） |
| **`Rar.exe` / `WinRAR.exe`**（共享软件 / 简体中文非商业个人版） | 用户自装 | ⛔ **绝不分发、绝不捆绑**（其许可本身禁止再分发与捆绑） | ✅ 只允许"**用户自装、我们检测与调用**"（`AGENTS.md` §3.1） | **未接线**（连探测都没有） |

**一句话**：我们只内置 **7-Zip**；RAR 侧一律走"**用户自己装、我们只检测与调用**"，
而且**只解压、绝不改包**（README「设计边界」的承诺，`AGENTS.md` §6 不变量 1/4/5）。

## 1. 我们的位置（先把边界说死）

1. **不捆绑、不默认依赖、不自动探测安装、不做安装包 / 自更新**（`AGENTS.md` §2 非目标）。
   WinRAR 许可证本身就禁止捆绑与再分发（`docs/WinRAR功能参考.md` §5.2 第 2 条），
   所以这条不是取舍，是**硬边界**：想捆也捆不了。
2. **只读归档**：所有引擎都**只用于解压（读）**。我们不实现建包、修包、改注释、改分卷、锁包 ——
   所以任何第二引擎也**只允许接它的解压能力**，不得因为"它有 `a`/`d`/`u` 命令"就顺手接进来。
3. **外部工具路径只有一个来源**：`Engines/ToolLocator.cs`（`AGENTS.md` §3.1）。
   禁止在任何别的文件里再拼一遍 exe 路径 —— 一旦有两处，"这次到底用的哪个引擎"就说不清了。
4. **能力按引擎版本记录**（`AGENTS.md` §3.1、设计.md §十八）：引擎名 / 版本 / 格式 / 操作 /
   能力结果 / 测试样本 / 已知问题。同一个引擎不同版本能力可能不同，不能只写一次"支持 RAR"。
5. **回退规则照设计.md §二十**：可换引擎的只有 `UnsupportedFormat` / `UnsupportedFeature` /
   `EngineUnavailable` / `ParserRejected` / `KnownCompatibilityIssue`；
   `WrongPassword` / `MissingVolume` / `UnsafePath` / `NoDiskSpace` / `PermissionDenied` /
   `SourceChanged` / `DeviceOffline` / `UserCancelled` / `OutputLimitExceeded` **换引擎也没用，直接报给用户**。
   备用引擎只解出一部分时，状态必须是 `PartiallyCompleted`，**不得显示 Completed**（不变量 6）。

## 2. 内置 7-Zip（`tools/7zip/7z.exe` + `7z.dll`，26.01）

- **现状**：这是唯一的引擎，走命令行（`Engines/SevenZip/SevenZipProcessRunner`）；
  `7z.dll` 的**进程内调用是预留通道**（只做了存在性检查），第一版不做。
- **许可证**：7-Zip 主体是 **LGPL**，其中 RAR 解码部分带 **unRAR restriction**（见下）。
- **分发义务（LGPL）**：
  1. 随包附上 **7-Zip 的许可文本**（`License.txt` / `DOC/License.txt` 一类）；
  2. 我们是**未修改原样**内置的（`AGENTS.md` §3.1 已写明），因此不需要附带我们的修改；
  3. 说明如何取得对应源码（指向 7-Zip 官方发布页即可）—— 分发前把这三件事一起做完。
- **`unRAR restriction` 的边界**（要点，原文为准）：7-Zip 的 RAR 解码源自 UnRAR 源码，
  允许在任何软件里**免费处理 RAR 归档**，但**不得**用它去开发 RAR（WinRAR）兼容的**压缩器**，
  也不得用它反向重建 RAR 压缩算法。
  → 我们的用法（**只解压**）正落在这条允许里；**将来也绝不允许**把 RAR 解码拿去做压缩。
- **已知的诚实边界**：`7z.exe` 是独立进程，**它自己的落盘我们看不见**
  → 两道防线只能是"解压前条目预检 + 解压后落点校验"（`README.md` 已知限制第 4 行）。
  第二引擎同样适用这条，不要以为换个引擎就有了额外保障。

## 3. RARLAB 的 `UnRAR.exe` / `UnRAR.dll`（将来"用户自装的第二引擎"）

- **它是什么**：RARLAB 官方的**解压专用**命令行 / DLL（`unrar x`、`unrar l`、`unrar t`），
  与共享软件的 `Rar.exe`（会压缩、受 40 天试用 / 注册限制）**不是一回事**。
- **为什么它是 RAR 侧的合理选择**：**免费可用于解压**，格式支持最正（RAR5、加密文件名 `-hp`、
  分卷、恢复记录都在），而且用户机器上常常已经装了 WinRAR —— 它自带的 `UnRAR.exe` 就在同一个目录里。
- **许可要点**（原文为准）：
  1. 解压用途**免费**；
  2. **不得**用于开发"RAR 兼容压缩器"或反向重建 RAR 压缩算法（与 unRAR restriction 同源）；
  3. 分发（含随包分发）**必须附带其许可文本**；若将来要随包分发 `UnRAR.exe`，
   把这件义务写进发布清单，并与内置 7-Zip 的许可文本一起放。
- **接线时要注意什么**（写给将来的实现者）：
  1. 它只接**解压侧的能力位**（`can_probe` / `can_list` / `can_test` / `can_extract` /
     `supports_password` / `supports_multi_volume` / `preserves_unicode_names` …），
     入口必须仍是 `IArchiveEngine` 的四件事（probe / list / test / extract），
     **不得**让 `Extraction/` 或 GUI 直接拼 `unrar` 参数（`AGENTS.md` §3.1 四条禁止项）；
  2. 路径来源只能加在 `ToolLocator` 里（"用户配置的路径 → 已知安装位置探测"），
     并且**探测顺序与当前生效引擎必须能在界面上看到**（设计.md §十九的"显示当前是否在用"）；
  3. 输出解析（退出码 / 进度 / 错误分类）**只允许写在它自己的引擎目录内**，统一映射成
     既有错误码；RAR 的退出码表可参考 `docs/WinRAR功能参考.md` §1.15；
  4. 界面里提到它时**只做事实性说明**（"检测到用户自装的 RAR 解压引擎，路径 …"），
     **不要**用 WinRAR / RAR 的名称或图标做宣传性表述（保守做法，见 `docs/WinRAR功能参考.md` §5.3 第 3 条）；
  5. 密码同样只存内存、命令行 `-p<明文>` 的固有限制照旧（不变量 5、README 已知限制第 1 行）。

## 4. `Rar.exe` / `WinRAR.exe`：共享软件，**绝不分发**

- **绝不做的四件事**（`AGENTS.md` §2 / §3.1）：捆绑、默认依赖、自动探测安装、复制其任何文件进本仓库。
- **`AGENTS.md` §3.1 保留的位置**只有这一种形态：
  **用户自装、自选路径，程序只检测与调用，并在界面显示当前是否在用**（正式分发前核对许可证）。
- **为什么这条没有商量余地**：本机这份许可（《简体中文 RAR 非商业个人版最终用户许可协议》）
  明确禁止再分发单独部分、禁止放进其它软件包分发、**禁止任何形式的捆绑**，
  并且限**自然人非商业**用途、不得去除其广告对话框（`docs/WinRAR功能参考.md` §5.2）。
  换句话说：即使将来想做 `Rar.exe` 支持，也只能是"读用户自己装的路径 + 传参调用"。
- **本版连检测都没做**：`ToolLocator` 里没有 rar / unrar 的探测位置（源码 grep 零命中），
  所以现在**不存在**"误用它的二进制"这条风险。将来加探测时，把这一节当验收清单。

## 5. `C:\Program Files\WinRAR\7zxa.dll` 是什么，以及为什么我们不需要它

- 它是 **WinRAR 自带的第三方组件**：来自 **7-Zip** 的**只解压 DLL**（LGPL 2.1 或以后），
  WinRAR 用它来解压 `.7z` 归档（`docs/WinRAR功能参考.md` §5.2 第 7 条 / §5.3 第 2 条）。
- **我们不需要它**：我们已经自带完整的 `7z.exe` + `7z.dll`（同一个上游项目，且版本更新、功能更全）。
  去借用 WinRAR 目录里的那份 DLL，只会把"我们的引擎来自哪里"搅浑，还多一层许可与版本不确定性。
- 顺带一个**有用的旁证**（不是结论）：WinRAR 在自己的闭源产品里未修改地使用 7-Zip 的 LGPL 组件来解压 7z，
  说明"未修改地使用 7-Zip 的解压组件"在 LGPL 下是被接受的做法。
  但**我们的形态不同**（内置的是独立可执行文件，且含带 unRAR restriction 的 RAR 解码）
  → **不能靠这个旁证直接下结论**，仍需按 §2 的义务逐条核对。
