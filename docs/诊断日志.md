# 诊断日志（日志升级 v2）

目标：用户只发日志、没有原包和工具时，也能回答「哪一份、哪一层、哪条判据、什么结论、动了哪个文件、机器是什么环境」。

## 三份日志

每次启动在日志目录生成同一时间戳的三份文件：

| 文件 | 用途 | 纪律 |
|---|---|---|
| `ArchiveFixer_*.log` | 人读日志 | 成功任务仍只留少量行 |
| `ArchiveFixer_*.jsonl` | 人读行的机器孪生 | 与 `.log` **一比一**，字段固定 |
| `ArchiveFixer_*.trace.jsonl` | **诊断事件**（新详细日志） | 不占人读行；一条事件一行 JSON |

「导出日志（本次操作）」与「导出全部日志」会把对应的 `.trace.jsonl` 附在导出文件末尾；用户只发这一份 txt 也不会丢诊断事件。

## 公共字段

所有 `.jsonl` / `.trace.jsonl` 记录都带：

- `schema`：`archivefixer.log.v2`
- `ts` / `level` / `msg`
- `seq`：本次运行内序号
- `run`：本次进程运行 id
- `pid` / `thread`
- `batch` / `round` / `sample` / `stage` / `task` / `layer`
- `file` / `identity`

判据行另有：`criterion / inputs / verdict / action`。

## 诊断事件（trace）

### `session.environment`
OS、架构、.NET、进程 id/名字/启动时间、机器名、用户、工作目录、程序版本、日志目录、区域设置。

### `session.settings`
本次设置（名字里带 `Password` / `密码` 的属性一律不写）与工具状态（7-Zip / UnRAR / WinRAR 的解析结果）。

### `batch.start` / `batch.end`
本批/本轮任务清单：路径、大小、最后写入时间、物理身份、检测格式、后缀状态、卷事实、输出层、父任务、内容卡（任务开始时另见 `task.begin`）。结束事件带每个任务的终态、错误、输出路径。

### `task.begin`
单个任务开始前的完整快照，含 `content_card`（格式 / BodyKind / Membership / 卷号 / 自述片数 / 自述整包字节 / 首卷标志 / ZIP EOCD/LH / 基名 / 规范卷名）。

### `engine.extract`
每次引擎解压：引擎 id、命令行摘要、退出码、错误类型、关键输出行、成功/失败。

### `group.linked`
第二大步建组/链接：组基名、族、状态、结论、入口、片顺序、缺片号、规范名计划证据。

### `file.rename` / `file.delete`
改名/删除：来源、目标、字节数、物理身份、结果。源包删除由 `PurgeLayerSourcePackage` 的唯一闸门写出。

### `exception`
异常类型、消息、内部异常、HResult、完整 `ToString()` 栈。

## 只看日志怎么排

1. 打开 `*.trace.jsonl`，先看 `session.environment` / `session.settings`：系统、版本、设置、工具。
2. 看 `batch.start`：本批到底有哪些文件、每个文件多大、内容卡是什么。
3. 按 `task` / `group` 筛：组建立没有、owner 是谁、片顺序/缺片号。
4. 看 `engine.extract`：引擎原话、退出码、错误类型。
5. 看 `file.rename` / `file.delete` 与 `batch.end`：动了哪些文件、终态与产物。
6. 判据行（`criterion`）给出输入与结论；任何“判不出”都应有 `inputs`。

⛔ 密码永远不会写进任何一份日志；导出时还会再统一过一遍脱敏。
