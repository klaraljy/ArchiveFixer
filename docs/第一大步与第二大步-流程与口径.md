## 0. 一句话

**一个轮 = 第一大步（单一压缩包全部解压）+ 第二大步（分卷，只解一层）。**
一轮结束时按「解出来的东西**是什么**」决定下一轮从哪一步开始（`Extraction/RoundProductClassifier.cs`）：

- 解出来的是**内容物** ⇒ 结束（进删除档）；
- 解出来的是**单一压缩包** ⇒ 下一轮第一大步；
- 解出来的是**分卷** ⇒ 下一轮直接第二大步（⛔ 不再过一次第一大步）。

⚠ 同一批产物**在不同轮里角色不同**（用户打的比方 `1+=1`）⇒ 每到轮边界**按盘上事实重新分类**，
⛔ 不许把上一轮的角色当继承属性带过去。R1（轮判定进代码 + 一行轮结论）与 R2（第二大步只解一层，
靠任务级事实位 `_volumeStepTasks`）已落地；**R3（每轮重算入口包/工作区/落点）还没做**。

## 1. 第一大步：三道工序，顺序不可颠倒

| 工序 | 要做什么 | 出处 |
|---|---|---|
| ① **识别底层** | 读**底层**（魔数 + 头尾若干字节），找出伪装文件；认不出 ⇒ 什么都不做 | `docs/分卷专属算法-待校验.md` §0/§1（唯一出口 `Detection/FileNature.Inspect`） |
| ② **还原** | 把伪装后缀**替换**成规范形态（⛔ 不是追加；基名一个字不动；只改名、内容零字节改动） | 同上；唯一出口 `Extraction/VolumeNameRepair.cs` + `VolumeGroupResolver.TryBuildCanonicalVolumeNameForIndex` |
| ③ **再匹配** | 还原之后**回到第一层重判一次**（"回环"），⛔ 不许拿伪装名直接去匹配 | `需求变更.md:5259-5274` |

**第一大步的范围**（`需求变更.md:5991-5993`）：

1. **能解压的统统解压**；
2. 剩下的才是分卷缺失的 ⇒ **先跳过**；
3. ⛔ **不在第一大步里写"分卷缺失"结论**（"没有到最后一步都是先跳过"）；被推迟的只有**缺卷结论**与**组卷归位**；
4. "**最后的文件全放在一起**我们就能看到了"。

**第一大步的红线**（`需求变更.md:5278-5288`）：

- 只碰**我们自己产出的内层包副本**；用户源目录一个字节不动（那一档归批首「修正后缀」）；
- 只改名、**全成或全不成**、绝不覆盖（目标被占 ⇒ 整组一个都不改 + WARN）；
- 判据只准转调既有两把尺子（骨架化 / 归档体还原），⛔ 不新造第三把；
- **判不出 ⇒ 什么都不做**。

## 2. 第二大步：分卷的解压，只解一层

- 第二大步的**原包**可以来自第一大步的内容物（"第一大步的内容物可能成为第二大步的原包"）；
- 处理对象 = **一个分卷组**，从**入口包**启动；
- **只解一层**（分卷专属那把尺子），位置 = **入口包所在那一层**（"对哪个包输入密码，就在哪个地方设工作区"）；
- ⛔ 只有走到第二大步才对分卷动手（第一大步遇到分卷片先跳过）。

**四族入口包**（落点契约的一部分，唯一出口 `Detection/GroupVolumeDirectory.cs`）：

| 族 | 入口 |
|---|---|
| 7z 分卷 | `X.7z.001` |
| RAR 分卷 | 第 1 卷（`X.part1.rar` / 老式 `X.rar`） |
| 跨盘 ZIP | **末片** `X.zip`（`.z01` 只是第 1 片） |
| ZIP 通用分片 | `X.zip.001`（对归档再分片） |

## 3. 缺卷 = 部分完成（用户 2026-10-08 拍板）

- 「最后一轮检测到了缺失分卷**这就是部分完成**，因为连完整的都没有，**这就不是程序的错误**」（`需求变更.md:6042`）；
- 「如果是完整的……有错误，比如说密码、和压缩包卷尾缺失了一块，**这就是失败的情况了**」；
- 判据 = **完整性**：不完整（缺卷）⇒ 部分完成；完整却解不开 ⇒ 失败；
- 落地按**状态常量**分流，⛔ 不比中文文案（`需求变更.md:6044`）；
- ⛔ 缺卷要**列进清单并点名缺哪几个**（不变量 7 的表面必须保住）；
- 半套分卷**不许**进可删的其余物（`RestVolumeCompletenessGate`）。

## 4. 其余物 = 按"来路"判，⛔ 不按名字判

出处：`docs/输出与整理模型.md:268-297`。

- 成员只有两个来路：**原包**（留到最后才删）、**过程物**（逐层删）；
- ⛔ **本链产出的内容物绝不进其余物** —— 它要落地，一个字节都不收起、不删除；
- 判"这是不是本链产出"只有一处：`ExtractionCoordinator.IsEngineOutputFile`（三条判据：
  ① `FinalOutputPath` ② 每层 `OutputPath` ③ 每层 `ManifestEntries`）；
- 判不出来路 ⇒ **什么都不做**；
- ⛔ 红线：不许把"本链产出 = 内容物"推成"暂存区里一切都是内容物"
  （会打掉三处分卷安全闸门 = 2026-09-30 那次 25 GB 被当其余物永久删除的防线）。

## 5. 落点契约（第二大步的入口）

- 落点 = 「**谁可以输入密码，就解压到谁那边**」的那个包所在的那一层 + 一层包名目录；
- 落点**最少两层**文件夹（最外层=包名目录，最里层=最后一个内层包层）；省层只能省中间的内层包层；
  普通文件夹永不摊平（唯一出口 `Extraction/PackageLayerRules.cs`）；
- 入口包还压在别的包里时，沿产出链**一层一层往上叠**算它将来落在哪一层（有防环上限）；
- ⛔ 不按任务表顺序、不按"缺卷那一单所在目录"选；
- ⛔ 用户源目录里的片**只硬链接、不改名不搬**（四次试做都打断管线）；
- 「接片」那一档：本单自己暂存目录里那一份**只建链接、绝不搬走**（唯一出口 `ShouldMovePieceIntoGroup`）。

## 6. 验收判据（大测试按这五条判红绿）

| 判据 | 含义 |
|---|---|
| ① | 内容物解出来（内容字节齐、能读） |
| ② | 内容物只在一个目录里（不再套多余层、不散落） |
| ③ | 没有残留脚手架（`.ArchiveFixer.work` / 过程物壳 / 临时名） |
| ④ | 落点按档（就地对/-指定位置两种口径） |
| ⑤ | 盘上没有 `.ArchiveFixer.work` 残留 |

## 7. 当前实现状态（2026-10-18 记账）

- **R1 / R2 已落**（轮判定 + 第二大步只解一层）；**R3 未做**（每轮重算入口包/工作区/落点）。
- **底层识别是第一判据**：`FileNature.Inspect` 一张卡（格式 / 分卷身份与卷号 / 名字线索 / 物理身份 /
  zip 内容事实），消费方一律先问卡再谈名字（`docs/分卷专属算法-待校验.md` §0）；
  名字只在内容给不出答案时参与，且只参与**定序**与**改名执行**。

  （`大测试-造困难包.ps1` 的 `Add-Wraps`），所以盘上单个文件可能是"装着一片的独立归档"——
  必须先按**单卷**解出来，再收拢成组；⛔ 不能把"尾部有 EOCD"当成"分片末片"
  （判据 = EOCD 里中央目录偏移 ≥ 本文件长度，或盘号 > 0，见 `VolumeNumberReading.ZipEndRecordMeansSplit`）。
- 已知未闭环：新造 30 份里 `19191919` / `24242424` / `30303030` / `6666` / `8888` 仍 ①✘②✘；
