# 阶段 2（分卷事实）依赖表与拆除顺序

> 范围：只换分卷事实/组裁决；不碰阶段 3 的落点/定稿/发布。
> 规则：先建事实，再修确定性缺陷，再切裁决，最后才删旧入口。

## 1. 现状的四个事实/裁决层

| 层 | 现在是谁 | 问题 |
|---|---|---|
| 单片的原始事实 | 第一大步卡 + 交接单 | 同一片在 `VolumePieceFact` 和 `GroupPieceFact` 各记一份，字段会漂 |
| 组级事实 | `PreparedVolumeGroup` | 已经可用，但外面还套了一层旧 `GroupAnalysis.GroupCandidate` |
| 组生命周期 | `VolumeGroupUnit` + `VolumeGroupService` | 已经有唯一建组口，但还接受旧 `GroupCandidate` 参数 |
| 旧全树组分析 | `GroupAnalysis` | 仍决定候选、完整性、字节补齐、让位；必须降为诊断 |

## 2. 五个停用门（Parked）

| 旧执行体 | 现在保护的旧行为 | 新入口 | 删除条件 |
|---|---|---|---|
| 跨层收卷 | 第一大步跨层收/改名 | 候选发现 + 组入口目录 | 候选发现能覆盖脏名/跨层片 |
| 伪装名还原 | 内层包名还原后重判 | 候选发现 + 名字候选 | 不再需要在解压前改名 |
| 收片结算 | 已解组卷按档收掉 | 新组结算 | 新组事实能给出“这一组已解完” |
| 接片/建链接 | 把未决片接进组入口层 | 组入口目录 | 组入口只从 `PreparedVolumeGroup` 建 |
| 收拢 | 收拢同组片 | 组入口目录 + 组服务 | 接片路径唯一 |

⛔ 顺序：先替换门后面的执行体，再删门；不许先删 `Parked` 让旧代码全部复活。

## 3. `GroupAnalysis` 现在仍在做的五件事

1. 找候选：交接单、脏名种子、全树扫描；
2. 分桶：基名 / 内容自述 / 字节补齐配对；
3. 判完整：`Complete/Missing/Unknown`；
4. 让位：prepared 组存在时删旧候选；
5. 字节补齐：不同基名按自述字节配成一组。

阶段 2 的归属：

- 1、2、5 → 新的候选发现（只产候选，不产 verdict）；
- 3 → 族 resolver/`PreparedVolumeGroup`；
- 4 → 删除（prepared 是唯一候选源）；
- `GroupAnalysis` 只留日志描述。

## 4. `VolumeNameRepair` 拆分

**保留（用户显式功能）**
- 用户点“按建议改名并重试”；
- 只改名字、全成或全不成、绝不覆盖；
- 手动入口与失败清单建议继续读同一套计划。

**删除（自动旧框架）**
- 解压前自动改名；
- 自动跨层收卷；
- 自动还原伪装内层包名；
- 名字直接建链接。

**新形态**
- 名字只产“候选名 + 置信度”，不直接改盘；
- 候选名由组入口目录/改名执行体消费。

## 5. 执行顺序

1. 事实：合并片事实，先影子对比，不改行为。
2. 缺陷：ZIP64 8 字节、锚点漏抄、内容优先于名字、字节补齐/子集删组。
3. 切裁决：候选发现独立；组服务只收 prepared；旧 verdict 退出。
4. 拆门：五个 Parked 门逐段替换。
5. 拆名字：保留手动，删自动。
6. 删旧：`GroupAnalysis` 裁决、`GroupCandidate` verdict、`Parked`、已归零的旧入口。
7. 阶段退出：一次全量 + format + 绿色目录。

## 6. 验收

- 同一组只有一个组事实 `VolumeGroupUnit`；
- `GroupAnalysis` 不再决定完整/缺片/owner/入口；
- `Parked` 和自动改名路径删干净；
- ZIP64、锚点、候选顺序、字节补齐各有红检；
- 中间只跑定向，阶段退出跑一次全量。
