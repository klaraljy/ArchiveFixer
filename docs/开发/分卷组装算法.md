# 分卷组装算法

> 适用版本：ArchiveFixer v0.2.2  
> 最后核对：2026-11-14，代码 HEAD `9e6e7b17`  
> 状态：现行。旧真机 walk-through/红检现场见 `docs/历史/旧开发文档/分卷组装算法-旧版.md`。

## 1. 目标

把“看起来是同一组”的多个文件，按**内容证据 + 名字线索 + 盘上身份**判成一组，决定：

- 是不是一组；
- 入口是哪一片；
- 缺哪几片；
- 能不能提交给引擎只解一层；
- 判不出时保留原样。

## 2. 证据

| 证据 | 来源 | 用途 |
|---|---|---|
| 格式 | `FileNatureCard.Format` / `VolumeContentInference` | 族判定，不信后缀 |
| 卷号/首卷 | `VolumeNumberFromContent`（RAR5/RAR4/ZIP） | 定序 |
| 自述整包/片数 | 7z start header | 7z 完整性/片数推算 |
| 名字卷槽 | `LegacyVolumeNames` / `VolumeNameRepair` | 入口/顺序线索 |
| 同基名兄弟 | `FirstStepFileLedger` / 目录扫描 | 组候选 |
| 物理身份 | `FileIdentity`（卷序列号+文件索引） | 去重/同名硬链接 |
| 试开 | `VolumeProbeVerifier` | 只读验证顺序/可打开 |

## 3. 三族

### 7z

- 首卷 `.001`；
- 起始头自述整包字节数 ≤ 自己 ⇒ 单卷完整；> 自己 ⇒ 首片；
- 片数由整包/片长事实推，不写死；
- 中间片魔数可能没有，靠名字/大小/试开定序；
- 非均匀分卷不按“首片大小推算所有片”。

### ZIP

- 跨盘：`.z01...` + 末片 `.zip`；入口是末片；
- 通用：`.zip.001...`；入口是首片；
- EOCD 盘号/中央目录偏移是分片证据；
- ZIP 家族内容容器（docx/epub/apk/jar）在候选层按条目识别，不当分卷。

### RAR

- RAR5：主头卷号/Volume 位；第 1 卷无卷号字段；
- RAR4 新：主头首卷标记 + 末卷/试开；
- RAR4 老：`.rar`=1，`.r00`=2，`.r01`=3；
- 加密头：按分卷形状/标准名/试开，不猜。

## 4. 组键与去重

- 组键：`SecondStepBaseName + FileIdentity`；
- 同基名跨目录仍属一组；
- 同一物理文件多个名字（硬链接/同目录副本）只算一片；
- 不同族或强锚点冲突 ⇒ 不混组，报 Unknown/SizeAnomaly。

## 5. 入口层与标准名

- 完整组在 `.ArchiveFixer.work\group-entry` 建标准名入口；
- `.001删`/脏名保持源名，逻辑规范名供引擎；
- 入口层硬链接/移动按 `VolumeGroupEntryLayer`；
- 失败/缺片/判不出不搬、不改名、不删。

## 6. 缺片/异常

- 缺片：报缺哪几号，不调引擎；
- `SizeAnomaly`：结构异常不可提交；不能变成 0 片候选替换发现层完整组；
- prepared 组必须有片才可提交；
- 判不出 ⇒ 保留原片，交用户处理。

## 7. 消费者

- `FirstStepFileLedger`：候选/事实；
- `VolumeCandidateDiscovery`：组分析；
- `RoundProductClassifier`：轮判定；
- `ExtractionCoordinator.Volume*`：入口层/试开/收片；
- `VolumeGroupService` / `PreparedVolumeGroup`：提交；
- `StandardNameFastPath`：逻辑标准名快通道。

## 8. 限制

- 同基名不同组成组冲突、非均匀分卷、加密头等依赖试开/证据；判不出不动；
- 源片只硬链接、不物理改名；
- 媒体前缀分卷不在当前识别范围；媒体前缀完整单卷仍支持。
