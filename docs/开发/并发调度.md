# 并发调度

> 适用版本：ArchiveFixer v0.2.4
> 最后核对：2026-11-14，代码 HEAD `9e6e7b17`  
> 状态：现行。旧自动并发方案见 `docs/历史/旧开发文档/并发调度-旧版.md`。

## 1. 当前行为

- 并发数由用户手选 **1–4**，默认 **2**（`MaxParallelExtractCount`）；
- 普通解压与特定解压共用这个上限；
- 程序不自动升降档；
- `ConcurrencyOverride` 只给无头夹具/排障固定串行，不暴露界面；
- `RunAtFullSpeed` 已退役，不参与调度。

## 2. 空间模式

- 「空间不足」是运行期开关，不落盘；
- 只收紧并发，不抬高用户 N；
- 按任务空间预算重新排序/延后；
- 强制过程物走彻底删除档；源包按用户档；
- 空间不足：并发/排序按空间收紧，成功后删源包，最后一层过程物固定保留；
- 两档互斥关系、确认框文案、日志都要与批首快照一致。

## 3. 调度组件

- `Storage/ExtractionScheduler`：批计划/排序；
- `Storage/SpaceGate`：可用空间/预留；
- `Storage/SpaceTrendMonitor`：运行中空间曲线；
- `ExtractionCoordinator.Schedule`（`ViewModels/Extraction/Steps/ExtractionScheduleHandler`，原 `ExtractionCoordinator.ExtractionScheduleStep` 分片已删）：并发/空间/延后/预算日志；
- `Storage/StorageDeviceProfile`：设备建议（只显示，不自动应用）。

## 4. 线程

- 解压任务在后台/异步执行；
- UI 只收进度/状态/日志；
- 产物扫描在后台（`OneClickCoordinator.CollectInnerLayersAsync`）；
- 工作区清理在 `PostProcessSuccessStep` 的 `Task.Run` 中；
- UI 停顿看 `UiResponsivenessMonitor` 的标记时间/线程，不把后台标记当 UI 阶段。
