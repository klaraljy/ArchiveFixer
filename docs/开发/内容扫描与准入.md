# 内容扫描与准入

> 适用版本：ArchiveFixer v0.2.4  
> 最后核对：2026-11-14，代码 HEAD `9e6e7b17`  
> 状态：现行。旧设计见 `docs/历史/计划与审计/内容探测与候选范围设计-旧.md`，不代表当前行为。

## 0. 一句话

**内容识别不是通用扫描。** 普通产物只做轻量“是不是归档”的判断；只有用户明确导入的源包，或已经进入同基名/分卷候选池的文件，才允许调用 `FileContentProbe` 做内容身份识别。

## 1. 三层事实，不要混用

| 事实 | 出口 | 回答什么 |
|---|---|---|
| 底层文件事实 | `Detection/FileNature.Inspect` | 格式、分卷身份、卷号、媒体结构、物理身份 |
| 内容身份 | `Detection/FileContentProbe` | `KnownContent` / `Archive` / `Unknown` |
| 准入范围 | `Detection/ContentAdmission` | 这一次值不值得做内容识别 |

`FileNature.Inspect` **不再调用内容探测**。它只保留已经由 `EmbeddedArchiveLocator` 证明的媒体前缀归档（`ContentClass=Archive`）；普通图片、视频、文档在卡上保持 `Unknown`，由准入点显式探测。

## 2. 唯一准入出口

```csharp
ContentAdmission.Probe(path, scope, deep)
```

`ContentAdmissionScope` 只有两种可探测范围：

- `UserSource`：用户明确导入、当前正在处理的源包；
- `VolumeCandidate`：已经通过同基名/分卷证据进入候选池的文件。

`None` 直接返回 `Unknown`，**不打开文件**。生产目录的逐文件循环不得自己调用 `FileContentProbe.Probe`。

## 3. 各消费点

### 3.1 一键处理产物扫描

`OneClickCoordinator.CollectInnerLayersAsync`：

- 逐文件只做既有的轻量归档判定（`ClassifyArchiveByContentAsync`）、0 字节/过程物/分卷后续卷等过滤；
- **不对普通内容物做内容识别**；
- 内容物跳过时写 `RememberTerminalProducedContent`，同一路径+大小+mtime 后续轮次不再重扫；
- 整个产物扫描在后台线程执行，只把候选和日志返回 UI，任务表由 UI 线程继续写。

### 3.2 递归解压

`RecursiveExtractor` 不再对每个解出的条目调用 `FileContentProbe`。内容容器由既有 `ContentContainerProtection` 按后缀保护，APK 由 `AndroidPackageDetector` 拦；普通图片/视频的 `BodyKind` 本身不是 `SingleComplete`，不会被当内层包。

### 3.3 第二大步候选人

只有以下位置允许使用 `ContentAdmissionScope.VolumeCandidate`：

- `FirstStepFileLedger.IsSecondStepCandidate`：仅 ZIP 候选、候选数量很少；
- `VolumeCandidateDiscovery`：同基名/分卷候选池；
- `RoundProductClassifier`：只用品类事实和内容容器后缀，不再深探测每个候选。

### 3.4 用户源包

`ExtractTaskMainStep.TrySkipKnownContent` 只对用户直接导入的根任务使用 `UserSource`。用户明确导入的 docx/epub/jar 等内容容器保留既有“源包可强制拆”语义；自动递归/产物里的同类文件仍不碰。

## 4. 缓存

- `FileContentProbe`：有界缓存，超过上限只淘汰最旧项，**禁止整表 `Clear()`**；浅探测已定案（`KnownContent`/`Archive`）时，深探测直接复用，不重复读头。
- `FileNature`：按路径 + 大小 + 修改时间缓存完整卡片；文件变化立即失效。
- `OneClickCoordinator`：内容物/内容容器/关键词跳过都写终态缓存，避免下一轮重复扫描。

## 5. UI 与诊断

- `CollectInnerLayersAsync` 整段在后台执行；目录枚举原本就在 `Task.Run`，现在逐文件分类也不在 UI 线程。
- `UiActivity.Mark` 只记录 UI 阶段；后台工作清理用 `UiActivity.MarkBackground`，不得覆盖 UI 阶段。
- 性能日志带标记时间和线程号；看到 WARN 先看“标记于多少毫秒前”，不要把恢复后的阶段当成停顿原因。

## 6. 行为边界

- 普通图片/视频/音频/文档/文本：不解压、不递归、不改名、不搬、不删。
- 媒体前缀的完整归档：`EmbeddedOffset > 0` 或 `ContentClass=Archive`，仍按归档处理。
- 真正的 APK：走 `AndroidPackageDetector` 专用闸门，不按普通 ZIP 解开。
- docx/xlsx/pptx/odt/epub/jar 等内容容器：自动路径默认保留；用户明确导入源包时保留既有强制拆能力。
- 判不出：不动，不猜。

## 7. 守门

- `FileContentProbeTests`：普通产物不被 `FileNature` 探测；`None` 不打开文件；同路径同版本复用同一张卡。
- `LargeContentScanTests`：4,000 个 PNG 产物，`ContentAdmission` 探测次数必须少于 100。
- `UiActivityTests`：后台标记不覆盖 UI 阶段。
- `SecondStepMediaContentEndToEndTests`：336 形状 WebP + `.001删` 仍能解出内容。
- `ContentKeepKeywordPipelineTests`、`AndroidPackageGateTests`、`VolumeGroupResolverTests.真案三`：既有路径不得回退。
