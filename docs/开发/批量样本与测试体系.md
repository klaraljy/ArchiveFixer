# 批量样本与测试体系

> 适用版本：ArchiveFixer v0.2.2  
> 最后核对：2026-11-11，代码 HEAD `23acb074`  
> 状态：现行。旧的 120 批口径与旧测试流程已归档到 `docs/历史/旧测试体系/`。

## 1. 三件东西

| 组件 | 作用 |
|---|---|
| 造包器 | 生成 125 份样本 + `recipe.json` |
| 操作测试 | 把样本交给真实 `OneClickCoordinator` 跑，落运行记录 |
| 检测测试 | 只读 recipe + 运行记录 + 磁盘，逐条判红绿 |

造包器**只写备份目录**；操作测试写测试区；检测测试只读。

## 3. 125 份构成

| 类别 | 数量 | 说明 |
|---|---:|---|
| 普通 | 55 | 前 50 份 8 场景轮转；51–55 是同基名形状 |
| 特定 | 20 | 1–10 旧形状；11–20 新形状 |
| 异常 | 25 | 缺片、坏片、空包、跨盘、危险/保留名、内容容器等 |
| 空间 | 15 + 10 | C01–C15 普通档，B01–B10 特定解压档 |

样本 ID 规则：

```text
普通：seed + 1 .. seed + 55
特定：seed + 100001 .. seed + 100020
异常：seed + 200001 .. seed + 200025
空间：C01..C15 / B01..B10
```

## 4. 造包

```powershell
pwsh -NoProfile -File E:\AF\造125批.ps1 `
  -SeedBase 927000000 `
  -OutputRoot E:\DeepSeekProjects\ArchiveFixer\_tmp\困难大测试 `
  -ContentRoot E:\AF\造包设计\原物\困难内容 `
  -MediaRoot E:\AF\造包设计\原物\生成的媒体 `
  -Mode All -Section All
```

不要使用脚本里的 H 盘默认路径；用户的数据统一放在项目 `_tmp\困难大测试` 下。生成后先看 `.logs\造包.log` 和 manifest/report。

## 5. 跑操作

```powershell
$env:ARCHIVEFIXER_120_SEED = '927000000'
dotnet test tests\ArchiveFixer.Tests\ArchiveFixer.Tests.csproj `
  --filter "FullyQualifiedName~Batch120OperationTests"
```

- 不带 `ARCHIVEFIXER_120_SEED` 时两组测试自动跳过。
- 操作测试只负责“真跑并落记录”，不做期望值断言；异常样本也照跑。
- 一份失败只影响自己，不拖累其它样本。

## 6. 跑检测

```powershell
$env:ARCHIVEFIXER_120_SEED = '927000000'
dotnet test tests\ArchiveFixer.Tests\ArchiveFixer.Tests.csproj `
  --filter "FullyQualifiedName~Batch120VerifyTests"
```

检测逐份输出 `E:\AF\120批检测\<seed>\<样本>.json`，红项直接失败。已知检查：

- 普通：落点、内容字节、源包、过程物、组状态；
- 特定：解压成功/内容层；
- 异常：预期结论、源包保留、危险/受保护条目未落盘；
- 空间：空间门/预期阻断。

## 8. 已知坑

- 造包器默认路径可能仍写着 H 盘旧位置；必须显式 `-OutputRoot/-ContentRoot/-MediaRoot`。
- 测试区与备份区不要混用；操作测试会复制样本到测试区，不会改备份。
- 空间样本 C/B 的 ID 不含 seed，换种子时不要与上一批测试区混在一起。
- 操作测试和检测测试是两个独立测试类；不要只用操作通过就宣布批次通过。
- 大批内容物（4,000 个 PNG）另有 `LargeContentScanTests`，不替代 125 批；它专门验证扫描准入次数。
- 旧的 120 批/80 份文档只作历史，不代表当前的 55/20/25/25 构成。
