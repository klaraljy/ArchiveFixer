# 部分完成发布

> 适用版本：ArchiveFixer v0.2.4
> 最后核对：2026-11-14，代码 HEAD `9e6e7b17`  
> 状态：现行。旧口径/日期见 `docs/历史/旧开发文档/部分完成发布-旧版.md`。

## 1. 目的

当一个包“已经解出一部分、但不是全部”时，只把**逐条核对过、确实解出来**的文件放进：

```text
<落点>\<包名>\部分完成\
```

缺的/坏的/引擎点名的条目不发布；判不出就一个字节都不发布。

## 2. 唯一判据

`PartialPublishPlanner`（纯函数）：

- 必须有可信清单；没有 ⇒ `NoManifest`，不发布；
- 逐条比对：清单存在、盘上存在、大小一致、引擎没点名 ⇒ 可发布；
- 缺条目 > 5 个且可发布字节比 < 95% ⇒ `TooMuchMissing`，不发布；
- 可发布一个都没有 ⇒ `NothingPublishable`；
- 引擎报错但点不出具体条目 ⇒ `UnnamedEngineErrors`，不发布；
- 其他无法逐条对账的引擎失败 ⇒ `UnreconciledEngineFailure`。

可发布条目最多 5 个缺失且字节比 ≥0.95 才走发布。

## 3. 执行

`PartialPublishRunner`：

1. 先做发布前二次空间体检；不够 ⇒ `BlockedBySpace`，不发布；
2. `PartialPublisher` 只搬计划里点名的文件；
3. 同名冲突自动让位，不覆盖；
4. 搬不动/让位失败 ⇒ 该条不发布并记录原因；
5. 发布落点是 `部分完成\`，不混进正常成品层。

## 4. 与终态

- 部分完成发布不等于 `TaskOutcome.Succeeded`；
- 源包删除/搬移仍只按成功档和 L4 完整性闸门；
- 发布失败只影响部分内容，不把整单改成成功。

## 5. 开关/边界

- `PartialPublishEnabled` 默认 false；开启后仍受上述判据；
- 工作区/其余物/源包处理与普通成功路径分开；
- 清单不可信、引擎失败不可对账、空间不足 ⇒ 不发布。
