# 诊断日志

> 适用版本：ArchiveFixer v0.2.4  
> 最后核对：2026-11-12  
> 状态：现行。旧日志排查条目见 `docs/历史/旧开发文档/诊断日志-旧版.md`。

## 1. 日志在哪

- 固定数据根：`%LOCALAPPDATA%\ArchiveFixer\logs\`；
- `logs` 根目录只放运行文件夹：`logs\run_yyyyMMdd_HHmmss_fff\operations\NNN-操作名-HHmmss\`；
- 每次操作一个子文件夹，内含：
  - `manifest.json`
  - `summary.json`
  - `operation.user.log`
  - `operation.log`
  - `operation.jsonl`
  - `operation.trace.jsonl`
- 旧版平铺 `ArchiveFixer_*.log/.user.log/.jsonl/.trace.jsonl` 首次启动移入 `logs\legacy\`，不删除；
- `EnableLog` 只控制文件日志，屏幕仍显示；
- 失败/取消任务始终保留细节，不受 `VerboseLog` 影响。

## 2. 一条日志要能回答

- 第几轮、第一/第二大步；
- 哪个任务、哪个文件/组；
- 判据输入（格式/卷号/首卷/自述/内容准入/缺片）；
- 做了什么（解/跳过/失败/定稿/清理）；
- 为什么（失败原因/终态/被哪道闸门拦下）。

## 3. 关键事件

- 扫描/识别结果；
- 闸门判定（内容物、APK、分卷成员、缺卷、路径/预算/空间）；
- 引擎调用参数摘要（密码脱敏）与原话；
- 定稿/校验/源包/其余物/工作区；
- 性能 WARN：`[性能] UI 线程明显停顿` 带阶段、标记时间、线程；不要把后台清理当 UI 阶段。

## 4. 结构化字段与错误码

- `.jsonl` schema 为 `archivefixer.log.v3`；
- 关键字段：`run/operation_id/span_id/parent_span_id/task_id/event_id/error_code/component/source_file/source_line/caller/code_source/stage/result/durationMs/engine/exitCode/stack`；
- 失败/异常/判据否定带稳定错误码（见 [诊断事件码表](诊断事件码表.md)）；
- `decision.stop` 记录递归/关键停因的判定点（error_code/source_file/source_line/caller）；`task.end` 优先带这个位置；
- `task.end` 是任务唯一收尾事件：outcome/status/reason/verification/error_code/source_file/source_line/engine/exit_code/durationMs；
- `tasks.json` / `failed-tasks.json` 与 `summary.failed_tasks` 都读任务上的同一份诊断事实，不按中文状态反推；
- 异常走 `LogService.Exception`，`detail` 含 Type/Message/Inner/HResult，`stack` 含完整栈；
- 普通屏幕日志仍保持简洁；详细内容只进 `.log/.jsonl/.trace.jsonl`。

## 5. 导出

- 「导出日志（本次操作）」只导最近一次操作；
- 「导出诊断包」把当前操作六件套 + 任务事实/环境/设置摘要打成 zip，用户只需发 zip；
- 诊断包内含 `extra/summary.json`、`tasks.json`、`failed-tasks.json`、`settings.redacted.json`、`tool-versions.json`、`error-codes.json`、`bundle.json`、`fatal`；
- `extra/summary.json` 的任务分项（task_count/succeeded/failed/partially_completed/cancelled/skipped/skipped_followers）**只能读 `BatchOutcomeTally`**，与界面、批末汇总、导出头部同一口径；`failed-tasks.json` 只列 `BatchOutcomeTally.IsCountedAsProblemTask` 认可的问题任务（跟班卷、内容组过程任务、缺卷待判不混入）；
- 「导出全部历史日志」拼接所有历史；
- 日志不写密码明文；剪贴板/报告同样脱敏。

## 6. 排查顺序

1. 先看任务状态/`TaskOutcome`；
2. 看该任务日志的闸门输入与结论；
3. 分卷看组分析/入口层/试开；
4. 内容物看 `ContentAdmission` 是否被调用；
5. UI 卡顿看 `[性能]` 标记时间，判断阻塞发生在标记前还是标记后；
6. 仍判不出再上调试器/ProcMon，不靠改代码猜。
