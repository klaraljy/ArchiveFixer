# 诊断事件码表

> 稳定错误码用于用户日志和诊断包。⛔ 错误码按问题分类，不按样本名、目录名、文件名生成。
> 每个失败/否定事件同时带 `source_file` + `source_line` + `caller`，码只负责分类，源码位置负责定位。

## 码表

| 错误码 | 组件 | 含义 | 代码入口 | 先看什么 |
|---|---|---|---|---|
| `AF-APP-000` | Application | 未归类的应用错误 | `LogService` 兜底 | 调用方 `source_file/source_line` 与同任务 `task.end` |
| `AF-TASK-001` | ExtractionCoordinator | 任务最终未成功 | 任务边界 / 兜底 | `task.end` 的 status/reason/verification |
| `AF-VERIFY-002` | OutputVerifier | 输出校验未通过 | 校验调用方 | `criterion` 的 expected/actual 与清单差异 |
| `AF-VOL-003` | VolumeBoundary | 分卷组缺片/不完整 | 分卷预检 | 组事实 pieces/missing 与入口卷判定 |
| `AF-IO-004` | FileOperations | 文件移动、删除、改名或建链接失败 | 文件操作 / 路径预检 | source/target、Win32 错误、目标目录状态 |
| `AF-ENGINE-003` | ArchiveEngine | 外部引擎调用失败或工具缺失 | 引擎调用边界 | `engine/exit_code`、引擎原话、工具版本 |
| `AF-UI-001` | UiResponsivenessMonitor | UI 线程停顿 | UI 心跳 | 停顿阶段、标记线程、后台标记 |
| `AF-UNHANDLED-007` | App | 未处理异常 | `App.xaml.cs` | `stack` 第一帧与 fatal 日志 |
| `AF-LOG-008` | LogService | 日志/诊断包写入失败 | `LogService` / 诊断包 | 磁盘权限、目录占用、fatal 旁路 |
| `AF-CONFIG-009` | SettingsService | 设置/配置读取或保存失败 | 设置服务 | `settings.redacted.json` 与配置文件状态 |
| `AF-PASSWORD-010` | PasswordService | 密码本读取、写入或匹配失败 | 密码服务 / 候选循环 | 候选数、来源；⛔ 不在日志里找明文 |
| `AF-DECISION-011` | Decision | 关键判据给出否定结论 | `LogService.Criterion` | `criterion/inputs/verdict/action` |
| `AF-ARCHIVE-012` | ArchiveEngine | 归档数据损坏或密码/损坏两义 | 递归/引擎结果 | 引擎原话与候选是否试完；两义不折成单因 |
| `AF-SPACE-013` | Storage | 磁盘空间不足 | 空间门 | requirement/available/shortfall 与目标盘 |
| `AF-SOURCE-014` | SourceGuard | 源文件在处理期间变化 | 源快照检查 | source 快照与当前 size/mtime/identity |
| `AF-LIMIT-015` | RecursionLimits | 撞上递归安全上限 | 递归核心 | depth/files/size/ratio 哪项超限 |
| `AF-SAFETY-016` | ArchivePathGuard | 危险条目或路径穿越被拦截 | 路径守卫 | entry path 与落点根目录 |

## 递归停因映射

| 停因 | 码 |
|---|---|
| `WrongPassword` / `PasswordAttemptsExceeded` / `EncryptedHeaders` | `AF-PASSWORD-010` |
| `MissingVolume` | `AF-VOL-003` |
| `EngineFailed` | `AF-ENGINE-003` |
| `Corrupted` / `PasswordOrCorrupted` | `AF-ARCHIVE-012` |
| `DiskSpaceInsufficient` | `AF-SPACE-013` |
| `SourceChanged` | `AF-SOURCE-014` |
| `MaxDepthReached` / `MaxTotalFilesReached` / `MaxTotalSizeReached` / `MaxSingleFileSizeReached` / `ExpansionRatioExceeded` / `TooManyInnerArchives` | `AF-LIMIT-015` |
| `UnsafeEntry` | `AF-SAFETY-016` |
| `Completed` / `NeedsDecision` / `BranchNotExpanded` / `UserCancelled` | 无失败码（由 `task.end`/`criterion` 说明） |

## 排查顺序

1. 打开 `extra/summary.json`，取 `error_codes` 与 `failed_tasks`；
2. 打开 `extra/failed-tasks.json`，看 `error_code`、`source_file`、`source_line`、`engine`、`exit_code`、`stack`；
3. 用 `task_id` 看 `operation/operation.trace.jsonl` 的 `task.begin` → `engine.*` → `task.end`；
4. 看 `operation/operation.jsonl` 中同 task 的 `criterion`/`inputs`/`verdict`；
5. 没有异常时，用 `task.end` 的 status/reason/verification 和最后一个 `engine.*` 判断停在哪一步；
6. `code_source=fallback` 表示该码是按终态兜底推的，不是失败行实际产生的码。

## 新增规则

- 新错误码只追加，不复用旧码；
- 一个码只表达一个分类；
- 不允许按样本名/文件名动态拼码；
- 关键失败出口必须显式给码；兜底码只用于未分类错误；
- 诊断包中的码表来自代码常量，不手写第二份。
