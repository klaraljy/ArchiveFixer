# 人工测试清单（v0.2.2）

> 最后核对：2026-11-14，代码 HEAD `9e6e7b17`

## 0. 使用方式

这是**用户真实操作路径**的验收清单，不替代自动测试。每轮至少完整走一次“导入 → 一键处理 → 看结果”；带 ⛔ 的项失败必须停，不允许用自动测试绿代替。

## 1. 启动与导入

- [ ] 独立版解压即用；安装版能正常启动、卸载。
- [ ] `%LOCALAPPDATA%\ArchiveFixer` 可写；旧 `data\` 只在首次启动迁移，不覆盖新数据。
- [ ] 添加文件/文件夹、拖放、追加到列表三种入口语义正确。
- [ ] 文件夹导入后能识别隐藏/系统文件设置与扫描模式。
- [ ] 无用物不会在“一键处理开工前”被自动移出列表。

## 2. 单一完整包（第一大步）

- [ ] 正常 7z/zip/rar 包：解压成功、内容物落到落点、校验通过。
- [ ] 伪装后缀包：按内容认格式，智能修正只改后缀、不动基名。
- [ ] 媒体前缀完整归档（视频/图片 + 尾部归档）：能抠取/直读，源文件不动。
- [ ] docx/xlsx/pptx/odt/epub/jar 作为**用户源包**时，手动「只解压」仍可拆；自动递归里的同类文件不碰。
- [ ] 真正 APK 不打开、不递归、不改名。

## 3. 分卷组（第二大步）

- [ ] 7z `.001..`、RAR partN、RAR 老编号、跨盘 ZIP `.z01..zip` 都能成组。
- [ ] 缺片时只报缺片，不调引擎、不删片；完整组只解一层。
- [ ] `.001删` 等伪装名保持源名，入口层用逻辑标准名；成功后源片不因改名丢失。
- [ ] 336 形状：`336.png` 实际 WebP + `336.7z.001删/.002`，组只算 2 片，不 SizeAnomaly、不 Pending。
- [ ] 同基名不同目录的片能成组；不同族/强锚点冲突不混组。

## 4. 内容物与递归

- [ ] 4,000 个图片/视频内容物：扫描不逐张做内容识别；UI 不出现百秒级停顿。
- [ ] 内容物保留关键词：命中项不解开、不改名、不搬、不删。
- [ ] 内容容器保护：自动路径保留 docx/xlsx/epub/jar。
- [ ] 递归续解：中间层目录按设置保留/省略；内容物跟上一层并层规则正确。
- [ ] 无内层包时正确停链，不空转、不重复解同一组。

## 5. 密码与引擎

- [ ] 空密码、统一密码、手动密码、密码本列表/映射、多本密码本都能命中。
- [ ] 每层尝试上限生效；到上限报“达到密码尝试上限”，不报“密码错误”。
- [ ] 7-Zip 与 UnRAR 优先级按设置生效；不可用引擎跳过，不阻塞。
- [ ] WinRAR 兜底只在可用时；日志能看出用了哪个引擎。

## 6. 落点与源包/其余物

- [ ] Original / Specified / 指定位置落点符合同名子文件夹规则。
- [ ] 源包 KeepInPlace：一个字节不搬、不删、不改名。
- [ ] 源包 DeleteInPlace：只有成功 + 校验通过后才删。
- [ ] 其余物 Keep / Delete 两档正确；失败/部分完成按档处理，成功过程物自动清。
- [ ] 危险条目/路径穿越/Windows 保留名被拦下，不落盘。

## 7. 空间不足与并发

- [ ] 并发 1–4 与用户选择一致，不自动升档。
- [ ] 空间不足模式只收紧并发；源包按档处理。
- [ ] 空间不足 + 不删原包互斥关系正确；确认框/日志不发假结论。
- [ ] 取消/停止后续语义正确：停止后续在安全点停；取消当前立即中断。

## 8. 打包

- [ ] 按卷数打包；密码同一套；外层 rar/7z 按设置。
- [ ] 打包成功后按 PackSourceHandling/PackRestHandling 处理。
- [ ] 失败/取消不动源包；确认框数字与实际一致。

## 9. 错误与日志

- [ ] 失败/部分完成/跳过/成功四类汇总与任务行一致。
- [ ] 日志带轮次、阶段、判据；UI 卡顿 WARN 带标记时间/线程，不把后台清理冒充 UI 阶段。
- [ ] 源包、密码、用户数据没有出现在日志/报告/剪贴板明文里。
