# 动不可逆路径之前

本项目的**最贵错误是删掉用户的数据**（2026-09-30 真机：25 GB 分卷被当"过程残留"永久删除，不可恢复）。红线出处：`AGENTS.md` §6 不变量 1 / 12、§9.5；现场见 `docs\真机事故复盘.md`。

## 1. 四条不许破的底线

1. **失败 / 部分完成 / 取消 ⇒ 源包原地不动、`其余物` 不生成**（不变量 1，任何设置都不改变这一条）。
2. **落点不许越出目标根**（不变量 4）：解压前预检条目名，解压后校验落点，两道都要。
3. **工作区只在解压的地方（`<目标目录>\.ArchiveFixer.work`）**，⛔ 绝不回落程序目录 / C 盘 / 源目录。
4. ⛔ **`E:\ArchiveFixer\data` 一个字节都不碰**；`H:\BaiduNetdiskDownload\...` 上的真样本**只读**。

## 2. 删除/移动类改动，动手前逐条自查

- [ ] **判据只读机器终态**（`TaskOutcome` / 校验枚举 / 结构化错误码），⛔ 绝不比中文文案。
- [ ] **同一件事只有一个出口**（§9.5）：新判据要么替换旧出口，要么转调旧出口并写清理由；⛔ 不许两处各判一遍。
- [ ] **兜底永远落在"什么都不做"那一档**：判不出来 ⇒ 不移动、不删除、不重命名，结论里**如实写"无法确认"**。
- [ ] **"属于某个分卷组"的文件永远不许进"可删残留"名单**（25 GB 那次就是这么没的）；分卷要进其余物，必须先**证明整组完整**。
- [ ] **失败名单有两处必须一致**：`OneClickCoordinator.IsFailureStatus` 与 `TaskSummaryService.IsExtractFailureStatus` —— 改一处就要同时改另一处（否则出现"①页算失败、汇总里算未处理"）。
- [ ] **不确定完整性时不许说成功**：部分成功 ≠ 成功；缺卷要报"缺哪几个"。
- [ ] 清理容器内的东西前，两道校验（在生效的工作区根之下 + 目录里只许有我们自己造的子目录名），越界只写 WARN、**一个字节都不删**。

## 3. 检验等级（L0–L6，闸门顺序）

L0 识别（不认识 ⇒ 什么都不做）→ L1 解前（路径预检 / 预算 / 空间 / 缺卷）→ L2 解后（落点 + 非空）→ L3 清单核对（**只在有可信清单时**）→ L4 **完整性分类**（判不出 ⇒ 不动任何源）→ L5 收尾复核 → L6 **删除闸门**（L4+L5 过 + 未被取消 + 属于本任务）。

⛔ 不许跳级：**"删源"必须过 L4 + L5**。落地细节见 `docs\检验等级.md`（若存在）与 `docs\输出与整理模型.md`；发现代码里的闸门顺序对不上，要么修、要么在文档里写成"已知缺口 + 位置"，⛔ 不许只写"已实现"。

## 4. 改动这类代码 = 大改动

按 §9.2 一律跑**全量**，并且每条修复都要**红检**：把新判据撤掉 ⇒ 对应守门用例必须变红（例如"判不出时也允许删源"必须能造出红）。改完把现场（现象 / `文件:行号` 根因 / 修法 / 红检）写进 `docs\真机事故复盘.md` 的结论区与 `修改日志.md`。
