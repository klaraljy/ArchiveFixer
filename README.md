# ArchiveFixer

Windows 桌面工具：批量识别**被改坏后缀**的归档文件、按真实格式修正文件名、按密码本批量解压（含分卷），
并给出可追踪的结果 —— 用尽可能少的操作，处理"来源不明、后缀可疑、加密、分卷"的资源包。

## 现在能做什么

- **格式识别**：读文件头魔数判真实格式，不信扩展名。覆盖 ZIP / 7Z / RAR4 / RAR5 / GZIP / BZIP2 / XZ / TAR /
  CAB / ARJ / LZH / Z / Zstandard / LZ4 / RPM / ISO。
- **双面文件 / 内嵌归档**（2026-09-24 放宽判据 + 新增**直读**）：前面是视频等数据、尾部拼着一个完整 ZIP
  的文件（真实资源包常见形态），后缀状态显示「**内嵌归档**」。
  一键处理**优先直读**：直接从原文件的 `[起点, 归档终点)` 流式解出条目，
  **不再产生那份等大的临时副本**（ZIP 段实测 487 MB–2.4 GB；原来必须先整段抠出来才能交给 7-Zip，
  峰值空间约等于包大小的 3 倍）。直读不支持时**自动回落**到"抠取 + 7-Zip"并在日志里写明原因
  （加密条目 / bzip2 等方法 / ZIP64 字段缺失 / 中央目录对不上 / 递归模式）。
  改成 `.zip` 没用：7-Zip 只容忍 8 MiB 以内的整体偏移。
  判据是**逐个 EOCD 候选自洽校验**（从后往前试，要求"算出来的中央目录位置真有 `PK 01 02`"且
  "算出来的归档起点真有 `PK 03 04`"），于是：**EOCD 之后允许还有别的数据**
  （真实文件就有 14,350–17,424 字节，那截**不属于归档**，抠取与直读都按 `EOCD + 22 + 注释长度` 截断）、
  **支持 ZIP64 收尾**（56 字节 ZIP64 EOCD + 20 字节 locator）。
  反过来，凑不出这两条签名的普通 MP4、自解压安装器**不会被误报**成内嵌归档。
- **后缀分析**：后缀正常 / 缺失 / 不匹配 / 多重后缀疑似伪装 / **分卷后缀**（分卷单独归类，不会被误当成伪装）。
- **批量改名**：智能修正、添加、替换、删除最后一个、删除多个 —— **一律先生成预览**，预览里可手工改新文件名。
  分卷文件受保护，不会被"智能修正"切断分卷链。
- **任务列表的勾选（2026-09-22 按用户要求重做；2026-09-24 第 12 条收紧为"只认勾选"）**：**一次点击即切换**
  （勾选框铺满整格，点击这一列的任何地方都算；以前点在格子空白处只会选中行，看起来"点了没反应"，得再点一次）；
  **全选 / 全不选 / 反选**按钮就在列表正上方，菜单「文件」里也有一份，键盘是 `Ctrl+A` / `Ctrl+D` / `Ctrl+I`；
  右键还有「**只勾选这一个**」—— "一整个文件夹都被勾上了、这次只想解其中一个"从"逐个点掉"变成**一个动作**。
  勾选一变，汇总里的「选中：N」与「只解压」的可用性立刻跟着走。
  **所有批量命令（一键处理 / 只解压 / 智能修正 / 移除选中 / 清理类）一律只认勾选**：一个都没勾就**什么都不做**，
  只提示"没有勾选任何任务"。⛔ 没有"没勾就按当前点中的那一行办"这回事（那是错的，已删除）。
- **导入语义（2026-09-24 第 12 条）**：点「**添加文件 / 添加文件夹**」（以及拖放一批新文件）= **先清空整张任务列表**
  再加入这次选的内容；想**追加**到现有列表后面，用菜单「**文件 → 追加到列表**」（追加文件 / 追加文件夹）。
- **分卷**：**一组分卷 = 一个任务**，只从第一卷启动；缺卷时直接报"缺哪几个"并拒绝开始。
  认五种命名：`.001` / `.z01` / `.r00` / `.partN.rar` / 本体（`x.zip`、`x.rar` 就是第一卷）。
- **密码**：统一密码、单任务密码、密码本（**列表式**一行一个 + **映射式** `名称:密码`，按归档名命中）、
  最近成功密码优先；可显式开启从**压缩包同目录的说明文件**里提取候选。**支持多本密码本**（导入过的每一本都被记住，
  启动时按记住的顺序逐本合并，设置里能逐项移除）。日志、报告、剪贴板里永远只有脱敏形态。
- **密码列表跨重启保留**（2026-09-24）：列表的**内容 / 顺序 / 启用状态 / 手工条目 / 备注**按本机
  **DPAPI（机器范围）**加密存在 `<程序目录>\data\password-list.dat`（跟 Windows 账号无关、不弹框、不写 C 盘），
  删除与清空记**墓碑**（重启不从密码本复活）；设置项「记住密码列表」**默认开**，可整个关掉（关掉 = 既不写也不读）。
  ⚠ 代价：同机任何本机用户都可能解开、换机器 / 重装系统解不开（**忽略并提示**，不崩不覆盖不删；
  出路是「写回密码本」）；日志、报告、剪贴板永远只有脱敏形态。
- **密码尝试上限**：每一层最多真的试 `MaxPasswordAttemptsPerLayer` 个候选（设置里可改，缺省 10，范围 1~1000）；
  到上限的状态是**达到密码尝试上限**，不是"密码错误" —— 候选没试完不等于密码本里就没有。
- **批量解压**：并发数按设置 `MaxParallelExtractCount`（1~8，**默认 4**；主界面另有 1/2/3/4/8 的下拉 +
  「按空间算建议」）；"停止后续"与"取消当前"是两套独立语义；
  解压前做**条目路径预检 + 资源预算**，解压后做**落点校验 + 结果校验（条目数/总大小）**。
  产物一旦越出目标根目录（含"产物目录里混进了目录联接点 / 符号链接"）就是**失败结论**：
  不归集、不处理源包，原因写进任务状态与错误信息 —— 不会只留一行日志却照样报"解压成功"。
- **空间门（解压之前就判，不足就不启动）**：每个任务启动前算一次峰值需求 ——
  **源包（分卷整组）+ 内容物 + 本次会额外产生的过程物（内嵌归档中间件、内层包再展开的增量）**，
  三者按路径与类别**去重**，并保留 512 MiB 余量。装不下就**不启动**该任务，
  状态落「**磁盘空间不足**」（与"解压失败"分开：归档没问题，只是一个字节都还没写），
  错误信息里给出**需要 X / 可用 Y / 差 Z** 与建议动作（清 `其余物` / 换输出盘 / 降并发 / 危险模式）。
  取不到可用空间时**不拦**（不把"探测失败"说成"空间不足"），只写一条 WARN。
- **空间感知的调度**：一键处理按空间需求**从小到大**排序（用户点名的反例"一开始就去解 5G+6G"因此不成立）；
  并发时账本记着"已经在跑的任务占了多少"，只有 `已经在跑的 + 我 ≤ 可用 − 余量` 才启动；
  装不下的**跳过它、先做后面装得下的**，批末**逐个点名**报告"谁被跳过、需要多少、差多少"（绝不静默跳过）；
  主界面的「按空间算建议」会显示"当前可用 X，建议并行 N 个"（与真正调度同一段实现）。
- **危险模式（红色按钮，默认关）**：并行解压 → 每个任务在「内容物已定稿并按落点策略排好 + 输出校验通过 +
  未取消」之后，**立刻把它自己的 `其余物`（源包 + 中间件）彻底删除**（不进回收站），于是净占用基本不变 ——
  这是它唯一能解决"空间不够"的原因。**失败 / 部分完成 / 取消的任务一个字节都不删**（不变量 1 的红线）。
  开启前必须先跑**自测**：拿「并发数 × 2」个文件真跑一遍，逐个检查
  「解压成功 + 输出校验通过 + 其余物按预期被彻底删除 + 空间曲线符合预期」，四条全过才允许开启，
  之后界面上常驻红色横幅写明风险四条。风险四条同时写在确认框、设置项说明与 `docs\使用说明.md` §12.4。
  ⚠ **自测凭证只覆盖它跑过的那一档并发**：把并发调高（例如 4 → 8）之后凭证盖不住，**该批不生效**
  （一个字节都不删、其余物照常进回收站），红色横幅与日志都会说明原因；调小不受限制。
  设置里"勾了危险模式 + 并发超出凭证"时保存会被拦下并说明 —— 免得存进一个开不起来的组合。
- **解压前的提醒（每次批量解压前最多弹一次，两段合并）**：① **可能的"无用物"** ——
  与本批压缩包同目录、不属于本批任务、而且**魔数认不出是压缩包**的说明/网址/工具类文件
  （`.txt` / `.url` / `.exe` / `.bat` / `.jpg` 等），提醒里写明**程序一个都不会动它们**，删不删由你决定；
  ② **需要密码但当前没有可用候选的包** —— 说清继续大概率会以「密码错误」或「达到密码尝试上限」结束
  （**不是**成功、也不是损坏），并给出"先去补密码本 / 先把它们取消勾选"两条出路。
  ⚠ 判据刻意窄：**伪装包绝不算无用物**（复用同一套魔数识别，不另写一份）；两段都为空时**不弹**；
  「本次运行不再提醒」只记在内存里，**绝不写设置文件**。
- **打包（文件夹 → 加密分卷 → 加密外层，**⑤「打包」选项卡**）**：选一个文件夹 A →
  用内置 7-Zip 生成**带密码的 7z 分卷**（`-mhe=on`：连文件名一起加密）到新建的文件夹 B →
  再按**外层容器三选一**压一层：**rar**（默认，用本机已装的 WinRAR 命令行，`-hp`）/
  **7z**（`-mhe=on`，**无需额外安装**：7-Zip 是 LGPL、随程序分发）/ **不做外层**（结果就是 B 里的分卷）。
  分卷大小默认 **512 MiB**（64–4096 可调：1 GB 内容切两卷、1.5 GB 切三卷），密码**必填**且只存内存。
  开始前判一次空间（不够不开始，报需要/可用/差；不做外层时只按分卷那一份算），完成后**按容器校验产物**
  （`.rar` 用 `Rar.exe` 读、`.7z` 用 `7z l -slt` 读），对不上不显示成功，结果区写明**容器类型 + 实际产物路径**。
  ⛔ 外层 rar **只认本机已装的 `Rar.exe`/`WinRAR.exe`**（共享软件，绝不分发）；没有时**在切分卷之前**
  就明确报错，并给**三条出路**（装 WinRAR / 换成 7z 外层 / 不做外层），
  ⛔ **绝不静默换容器**、也**绝不用 7-Zip 假装生成 `.rar`**（7-Zip 造不出 RAR）。
  **②「解压方式」页 → 引擎**里有 **`Rar.exe 路径`** 一格（+ 浏览按钮），文案写明许可边界、留空 = 自动用已装目录那份。
  完整设计（含 EULA 依据）见 `docs\打包功能.md`。
- **需要你处理的窗口"叫得住人"**：警告 / 错误 / 询问 / 密码输入 / 密码本这些窗口出现时
  **任务栏图标一直闪（闪到你点它为止）+ 连响三声提示音**，并把窗口从别的窗口后面**拎到最前面** ——
  以前它们会躲在主窗口后面"只有声音、没有闪烁"。音量上限就是 Windows 的提示音音量（见「已知限制」）。
- **递归解压**：三种模式 —— **只解当前层（默认）** / 单链自动展开（只有一个内层包时才继续）/ 展开所有分支；
  多分支**必须问你**；层数、文件数、总大小、展开比、密码尝试次数都有硬上限，到顶停下并说清停在哪一层。
  内层包同样要过安全预检与落点校验，越界即失败（与单层同一口径）。
- **其余物（原「过程物」）**：为得到内容物而产生、用户不需要的东西**集中一处** `其余物\` ——
  内层归档、分卷、抠出来的中间 ZIP（**只在直读不支持时才产生**）、纯壳文件夹，**以及源包本身**。
  每包一个目录的落点就是 `111\222\其余物\`；多个包共用同一个输出目录时（"添加文件夹 + 指定位置"那一档的 `BBB\222\`）
  按包名分层 `111\其余物\222\`，不会互相撞名。老版本留下的 `过程物\` 仍然认（删除功能能清掉它）。
- **源包处理（默认移入其余物；一键处理与手动「只解压」同一套规则）**：在"内容物已定稿 + 输出校验通过 +
  未取消 + 属于本任务分卷组"四条同时成立之后，按设置处理源包 —— `MoveToRest`（**默认**，整组移入 `其余物\`，
  同名加 `(1)` 绝不覆盖，跨盘先复制成功再删原件）/ `KeepInPlace`（一个字节都不搬）/ `DeleteAfterVerify`（沿用清理源包的规则）。
  搬不动（只读 / 被占用）时任务标「部分完成」并写明"内容物已好，源包未能移入其余物"，内容物结论不受影响。
  ⚠ **手动「只解压」也照这一档走**（用户 2026-09-22 版本二：早先"地基路径永远不动源包"的说法已被推翻）；
  失败 / 部分完成 / 取消时源包一律原地不动、`其余物` 不生成。想要"传统解压器"语义就把档位设成 `KeepInPlace`。
- **解压引擎（两个，按格式与优先级自动分派）**：RAR / RAR4 / RAR5 → **UnRAR**（RARLAB 官方免费件，
  已内置 `tools\unrar\UnRAR.exe`，7.23 稳定版；缺卷时它直接点名缺哪一卷、加密文件名有显式标志）；
  zip / 7z / tar / iso 等其余格式 → **7-Zip**（已内置 26.03）。
  顺序由设置项 `EnginePriority` 决定（默认 `winrar → sevenzip`），规则是**先按能力筛、再用优先级做先后**，
  **不可用的引擎直接跳过** —— 没装 UnRAR、把内置关掉、或把它从优先级里去掉，RAR 仍然由 7-Zip 正常解开。
  每个任务在详情/失败清单里记的是**它实际用的**引擎名 + 版本（不是"当前设置里的第一个"）。
- **同名冲突（`ConflictAction` 一处设置、两处生效）**：输出目录已存在且非空、定稿搬运时同名、以及改名预览里的同名，
  都按同一档处理 —— `Skip` / `Overwrite`（走"先挪到临时名 → 落位 → 再删旧的"两阶段，绝不先删后移）/
  `AutoRename`（**默认**，新产物落成 `名字(1)`，绝不覆盖）/ `Ask`。
  `Ask` 是**真的会问**，而且**两条路径都问**：
  ① **解压落位**第一次撞上同名时暂停该任务、弹一次聚合询问（覆盖 / 跳过 / 自动重命名，勾上
  「对后面所有同名冲突都照此办理」就对整批生效，本批不再问第二次；关掉窗口 = 取消本批）；
  ② **改名冲突在改名预览表里逐条确认** —— 撞名的行出现「冲突选择（询问档）」下拉
  （自动重命名 / 跳过 / 覆盖），没选就不放行（也可以点「冲突全部自动重命名」一次处理完）；
  **不选或直接关掉预览窗口都按保守档自动重命名，绝不覆盖**。没有界面宿主时也降级为"自动重命名 + 写日志"。
  真正覆盖前先写日志留痕（列出被顶掉的落点）。
- **收尾**：结果可**归集**到统一目录（同名自动改名不覆盖）；可**可选清理源包**（默认关闭；
  它只在「源包处理」选了 `KeepInPlace` 时的手动「只解压」路径上参与 —— 那是"传统解压器 + 解压后清理"
  的老组合，默认的 `MoveToRest` 档下它不参与，否则刚搬进 `其余物` 的源包会被立刻删掉；
  且只有"解压成功 + 校验通过"才删）；失败清单可复制或导出成 txt。
- **其余物 / 空文件夹清理（多任务只问一次）**：勾了 N 个任务时**不再逐个弹预览 + 逐个确认**
  （勾 5 个 = 5 次点击，用户明确说这是冗余）——先一次预览**全部**目标，合成**一个**确认框：
  逐个列出**每个任务的作用范围（哪个目录）**、**合计**条目数 / 字节数、以及**哪些任务含源包**
  （含就点名，删了要重新下载）；确认**一次**，默认移入回收站，勾「改为彻底删除」走激进档
  （红色 + 二次确认，整批也只来这一次）；之后**逐个执行**，**单个任务失败不中断整批**，
  最后给**一次**汇总：成功 N / 失败 M（各自原因）/ 释放字节数 —— 有任何一项没删掉就**不会**显示成全部成功。
- **一键处理**：识别 → 修正伪装后缀（出一次预览确认）→ 按密码本解压 → **自动续解本轮新出现的内层包**
  （最多 3 轮；达到上限会明说"还有更深的内层包没解"）→ 一行汇总
  （成功 / 失败 / 跳过等分项**互斥且可加**，合计恒等于任务总数，不会一个任务被算两次）。
  没有任何需要改名的任务时，改名这步整个跳过，真正零确认；按下「停止后续」后不再续解。
  默认会把**源包**（含分卷整组）移入输出目录里的 `其余物\`，整理完删一个目录就干净了；可在设置里改成"留在原地"或"校验通过后删除"。
- **进度可见（不再是"处理中/完成"两态）**：任务列表的状态列显示**百分比**（`解压中 45%`，不新增列），
  任务详情多一行**当前正在解哪个条目**（`45% · payload 08 数据.bin`），**耗时**跟着进度实时走；
  进度来自两台引擎自己的输出（7-Zip `-bsp1` / UnRAR 的百分比），归一化成同一个进度对象、
  **最多 250ms 上报一次**（否则会把界面刷爆）；只会在**跨过 10% 档位**时写一行日志（最多 10 行）。
  ⚠ 超过 **90 秒没有任何引擎输出**时：写一条 WARN + 在任务上挂「长时间无响应」提示
  （`解压中 45% · 长时间无响应`，详情里也有一条），**只提示、不杀进程** ——
  要不要中止由你点「取消当前」决定（"取消当前"与"停止后续"仍是两套独立语义）。
  任务一收尾百分比立刻消失（失败的包绝不会显示"解压失败 100%"）。
- **一键处理 · 本次选项面板**：点「一键处理」时**先问一次**这一次怎么跑 ——
  **本次落点**二选一 / **指定位置** / **终端落法** / **源包处理**，外加
  ☐「把本次选择存为默认」与 ☐「以后不再询问，直接按设置走」。
  整批**只问这一次**（50–200 个包不会逐个问）；面板上的每一项默认值都取设置里的当前值，
  所以"直接点开始"与"没有面板"的行为完全一致。
  ⚠ **不勾「存为默认」时 `appsettings.json` 一个字节都不会改**（有回归测试钉住文件字节哈希）；
  勾了才把这一组选择写进设置。**无界面宿主**（自动测试 / 控制台）下不弹窗、不死等，直接按设置值继续。
  本次实际用的落点会写进**日志**、**任务详情**（失败清单第二级与「复制任务信息」），
  所以"这次为什么解到这里"事后能回答。落点仍然只有一处实现（`OutputPlacement`），面板只是运行期覆盖。
- **可恢复**：中间产物放在 `<程序目录>\data\work`；中断/取消时**不发布、不清理**，
  启动时报告未完成的工作区（只报告，不自动删）。
- **中间工作区不留垃圾**：任务**成功且产物已经发布**之后，两处工作区都会被清掉 ——
  本任务抠出来的内嵌归档（`data\work\<任务名>\`，双面文件动辄几百 MB；**走直读时根本没有这一份**）
  与**递归解压的逐层工作区**（`data\work\recursive\<任务号>\`，成功一次同样可能是几百 MB）；
  删前删后各写一条日志，删失败只记 WARN、**不会**让已经成功的任务变成失败。
  取消 / 部分完成 / 校验失败 / 越界检出时**一律保留**（这些中间件是用户唯一的线索）。

## 设计边界（对用户的承诺）

下面五条是**承诺**，不是"目前还没做"。它们决定了这个工具是什么、不是什么 ——
与 WinRAR 这类"压缩管理器"的能力边界差别，逐条理由见 `docs/WinRAR功能参考.md`：

| 承诺 | 含义 |
|---|---|
| **只读归档，绝不修改 / 回写压缩包** | 不建包、不修包、不改注释、不改分卷、不锁包：对归档**只做"读 + 解压"**。识别出后缀被改坏时，改的是**你自己选中的文件名**（先预览再改），从不碰压缩包里的内容 |
| **检出产物越界即整包失败** | 产物一旦越出目标根目录（含"产物目录里混进了目录联接点 / 符号链接"），就是**整包失败结论**：**不归集、不处理源包、其余物不生成**，原因写进任务状态与错误信息 —— 不会只留一行日志却照样报"解压成功" |
| **失败 / 部分完成 / 取消时源包原地不动** | 只有"内容物已定稿 + 输出校验通过 + 未取消 + 属于本任务分卷组"四条同时成立，才可能按你选的档位动源包（默认移入 `其余物`；`KeepInPlace` 档一个字节都不搬） |
| **绝不默认覆盖** | 同名一律走"跳过或自动重命名"（默认 `AutoRename` → `名字(1)`）；即使选了覆盖，也是"先挪到临时名 → 落位成功 → 再删旧的"，不做"先删后移" |
| **不联网、不写系统盘** | 不自动下载任何引擎、不上传任何东西；配置 / 日志 / 临时文件 / 工作区都在 **`<程序目录>\data\`**（`%AppData%` 与 C 盘缓存都已被明确否掉） |

## 怎么拿到（打包命令 + 产物位置）

```powershell
pwsh -File scripts/package.ps1                 # 框架依赖版（默认，体积小）
pwsh -File scripts/package.ps1 -SelfContained   # 独立版（自带 .NET 运行时，体积大）
```

| 产物 | 位置 |
|---|---|
| 分发目录（解压即用） | `dist\ArchiveFixer-<版本>\`；独立版另开一个目录 `dist\ArchiveFixer-<版本>-独立\`（两档互不覆盖） |
| 分发的 zip | `dist\ArchiveFixer-<版本>-框架依赖.zip` / `dist\ArchiveFixer-<版本>-独立.zip`（zip 里带一层同名顶层文件夹，解压即得一个现成目录） |
| 发布中间产物与 publish 日志 | `E:\DeepSeekProjects\_tmp\ArchiveFixer\package\`（临时目录，不入仓库） |

脚本做五件事：`dotnet publish -c Release` 到临时目录 → 组装分发目录（exe 与运行时文件 +
`tools\7zip\`（含 `License.txt` / `README.md`）+ `tools\unrar\`（含 `license.txt` / `README.md`）+
`LICENSE` + `README.md` + `使用说明.md`）→ 打 zip → **自检** → 汇总。

硬要求（脚本里都实现了，别绕过它手工打包）：

- **版本号从 `ArchiveFixer/ArchiveFixer.csproj` 的 `<Version>` 读**，**不写死**在脚本里；
- **幂等**：同一档重复跑先清掉自己那一份（同名分发目录 + 同名 zip）再重建；另一档的产物不受影响；
- **自检**：zip 里必须能找到 `ArchiveFixer.exe`、`tools/7zip/7z.exe`、`tools/unrar/UnRAR.exe`、`LICENSE`
  四样（另加两份第三方许可文本与 `README.md` / `使用说明.md` —— 它们是分发合规项），
  并断言包里**没有** `data\` / 密码本 / 日志 / 样本 / 测试文件；
  **缺任何一样就删掉这个 zip 并非零退出**，绝不产出半成品；
- **被占用就明确报错**：分发目录里的程序正在运行（或被别的进程占着）时，脚本直接报错让你先关程序，
  **不静默失败、也不替你去杀进程**；
- 分发目录里**没有** `.pdb`（分发包只需要能跑；要连调试符号一起发就加 `-IncludeSymbols`）。

| `MaxParallelExtractCount` | ✅ ②解压方式 → 并发与空间 | 并发解压数（1~8，**默认 4**）；**真的生效**，不是摆设。默认值由 1 改成 4 的依据是 2026-09-22 的**并行实测**：并发 1→4 吞吐 **3.08×**（保守 2.70×），**4→8 只再快 1.9%**，而单包耗时 6.63→10.91 s（+108%）、整机 CPU 均值 48.7%→72.7% —— 根因是 6 物理核超订（第 1 波 8 个并发单包 11.9–14.2 s，降到 4 个立刻回到 5.9–6.8 s）；正确性三档 36/36 逐字节一致、心跳三档无 >400 ms 卡顿、取消语义 6/6 通过。界面上这一项旁边写着「建议不超过物理核心数（当前检测到 N 核）」，同一个分组里还有「全速」与「按空间算建议」。⚠ 它与 `LowProcessPriority` 是**两个互相独立的旋钮**，改一个不会动另一个。⚠ 并发越高，"同时在盘上的峰值"越大 —— 空间不够时程序会在启动前拦下装不下的任务（状态「磁盘空间不足」） |
| `DangerousSpaceModeEnabled` | ✅ ②解压方式 →「高风险区」红按钮 / ③清理与删除 | **危险模式**（默认关）：并行解压，每个任务成功后立刻彻底删它自己的其余物（源包 + 中间件，不进回收站）。**失败 / 部分完成 / 取消一律不删**。⚠ **没有自测凭证时这个开关会被自动关回去**（手改 json 也一样）——这是自测协议唯一能自动执行的地方。风险四条写在确认框、②页「高风险区」与 `docs\使用说明.md` §12.4 |
| `DangerModeSelfTestStamp` | ⚠ 只能由自测写 | 「自测通过」的凭证（形如 `自测通过\|2026-09-22 21:30:00\|并发=2\|样本=4`）。空 = 没自测过 → 上面的开关开不起来。它由②页那个红按钮那条路径**自动**写出，不建议手改；关掉危险模式**不会**清掉它（它记录的是"这台机器做过自测"这个事实） |
| `LowProcessPriority` | ✅ ⑥设置 → 启动时行为 | **低运行优先级**（默认开）：让本程序与它启动的解压进程让出 CPU / 磁盘优先级。**改完重启程序才生效**（启动时读一次） |
| `OpenOutputFolderWhenDone` | ✅ ②解压方式 → 解压前与完成后 | **定稿完成后在资源管理器里打开输出目录**（默认关）。只在"定稿成功 + 输出校验通过"后打开；失败 / 取消不打开，整批只开一次。只打开文件夹，**不会**把程序窗口置前或最大化（`AGENTS.md` §13 同精神） |
| `RestRemovalDefaultMode` | ✅ ③清理与删除 | 「其余物 / 空文件夹」清理的**默认档**：`RecycleBin`（默认，可从回收站还原）/ `Permanent`（彻底删除）。只是确认框里那个勾选框的默认状态 —— 删除前**永远**先预览 + 确认 |
| `ReportDangerousEntries` | ✅ ②解压方式 → 解压前与完成后 | **危险条目统计**（默认开）：在解压前那一遍条目预检里顺便数出 **22 种**可执行 / 脚本类后缀，把"本包含 N 个可执行 / 脚本类条目"写进**任务详情窗口与失败清单**。**只提示、绝不阻断** |
| `EnginePriority` | ✅ ②解压方式 → 引擎 | **引擎优先级**（默认 `["winrar","sevenzip"]`）。规则是**先按能力筛、再用优先级做 tiebreaker**，不可用的引擎直接跳过 —— 排第一但没装不会导致打不开包。界面只能上移/下移；落盘的顺序就是生效顺序（点「保存设置」时立刻推给引擎层，不必重启） |
| `CustomSevenZipExePath` / `CustomUnRarExePath` | ✅ ②解压方式 → 引擎 | 自选外部工具路径。**留空 = 自动**（7z：程序内置 `tools\7zip`；UnRAR：用户自选 → 已装 WinRAR 目录 → 内置 `tools\unrar`）。⚠ 填了一个**不存在**的文件时，点「保存设置」会被拦下并说明改法（以前是"设置已保存"+ 静默丢弃这一格 —— 有测试钉住现在不会） |
| `CustomRarExePath` | ✅ ②解压方式 → 引擎 | **打包**做外层 rar 时用的 `Rar.exe`（2026-09-23 加的界面入口）。⚠ 它指向的是**你自己安装 / 下载的 WinRAR** 里的那一份：程序只检测与调用，**绝不随包分发**（WinRAR 是共享软件）。留空 = 自动用本机已装 WinRAR 目录里的那一份；填了不存在的文件同样**拦在保存之前**。没装 WinRAR 也可以把⑤打包页的外层容器改成 7z 或"不做外层" |
| `KeepBrokenFiles` | ✅ ②解压方式 → 引擎 | **保留受损的文件**（默认关）：校验和错误的半成品**留不留**。⚠ 只对 RAR 引擎（UnRAR）生效 —— 7-Zip **没有** `-kb` 这个开关（实测 `Unknown switch: -kb`，退出码 7），它本来就保留半成品。⚠ 它与成败判定**无关**：留着半个文件仍然是"失败 / 部分完成" |
| `RecursionMode` / `MaxRecursionDepth` | ✅ ②解压方式 → 嵌套与覆盖 | 递归模式（默认 `SingleLayer`）与最大层数（1~10）；改完当场生效，不必重启 |
| `CollectResultsToDirectory` / `CollectTargetDirectory` | ✅ ②解压方式 → 解压前与完成后 | 结果归集开关与目标目录 |
| `SourceHandling` | ✅ ③清理与删除 | 怎么处理源包：`MoveToRest`（默认，移入其余物）/ `KeepInPlace`（不动）/ `DeleteAfterVerify`（校验通过后删）。**一键处理与手动「只解压」读的是同一档**（用户 2026-09-22 版本二） |
| `DeleteSourceAfterExtract` | ✅ ③清理与删除 | 老的地基清理开关（默认关）：**只在 `SourceHandling = KeepInPlace` 的手动「只解压」路径上参与**，且只有"解压成功 + 校验通过"才删 |
| `RemindBeforeExtract` | ✅ ③清理与删除 | **解压前的提醒**（**默认开**，用户 2026-09-24 第 15 条要求可关）：每次解压前扫一遍源目录，列出"可能的无用物"与"一个可用密码都没有"的包。关掉 = **不扫也不弹**，直接开始 |
| `EnableSidecarPassword` | ✅ ④密码 | 从压缩包同目录的说明文件里提取密码候选（默认关） |
| `EnableLog` | ✅ ⑥设置 → 日志 | 是否往 `data\logs` 追加文件日志（默认开；屏幕日志不受影响） |
| `RememberLastOutputDirectory` | ✅ ⑥设置 → 启动时行为 | 启动时是否把上次的输出目录填回「当前输出位置」。⚠ 主窗口**没有**临时改输出目录的入口（输出位置只在②解压方式页改），所以它的实际作用就是"要不要沿用上次那个自定义根" |
| `CacheRootDirectory` | ✅ ⑥设置 → 缓存与工作区目录 | 日志 / 临时 / 递归工作区 / 配置的根目录。留空 = 程序目录下的 `data`；**填了不能是 C 盘**（点「保存设置」时会被拦下并说明改法） |
| `PasswordBookPath` | ✅ ④密码 → 导入密码本 | 上次导入的密码本路径，启动时若文件仍在就自动加载 |
| `PreviewBeforeRename` | ⚠ 无（已从界面移除） | ⚠ **这个键不产生任何行为差异**：改名**永远**先预览（不变量 3），主流程恒为 `true`。留着只是因为 `RenameOptions.FromSettings` 还会读它；将来连同它一起删 |

## 已知限制

这些是**已知且记录在案**的，不是"没想到"：

| 限制 | 说明 / 计划 |
|---|---|
| 密码明文出现在进程命令行 | **命令行引擎的固有限制**（7-Zip 与 UnRAR 都是 `-p<密码>`、打包功能的 rar 用 `-hp<密码>`，都会出现在进程列表里）；日志/报告/清单层已脱敏（`PasswordMasker` 同时掩 `-p` 与 `-hp`），但进程列表能看到。**不假装解决了** |
| **手动添加的密码默认跨重启保留**（本机加密；也可整个关掉） | 2026-09-24 起，密码列表的**内容 / 顺序 / 启用状态 / 手工条目 / 记住的密码本**按本机 **DPAPI（机器范围）** 加密存在 `<程序目录>\data\password-list.dat`（用户选定；跟 Windows 账号无关、不弹框、绝不写 C 盘），重启原样恢复；删除与清空会记**墓碑**，重启不许从密码本里复活。设置项「**记住密码列表**」**默认开**，关掉 = **既不写也不读**（磁盘上已有的那份不会被删），列表退回"只在本次运行内有效"。⚠ **代价**：机器范围意味着**同机任何本机用户都可能解开它**（它保护的是"文件被别人拿到也看不懂"，不是防住同机的其他账号）；**换机器 / 重装系统解不开** → 程序**忽略并提示**（不崩、不覆盖、不删文件），出路是在原机器上用「**写回密码本…**」把手工条目**追加**进你自己的 txt（写前自动备份成同目录 `.bak-日期时间`、只追加不重排、保持原编码与行尾、按值去重、空密码跳过、写完用解析器自检），⛔ 绝不写进 `appsettings.json`。另有一条容易撞上的边界：写回是追加到**密码本末尾**，而候选顺序里密码列表排在映射式命中与统一密码之后，条目多时会被「每层密码尝试上限」截断（状态是「达到密码尝试上限」，不是「密码错误」）—— 确认框与「未写回」标记上都写着这条提醒 |
| 进度只到"整包一个百分比" | 两台引擎报的都是**整包累计百分比 + 当前条目**，没有"第几个文件 / 还剩多少时间"这种粒度（7-Zip 的 `-bsp1` 与 UnRAR 的百分比都只有这些字段）；`ProcessedBytes/TotalBytes` 大多是未知，界面不会编一个数字出来。列目录（`l -slt`）那一步**故意不接进度**（要逐行解析，风险大于收益） |
| 压缩炸弹**拦不住已写出的那一次** | 只能"解压前按清单拦 + 解压后按实测量拦并停止后续"；7z 写盘时我们看不到它的写入 |
| 落点校验只看得见目标目录**里面** | 引擎绕过我们直接写到别的目录去，进程外发现不了。两道防线（解压前条目预检 + 解压后落点校验）也只能覆盖"产物目录内可观察"的越界；已经写出去的那一次同样拦不住 |
| 可疑条目只提示、不阻断 | `.exe` / `.scr` / `.lnk` 之类**只统计提示、绝不阻断**（设置项 `ReportDangerousEntries` 默认开，把"本包含 N 个可执行 / 脚本类条目"写进**任务详情窗口与失败清单**）；**不做** WinRAR 那种全局硬排除掩码 —— 我们的场景里安装器 / 补丁经常就是内容物。⚠ 它只是"数出来告诉你"，**不是**恶意软件判定，也没有任何"能不能打开"的结论 |
| 源文件变化检测**只比"大小 + 修改时间"** | **已实现**（`AGENTS.md` §6 第 11 条 / 设计.md 不变量 11）：扫描那一刻记下源包（分卷则整组）的大小与修改时间，**真正调引擎之前**对一遍，对不上就**不启动引擎**、状态落「**源文件已变化**」、错误信息点名是哪个文件哪一项变了（`大小 1.2 GiB → 1.3 GiB` / `修改时间 … → …` / `文件不见了`；分卷则点名是哪个卷），并给出出路「右键 → 重新扫描此文件」，与「分卷缺失」同一口径。这一拦**什么都没做**：引擎一次都没被调用、源包原地不动、`其余物` 不生成。⚠ 边界两条：**不比对内容哈希**（全量读一遍几百 GB 的分卷组代价不可接受），所以被别的工具"摸"过时间戳（甚至只是被某个程序打开过一次）也会触发；反过来，被换成**大小和修改时间都恰好一样**的另一份则检测不出来。比对点是**每次任务开工前**，解压进行中改了源文件拦不住那一次（与"压缩炸弹拦不住已写出的那一次"同一性质） |
| **空间门按"输出盘"核算** | 探的是**输出目录所在的那块盘**（开了结果归集时是归集目标盘）。工作区（`CacheRootDirectory`）被指到**另一块盘**时，那块盘不重复核算 —— 它写满时由引擎报错兜底（那时是「解压失败」，不是「磁盘空间不足」） |
| 空间需求是**估算**，不是保证 | 内容物能读清单时用真实数字；读不到（加密头 / 引擎拒绝列目录）时按源包体积估并标明"估"。估算**宁可高估**（不敢说够），所以偶尔会拦下本来勉强能跑的任务。内层包"再展开"的增量按它自身体积估（没有清单可查，只能给上界假设） |
| **取不到可用空间时不拦** | 盘未就绪 / 路径异常 / 网络盘取不到大小时，空间门**不做判断**（不把"探测失败"说成"空间不足"），只写一条 WARN。这种情况下写满仍由引擎报错兜底 |
| **危险模式的风险与边界**（用户 2026-09-22 明确要求如实写） | ① 源包**永久删除**（不进回收站、只能重新下载）；② 删除发生在"内容物已排好 + 校验通过"之后，但**校验不等于你确认过内容**；③ 断电 / 蓝屏 / 强杀可能停在"源包已删、内容物未完成"；④ 只在该用的时候用。另外三条边界：**自测只能证明"在这台机器 + 这几个样本上按预期工作"**，不能保证每一批都万无一失；**关掉模式不会找回已删的文件**；**没自测凭证时开关会被自动关回去**（手改 `appsettings.json` 也一样） |
| 自测本身不可逆 | 自测会**永久删除**样本文件（并发数 × 2 个，从需求最小的开始挑）的源包 —— 那正是它要验证的动作。凑不够样本时自测**不会开始** |
| 危险模式只保护"没成功的那些" | "失败 / 部分完成 / 取消 → 一个字节都不删"是硬规则，但它保护不了**成功之后你自己发现解错了**的情况 —— 那时源包已经没了。这正是风险第②条的含义 |
| 符号链接条目看不出来 | 归档条目列表里没有链接目标，名字干净的链接条目仍可能把内容写到别处；现在靠"解压后落点校验"发现（**发现即判失败，不归集、不清理**），但拦不住那一次写入 |
| 外接盘 / 网络路径未专门适配 | 是非目标（`AGENTS.md` §2）：只保证不写死盘符、不在源目录建工作区 |
| ~~`ResetSettingsCommand` 没有任何界面入口~~ | **2026-09-24 已解决**：界面重构之后，⑥「设置」页底部的「**恢复默认设置**」绑的就是它（带确认框），这条已知限制不再成立 —— 保留在此只是为了说明它曾经是死命令 |

| **内嵌归档直读的边界** | 直读只认 ZIP，且只在"中央目录声明偏移 == 从 EOCD 反推的实际起点 + 方法 ∈ {0 stored, 8 deflate} + 无加密位 + ZIP64 字段齐全 + 数据区不越过中央目录"时成立；任一条不成立就**回落**"抠取 + 7-Zip"（日志写明原因），加密条目 / bzip2 等方法 / 分卷 ZIP 都不猜。**递归模式**下第 0 层仍交给 7-Zip 展开，因此仍会抠一份副本（空间核算照实记那一笔）。已动过盘之后的失败（写盘失败、解出字节数与清单不符）**不回落**，如实报失败 |
