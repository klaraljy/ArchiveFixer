# 代码修改验收造包流程

> 适用版本：ArchiveFixer v0.2.4
> 状态：现行。用于**每次代码修改后的最小验收**，不是 125 批的替代品。

## 1. 定位

- 批次造包器：125 份固定批次，进 `备份位置`；
- 代码修改验收造包器：按改动模块造最小样本，进 `修改测试位置`；
- 两者脚本都放 `测试\造包器`，但**输出、用途、验收标准完全不同**，禁止混用。

## 2. 位置

```text
生成器：E:\DeepSeekProjects\ArchiveFixer\测试\造包器\代码修改验收造包.ps1
输出：  E:\DeepSeekProjects\ArchiveFixer\测试\修改测试位置\<yyyyMMdd-序号-名称>\
        ├─ 样本\
        ├─ 结果\
        └─ 日志\
```

示例：

```text
测试\修改测试位置\20261111-01-内容扫描准入\
```

## 3. 参数

建议统一入口：

```powershell
pwsh -NoProfile -File "E:\DeepSeekProjects\ArchiveFixer\测试\造包器\代码修改验收造包.ps1" `
  -ChangeId 20261111-01-内容扫描准入 `
  -Module ContentAdmission `
  -Shape content-scan
```

参数：

| 参数 | 说明 |
|---|---|
| `-ChangeId` | `yyyyMMdd-序号-名称`，决定输出目录；同名已存在时拒绝覆盖 |
| `-Module` | 改动模块，如 `ContentAdmission`/`Volume`/`Output`/`Packing`/`Source` |
| `-Shape` | 最小形状，如 `single`/`volume`/`disguised`/`content`/`packing` |
| `-Force` | 只重建本次 ChangeId，不删其它 |
| `-KeepWork` | 保留 `.build` 现场 |

一个总入口 + 必要的模块小脚本；所有脚本都放 `测试\造包器`。

## 4. 造包原则

- 只造验证本次改动所必需的最小内容；
- 不复制 125 批样本；
- 不写入 `备份位置`/`测试位置`/`指定位置`；
- 不修改 `测试\原物` 原物；
- 需要引擎/密码时使用现有 test tools；
- 每份样本必须带 `recipe.json`，字段至少：schemaVersion、changeId、module、shape、expectedOutcome、expectedSourceKeep、expectedProcessKeep、expected*、case 描述。

## 5. 验收流程

```text
改代码
→ 造最小样本
→ 跑定向测试/一键流程
→ 检查任务终态、输出、源包/过程物、日志
→ 结果写 结果\，日志写 日志\
→ 通过则保留记录；失败保留现场
→ 手动按清理流程处理
```

最低检查：

- 功能行为符合改动目标；
- 无回归到相邻模块；
- 日志能说明判据；
- 失败时源包/用户文件不被误删；
- 每次修改不靠 125 批代替。

## 6. 与批次的关系

- 简单验收通过后才允许跑 125 批；
- 125 批用于批次回归，不用于单次修改的快速验收；
- 简单验收的样本**不能**成为批次样本，除非按 `批次造包器更新流程.md` 正式纳入并更新 125 设计和自检。

## 7. 清理

- 修改验收目录不自动清理；
- 由用户/代理按 `造包清理流程.md` 手动清理；
- 清理只删 `修改测试位置\<ChangeId>`，不碰备份/造包器/原物/设计文档。
