
基线仍在：`H:\BaiduNetdiskDownload\困难大测试\大测试\916000000`（旧困难包 50 份）。

## 1. 阶段 0：骨架收口（不动任何样本形状）

### D1 能只跑一类

`-Mode All` 尊重 `-Section`。新增 `Get-ScopeIds`，返回本次要生成的 `(类别, 序号, ID)` 有序表；
All 与 Single 共用这一张表，循环边界只在一处定义。

### D2 单份重建，不整批擦

`Assert-SafeRoot` 拆成两个动作：

```text
Assert-BatchRoot      只校验：有 .120-generated 标记、标记内容等于 seed、顶层只有已知名字  —— 不删
Remove-TargetSamples  只删本次要重建的那几个样本目录
```

整批根目录永不整删。效果：改特定解压包不会碰到已验收的普通 50。

### D3 清单跟磁盘一致

`120-manifest.json` / `120-report.json` 改为**扫盘重建**：遍历批次目录下每份 `recipe.json`，
按 `sampleId` 排序写出。跑单份不再把 50 条清单冲成 1 条。
全量闸门只在 `-Section All` 且实际不等于 120 时报错。

### D4 空间 C / B 分开迭代

`-Section` 增加 `SpaceC`（C01–C15）与 `SpaceB`（B01–B10）；`-Only 0` 表示该类全部。

### D5 单份失败不打断整轮

主循环改成：

```text
foreach (目标样本) {
    try   { Generate-X }
    catch { 记录 {sampleId, error}；写 ERROR 日志；继续下一份 }
}
```

末尾有失败：清单/报告照常落盘，把失败写进 report，退出码 1。

### 阶段 0 判据

```text
① 连跑两次 -Mode All -Section Normal 结果一致，且不删 .logs
② 先跑普通 50，再跑 -Section Specific，普通 50 个目录仍在且文件大小不变
③ 跑完 -Section Normal，manifest 条数 = 磁盘样本数 = 50
④ -Section SpaceC -Only 3 出 C03；-Section SpaceB -Only 4 出 B04
⑤ 故意让一份失败（临时造一个非法名），其余样本仍生成完，report 里有该失败
```

## 2. 阶段 1：特定 20

1. 读 `E:\AF\大测试-造特定解压包.ps1`，产出形状表：每条的源包相对路径、包内结构、层数、
   格式、是否加密、落点（Original/Specified）、期望产物与字节。
2. 写成 `$SpecificShapes`：1–10 = 旧脚本书的 10 个形状（placement = Original）；
   11–20 = 新增 10 个（placement = Specified），候选按 `docs/120批造包器-最终口径.md` §5：
   直接单包 / 两层标准分卷 / 两层单包 / 三层单包 / 三层中间分卷 / 最后一层落在文件夹 /
   跨盘分卷 / 密码错误 / 空内容 / 指定位置+原位置各一份。
   —— 读脚本后先与旧的 10 个去重，保证"真正不同"，不许换名充数。
3. 扩展 `对拍.ps1`：按 recipe 的 `category` 选比较器。Specific 比
   `targets[].sourceRelative` / `expectedOutputRelative` / `expectedContentBytes` + `原包` 树。
4. 同 seed 跑旧脚本一份、新脚本 `-Mode All -Section Specific` 一份，逐份对拍。
5. 新增的 10 个没有基线，用生成器自检判：文件真实存在、字节等于声明、20 个形状两两不同。

## 3. 阶段 2：异常 25

1. 读 `E:\AF\大测试-造异常包.ps1`，列 20 个 case：源包路径、损坏方式、期望 outcome / reason。
2. 与 §6 的 5 个新异常去重：空归档 / ZIP EOCD 截断 / RAR 分卷头冲突 /
   内层最终组分卷缺片 / 同基名不同族强锚点。
3. 20 个旧 case 逐一对拍；5 个新的用自检。
4. 扩展比较器：Abnormal 比 `sourceRelative` + `expected.outcome` / `expectedReason` + `原包` 树。

## 4. 阶段 3：空间 C15 / B10

1. 读 `E:\AF\大测试-造空间不足20矩阵.ps1`，**先把 case 数数清楚**：旧脚本名是"20 矩阵"，
   而口径要 C01–C15 + B01–B10 = 25。缺的那几条才是新形状，不许拿重复档凑数。
2. C 保持矩阵结构：`packages[].fileName/sourceBytes/contentBytes/format/shape/corrupt/expected`、
   `space.freeBytes/reserveBytes/concurrency`、`expected.blocked[]/failed[]`。
3. B 保持特定解压形状，补 `expectedTaskFileName` / `expectedTaskFileNames`；B 没有 contentBytes，
   只有 contentFiles，期望字节由 contentFiles 算。
4. 扩展比较器：Space 比 `packages[]` + `space{}` + `expected.blocked[]/failed[]` + `原包` 树；
   B 额外比两个 task 字段。

