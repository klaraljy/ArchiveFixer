# 批次造包器更新流程

> 适用版本：ArchiveFixer v0.2.3  
> 状态：现行。只用于更新 125 批造包器本身；不用于普通代码修改验收。

## 1. 什么算“新批次/更新”

满足任一条件：

- 新增/删除/修改样本形状；
- 改分类数量（Normal/Specific/Abnormal/Space）；
- 改 8 场景矩阵；
- 改样本 ID/seed/recipe 字段；
- 改路径/命名/自检/备份闸门；
- 改原物或生成器依赖。

普通代码修改只在 `代码修改验收造包流程` 处理，不改 125 批次。

## 2. 先改设计文档

更新本目录：

- `批次造包流程.md`：构成、ID、8 矩阵、Normal/Specific/Abnormal/Space 明细；
- 本文件：版本、修改时间、变更原因、验证命令；
- 必要时 `测试操作流程.md` / `测试检测流程.md`：样本/矩阵变化影响。

设计文档未写清，不改脚本。

## 3. 版本与时间

- 生成器头部固定写：`# 版本：125-YYYYMMDD-NN；修改时间：YYYY-MM-DD`；
- 运行时 `$GeneratorVersion`、`$GeneratedAt` 写入 `125-report.json`；
- 每次更新递增版本号，不覆盖历史版本号；
- 变更记录写在本文件“版本记录”一节。

## 4. 修改步骤

1. 只改 `测试\造包器\造125批.ps1` 和必要的 `造形状-*.ps1`；
2. 不动 `测试\造包器\旧版`；
3. 不动已有 `备份位置` 的批次；
4. 改完先改文档/自检，再跑：

```text
-Mode SelfCheck
-Mode Single -Section <Section> -Only <N>
```

5. 单样本验证 recipe/manifest/大小/密码/期望；
6. 用新 seed（如 928000000）造整批 125；
7. 运行测试操作 + 检测；
8. 造包器 recipe 的 8 场景覆盖核对；测试操作按 20/20 表核对；
9. 通过后记录版本/seed/结果；失败保留样本和日志，不覆盖旧备份。

## 5. 自检

至少检查：

- 125 总数；
- Normal=55（45/5/5，30/25）；
- Specific=20、Abnormal=25、Space=15+10；
- ID 不重复、recipe 可读、manifest/report 完整；
- 造包器 recipe 的 8 场景至少各一份；测试操作另按 20/20 位置表核对；
- 备份已有 marker 时拒绝覆盖/改名；
- `-Force` 只重建点名样本；
- 原物/工具路径可读。

## 6. 回滚

- 生成器改坏：回退到上一个版本，不动已有备份；
- 新批次不合格：保留目录/标记 `失败`，不冒充合格批次；
- 旧 927/旧 -120 批次不参与回滚，不覆盖。
