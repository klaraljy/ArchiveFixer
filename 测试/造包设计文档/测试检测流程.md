# 测试检测流程

> 适用版本：ArchiveFixer v0.2.4
> 批次：125 批  
> 状态：现行。检测只读 recipe、操作记录、磁盘和日志，不修产物、不写备份。

## 1. 输入

```text
备份 recipe：测试\备份位置\<seed>-125批次-备份\<sampleId>\recipe.json
操作记录：  测试\日志位置\<seed>-125批次-日志\操作\<sampleId>.json
操作日志：  测试\日志位置\<seed>-125批次-日志\操作\<sampleId>\
测试磁盘：  测试\测试位置\... / 测试\指定位置\...
```

## 2. 输出

```text
测试\日志位置\<seed>-125批次-日志\检测\<sampleId>.json
测试\日志位置\<seed>-125批次-日志\汇总.md
```

检测结果必须带：

- sampleId/category/placement；
- 每条检查 id、期望、实际、绿/红；
- 红项原因；
- 日志中对应证据行/位置；
- 整批通过/失败计数。

## 3. 检测顺序

1. 读 recipe + 操作记录；
2. 读操作日志；没有日志直接红（“日志缺失”）；
3. 核对磁盘快照；
4. 按类别检查；
5. 按 8 场景矩阵检查覆盖；
6. 写单样本 JSON；
7. 汇总 `汇总.md`；
8. 有任何红项，整批不通过。

## 4. 通用检查

| 检查 | 内容 |
|---|---|
| G1 运行无异常 | 操作记录无异常/崩溃 |
| G2 类别/落点 | recipe 与记录一致 |
| G3 跑前快照 | 非空、可读 |
| G4 任务非空 | 至少一条任务 |
| G5 终态 | 每个任务有终态，不残留 Pending |
| G6 磁盘一致 | 记录与磁盘文件数/字节一致 |
| G7 工作区 | 成功后无残留工作区；失败按档保留 |
| G8 落点 | Original 不写指定位置；Specified 确实在指定位置 |
| G9 日志 | 必须存在；关键判据能对上 |

## 5. 按类别

### Normal

- 成功样本：内容文件/字节与 recipe 一致；落点正确；源包按档；最后一层过程物按档；组完整；
- 缺片 41–45：缺卷/部分完成，不误报成功，不调引擎；
- 坏片 46–50：损坏/部分完成，原因可定位；
- 51–55：同基名外层与内层不混组，只解对应组，不重复；
- 8 场景覆盖：Normal 1–40 的 8 组合至少各一份；位置 20/20；不要求每组 5 份。

### Specific

- 1–10/11–20 的层数/密码/分卷/落点；
- 密文/内层包/空内容/跨盘/文件夹结果；
- 与 recipe `expected*` 对齐。

### Abnormal

- 1–25 每项按 recipe 预期：
  - 缺卷/损坏/空包/跨盘/长路径/保留名/穿越/炸弹；
  - docx/xlsx 保护；
  - 同基名不同目录/双名/伪分卷；
  - 源包 docx 手动只拆；
  - EOCD/RAR/7z CRC/中央目录等坏包；
  - 同基名不同族不混组。
- 安全项：危险条目未落盘；错误路径没有写到外面。

### Space

- C01–C15/B01–B10：按 recipe `expected.blocked`/`failed` 核对；
- 空间门只拦预期项，不误报/漏报；
- 并发/排序/源包档符合 recipe。

## 6. 8 矩阵核对

检测必须把 Normal 1–40 的 8 组合列成表：

```text
Original × KeepInPlace × Keep/Delete
Original × DeleteInPlace × Keep/Delete
Specified × KeepInPlace × Keep/Delete
Specified × DeleteInPlace × Keep/Delete
```

判据：

- 位置必须 **20 份 Original / 20 份 Specified**；
- 源包、最后一层过程物纯随机，不要求各半；
- 8 个组合至少各出现一次，不要求每个组合 5 份；
- 每个样本的实际设置以操作记录为准，不用 recipe 的 scenario 覆盖记录；
- 每个样本的实际落点/源包/过程物与操作记录对得上；缺一列或位置不是 20/20 即红。

41–50、51–55 不参与本表；它们的设置仍按 recipe。

## 7. 日志检查

必须看，不是可选：

- 轮次/第一第二大步是否走到；
- 组分析/入口层/缺片；
- 内容物/APK/内容容器闸门；
- 引擎调用/退出码/密码上限；
- 定稿/校验/源包/其余物；
- `[性能]` 停顿与当前阶段（结合标记时间判断，不把后台清理当 UI 阶段）。

日志缺失、日志与任务终态矛盾、密码明文出现，均判红。

## 8. 通过标准

- 125/125 单样本检测无红；
- 8 场景覆盖表完整；
- 每份日志存在且关键事件可对上；
- `汇总.md` 写明通过/失败/跳过/红项；
- 红项必须带可复现路径与日志位置。

## 9. 禁止

- 检测阶段修改 recipe/磁盘/日志；
- 删掉失败样本“让批次变绿”；
- 只看操作测试绿就宣布批次通过；
- 把跳过当通过。
